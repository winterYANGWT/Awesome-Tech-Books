# 第 84 章 MD C++ baseline：从邻居表到热点定位

这一部分用四章完成一个端到端案例：把一个分子动力学（MD）模拟程序从 C++ 串行版本逐步迁移到 CUDA。本章先看 CPU 版本本身；[第 85 章](ch085.md)把最热的求力函数移植成 kernel；[第 86 章](ch086.md)讨论如何让主循环数据常驻 device；[第 87 章](ch087.md)用图把三个阶段的数据流放在一起比较。

> 本部分的示例选题参考了樊哲勇《CUDA 编程：基础与实践》（清华大学出版社，2020）。该书基于 CUDA 10.x 编写，部分工具和性能结论已经过时，这里只沿用示例思路。

## 84.1 问题的由来

前面各章讲了大量 CUDA 机制，但读者还需要看到一个真实程序是怎样被拆解的：哪些数据结构决定并行形状，哪个函数是热点，哪些数据必须留在 device，哪些优化不应该一开始就做。分子动力学程序正好适合做这样的端到端练习。

本章的 CPU baseline 包含邻居表、Lennard-Jones 力、最小镜像约定、速度-Verlet 积分、能量守恒检查和热点计时，这些共同构成了迁移之前的工程上下文。

## 84.2 核心模型

| 部分 | 工程含义 |
|---|---|
| `MdSystem` 结构体 | 保存位置、速度、力、势能、邻居表和盒子信息 |
| 邻居表 `nbr_count/nbr_list` | 限制 pair interaction 搜索范围 |
| `compute_forces_cpu` | 主要热点，适合先迁移到 GPU |
| Lennard-Jones | 每对粒子的力和势能计算 |
| 最小镜像约定 | 周期边界条件下修正相对位移 |
| 速度-Verlet | 主时间推进框架，用来验证模拟稳定性 |

## 84.3 详解

CPU 版本把粒子数据按“每个物理量一个数组”的方式放在 `MdSystem` 里。求力函数 `compute_forces_cpu` 先清零每个粒子的力和势能，再按邻居表遍历 pair：

```cpp
struct MdSystem {
    int count = 0;                    // 粒子数
    int max_nbr = 0;                  // 每个粒子最多记录多少个邻居
    double box_len = 0.0;             // 立方盒子的边长，三个方向都是周期边界
    std::vector<double> x, y, z;      // 位置
    std::vector<double> vx, vy, vz;   // 速度
    std::vector<double> fx, fy, fz;   // 力
    std::vector<double> epot;         // 每个粒子分到的势能
    std::vector<int> nbr_count;       // nbr_count[i]：粒子 i 的邻居数
    std::vector<int> nbr_list;        // 粒子 i 的第 k 个邻居：nbr_list[i * max_nbr + k]
};

// 最小镜像：周期盒子里每个粒子都有无数个像，位移取离得最近的那个
double nearest_image(double d, double len)
{
    return d - len * std::round(d / len);
}

// Lennard-Jones 力，约化单位（epsilon = sigma = 1），截断半径 2.5
void compute_forces_cpu(MdSystem& s)
{
    const double cutoff2 = 2.5 * 2.5;
    const double inv_rc6 = 1.0 / (cutoff2 * cutoff2 * cutoff2);
    const double e_shift = 4.0 * inv_rc6 * (inv_rc6 - 1.0);   // 平移势能，让它在截断处为 0
    std::fill(s.fx.begin(), s.fx.end(), 0.0);
    std::fill(s.fy.begin(), s.fy.end(), 0.0);
    std::fill(s.fz.begin(), s.fz.end(), 0.0);
    std::fill(s.epot.begin(), s.epot.end(), 0.0);

    for (int i = 0; i < s.count; ++i) {
        for (int k = 0; k < s.nbr_count[i]; ++k) {
            const int j = s.nbr_list[i * s.max_nbr + k];
            if (j < i) continue;   // 邻居表是双向的，每个 pair 只在 i < j 时算一次
            const double dx = nearest_image(s.x[i] - s.x[j], s.box_len);
            const double dy = nearest_image(s.y[i] - s.y[j], s.box_len);
            const double dz = nearest_image(s.z[i] - s.z[j], s.box_len);
            const double r2 = dx * dx + dy * dy + dz * dz;
            if (r2 > cutoff2) continue;
            const double inv_r2 = 1.0 / r2;
            const double inv_r6 = inv_r2 * inv_r2 * inv_r2;
            const double e = 4.0 * inv_r6 * (inv_r6 - 1.0) - e_shift;        // 这一对的势能
            const double f = 24.0 * inv_r2 * inv_r6 * (2.0 * inv_r6 - 1.0);  // 力的大小除以 r
            // 牛顿第三定律：i 受力 f·(dx, dy, dz)，j 受到大小相等、方向相反的力
            s.fx[i] += f * dx;  s.fx[j] -= f * dx;
            s.fy[i] += f * dy;  s.fy[j] -= f * dy;
            s.fz[i] += f * dz;  s.fz[j] -= f * dz;
            s.epot[i] += 0.5 * e;  s.epot[j] += 0.5 * e;   // 势能两个粒子各记一半
        }
    }
}
```

邻居表是双向的：`j` 出现在 `i` 的表里，`i` 也出现在 `j` 的表里。同一粒子的邻居在 `nbr_list` 里连续存放，第 `i` 行从 `i * max_nbr` 开始。邻居表通常按截断半径再加一层缓冲来构建，几步才重建一次，所以循环里还要再判断一次 `r2 > cutoff2`。势能减去 `e_shift` 是为了让它在截断半径处连续：不平移的话，粒子对每次跨过截断半径，总能量都会跳一下，能量守恒检查就看不出积分本身的误差了。

这个 CPU baseline 仍然是串行的双层循环，但已经暴露出并行结构：每个粒子的邻居计算可以分给不同线程。它也暴露了迁移风险：CPU 版本对 `i`、`j` 两个粒子同时累加力，直接并行化会产生写冲突。

## 84.4 代码示例

一个典型的 MD CPU 程序由几部分组成：初始化原子位置和速度，构建邻居表，在时间步循环中做速度-Verlet 积分并调用 `compute_forces_cpu`，统计能量和温度，按一定间隔输出。读这类程序时，建议先找到时间步主循环，看每一步调用了哪些函数、读写了哪些数组，再结合计时结果确定热点，这比从头逐行读更快。

## 84.5 工程判断

| 问题 | 判断 |
|---|---|
| 为什么先保留 CPU baseline | 它提供正确性、能量守恒和性能热点的参照 |
| 为什么先迁移 `compute_forces_cpu` | pair interaction 通常占用主要时间，且并行形状清楚 |
| 为什么不能机械复制 CPU 写法 | CPU 对 `i/j` 对称累加会在 GPU 上引入写冲突 |
| 迁移前应该测什么 | 总时间、`compute_forces_cpu` 时间、能量漂移、输入规模和邻居数 |

## 84.6 API 与要点速查

| 要点 | 说明 |

读完本章，你应该能够把一个科学计算程序拆成 baseline、热点、数据结构和正确性指标。写 CUDA 之前，先弄清要迁移哪一段、为什么迁移、迁移后怎么证明没算错。
