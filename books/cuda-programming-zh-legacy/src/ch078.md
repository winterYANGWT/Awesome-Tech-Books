# 第 78 章 Thrust prefix scan：从容器接口到 raw device pointer

这一部分讨论几个常用的 CUDA 库：Thrust、cuBLAS、cuSolver、cuRAND 和 cuFFT，最后用一章把调用这些库时的错误处理放在一起对照。每章都围绕一个最小示例，讲清楚这个库解决什么问题、调用路径是什么、工程上要注意什么。

> 本部分的示例选题参考了樊哲勇《CUDA 编程：基础与实践》（清华大学出版社，2020）。该书基于 CUDA 10.x 编写，部分工具和性能结论已经过时，这里只沿用示例思路。

## 78.1 问题的由来

很多 CUDA 入门材料会让读者先写 kernel，但真实工程里并不是所有并行操作都值得手写。前缀和、排序、规约、筛选这类通用数据并行操作已经由 Thrust 提供了稳定实现；动手之前，先判断自己是在写一个新算法，还是在表达一个已有的并行原语。

本章用前缀和（prefix scan）做例子，给出两条调用路径：一条使用 `thrust::device_vector`，另一条直接使用 `cudaMalloc` 得到的 device pointer。

## 78.2 核心模型

| 层次 | 读者应该看到什么 |
|---|---|
| 容器层 | `thrust::device_vector<T>` 管理 device 端序列，接口接近 STL 容器 |
| 算法层 | `thrust::inclusive_scan(first, last, out)` 表达并行前缀和 |
| 指针层 | raw device pointer 需要显式 execution policy，例如 `thrust::device` |
| 边界层 | 默认策略（`thrust::device`、`thrust::cuda::par`，或直接传 `device_vector` 迭代器）下，`inclusive_scan` 这类算法返回前会同步所在 stream；只有 `thrust::cuda::par_nosync` 允许算法在 kernel 完成前返回，这时 host 读结果前要自己同步 |

前缀和的输入是 `[1, 2, 3, ...]`，inclusive scan 的输出是 `[1, 3, 6, ...]`。本章关心的不是这个数学定义，而是一种工作习惯：先识别出通用并行原语，再决定是否需要手写 kernel。

## 78.3 详解

第一种写法使用 `device_vector`：

```cpp
thrust::device_vector<int> x(N, 0);
thrust::device_vector<int> y(N, 0);
thrust::inclusive_scan(x.begin(), x.end(), y.begin());
```

这条路径适合教学和原型验证。它把分配、释放和迭代器边界藏在容器里，读者能把注意力放在算法含义上。

第二种写法使用 raw device pointer：

```cpp
cudaMalloc((void **)&x, sizeof(int) * N);
cudaMalloc((void **)&y, sizeof(int) * N);
thrust::inclusive_scan(thrust::device, x, x + N, y);
```

这条路径更接近已有的 CUDA 工程。项目里往往已经有 `cudaMalloc` 得到的缓冲区，这时不需要为了调用 Thrust 重写数据结构，只要把 execution policy 和指针范围交给 Thrust。

## 78.4 代码示例

下面的程序把两种写法放在两个函数里，结构相同：在 device 上准备输入序列，调用 `thrust::inclusive_scan`，再把结果取回 host 检查。区别只在 device 内存由谁管理：

- `device_vector` 版本中，分配和释放由容器负责；
- raw pointer 版本中，`cudaMalloc`、`cudaFree` 和 host/device 之间的拷贝都要自己写，Thrust 只负责算法本身。

```cpp
// scan.cu：nvcc scan.cu -o scan
#include <thrust/copy.h>
#include <thrust/device_vector.h>
#include <thrust/execution_policy.h>
#include <thrust/scan.h>
#include <thrust/sequence.h>
#include <cstdio>
#include <vector>

const int N = 8;

void print(const char* tag, const std::vector<int>& v)
{
    printf("%-14s", tag);
    for (int a : v) printf(" %d", a);
    printf("\n");
}

// 写法一：device_vector 负责 device 内存的分配和释放
void scan_with_device_vector()
{
    thrust::device_vector<int> x(N, 0);
    thrust::device_vector<int> y(N, 0);
    thrust::sequence(x.begin(), x.end(), 1);             // x = 1, 2, ..., N
    thrust::inclusive_scan(x.begin(), x.end(), y.begin());
    std::vector<int> h(N);
    thrust::copy(y.begin(), y.end(), h.begin());         // 取回 host
    print("device_vector", h);
}

// 写法二：缓冲区由 cudaMalloc 分配，Thrust 只负责算法
void scan_with_raw_pointer()
{
    std::vector<int> h(N);
    for (int i = 0; i < N; ++i) h[i] = i + 1;
    int *x = nullptr, *y = nullptr;
    cudaMalloc((void **)&x, sizeof(int) * N);
    cudaMalloc((void **)&y, sizeof(int) * N);
    cudaMemcpy(x, h.data(), sizeof(int) * N, cudaMemcpyHostToDevice);
    // 裸指针本身不带“在 device 上”的信息，必须用 thrust::device 指明
    thrust::inclusive_scan(thrust::device, x, x + N, y);
    cudaMemcpy(h.data(), y, sizeof(int) * N, cudaMemcpyDeviceToHost);
    cudaFree(x);
    cudaFree(y);
    print("raw pointer", h);
}

int main()
{
    scan_with_device_vector();   // 两行输出都应是 1 3 6 10 15 21 28 36
    scan_with_raw_pointer();
    return 0;
}
```

建议把两个函数对照着读，这样能看清容器式接口和传统 CUDA 缓冲区是怎样接上的。为了短，程序省略了错误检查，补法见[第 83 章](ch083.md)。Thrust 是随 CUDA Toolkit 一起安装的头文件库，用 `nvcc` 编译即可，不需要额外链接库。

## 78.5 工程判断

| 场景 | 建议 | 原因 |
|---|---|---|
| 原型验证、教学示例 | 优先用 `device_vector` | 生命周期清楚，代码短，读者更容易看懂算法 |
| 已有 device buffer | 用 raw pointer 加 `thrust::device` | 避免为了调用库重排数据结构 |
| 性能热点已经明确 | 先用 Thrust 建 baseline，再决定是否手写 kernel | 避免过早优化 |
| 需要精确控制共享内存、warp 协作或融合多个操作 | 考虑手写 kernel | 通用算法库不一定表达复杂融合逻辑 |

## 78.6 API 与要点速查

上面的最小示例之外，实际使用时还要注意三点：

| 要点 | 说明 |
|---|---|
| 同步边界 | host 读取 `device_vector` 元素或调用 `cudaMemcpy` 时，会把 GPU 上的计算结果拉回 host，这里就是同步点；改用 `thrust::cuda::par_nosync` 后，算法返回不代表结果已经算完 |
| 错误处理 | 保留 CUDA Runtime 的错误检查；Thrust 的错误通常以 C++ 异常的形式抛出，需要单独捕获处理（见[第 83 章](ch083.md)） |
| 版本背景 | 示例只用到 Thrust 的基础调用方式；更高级的接口以所用 CUDA 版本的 Thrust 文档为准 |

## 78.7 小结

读完本章，你应该能够：

- 遇到 prefix scan 这样的通用数据并行操作时，先考虑 Thrust；
- 数据已经在 raw device pointer 中时，用 execution policy 把它接到 Thrust 算法上；
- 只有在算法库无法表达融合、访存或同步需求时，才去手写 kernel。
