# 第 80 章 cuSolver eigenvalue：workspace、devInfo 与状态检查

## 80.1 问题的由来

很多读者第一次见 cuSolver 会觉得它比 Runtime API 难读：求解之前还要先查询 workspace，参数里多出一个 `devInfo`，函数名里还有 `Dsyevd` 这样的 LAPACK 风格缩写。本章的例子给出一条完整路径：准备矩阵 → 查询 workspace → 求解 → 取回结果。

## 80.2 核心模型

| 组件 | 作用 |
|---|---|
| `cusolverDnHandle_t` | dense solver 的上下文 |
| `cusolverDnDsyevd_bufferSize` | 查询本次求解需要的 workspace 元素数 |
| `work/lwork` | device 侧临时工作区 |
| `devInfo` | device 侧状态码（示例中是 `dInfo`），求解结束后需要读回检查 |
| `jobz/uplo` | 控制是否计算特征向量、使用矩阵哪一部分 |

使用 solver API 要习惯两件事：先为数值算法准备足够的工作区；把状态码当作结果的一部分来处理，而不是指望“一个函数算出答案”。

## 80.3 详解

示例求一个 `dim` 阶实对称矩阵的特征值，矩阵已经拷到 device 上的 `dS`。核心路径如下：

```cpp
cusolverDnHandle_t solver;
cusolverDnCreate(&solver);

// 1. 先问库：这个尺寸、这组参数需要多大的 workspace（单位是 double 的个数）
int lwork = 0;
cusolverDnDsyevd_bufferSize(solver, CUSOLVER_EIG_MODE_NOVECTOR, CUBLAS_FILL_MODE_LOWER,
                            dim, dS, dim, dW, &lwork);

// 2. 按查询结果分配 workspace
double* work = nullptr;
cudaMalloc(&work, sizeof(double) * lwork);

// 3. 求解：特征值按升序写进 dW，dS 的内容会被改写，状态码写进 device 上的 dInfo
cusolverDnDsyevd(solver, CUSOLVER_EIG_MODE_NOVECTOR, CUBLAS_FILL_MODE_LOWER,
                 dim, dS, dim, dW, work, lwork, dInfo);

// 4. 把 dInfo 读回 host，0 表示成功，之后才能使用 dW
int info = -1;
cudaMemcpy(&info, dInfo, sizeof(int), cudaMemcpyDeviceToHost);

cudaFree(work);
cusolverDnDestroy(solver);
```

`CUSOLVER_EIG_MODE_NOVECTOR` 表示只要特征值；`CUBLAS_FILL_MODE_LOWER` 表示只读矩阵的下三角，对称矩阵的另一半是冗余的。参数里的两个 `dim` 分别是矩阵阶数和 leading dimension，和 cuBLAS 一样，矩阵按 column-major 存放。

`Dsyevd` 里的 `D` 表示 double，`syevd` 表示对称矩阵的特征值分解（`sy` 是 symmetric，`ev` 是 eigenvalue，`d` 表示 divide-and-conquer 算法）。读者不需要一开始就背完整的命名体系，但应该知道函数名里包含了数据类型、矩阵性质和算法族。

## 80.4 代码示例

把这些片段串起来，一次 dense 特征值求解的完整流程是：

1. 在 host 上准备实对称矩阵 `S`，拷到 device 的 `dS`；
2. 分配存放特征值的 `dW` 和状态码 `dInfo`；
3. 创建 handle，用 `cusolverDnDsyevd_bufferSize` 查询 `lwork`，再分配 `work`；
4. 调用 `cusolverDnDsyevd` 求解；
5. 把 `dInfo` 和 `dW` 拷回 host，先检查 `info`，再使用结果；
6. 释放 `work`、各个缓冲区和 handle。

下面的程序按这六步求一个 3×3 实对称矩阵的特征值。矩阵是用三个互相正交的方向和特征值 1、10、19 构造出来的，答案事先已知，可以直接比较：

```cpp
// eig.cu：nvcc eig.cu -o eig -lcusolver
#include <cuda_runtime.h>
#include <cusolverDn.h>
#include <cmath>
#include <cstdio>

int main()
{
    const int dim = 3;
    // 实对称矩阵，column-major 存放（对称矩阵按行、按列写出来一样）。
    // 手工核对：迹 13 + 10 + 7 = 30 = 1 + 10 + 19，行列式 190 = 1 × 10 × 19
    const double S[dim * dim] = { 13, -6,  0,
                                  -6, 10, -6,
                                   0, -6,  7 };
    const double expected[dim] = { 1.0, 10.0, 19.0 };   // syevd 按升序返回

    double *dS = nullptr, *dW = nullptr, *work = nullptr;
    int* dInfo = nullptr;
    cudaMalloc(&dS, sizeof(S));
    cudaMalloc(&dW, sizeof(double) * dim);
    cudaMalloc(&dInfo, sizeof(int));
    cudaMemcpy(dS, S, sizeof(S), cudaMemcpyHostToDevice);

    cusolverDnHandle_t solver;
    cusolverDnCreate(&solver);
    const cusolverEigMode_t jobz = CUSOLVER_EIG_MODE_NOVECTOR;   // 只要特征值
    const cublasFillMode_t uplo = CUBLAS_FILL_MODE_LOWER;        // 只读下三角
    int lwork = 0;
    cusolverDnDsyevd_bufferSize(solver, jobz, uplo, dim, dS, dim, dW, &lwork);
    cudaMalloc(&work, sizeof(double) * lwork);
    cusolverDnDsyevd(solver, jobz, uplo, dim, dS, dim, dW, work, lwork, dInfo);

    int info = -1;
    double W[dim];
    cudaMemcpy(&info, dInfo, sizeof(int), cudaMemcpyDeviceToHost);
    cudaMemcpy(W, dW, sizeof(W), cudaMemcpyDeviceToHost);

    int status = 0;
    if (info != 0) {                       // 先看 info，再决定 W 能不能用
        printf("cusolverDnDsyevd failed, info = %d\n", info);
        status = 1;
    } else {
        for (int i = 0; i < dim; ++i) {
            double diff = std::fabs(W[i] - expected[i]);
            printf("lambda[%d] = %.12f  expected %4.1f  |diff| = %.1e\n",
                   i, W[i], expected[i], diff);
            if (diff > 1e-10) status = 1;
        }
    }

    cudaFree(work);
    cudaFree(dInfo);
    cudaFree(dW);
    cudaFree(dS);
    cusolverDnDestroy(solver);
    return status;
}
```

第 5 步最容易被省略。这个程序读回了 `info`，但只做了最简单的判断，cuSolver 和 Runtime API 自己的返回状态也都没有检查；工程代码里三者都要检查，具体写法见[第 83 章](ch083.md)。编译时要链接 cuSolver 库（`nvcc` 加 `-lcusolver`）。

## 80.5 工程判断

| 场景 | 建议 |
|---|---|
| 第一次接入 solver | 先写 buffer size query、workspace 分配、状态检查三步骨架 |
| 求解失败或结果异常 | 同时检查 API 返回值和 `devInfo` |
| 多次同形状求解 | 复用 handle 和 workspace，减少重复分配 |
| 输入矩阵来自 row-major C++ 数组 | 明确布局转换或参数解释，不要默认当作 cuSolver 期望布局 |

## 80.6 API 与要点速查

| 要点 | 说明 |
|---|---|
| `devInfo` | 状态码是求解结果的一部分：为 0 表示成功，非 0 时按对应函数的文档解释 |
| 同步 | 读取 `W` 或 `devInfo` 前，要通过 `cudaMemcpy` 或显式同步确认求解已经完成 |
| 错误检查 | cuSolver status、Runtime API status、`devInfo` 是三类不同的结果，要分别检查 |

## 80.7 小结

读完本章，你应该能够把 solver 类库的调用看成四段：创建上下文、查询 workspace、执行求解、检查状态并取回结果。四段中缺了任何一段，代码都还不能直接用到工程里。
