# 第 48 章 Kernel 内部异步拷贝：LDGSTS 与 `cuda::memcpy_async`

`cudaMemcpyAsync` 是 host 提交的异步拷贝；本章讲的是 kernel 内部的异步拷贝：把 global memory 到 shared memory 的搬运变成可等待的异步操作。Compute capability 8.0 起，LDGSTS 硬件路径让 global-to-shared copy 不必先绕寄存器。

这类机制是 tiled GEMM、stencil、卷积等 kernel 的基础优化工具。

## 48.1 问题的由来

传统 global-to-shared：

```text
shared[t] = global[i];
__syncthreads();
compute(shared);
```

拷贝和计算严格串行。异步 copy 允许先发起 copy，再在等待前做一些独立工作，或配合 pipeline 做多阶段重叠。

## 48.2 核心模型

正确性的边界是：目标 shared memory 在 async copy 完成前不能被消费或覆盖。图 48.1 是这条数据路径：global memory 中的 tile 经 `cuda::memcpy_async`（硬件上对应 LDGSTS）进入 shared memory buffer，线程先通过 barrier 或 pipeline 等待拷贝完成，然后才能计算这块 shared tile。

## 48.3 详解

### 48.3.1 API 层级

| 层级 | 代表 |
|---|---|
| C++ 高层 | `cuda::memcpy_async` |
| Cooperative Groups | `cooperative_groups::memcpy_async` |
| C primitive | `__pipeline_memcpy_async` |
| PTX/硬件 | LDGSTS |

普通代码优先高层接口。底层 primitive 适合库或极限优化。

### 48.3.2 对齐

异步 copy 对对齐敏感。常见写法用 `cuda::aligned_size_t<N>` 表达对齐承诺：

```cpp
cuda::memcpy_async(block,
                   smem,
                   gmem,
                   cuda::aligned_size_t<16>(bytes),
                   barrier);
```

承诺不成立会导致错误或性能问题。不要为了性能随便写更高对齐。

### 48.3.3 Barrier 或 pipeline

`cuda::memcpy_async` 可以和 barrier 结合，也可以和 pipeline 结合：

- barrier：适合单次 async copy 后等待。
- pipeline：适合多阶段双缓冲/多缓冲。

### 48.3.4 参与者一致性

条件分支中 async copy 最容易出错。如果部分线程发起 copy，另一部分线程等待 barrier，expected count 或 transaction count 不匹配就会 hang。

## 48.4 代码示例

Barrier 版本：每个 block 把自己负责的 `tile` 个 float 异步拷进 dynamic shared memory，等拷贝完成后乘一个系数写回。

```cpp
#include <cooperative_groups.h>
#include <cuda/barrier>
namespace cg = cooperative_groups;

// 每个 block 处理 tile 个连续的 float：out = in * factor
__global__ void scale_tile(const float* in, float* out, float factor, int tile)
{
    extern __shared__ float buf[];   // 容量由 launch 的第三个参数给出
    __shared__ cuda::barrier<cuda::thread_scope_block> bar;

    cg::thread_block block = cg::this_thread_block();
    if (block.thread_rank() == 0) {
        init(&bar, block.size());
    }
    block.sync();

    const float* src = in + blockIdx.x * tile;
    // 整个 block 一起发起拷贝，完成情况记到 bar 的当前 phase 上
    cuda::memcpy_async(block, buf, src, sizeof(float) * tile, bar);

    bar.arrive_and_wait();           // 拷贝完成、所有线程到达后才返回

    for (int i = block.thread_rank(); i < tile; i += block.size()) {
        out[blockIdx.x * tile + i] = buf[i] * factor;
    }
}

// host 端：dynamic shared memory 的字节数要和 tile 对应
// size_t smem = tile * sizeof(float);
// scale_tile<<<n / tile, 256, smem>>>(d_in, d_out, 2.0f, tile);
```

`buf` 声明成 `extern __shared__` 的无界数组，它的实际大小不写在 kernel 里，而是由 launch 配置的第三个参数（字节数）决定，所以 host 端传入的字节数必须覆盖 `tile` 个 float。`cuda::memcpy_async` 由整个 block 共同调用，拷贝的完成被记到 `bar` 的当前 phase 上；`arrive_and_wait` 返回意味着这一 phase 的所有线程都已到达、拷贝也已完成，此后才能读 `buf`。

Pipeline 版本见[第 47 章](ch047.md)，核心是把 copy 放在 `producer_acquire/commit` 之间。

## 48.5 工程判断

| 需求 | 机制 | 注意点 |
|---|---|---|
| 单次 global-\>shared async copy | `cuda::memcpy_async` + barrier | 等待完成后才能读 shared |
| 多 tile 重叠 | `cuda::memcpy_async` + pipeline | stage 生命周期要正确 |
| group 风格代码 | `cooperative_groups::memcpy_async` | group 参与者一致 |
| 库级极限控制 | `__pipeline_memcpy_async` | 对齐和等待更容易写错 |
| 条件分支 copy | 统一参与集合或重构 | barrier count 不匹配会 hang |
| 大块多维 tensor tile | TMA | LDGSTS 更适合小块 element-wise |

## 48.6 API 与要点速查

Async copy 关键点：

| 项 | 说明 |
|---|---|
| LDGSTS | global-to-shared 硬件路径 |
| 方向 | 主要是 global -\> shared |
| 对齐 | 影响合法性和性能 |
| L1 behavior | 不同 copy size 可能走不同 cache mode |
| 等待 | barrier、pipeline 或 primitive wait |
| 同步 | copy 完成不等于所有线程都能无同步共享数据 |

API：

| 名称 | 用途 |
|---|---|
| `cuda::memcpy_async` | C++ async copy |
| `cooperative_groups::memcpy_async` | group async copy |
| `cooperative_groups::wait` | 等待 group async copy |
| `__pipeline_memcpy_async` | primitive async copy |
| `__pipeline_commit` | primitive commit |
| `__pipeline_wait_prior` | primitive wait |

## 48.7 小结

读完本章，你应该能够：

- 区分 host `cudaMemcpyAsync` 和 kernel 内 async copy。
- 解释 LDGSTS 的 global-to-shared 价值。
- 用 barrier 或 pipeline 等待 async copy。
- 识别条件分支和参与者不一致风险。
