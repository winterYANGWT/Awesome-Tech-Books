# 第 79 章 cuBLAS GEMM：column-major、leading dimension 和 handle 生命周期

## 79.1 问题的由来

矩阵乘法是 CUDA 入门中最常见的练习，但在工程里，很少需要把 GEMM 从零写成教学 kernel。更常用的能力是正确调用 cuBLAS，并且不被 column-major、leading dimension 和转置参数绕晕。

本章的示例把整条路径放在一个程序里：host 矩阵初始化、device 分配和拷贝、`cublasDgemm`，以及 handle 的创建和销毁。

## 79.2 核心模型

| 概念 | 含义 |
|---|---|
| handle | cuBLAS 库上下文，承载库调用所需状态 |
| column-major | cuBLAS 遵循 BLAS 传统布局，连续存储的是列 |
| leading dimension | 每一列在内存里的跨度；示例中 `A` 的 `lda` 是 `m` |
| alpha/beta | `C = alpha * op(A) * op(B) + beta * C` 的缩放系数 |

读 cuBLAS 代码时，第一步是把数学上的矩阵和它在内存里的布局分开看，而不是去背 API 参数。

## 79.3 详解

示例先用 host 数组准备 `A`、`B`，再把它们复制到 device 上的 `dA`、`dB`，结果写进 `dC`。库调用本身集中在下面几行：

```cpp
// C(m×n) = alpha * A(m×k) * B(k×n) + beta * C，三个矩阵都按 column-major 存放
const double alpha = 1.0;
const double beta = 0.0;            // beta 为 0 时不读 C 的原值，dC 不必初始化
cublasHandle_t blas;
cublasCreate(&blas);
cublasDgemm(blas, CUBLAS_OP_N, CUBLAS_OP_N,   // A、B 都不转置
            m, n, k,                          // C 有 m 行 n 列，归约维度是 k
            &alpha,
            dA, m,                            // A：m×k，一列 m 个元素，lda = m
            dB, k,                            // B：k×n，一列 k 个元素，ldb = k
            &beta,
            dC, m);                           // C：m×n，一列 m 个元素，ldc = m
cublasDestroy(blas);
```

这里的 `m, n, k` 对应结果矩阵 `C` 的形状（`m` 行 `n` 列）和归约维度 `k`；`dA, m`、`dB, k`、`dC, m` 则分别给出每个矩阵的 device 首地址和 leading dimension。矩阵紧密存放时，leading dimension 就等于矩阵的行数：column-major 下第 `r` 行、第 `c` 列的元素位于下标 `c * ld + r`，从一列走到下一列要跨过 `ld` 个元素。下面的程序用一个小函数 `at(r, c, ld)` 计算这个下标，填数、打印和 host 端核对都通过它进行。

## 79.4 代码示例

把上面的片段串起来，一个最小的 cuBLAS 程序大致是这样的骨架：

1. 在 host 上按 column-major 准备 `A`（m×k）和 `B`（k×n），并用三重循环算出参考结果；
2. 用 `cudaMalloc` 分配 `dA`、`dB`、`dC`，用 `cudaMemcpy` 把 host 数据写到 device；
3. `cublasCreate` 创建 handle，调用 `cublasDgemm`，用完后 `cublasDestroy`；
4. 用 `cudaMemcpy` 取回 `C`，按行打印，并和参考结果逐元素比较；
5. 释放 device 内存。

下面的程序用 2×3 的 `A` 乘 3×4 的 `B`，得到 2×4 的 `C`。三个矩阵都不是方阵，`m`、`n`、`k` 和三个 leading dimension 填错任何一个，结果都会对不上：

```cpp
// gemm.cu：nvcc gemm.cu -o gemm -lcublas
#include <cublas_v2.h>
#include <cuda_runtime.h>
#include <cmath>
#include <cstdio>
#include <cstdlib>
#include <vector>

// 这里只检查 Runtime API；cuBLAS 自己的返回状态留到第 83 章处理
#define CHECK_CUDA(call)                                               \
    do {                                                               \
        cudaError_t err_ = (call);                                     \
        if (err_ != cudaSuccess) {                                     \
            fprintf(stderr, "%s:%d: %s\n", __FILE__, __LINE__,         \
                    cudaGetErrorString(err_));                         \
            exit(EXIT_FAILURE);                                        \
        }                                                              \
    } while (0)

// column-major 下标：第 r 行、第 c 列，ld 是一列的跨度
int at(int r, int c, int ld) { return c * ld + r; }

int main()
{
    const int m = 2, k = 3, n = 4;          // A：m×k，B：k×n，C：m×n
    std::vector<double> A(m * k), B(k * n), C(m * n), expect(m * n);

    // A = [1 3 5; 2 4 6]，B = [1 2 3 4; 0 1 2 3; -1 0 1 2]
    for (int r = 0; r < m; ++r)
        for (int c = 0; c < k; ++c) A[at(r, c, m)] = 1 + r + 2 * c;
    for (int r = 0; r < k; ++r)
        for (int c = 0; c < n; ++c) B[at(r, c, k)] = c - r + 1;

    // host 参考结果：最直接的三重循环
    for (int r = 0; r < m; ++r)
        for (int c = 0; c < n; ++c) {
            double sum = 0.0;
            for (int p = 0; p < k; ++p) sum += A[at(r, p, m)] * B[at(p, c, k)];
            expect[at(r, c, m)] = sum;
        }

    double *dA = nullptr, *dB = nullptr, *dC = nullptr;
    CHECK_CUDA(cudaMalloc(&dA, sizeof(double) * m * k));
    CHECK_CUDA(cudaMalloc(&dB, sizeof(double) * k * n));
    CHECK_CUDA(cudaMalloc(&dC, sizeof(double) * m * n));
    CHECK_CUDA(cudaMemcpy(dA, A.data(), sizeof(double) * m * k, cudaMemcpyHostToDevice));
    CHECK_CUDA(cudaMemcpy(dB, B.data(), sizeof(double) * k * n, cudaMemcpyHostToDevice));

    const double alpha = 1.0, beta = 0.0;
    cublasHandle_t blas;
    cublasCreate(&blas);
    cublasDgemm(blas, CUBLAS_OP_N, CUBLAS_OP_N, m, n, k,
                &alpha, dA, m, dB, k, &beta, dC, m);
    cublasDestroy(blas);

    CHECK_CUDA(cudaMemcpy(C.data(), dC, sizeof(double) * m * n, cudaMemcpyDeviceToHost));

    // 按行打印 C，同时逐元素和参考结果比较
    int mismatches = 0;
    for (int r = 0; r < m; ++r) {
        for (int c = 0; c < n; ++c) {
            printf("%6.1f", C[at(r, c, m)]);
            if (std::fabs(C[at(r, c, m)] - expect[at(r, c, m)]) > 1e-12) ++mismatches;
        }
        printf("\n");
    }
    if (mismatches == 0)
        printf("all %d elements match the host result\n", m * n);
    else
        printf("%d elements differ from the host result\n", mismatches);

    CHECK_CUDA(cudaFree(dA));
    CHECK_CUDA(cudaFree(dB));
    CHECK_CUDA(cudaFree(dC));
    return mismatches == 0 ? 0 : 1;
}
```

正确的输出是 `C = [-4 5 14 23; -4 8 20 32]`。可以试着把 `cublasDgemm` 里的 `lda` 改成比 `m` 小的值：cuBLAS 会拒绝执行这次调用（终端上可能出现一行参数错误的提示），但程序本身没有检查 cuBLAS 的返回值，照样往下走，只能从最后的比较里发现结果不对，[第 83 章](ch083.md)处理的就是这个问题。编译时要链接 cuBLAS 库（`nvcc` 加 `-lcublas`）。矩阵紧密存放时，直接用 `cudaMemcpy` 整块拷贝就够了；cuBLAS 也提供 `cublasSetMatrix`/`cublasGetMatrix`，它们按 leading dimension 拷贝，适合只搬一个子矩阵的情形。这个例子练的是“调用成熟库”和“读懂矩阵布局”，不是优化手写 GEMM。

## 79.5 工程判断

| 问题 | 判断 |
|---|---|
| 要不要自己写 GEMM | 默认不要，先用 cuBLAS 建正确性和性能 baseline |
| 结果不对 | 先查 column-major、`CUBLAS_OP_*`、`lda/ldb/ldc`，再查数据传输 |
| handle 放在哪里 | 小例子可在函数内创建销毁，真实工程应复用并明确 stream 归属 |
| 与 C/C++ row-major 数据相接 | 可以调整转置参数或重新解释 leading dimension，但必须写清楚 |

## 79.6 API 与要点速查

| 要点 | 说明 |
|---|---|
| 错误检查 | 示例主要检查 Runtime API 的返回值；cuBLAS 函数返回的 `cublasStatus_t` 也要检查（见[第 83 章](ch083.md)） |
| stream 绑定 | 示例没有设置 stream；需要和其他异步工作排进同一条 stream 时，用 `cublasSetStream` 把 handle 绑定到该 stream |
| 版本背景 | 示例只演示基础调用方式；批量 GEMM、混合精度等扩展接口以 cuBLAS 官方文档为准 |

## 79.7 小结

读完本章，你应该能够用 `cublasDgemm` 建立矩阵乘法的 baseline，并能解释每个尺寸参数和 leading dimension 为什么这样填。矩阵布局没想清楚时，代码就算能跑通，结果也未必对。
