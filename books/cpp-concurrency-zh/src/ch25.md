# 第 25 章 进程：fork、exec 与回收

kvd 每来一个连接就 `fork` 一个子进程。客户端 A 在一条连接上 `SET k 1` 得到 `OK`，客户端 B 换一条连接 `GET k` 却得到 `NOT_FOUND`；客户端断开后，`ps` 里还留着一排 `Z`。

| 连接 | 请求 | 响应 |
|---|---|---|
| A | `SET k 1` | `OK` |
| B | `GET k` | `NOT_FOUND` |

两件事都出在进程边界上：`fork` 复制了地址空间，也复制了 fd 表；子进程退出后，父进程不 `wait` 就留下僵尸。

- 父进程里返回子进程的 PID，大于 0；
- 子进程里返回 0；
- 失败返回 -1 并设置 `errno`：`EAGAIN` 表示触及 `RLIMIT_NPROC`、`/proc/sys/kernel/threads-max`、`pid_max` 或 cgroup 的 `pids.max`，`ENOMEM` 表示内核结构分配失败。

父子都从 `fork` 的下一条语句继续，谁先运行由调度器决定；示例里靠 `waitpid` 把输出顺序固定下来，不靠调度顺序。

复制和共享的边界可以列成四项：

- **地址空间**：写时复制。子进程看到的是 fork 那一刻的内存内容，之后的修改互不可见。
- **fd 表**：表本身复制，表项是引用。父子各自的 fd 3 指向同一个打开文件描述，共享文件偏移和 `O_NONBLOCK` 等状态标志。
- **信号**：处置函数和信号掩码都继承，未决信号集清空。父进程装了处理函数，子进程里它仍然有效；`exec` 才把捕获的处理函数重置为默认。
- **内核资源**：锁、数据库连接、`epoll` fd 都会继承。子进程要么接着用，要么关掉，不要假设它“重新开始”。

`posix_spawn_file_actions_adddup2` 把管道的写端复制到子进程的 fd 1，父进程从读端读到 `hello from posix_spawn`。`posix_spawnattr_*` 还能设信号掩码、调度参数和进程组。实现上有三点：

- glibc 2.24 起用 `clone(CLONE_VM | CLONE_VFORK)`，子进程在 exec 前只做固定的清理工作；

- 它不是万能的：`file_actions` 只能表达 fd 操作，复杂的前置逻辑仍要自己写。

fork 之后、exec 之前，子进程只能调用 async-signal-safe 函数，下面这些调用都可能死锁：

- `printf` 可能卡在 stdio 锁上；
- `malloc` 可能卡在分配器锁上；
- `pthread_mutex_lock` 可能卡在父进程其他线程持有的锁上。

| 写法 | 是否替换映像 | fd 继承 | 错误报告 | 多线程安全性 |
|---|---|---|---|---|
| `fork` + `exec` | 子进程替换，父进程不变 | 除 `FD_CLOEXEC` 外全部继承 | fork 失败看 `errno`；exec 失败要在子进程里通过管道或退出码报告 | 子进程只能调 async-signal-safe 函数，锁状态被复制 |
| `posix_spawn` | 子进程替换，父进程不变 | 同样继承，可用 `file_actions` 增删 | 返回值就是错误码；exec 失败子进程退出 127 | 实现用 `CLONE_VM`/`CLONE_VFORK`，不执行父进程的锁代码；`file_actions` 能力有限 |
| `std::system` | 不替换：启动 `/bin/sh -c` 并等待 | 由 shell 和命令决定 | 返回值是 shell 的退出状态，`errno` 只在启动失败时有意义 | 内部 fork/exec 再 wait，和信号、SIGCHLD 处理混用时行为复杂 |

pthread 侧只有 `pthread_atfork`（[26.5 节](ch26.md)）能注册 fork 前后的回调；`std::thread` 只能建线程，不能建进程。

## 25.3 回收：waitpid、僵尸、孤儿与 SIGCHLD 合并

{{#fig ch25/zombie}}

第 2 步子进程退出，第 3 步它的表项以 `Z` 留下；第 4、5 步父进程 `waitpid` 取走退出状态，第 6 步内核才删除表项。

僵尸是“已经退出、父进程还没 `wait`”的进程；孤儿是“父进程先退出、自己还在运行”的进程，会被 init 或最近的 subreaper 收养。两者不是一回事。

`waitpid` 的返回值要分三种情况：

- 大于 0：回收了一个子进程，PID 就是这个返回值；
- 0：还有子进程，但都没有可报告的状态（只在 `WNOHANG` 下出现）；
- -1：出错；`ECHILD` 表示没有可等的子进程，`EINTR` 表示被信号打断。

所以回收循环必须一直调到 0 或 -1。`wait(&status)` 等价于 `waitpid(-1, &status, 0)`。

状态用宏解释：`WIFEXITED`/`WEXITSTATUS`、`WIFSIGNALED`/`WTERMSIG`、`WIFSTOPPED`/`WSTOPSIG`。`WIFSTOPPED` 是“被信号暂停”，不是“意外终止”；暂停的进程还可以 `SIGCONT` 继续。

{{#fig ch25/sigchld_coalesce}}

SIGCHLD 是标准信号，不排队：三个子进程先后退出，未决位始终只有一位，处理函数只被调用一次。所以处理函数里必须循环 `waitpid`；`waitpid` 是 async-signal-safe 的，`printf` 不是。

## 25.4 进程组、会话、资源限制与守护进程化

{{#fig ch25/session}}

终端属于原会话，shell 在前台进程组里。第一次 fork 的子进程调用 `setsid()` 成为新会话的首领，再 fork 的孙进程不再拥有控制终端。

终端的前台进程组会收到 Ctrl-C 的 SIGINT；终端关闭时，会话首领收到 SIGHUP。

`kill` 的第一个参数决定发给谁：

| `kill` 的 pid | 目标 |
|---|---|
| `> 0` | 指定进程 |
| `0` | 调用者所在的进程组，包括调用者自己 |
| `-1` | 除 init 外所有有权限的进程 |
| `< -1` | 进程组 `-pid` |

`kill(-pgid, sig)` 发给整个进程组，`kill(pgid, sig)` 只发给 PID 等于 `pgid` 的那一个进程，负号不能省。

改变进程组和会话的两个接口：

- `setpgid(0, 0)` 让当前进程自成一个进程组；
- `setsid()` 新建会话并成为会话首领，调用者不能已经是进程组首领，否则返回 `EPERM`。

`setsid` 之后，新会话最初没有控制终端。会话首领退出时，内核向前台进程组发 SIGHUP。

`getrlimit`/`setrlimit` 管的是每个进程（或每个真实用户）的上限：

- `RLIMIT_NOFILE`：每进程能打开的 fd 数，直接决定服务器能接多少连接；超过时 `open`/`accept` 返回 `EMFILE`，监听 socket 本身不受影响。
- `RLIMIT_NPROC`：真实用户 ID 下的进程/线程总数上限，`fork` 失败返回 `EAGAIN`。
- `RLIMIT_SIGPENDING`：真实用户 ID 名下排队信号的总数，Linux 2.6.8 起；它只对 `sigqueue` 强制，`kill` 仍可留下一个实例（如果同种信号还没有在排队）。

软限制是当前生效值，硬限制是软限制的上界。普通进程可以把软限制提高到硬限制以内，也可以降低硬限制；提高硬限制要 `CAP_SYS_RESOURCE`。

- 先停 `accept`，不再接新连接；
- 再给子进程发 SIGTERM；
- 最后循环 `waitpid` 回收。

输出里的 `residual zombie children: 0` 说明没有留下 `Z`。

父进程也可以用 `SIG_IGN` 或 `SA_NOCLDWAIT` 让内核自动回收，但那样拿不到退出状态，排错时少一条线索。

每连接一个进程的代价和取舍很直接：

- 连接数等于进程数，每个进程一套页表、栈和 `store` 副本；长连接多了，内存和上下文切换成本都上来。
- 每次 fork 都要复制页表、更新引用计数，连接建立得频繁时这部分开销也显出来。
- 子进程继承父进程的所有 fd，必须逐个关掉不用的，漏一个就多一点泄漏。
- 故障隔离好：一个子进程崩溃不会带走父进程和其他连接；代价是进程间共享数据要靠 IPC，这正是第 27 章 `kvd_shm` 要解决的问题。

服务器的退出顺序要固定：先停 `accept`（不再接新连接），再给子进程发 SIGTERM，最后 `waitpid` 到 `ECHILD`。只杀父进程会把子进程变成孤儿，连接和端口都可能留着。

| `waitid(P_PIDFD, pidfd, ...)` | pidfd 绑定的那个进程 | 能：句柄不随 PID 复用而改变 | 是 |
| `pidfd` + `poll`/`epoll` | 进程退出事件 | 能 | 否：还要再调 `waitid` |

`clone3`（Linux 5.3）能控制命名空间、退出信号等，但结构体带版本和大小，老内核或 seccomp 过滤可能返回 `ENOSYS`，要留回退到 `clone`/`fork` 的路径。glibc 2.34 起 `pthread_create` 就是先试 `clone3`、遇到 `ENOSYS` 再退回 `clone`；早期 Docker 的默认 seccomp 规则对 `clone3` 返回 `EPERM`，glibc 不回退，容器里连线程都建不起来，后来 Docker 改成返回 `ENOSYS`。

pthread 侧只对照 `pthread_atfork`（[26.5 节](ch26.md)）：它注册 fork 前、父进程、子进程三个回调，能处理已知的锁；没注册过的锁仍然可能在子进程里死锁。`std::thread` 不能创建进程。

## 速查

| 接口或写法 | 作用 | 默认/起始版本 | 坑 |
|---|---|---|---|
| `fork` | 复制当前进程 | POSIX | 返回两次；失败 `EAGAIN`/`ENOMEM` |
| `_exit`/`_Exit` | 子进程退出，不刷 stdio | POSIX | fork 后子进程该用它 |
| `exit` | 刷 stdio、跑 `atexit` | C 标准 | 子进程用它会重复输出父进程的缓冲 |
| `execve` | 替换进程映像 | POSIX | 成功不返回；默认保留 fd |
| `execl`/`execvp` | `execve` 的包装 | POSIX | 参数以 `NULL` 结尾；`p` 版本查 `PATH` |
| `posix_spawn` | 实现内部的 fork+exec | POSIX.1-2001；glibc 2.24 起用 `CLONE_VM`/`CLONE_VFORK` | 子进程 exec 失败退出 127；能力受 `file_actions` 限制 |
| `posix_spawn_file_actions_adddup2` | 子进程 fd 重定向 | POSIX.1-2001 | `dup2` 会清掉新 fd 的 `CLOEXEC` |
| `wait`/`waitpid` | 回收子进程 | POSIX | 循环到 0 或 -1；`WNOHANG` 不阻塞 |
| `WIFEXITED`/`WEXITSTATUS` | 正常退出状态 | POSIX | 先判断宏再取状态 |
| `WIFSIGNALED`/`WTERMSIG` | 被信号终止 | POSIX | `WTERMSIG` 是终止信号 |
| `WIFSTOPPED`/`WSTOPSIG` | 被信号暂停 | POSIX | 不是“意外终止” |
| `SIGCHLD` | 子进程状态变化通知 | POSIX | 标准信号不排队，必须循环回收 |
| `SIG_IGN`/`SA_NOCLDWAIT` | 让内核自动回收 | POSIX | 拿不到退出状态；默认处置不等于显式 `SIG_IGN` |
| `setpgid`/`setsid` | 改进程组/会话 | POSIX | 会话首领不能调 `setsid` |
| `kill` | 发信号 | POSIX | `0` 是本组，`-1` 是几乎所有进程 |
| `getrlimit`/`setrlimit` | 读/写资源限制 | POSIX | 提高硬限制要特权 |
| `RLIMIT_NOFILE` | 每进程 fd 上限 | POSIX | 满了 `open`/`accept` 返回 `EMFILE` |
| `RLIMIT_NPROC` | 真实 UID 的进程/线程上限 | POSIX | 满了 `fork` 返回 `EAGAIN` |
| `RLIMIT_SIGPENDING` | 真实 UID 的排队信号上限 | Linux 2.6.8 | 只对 `sigqueue` 强制 |
| `pidfd_open` | 取进程句柄 | Linux 5.3 | 句柄绑定进程，不随 PID 复用改变 |
| `waitid(P_PIDFD)` | 用句柄取退出状态 | Linux 5.4 | 仍然要回收 |
| `pidfd_send_signal` | 用句柄发信号 | Linux 5.1 | 不会杀错复用的 PID |
| `close_range` | 批量关闭 fd | Linux 5.9 | `close_range(3, ~0U, 0)` 关 3 及以上 |
| `prctl(PR_SET_CHILD_SUBREAPER)` | 收养孤儿 | Linux 3.4 | 只影响后代，不是全局 |
| `clone3` | 可控的进程创建 | Linux 5.3 | 老内核可能 `ENOSYS`，留回退 |

## 思考题

1. 把 `25_1_fork_stdio.c` 改成 `setvbuf(stdout, nullptr, _IONBF, 0)`，子进程仍用 `exit(0)`，重复输出还会出现吗？为什么？

   <details><summary>提示</summary>

   不会。无缓冲时每次 `printf` 立刻写出去，fork 时 stdio 缓冲里没有待刷的内容，父子都没有可重复的副本。`exit` 仍会跑 `atexit`，但不会凭空多出一行输出。把示例里的 `_IOFBF` 改成 `_IONBF` 跑一次即可验证。

   </details>

2. 25.3 的处理函数如果只调用一次 `waitpid`，在什么调度下会漏掉子进程？把 `SA_NOCLDWAIT` 打开后，`waitpid` 的返回值会怎样变化？

   <details><summary>提示</summary>

   多个子进程在 SIGCHLD 被屏蔽或处理函数运行期间先后退出时，标准信号只保留一个未决位，处理函数只会再进来一次，于是只收一个，其余留在 `Z`。打开 `SA_NOCLDWAIT` 后子进程不再变成僵尸：还有子进程在跑时 `WNOHANG` 返回 0，全部结束后返回 -1/`ECHILD`，不会返回某个子进程的 PID。

   </details>

3. kvd 用“每连接一个进程”和“每连接一个线程”，在隔离性、内存、fd 继承和故障恢复上各有什么代价？什么情况下进程版反而更合适？

   <details><summary>提示</summary>

   进程版隔离好，一个连接把堆写坏不会影响别的连接；代价是每连接一套页表、栈和 `store` 副本，fd 继承后要逐个关，跨连接共享数据要 IPC。线程版内存省、共享直接，但一个线程崩溃会带走整个进程，还要处理数据竞争。连接来自不可信用户、需要强隔离，或每个连接的计算会崩溃时，进程版更合适。

   </details>

4. 把 25.5 的父进程改成 subreaper，并让子进程再 fork 孙进程；SIGTERM 到来时，父进程要按什么顺序回收，才能既不留僵尸也不丢连接？

   <details><summary>提示</summary>

   先停 `accept` 并关监听 fd，不再接新连接；再给子进程（最好整组）发 SIGTERM，让它们处理完手头的请求再退出；然后循环 `waitpid(-1, ..., 0)` 到 `ECHILD`。subreaper 会把孙进程也收养到父进程名下，所以这个循环能同时收到子进程和孙进程；如果先退父进程，孙进程会被 init 收养，退出状态就收不到了。

   </details>
