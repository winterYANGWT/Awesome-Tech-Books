# 第 32 章 I/O 模型与 I/O 复用：select、poll、epoll

`select` 的 fd（文件描述符，file descriptor）集合只有 1024 位，连接一多就越界；换成 epoll 的 ET 后，压测又偶发卡住——监听 fd 只 `accept` 了一次，后面的连接一直躺在队列里。两个故障都出在“就绪之后该做什么”。

## 32.1 socket 接口回顾：一条连接的一生与就绪条件

{{#fig ch32/stream_framing}}

TCP 连接从 `socket` 开始：`socket(AF_INET, SOCK_STREAM | SOCK_NONBLOCK | SOCK_CLOEXEC, 0)`（Linux 2.6.27 起支持后两个标志）→ `bind` → `listen(backlog)`。

- `backlog` 只是提示，内核会用 `/proc/sys/net/core/somaxconn` 截断。

- `SOCK_CLOEXEC` 防止 `exec` 后把监听 fd 泄漏给子进程；服务器 `fork`/`exec` 外部程序时，这个标志比在 `exec` 前逐个关闭更可靠。

前三次读写刚好都是 16 字节，最后一组却一次读到了两条请求。TCP 只保证字节顺序，不保证读写次数对齐，所以服务器要自己定界。

- 一次 `recv` 可能只有半行，也可能包含多个请求。
- `send` 可能短写，返回值小于请求的字节数。
- `recv` 返回 0 表示对端关闭；返回 -1 且 `errno` 是 `EAGAIN`/`EWOULDBLOCK` 只表示暂时没数据。
- 被信号打断时返回 `EINTR`，要重试。

服务器必须自己维护输入缓冲和“请求到哪里结束”的增量解析。`listen` 的队列分半连接和全连接两段，`accept` 只是从全连接队列取走一个。队列满了以后，Linux 默认丢弃新的 SYN，客户端看到的是重传和超时，不是 `ECONNREFUSED`。

| 事件 | socket 的就绪条件 |
|---|---|
| 可读 | 接收缓冲区达到 `SO_RCVLOWAT`（默认 1 字节）、对端关闭、监听 socket 有新连接、socket 上有未处理错误 |
| 可写 | 发送缓冲区达到 `SO_SNDLOWAT`、写方向被关闭、非阻塞 `connect` 完成、socket 上有错误 |
| 异常 | 带外数据（out-of-band data） |

套接字选项要在正确的时机设，名字解析接口的线程安全也不同。

- `SO_REUSEADDR` 要在 `bind` 前设。
- `SO_REUSEPORT`（Linux 3.9）让多个执行体各自 `listen` 同一端口。
- `TCP_NODELAY` 关 Nagle；`SO_LINGER` 只对连接 socket 有意义。
- `getaddrinfo`/`getnameinfo` 可以在多线程中使用；`gethostbyname`/`getservbyname` 不行，要用 `_r` 版本。
- `inet_ntoa` 的返回值指向会被下一次调用覆盖的缓冲区；glibc 把它放在线程局部存储里，所以不跨线程竞争，但同一线程连续调用仍会互相覆盖。

## 32.2 I/O 模型：谁搬数据、谁通知谁

{{#fig ch32/io_models}}

前四种模型通知的都是“就绪”：数据从内核复制到用户缓冲，发生在应用随后调用的 `read`/`recv` 里，复制期间应用等着。只有 POSIX 异步 I/O 通知“完成”，调用返回时复制已经做完。

| 模型 | 应用阻塞在哪 | 复制在哪里完成 | 通知什么 |
|---|---|---|---|
| 阻塞 | `read`/`recv` | 同一次 `read` 里 | 无，调用返回即有数据 |
| 非阻塞 | 不阻塞 | 之后成功的那次 `read` 里 | 无，应用轮询或等复用 |
| I/O 复用 | `select`/`poll`/`epoll_wait` | 就绪后的 `read` 里 | 就绪 |
| SIGIO | 不阻塞 | 收到信号后的 `read` 里 | 就绪 |
| POSIX AIO | 不阻塞 | 内核或辅助线程在后台做完 | 完成 |

阻塞 `accept`/`recv`/`send` 可能挂起。

- 非阻塞版本立即返回 `EAGAIN`。
- 非阻塞 `connect` 返回 `EINPROGRESS`，要用可写事件加 `SO_ERROR` 判断结果（32.7）。
- 非阻塞 `connect` 只是把等待从 `connect` 挪到 `epoll_wait`，握手并没有变快；它的价值是能同时等很多个连接。
- SIGIO 的信号处理函数只能调用 async-signal-safe 函数，复杂处理要挪到事件循环。

## 32.3 select 与 poll：每次重建的位图和数组

{{#fig ch32/select_poll_copy}}

`poll(struct pollfd *fds, nfds_t nfds, int timeout)` 把兴趣和结果分开：`events` 输入、`revents` 输出，下次调用不必重置；`timeout` 单位毫秒，-1 无限、0 立即返回。

- `POLLERR`/`POLLHUP`/`POLLNVAL` 即使没有请求也可能返回。
- `POLLRDHUP` 是 Linux 2.6.17 的 GNU 扩展，要定义 `_GNU_SOURCE`。
- `nfds_t` 是 `unsigned long`，fd 数不受 65535 限制；每进程上限由 `RLIMIT_NOFILE` 决定，本机用 fd 70000 验证过。
- 每次调用都要把整个集合复制进内核并 O(n) 扫描；连接多、活跃连接少时，大部分扫描是浪费。

需要原子替换信号掩码时用 `pselect`/`ppoll`。`ppoll` 用 `timespec`，精度比 `select` 的 `timeval` 高。

连接数增加时线程数跟着涨：主线程加每个连接一个 worker，B 的 `GET` 几乎立刻完成，不用等 A。线程版的问题在连接数：1 万条长连接就是 1 万个栈和 1 万个调度实体，大部分时间在等 `recv`。

单线程 epoll 用一张事件表代替每连接一个线程：1 万条连接只占 1 个栈，只有就绪的连接才进入处理函数。代价是一个慢请求会拖住整个循环，所以回调里不能做阻塞操作。

`epoll_create1(EPOLL_CLOEXEC)`（Linux 2.6.27）建内核事件表，epoll fd 本身也要 `close`。`epoll_create(size)` 的 `size` 自 Linux 2.6.8 起被忽略，但仍必须大于 0（本机 `epoll_create(0)` 返回 `EINVAL`）。

- `epoll_ctl` 的 `op` 是 `ADD`/`MOD`/`DEL`。
- `events` 可带 `EPOLLIN`/`EPOLLOUT`/`EPOLLRDHUP`/`EPOLLET`/`EPOLLONESHOT`/`EPOLLEXCLUSIVE`。
- `data` 是 union，`ptr` 和 `fd` 只能用一个。

`epoll_wait` 返回就绪个数，0 是超时，-1/`EINTR` 要处理，`maxevents` 必须大于 0。`events` 只输出，开销与本次就绪的事件数成正比，不是 O(1)。

- `struct epoll_event` 在 x86-64 上是 12 字节的 packed 结构（本机 `sizeof` 为 12），不要假设自然对齐。
- 把连接对象的指针放进 `data.ptr`，可以避免 fd 被复用后事件投错对象。
- 关闭 fd 会自动从 epoll 集合删除；只要还有 `dup` 出来的副本指向同一打开文件描述，注册就还在。
- `epoll_pwait2`（Linux 5.11）用 `timespec` 表示纳秒级超时。

用 `data.ptr` 时，fd 只存在连接对象里；关闭连接要先把 fd 取出来，不能依赖 `data.fd`。

kvd_epoll 的每条连接有自己的 `Parser`、输入缓冲和输出缓冲。`recv` 读到 `EAGAIN` 后把解析出的响应追加到输出缓冲；`send` 短写就注册 `EPOLLOUT`，下次可写时从断点继续。

LT 模式下，接收缓冲还有数据时，下一次 `epoll_wait` 还会报告同一个 fd。ET 模式不重复报告，所以读循环必须一直读到 `EAGAIN` 才停。

| 对照项 | select | poll | epoll |
|---|---|---|---|
| 事件集怎么传 | 三组 `fd_set` 每次复制，返回时被改写 | `pollfd` 数组每次复制，`events` 不被改写 | `epoll_ctl` 注册一次，内核长期保存 |
| fd 上限 | `FD_SETSIZE`（1024） | 受 `RLIMIT_NOFILE` 限制 | 受 `RLIMIT_NOFILE` 限制 |
| 触发模式 | 只有 LT | 只有 LT | LT、ET、`EPOLLONESHOT` |
| 每次调用成本 | 复制并扫描全部 fd | 复制并扫描全部 fd | 与本次就绪数成正比 |
| 信号掩码原子替换 | `pselect` | `ppoll` | `epoll_pwait`/`epoll_pwait2` |
| 起始版本 | POSIX | POSIX | Linux 2.6 |

事件表不会像 `select` 那样每次整体复制，但每个注册项仍占内核内存。百万连接时这部分开销要单独粗略估算，不能只算用户态的连接对象。

## 32.5 LT 与 ET：触发次数、EAGAIN 与漏读

{{#fig ch32/lt_vs_et}}

LT（水平触发，level-triggered）是默认模式：条件仍成立就反复报告。ET（边缘触发，edge-triggered）只在状态变化时报告一次，所以 fd 必须非阻塞，并且一次把数据读到 `EAGAIN`。漏读会丢事件，直到下一次状态变化才可能再报。

ET 不是“效率更高”的同义词：它减少重复触发，但要求更多系统调用和更复杂的循环。活跃连接多时 epoll 未必比 poll 快。

## 32.6 一个连接归谁：EPOLLONESHOT、EPOLLEXCLUSIVE、SO_REUSEPORT

同一连接不能被两个线程同时读写。用 `EPOLLONESHOT` 把连接“借”给一个 worker，或把连接固定到某个 worker 的事件循环（第 35 章）。

多个执行体等同一个监听 fd 时，默认会被全部唤醒；`EPOLLEXCLUSIVE`（Linux 4.5）让内核优先挑一个等待者唤醒，减少惊群（thundering herd）。它不保证每次只唤醒一个。

- 默认模式下每次连接会唤醒多个 worker；加上 `EPOLLEXCLUSIVE` 后通常只唤醒一个。
- `EPOLLEXCLUSIVE` 不保证公平，也不保证每次只唤醒一个：同一个 worker 可能连续拿到多次唤醒。

同一个程序先跑默认模式，再跑 `EPOLLEXCLUSIVE`：每次连接的唤醒次数从多个降到通常一个。`EPOLLEXCLUSIVE` 只能用于 `EPOLL_CTL_ADD`，不能和 `MOD` 混用，也不能保证绝对公平；对同一个 fd 带 `EPOLLEXCLUSIVE` 做过 `ADD` 之后，再 `MOD` 会返回 `EINVAL`。

| 做法 | 谁 accept | 是否传 fd | 惊群 | 分布 | 复杂度 |
|---|---|---|---|---|---|
| 共享 listen fd | 任意一个被唤醒的执行体 | 否 | 有 | 由调度决定 | 低 |
| 共享 listen fd + `EPOLLEXCLUSIVE` | 被内核选中的一个 | 否 | 基本消除 | 由调度决定 | 低 |
| 各自 `SO_REUSEPORT` | 各自的 listener | 否 | 无 | 按四元组哈希，可能不均 | 中 |
| 父进程 accept 再传 fd | 父进程 | 是（`SCM_RIGHTS`） | 无 | 父进程控制 | 高 |

父进程 `accept` 后用 `sendmsg` 的 `SCM_RIGHTS` 把 fd 传给 worker，连接归属最清楚，但每连接一次进程间传递，父进程也可能成为瓶颈。

`accept4` 一次设好 `SOCK_NONBLOCK | SOCK_CLOEXEC`；遇到 `EMFILE` 要预留一个 fd 或暂时关闭监听，避免 `accept` 失败后立刻又回到 `epoll_wait` 空转。

`epoll_wait` 报告可写，`SO_ERROR` 却是 `ECONNREFUSED`：可写只表示“有结果”，不表示成功。

- `SO_ERROR` 读出后会被清除，不要读第二次。
- 失败要 `close`；成功后可保留非阻塞或恢复原标志。

同时连 100 个后端时，为每个连接保存 fd、目标地址、绝对截止时间和状态。所有 fd 注册 `EPOLLOUT`，事件到达后只做非阻塞的 `getsockopt` 和状态转移，绝不在单个连接上等待。

- 每个连接单独存 `SO_ERROR`，不要共用一个变量。
- 连接失败也要从 epoll 删除并 `close`，否则 fd 泄漏。
- `close` 不保证未发送的数据已经送达；需要确认对端收到，先 `shutdown(SHUT_WR)`，再等读方向关闭。
- 超时要自己算：`epoll_wait` 的超时会被其他 fd 的事件打断，返回后要用当前时间重算剩余。

`TCP_USER_TIMEOUT`（Linux 2.6.37）规定已发出的数据最多能多久得不到确认，超时就关掉连接；它不改变什么时候重传，也不管 SYN 超时。同时连 100 个后端时，用一个 epoll 等所有 fd 的可写事件，比每个连接一个线程省资源。

| 接口或写法 | 作用 | 注意 |
|---|---|---|
| `socket(AF_INET, SOCK_STREAM \| SOCK_NONBLOCK \| SOCK_CLOEXEC, 0)` | 建非阻塞、exec 时关闭的 socket | 两个标志 Linux 2.6.27 起 |
| `accept4(..., SOCK_NONBLOCK \| SOCK_CLOEXEC)` | 接受连接并原子设置标志 | 2.6.28 起；不继承监听 fd 的 `O_NONBLOCK` |
| `listen(fd, backlog)` | 开始监听 | backlog 受 `somaxconn` 截断 |
| `connect` | 主动建连 | 非阻塞时返回 `EINPROGRESS`，结果看 `SO_ERROR` |
| `recv`/`send` | 收/发字节 | 可能短读短写；`EAGAIN` 不是错误 |
| `shutdown`/`close` | 半关闭/关闭 | `close` 不保证未发送数据送达 |
| `fcntl(F_GETFL/F_SETFL)` | 读写打开文件描述的状态标志 | `dup`/`fork` 共享，改一个影响全部 |
| `select`/`FD_SET` | 等三组 fd 集合 | `FD_SETSIZE` 1024；集合每次重建 |
| `poll`/`struct pollfd` | 等一个数组 | `POLLERR`/`POLLHUP` 可能主动返回 |
| `POLLRDHUP` | 对端关闭写方向 | Linux 2.6.17，GNU 扩展 |
| `epoll_create1(EPOLL_CLOEXEC)` | 建内核事件表 | 2.6.27；epoll fd 要 `close` |
| `epoll_ctl` | 增删改兴趣表项 | `data.ptr` 与 `data.fd` 只能用一个 |
| `epoll_wait` | 取就绪事件 | 0 是超时；成本随就绪数增长 |
| `EPOLLIN`/`EPOLLOUT` | 可读/可写兴趣 | 事件到达后由 `events` 回填 |
| `EPOLLET` | 边缘触发 | fd 必须非阻塞，读到 `EAGAIN` |
| `EPOLLONESHOT` | 只触发一次 | 处理完用 `MOD` 重置 |
| `EPOLLEXCLUSIVE` | 减少惊群 | 4.5；通常只唤醒一个；只能 `ADD`，之后 `MOD` 返回 `EINVAL` |
| `EPOLLRDHUP` | 对端关闭 | 先读完数据再关闭 |
| `SO_RCVLOWAT`/`SO_SNDLOWAT` | 可读/可写的水位 | 默认都是 1 字节；`SO_SNDLOWAT` 在 Linux 上不可改 |

| `TCP_NODELAY` | 关 Nagle | 小请求低延迟 |
| `TCP_USER_TIMEOUT` | 已发数据最多多久得不到确认，超时关闭连接 | 2.6.37；不改变重传时机，不管 SYN |

## 思考题

1. 把 32.5 的 `32_5_lt_et_count.c` 每次读的缓冲从 10 字节改成 100 字节，LT 和 ET 的 `epoll_wait` 返回次数各是多少？如果 ET 只读 50 字节就停，下一次写数据还会触发吗？

   <details><summary>提示</summary>

   LT 读一次就取完 100 字节，返回 1 次；ET 也是 1 次。ET 只读 50 字节时，剩下的 50 字节不会再触发事件；但下一次写来新数据，Linux 会再通知一次（本机实测：读掉一部分后 `epoll_wait` 返回 0，再写新数据返回 1）。问题在于，如果之后再也没有新数据，剩下的数据就一直没人读，所以 ET 要循环读到 `EAGAIN`。

   </details>

2. 把 32.6 的 `EPOLLEXCLUSIVE` 代码从 `EPOLL_CTL_ADD` 换成 `EPOLL_CTL_MOD`，内核会返回什么？为什么？

   <details><summary>提示</summary>

   返回 `EINVAL`。`EPOLLEXCLUSIVE` 只允许出现在 `ADD` 的 `events` 里，`MOD` 一看到它就拒绝，不管之前有没有 `ADD`。要改事件掩码，先 `DEL` 再 `ADD`。

   </details>

3. 单线程 epoll、每连接一线程、每 worker 一个 epoll，在“1 万长连接、每连接每秒 1 个请求”下各自的瓶颈是什么？用 32.4 和 32.6 的实验说明。

   <details><summary>提示</summary>

   每连接一线程的瓶颈是线程数和栈内存，1 万条连接大部分在等 `recv`，调度和上下文切换占主导；单线程 epoll 的瓶颈是一个核的处理能力和回调里的阻塞操作；每 worker 一个 epoll 把连接分片，瓶颈变成分片是否均匀和跨 worker 的负载迁移。

   </details>

4. 把 32.7 的非阻塞 connect 用到“同时连 100 个后端”：如何组织 fd 数组、超时和 `SO_ERROR` 检查，才能不让一个慢连接拖住全部？

   <details><summary>提示</summary>

   每个连接一个状态机，全部注册到同一个 epoll 的 `EPOLLOUT`；用 `data.ptr` 指回连接对象，事件到达时逐个检查 `SO_ERROR`。超时用绝对截止时间加 `epoll_wait` 的超时重算，到期的连接单独 `close`，不要在一个连接上阻塞等待。

   </details>
