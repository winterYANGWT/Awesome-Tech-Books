# 第 8 章 信号量、闩与屏障

各线程算完自己的部分和，0 号线程负责汇总。汇总代码没有等别人：

```cpp
partials[i] = my_sum;          // 第一阶段：每个线程写自己那一格
if (i == 0) {                  // 第二阶段：0 号线程立刻合并
    total = partials[0] + partials[1] + partials[2] + partials[3];
}
```

结果偶尔偏小：0 号线程可能在其他线程写完之前就读了。加 `sleep(10ms)` 只是把窗口挪开，换一台机器又会坏；这里要的是“所有线程都到齐再继续”，也就是屏障（barrier）。

## 8.1 信号量：计数与通知

信号量（semaphore）是一个带计数的同步变量。`acquire()`/`wait()` 把计数减一，计数为 0 时阻塞；`release()`/`post()` 把计数加一并唤醒等待者。

它没有持有者：任何线程都能 `post`，不需要“谁锁谁解”。这让它适合做通知和计数，而不适合当互斥量用。

C++20 的接口在 `<semaphore>`：

- `std::counting_semaphore<LeastMaxValue>`：构造时给初值；`acquire()`、`try_acquire()`、`try_acquire_for()`/`try_acquire_until()`、`release(ptrdiff_t update = 1)`。
- `std::binary_semaphore` 就是 `counting_semaphore<1>`，只有 0 和 1 两个状态。
- `LeastMaxValue` 是“保证支持的最小上界”，`max()` 返回实际上界，可以更大。初值不能超过 `max()`；一次 `release` 的增量不能超过 `max()` 减当前计数，否则是未定义行为。

`try_acquire()` 允许在没有竞争时也返回 `false`（标准允许这种虚假失败），所以它只适合“试一次”，不能用来证明信号量已经空了。

## 8.2 生产者-消费者与消息环

有界队列需要两种保证：还有几个空位、几个元素；队列内部结构不被同时改。前者用两个信号量，后者用一把互斥量。

- 生产者：`empty.acquire()` → 锁住队列 `push` → 解锁 → `full.release()`。
- 消费者：`full.acquire()` → 锁住队列 `pop` → 解锁 → `empty.release()`。
- `empty` 初值是容量，`full` 初值是 0；获取顺序不能反，先拿 `full` 再拿 `empty` 会把两个方向的等待缠在一起。

图中队列只有 2 个槽位，方便看到阻塞：两个槽位满后，生产者卡在 `empty.acquire()`；消费者取走一个，归还一个空位，生产者的 `acquire` 才返回。信号量管“多少个”，互斥量管“怎么改”，两者不能互相替代。

| 项目 | 两个信号量 | 条件变量 |
|---|---|---|
| 等待的依据 | 计数本身（空位/元素） | 队列状态（`!empty() \|\| closed`） |
| 通知会不会丢 | 不会，许可留在计数里 | 会，`notify` 在 `wait` 之前发出就丢了 |
| 谁来通知 | 任何线程都能 `release` | 任何线程都能 `notify_one`/`notify_all` |
| 关闭队列 | 要额外的关闭标志或哨兵元素 | `closed` 标志加 `broadcast` |

8.1 的消息环也是这一节的做法：初值 0 表示“消息未到”，信号量只做通知，不携带数据。另外三点：

- `sem_wait` 是取消点。线程在等待时被取消，计数不会被它减掉；已经 `acquire`、还没 `release` 就被取消，许可就漏了。
- `eventfd` 也能做计数型通知，但它的语义是“这个 fd 可读”，不是信号量；需要把通知放进 `epoll` 时用它。
- C++20 信号量没有 `pshared`。跨进程的生产者-消费者要把 POSIX `sem_t` 放进共享内存，用 `sem_init(pshared=1)` 或 `sem_open`。

## 8.3 闩与屏障

`std::latch` 是一次性计数器：构造给计数，`count_down(n=1)` 减一，`wait()` 阻塞到 0，`arrive_and_wait(n=1)` 减一并等待，`try_wait()` 查询。减到 0 后永远保持就绪，不能重置；计数减过头是未定义行为。

`std::barrier` 可复用：构造给参与线程数和可选的完成函数，`arrive()` 返回 token，`wait(token)` 等那一轮结束，`arrive_and_wait()` 到达并等待，`arrive_and_drop()` 到达后退出后续轮次。每轮所有参与者到齐后，完成函数由一个线程执行一次，然后进入下一轮。

- 完成函数不能改变参与线程数：它没有返回值，标准也不允许借它调整下一轮人数；`arrive_and_drop` 是唯一减少后续参与者的接口。
- 完成函数必须不抛异常；它在本轮的完成步骤里执行，执行完才放行等待者。
- 计数减到 0 是 latch 的终点；barrier 的“到 0”只是本轮的终点，计数随后重置。

{{#fig ch08/latch_barrier}}

上半段是 latch：三个线程各 `count_down` 一次，计数到 0 后主线程的 `wait` 返回；latch 不能重置，之后再 `wait` 会立即返回。下半段是 barrier：同一个对象跑两轮，每轮到齐后一起继续。

|---|---|---|---|---|---|

## 8.4 自己实现屏障：忙等、信号量、条件变量

自己实现屏障，核心是三个变量：计数、代（generation）、以及“谁来重置”。最后一个到达的线程负责清零、推进代、唤醒其他人，等待者用代判断“我等的这一轮结束了没有”。`std::barrier` 内部也是计数 + 代 + 完成函数，只是把细节封装好了。

{{#fig ch08/barrier_impl}}

图里最后到达者是唯一的收尾者：它清零计数、把代加一、执行完成函数，再唤醒等待者。代的作用是让下一轮的到达和这一轮的等待分开。

- 每个线程把计数器加一，然后自旋到计数等于线程数。

| `std::counting_semaphore` | 构造参数 | 否，只在进程内 | 否 | 标准可抛 `system_error`；libstdc++ 15 不抛 | 无 | 否 |
| POSIX `sem_t` | `sem_init` 的 `value` | `pshared≠0` 且 `sem_t` 在共享内存 | `sem_open` | -1/`errno` | 无 | 否，不是 fd |
| System V 信号量 | `semctl(SETVAL)` | 是，内核对象 | key/`IPC_PRIVATE` | -1/`errno` | `SEM_UNDO` | 否，不是 fd |

System V 信号量（`semget`/`semop`/`semctl`）是另一套接口，操作的是信号量集；`SEM_UNDO` 只在进程退出时反向补偿它做过的修改，不是万能的。新代码优先 POSIX 信号量。

> **旧资料提示**：用 System V 信号量，或 `sem_init(pshared=1)` 却把 `sem_t` 放在普通栈上，都是旧写法。跨进程必须把 `sem_t` 放进共享内存；新代码优先 `sem_open`，或 `sem_init` 加 `mmap(MAP_SHARED)`。见 [41.6 节](ch41.md)。

## 速查

| 接口或写法 | 作用 | 注意 |
|---|---|---|
| `std::counting_semaphore<N>` | 计数信号量 | 初值和 `release` 增量不能超过 `max()`；只在进程内 |
| `std::binary_semaphore` | 0/1 信号量 | 就是 `counting_semaphore<1>` |
| `acquire` / `try_acquire` | 减一/试减 | `try_acquire` 允许虚假失败 |
| `try_acquire_for` / `try_acquire_until` | 带超时的获取 | `_for` 收时长，`_until` 收时间点 |
| `release(update=1)` | 加一并唤醒 | 增量过大是未定义行为 |
| `std::latch` | 一次性计数 | 到 0 后永久就绪；减过头是未定义行为 |
| `count_down` / `wait` / `arrive_and_wait` | latch 操作 | `arrive_and_wait` 等于 `count_down` 加 `wait` |
| `std::barrier` | 可复用屏障 | 完成函数每轮执行一次，不抛异常 |
| `arrive` / `wait(token)` | 到达与等待分开 | token 关联相位，不能跨轮混用 |
| `arrive_and_drop` | 到达并退出后续轮次 | 后续每轮期望人数减一 |
| `pthread_barrier_init` / `wait` / `destroy` | POSIX 屏障 | 没有静态初始化器；一个线程拿到 `PTHREAD_BARRIER_SERIAL_THREAD` |
| `sem_init` / `sem_destroy` | 初始化/销毁未命名信号量 | 跨进程时 `sem_t` 必须在共享内存里 |
| `sem_wait` / `sem_trywait` / `sem_post` | POSIX 信号量操作 | -1/`errno`；`EINTR` 要重试，`EAGAIN` 表示计数为 0 |
| `sem_open` / `sem_unlink` / `sem_close` | 命名信号量 | 名字以 `/` 开头；`unlink` 后已打开的句柄仍有效 |
| `mmap(MAP_SHARED)` | 放 `sem_t` 的共享内存 | `pshared=1` 只有在共享内存里才成立 |
| `#pragma omp barrier` | OpenMP 团队屏障 | worksharing 末尾通常有隐式屏障，`nowait` 取消 |

## 思考题

1. 预测：`8_2_bounded_queue_sem.cpp` 如果把生产者的 `empty.acquire()` 和 `full.release()` 顺序调换，容量为 1 时会怎样？容量为 8 呢？

   <details><summary>提示</summary>

   先 `full.release()` 再 `empty.acquire()`，消费者可能在元素还没入队时就被唤醒，`pop_front` 撞上空队列。这不是死锁，而是未定义行为：`pop_front` 要求容器非空。容量 1 和 8 都可能撞上，只是窗口大小不同；信号量的顺序必须与数据写入的顺序一致。

   </details>

2. 找错：`8_4_barrier_busy.cpp` 的忙等屏障只跑一轮为什么正常？第二轮需要改哪两个变量才能复用？

   <details><summary>提示</summary>

   只跑一轮时计数从 0 加到 4，到齐就结束，没有“清零”这一步。第二轮要同时有计数和代：计数只统计本轮到达，代标记轮次；等待者等代变化，最后一个到达者清计数、加代、唤醒。只清计数会让下一轮的增量被抹掉，只加代不清计数会让计数越积越大。

   </details>

3. 权衡：`std::barrier`、`pthread_barrier_t`、忙等屏障，在 4 个线程、1000 轮、每轮 1 微秒计算的情况下谁更合适？

   <details><summary>提示</summary>

   每轮计算只有 1 微秒，屏障的阻塞/唤醒开销占主导。忙等屏障在核数够、线程数少时可能延迟更低，但一直占着 CPU；`std::barrier` 会阻塞，开销稳定，跨平台；`pthread_barrier_t` 只在 POSIX 上可用，接口更底层。先用 `std::barrier` 测，再按测量结果换。

   </details>

4. 迁移：把 `8_5_sum_barrier.cpp` 改成“每个线程算完就 `arrive_and_drop`”，0 号线程还能安全合并吗？需要哪些额外条件？

   <details><summary>提示</summary>

   0 号在第一个屏障之后合并是安全的：`arrive_and_drop` 也参与本轮到达，完成步骤会等所有线程。问题在第二个屏障：四个线程都 drop 后，后续每轮的期望人数是 0，0 号再 `arrive_and_wait` 违反前置条件。要么只让 1–3 号 drop、0 号继续参加两个屏障，要么另用 `std::latch` 或原子量等第一轮完成，0 号不再碰同一个 barrier。

   </details>
