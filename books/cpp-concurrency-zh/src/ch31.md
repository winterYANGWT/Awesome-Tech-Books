# 第 31 章 分布式案例：并行排序、n 体与树搜索

4 个进程的奇偶排序结果正确，换成 16 个进程却每人才分到 1 个键值，每个阶段都在通信。空闲计数器版会提前退出，把还在路上的工作丢掉；能量版要收齐 p 单位才停。

三个案例——并行排序、n 体、TSP 树搜索——串行算法都不难，难的是把比较、受力和搜索任务切开之后，通信模式与终止条件跟着改。

## 31.1 从冒泡到奇偶交换：算法变换

{{#fig ch31/odd_even_phases}}

冒泡排序的第 i 轮依赖第 i−1 轮，不能把所有比较同时放开。奇偶交换把阶段分成偶阶段和奇阶段：偶阶段比较 `(0,1),(2,3),…`，奇阶段比较 `(1,2),(3,4),…`，同一阶段内的比较不重叠，可以并行。n 个元素至多 n 个阶段排好。

- 每个阶段只比较相邻元素，阶段之间必须按顺序；
- 串行版看到“没有交换”可以退出，并行版不能各块单独退出。

偶阶段 rank 与 `rank^1` 配对，奇阶段奇数 rank 找 `rank+1`、偶数 rank 找 `rank-1`，越界就置 `MPI_PROC_NULL`。p 为偶数时 0 和 p−1 落单，本章 p=4 只有 1↔2。`MPI_PROC_NULL` 上的发送/接收立即返回，不需要特判。

| 阶段 | 配对 | 边界 |
|---|---|---|
| 偶 | 0↔1、2↔3 | p 为偶数时全部配对 |
| 奇 | 奇数 rank↔rank+1 | p 为偶数时 0 和 p−1 落单，用 `MPI_PROC_NULL` |

交换用 `MPI_Sendrecv` 或 `MPI_Sendrecv_replace`：前者发送缓冲和接收缓冲分开，后者用同一块缓冲先发后收，省一份内存。`MPI_Sendrecv` 由 MPI 调度发送和接收，避免“所有进程先 Send 再 Recv”的死锁。

`MPI_Ssend` 要等对方投递匹配的接收；所有 rank 都停在发送上，形成环上等待。偶数先发/奇数先收能破这个环，但阶段奇偶一变，谁先发就变，边界还要处理 `MPI_PROC_NULL`，容易写错。

- 小消息的 `MPI_Send` 本来就可能立即返回，换成 `MPI_Ssend` 才暴露等待；
- 死锁只说明程序依赖了缓冲，不能反过来证明原来的程序正确。

为什么是 p 个阶段而不是 n 个？每个块内部已经有序，一个阶段最多让一个块越过一个邻居；p 个块最多需要 p 个阶段就能落到全局位置。

用 0-1 原理看：只要所有 0 都在 1 前面，排序就正确。每阶段消掉相邻的逆序，p 个阶段足够；正式证明不展开。

| 部分 | 每个 rank 的量 | 说明 |
|---|---|---|
| 本地排序 | O((n/p) log(n/p)) | 只排自己那一块 |
| 每阶段通信 | 发送 n/p、接收 n/p | 共 2n/p 个键值 |
| 同步 | p 个阶段 | 每阶段一次 `MPI_Sendrecv` |

n 固定、p 增大时，本地排序变小、通信占比上升；n=p 时每阶段只交换 1 个键值，通信比计算还慢。旧资料里的性能表不能直接外推，核数、网络和 MPI 实现都变了。

基本版按粒子块划分：每个 rank 负责 n/p 个粒子的更新，但算力需要所有粒子的位置和质量，`MPI_Allgather` 要保留 O(n) 的全局位置缓冲。质量在初始化时 `MPI_Bcast` 一次，位置和速度用 `MPI_Scatter` 分发；每个时间步用 `MPI_Allgather` 收集更新后的位置。

`MPI_Allgather` 要求每个 rank 贡献同样多的元素；n 不能被 p 整除时改用 `MPI_Allgatherv` 并给出 `counts`/`displs`。`MPI_IN_PLACE` 让每个 rank 把自己的块直接放进全局数组，省一次复制。

- 等质量：每对只算一次，正力和负力直接对应；
- 不等质量：要按力存，再除以各自的质量。

在这个共享内存测试里，环形反而比 Allgather 慢：每步要发 p 轮、每轮四条消息，消息数多。它的优势是内存只留一个块、计算量减半；网络延迟高、p 大、内存紧时要重新测，不能照搬旧资料。

- 计算量减半：每对粒子只算一次；
- 消息数增加：每步 p 轮，每轮位置 x/y 和力 x/y 四条消息；
- 内存减少：只保留一个 n/p 的块和 `tmp_forces`。

| 版本 | 每步通信 | 计算量 | 内存 | 适用 |
|---|---|---|---|---|
| Allgather | 每个 rank 收发 2n 个数（x/y） | 所有粒子对 | O(n) | p 不大、实现简单 |
| 环形传递 | 每个 rank 发 p 轮、每轮 4n/p 个数 | 每对只算一次 | O(n/p) | 内存紧、计算重 |

> **旧资料提示**：每个时间步阻塞 `MPI_Allgather` 收集位置，可以换成 `MPI_Iallgather`（MPI-3.0）重叠通信和计算；MPI-4.0 还有持久集合通信。见 [第 40 章](ch40.md)。

## 31.5 动态划分与分布式终止检测

空闲 rank 计数器看起来简单：每个 rank 没工作就告诉 rank 0，计数到 p 就退出。

问题在于“没工作”的通知可能比“工作”的消息先到；rank 0 先收齐通知，工作在途中，任务就丢了。图里的第 4 步就是这个误判。

分布式内存没有集中式等待队列，空闲 rank 主动发 `WORK_REQUEST`；忙 rank 用 `MPI_Iprobe` 查请求，栈里多于一条就分一半，用 `MPI_Pack` 打包后回 `WORK`，否则回 `NO_WORK`。请求目标可以轮转、由 rank 0 维护或随机选。

- `WORK_REQUEST`：要工作；
- `WORK` / `NO_WORK`：给任务或拒绝；
- `ENERGY`：交能量；
- `TERMINATE`：rank 0 广播终止。

| 案例 | 通信模式 | 负载均衡 | 终止检测 | 内存 | 适用规模 |
|---|---|---|---|---|---|
| 并行排序 | 每阶段邻居交换 | 固定块，较均匀 | p 个阶段固定结束 | O(n/p) | n/p 足够大 |
| n 体 Allgather | 每步全收集 | 固定块，较均匀 | 固定步数 | O(n) | p 不大、实现简单 |
| n 体环形 | 只和邻居交换 | 固定块，较均匀 | 固定步数 | O(n/p) | 内存紧、计算重 |
| TSP 静态 | Scatterv + MINLOC | 子树工作量不均 | 搜索完归约 | O(n²)+栈 | 任务多、可静态切 |
| TSP 动态 | 请求/工作/能量 | 运行时偷工作 | 能量守恒 | O(n²)+栈 | 负载差距大 |

选型先看通信量、负载均衡和终止检测，不要先选 API。

数据能在单节点放下、通信频繁，优先共享内存；要跨节点、内存放不下、通信/计算比低，选 MPI。多核集群常用两种混合方式：

- MPI+OpenMP：节点间走 MPI，节点内用 OpenMP 线程；
- MPI+X：节点内用 GPU 或别的加速器，节点间仍然走 MPI。

共享内存的 Pthreads/OpenMP 版 TSP 通常比 MPI 快，因为通信是内存操作；但 MPI 动态版在进程数增大、负载更分散时可能反超。这个结论依赖机器和问题，不能当普遍规律。

报告加速比时同时报告绝对时间和校验和，避免“算错了所以很快”。固定 CPU、NUMA、网络、MPI 实现和版本；旧资料里的绝对时间不能直接比较。

> **旧资料提示**：旧资料里的 4 核/8 核/Infiniband 性能表不能外推到今天的集群；核数、NUMA、网络、内存带宽都变了，必须重测。见 [第 40 章](ch40.md)。

## 速查

| 接口/协议 | 作用 | 通信量 | 坑 |
|---|---|---|---|
| `MPI_Scatter` | 等长块分发 | 每 rank 一块 | n 不能被 p 整除就错 |
| `MPI_Scatterv` | 不等长分发 | 每 rank 一份 | `displs` 以 sendtype 为单位 |
| `MPI_Gather`/`MPI_Gatherv` | 收回等长/不等长块 | 汇聚到 root | `recvcount` 是每 rank 一份 |
| `MPI_Allgather`/`MPI_Allgatherv` | 所有 rank 收集全部块 | 每人一份 | 每 rank 贡献必须等长（v 版除外） |
| `MPI_Sendrecv` | 同时发和收 | 一对缓冲 | 不要在环上先 Send 后 Recv |
| `MPI_Sendrecv_replace` | 单缓冲先发后收 | 省一份内存 | 发送期间缓冲不能改 |
| `MPI_Ssend` | 同步发送 | 等对方接收 | 可用来暴露死锁，不是证明 |
| `MPI_Isend`/`MPI_Irecv`/`MPI_Waitall` | 非阻塞通信 | 提交后立即返回 | 完成前不能复用缓冲 |
| `MPI_Iprobe`/`MPI_Probe`/`MPI_Get_count` | 探消息 | 不取走数据 | `ANY_SOURCE` 时靠 tag 区分 |
| `MPI_Pack`/`MPI_Unpack`/`MPI_PACKED` | 打包连续缓冲 | 显式复制 | `position` 要重置；先算 `MPI_Pack_size` |
| `MPI_Allreduce`/`MPI_MINLOC`/`MPI_2INT` | 归约最小值及位置 | 集合通信 | 平局取较小 rank |
| `MPI_Comm_split`/`MPI_Comm_split_type` | 按颜色/节点分组 | 建新通信子 | 集合通信，所有 rank 都要调用 |
| `MPI_Barrier`/`MPI_Wtime` | 对齐、计时 | 全局同步 | 不同 rank 的时钟不保证同步 |

## 思考题

1. 31.2 的并行奇偶排序在 n=1024、p=8 时，本地排序、每阶段通信、compare-split 各占多少？p 增加到 32 时哪个部分先成为瓶颈？

   <details><summary>提示</summary>

   先估本地排序：每块 128 个键值，排序约 128 log₂128 次比较；每阶段通信 2×128 个键值，compare-split 约 128 次比较。p=32 时每块只有 32 个键值，通信和启动开销占比更大，本地排序不再是主体。

   </details>

2. 31.5 的“空闲 rank 计数器”在什么消息时序下会误判？把三进程时序改成四进程，还能不能构造出丢失工作的例子？

   <details><summary>提示</summary>

   关键是“工作”和“空闲通知”走不同消息、到达顺序可以反过来。四个进程时让 rank 1 的工作消息慢、空闲通知快，rank 0 先收到 rank 2、rank 3 的空闲通知，再加上自己就到 4；工作在途中，仍然会丢。用 `MPI_Isend` 发大消息、`MPI_Send` 发小通知可以稳定复现。

   </details>

3. 31.3 的 Allgather 版和环形传递版，在 p 较小、p 接近 n、网络延迟高、内存带宽受限四种情况下各自什么时候更好？

   <details><summary>提示</summary>

   p 小、实现简单时 Allgather 好；p 接近 n 时每个 rank 只有很少粒子，环形传递的 p 轮消息和 Allgather 的集合开销都不小，要按消息延迟算。网络延迟高时环形每步 p 轮往返更吃亏，除非能重叠；内存带宽受限时 Allgather 的 O(n) 复制更贵，环形只留 O(n/p) 的块更有优势。

   </details>

4. 把 31.4 的 `MPI_MINLOC` 归约用到 31.5 的动态 TSP 上，动态任务的“当前最佳代价”怎么在请求/工作消息之间传播？能量终止还需不需要额外的“最佳代价”消息？

   <details><summary>提示</summary>

   请求可以带请求方当前的 `best`，工作消息带发送方的 `best`；接收方取较小值作为新的上界，搜索时立即用它剪枝。能量终止只负责“是否还有工作”，不负责传播代价；即使没有额外的最佳代价消息，最后仍可用一次 `Allreduce + MINLOC` 收口。传播是优化，不是正确性的必要条件。

   </details>
