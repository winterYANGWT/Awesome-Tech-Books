# 第 30 章 MPI 集合通信、派生数据类型与性能

4 个进程的 π 程序用 `MPI_Reduce` 求和，结果和串行版差最后几位；另一个版本把 `MPI_Bcast` 放进只有 rank 0 会进入的 `if`：

```cpp
if (rank == 0) {
    MPI_Bcast(&n, 1, MPI_INT, 1, MPI_COMM_WORLD);  // 只有 rank 0 进来
}
MPI_Reduce(&local, &sum, 1, MPI_DOUBLE, MPI_SUM, 0, MPI_COMM_WORLD);
```

rank 0 在 Bcast(root=1) 里等 rank 1 调用 Bcast；rank 1 的 Reduce 可以先返回，它和 rank 2、3 随后卡在 `MPI_Finalize`，等 rank 0。root 0 的版本有时能靠缓冲跑完，所以反例用 root 1 稳定复现：集合通信没有 tag，错一次就可能是整个作业停住，而不是返回错误码。

## 30.1 集合通信的规则：所有进程、顺序匹配、不得别名

{{#fig ch30/collective_rules}}

前三行是正确的：四个 rank 都调用 Bcast、Reduce、Allreduce，顺序和 root 一致。第四行是反例：rank 0 在 Bcast，其余在 Reduce。

rank 0 等的发送方没有出现，作业挂起；集合操作按 communicator 和调用顺序匹配，没有 tag 可以区分。

四条规则先记住：

- communicator 内**所有**进程都要调用同一个集合函数，参数相容，调用顺序一致。
- 集合通信没有 tag；同一个 communicator 上，第 k 个集合调用只和第 k 个匹配。需要区分时用 `MPI_Comm_dup` 建不同 communicator。
- 输入和输出缓冲区不能别名（`sendbuf == recvbuf`），否则结果不可预测；例外是 `MPI_IN_PLACE`。
- 集合通信出错常常表现为挂起，不是错误码。先查“所有 rank 都调用了吗”“顺序一样吗”“root 一样吗”“count/datatype 相容吗”。

`count` 的单位最容易写错：

| 调用 | `count` 是谁的 | root 的缓冲区 |
|---|---|---|
| `MPI_Reduce` | 每个进程发送的元素数 | 收 `count` 个，不是 `count×p` |
| `MPI_Allreduce` | 每个进程发送的元素数 | 没有 root，所有 rank 都收 `count` 个 |
| `MPI_Bcast` | 元素个数 | root 的 `buf` 是输入，其他 rank 是输出 |
| `MPI_Scatter` | 每个 rank 收到的一块 | root 的 `sendbuf` 有 `p` 块 |
| `MPI_Gather` | 每个 rank 贡献的一块 | root 的 `recvbuf` 有 `p` 块 |

## 30.2 归约、广播、全归约：树与蝶形

{{#fig ch30/collectives}}

第 1–3 步是树形归约：每轮把一对 rank 的部分和合并，`p` 个值经过 `log₂p` 轮到达 root。第 4–5 步是树形广播，root 沿同一棵树把结果发回去。第 6–9 步是蝶形全归约：每轮两两交换部分和，`log₂p` 轮后所有 rank 都有总和。

线性归约要 `p−1` 次接收和加法；树形只要 `log₂p` 轮。树的结构不唯一，MPI 实现可以按网络拓扑选择配对。

Allreduce 的两种结构：

- 树形归约 + 树形广播：root 先收齐，再沿树分发。
- 蝶形：每轮两两交换部分和，所有 rank 同时参与。

教科书里的蝶形按 `p` 是 2 的幂写；`p` 不是 2 的幂时，实现要补一轮或退回别的算法。

不要假设结构体可以按字节直接发：填充、对齐和字节序都可能变。要么用派生类型描述布局，要么拆成字段。

`MPI_MAXLOC`/`MPI_MINLOC` 把值和“拥有它的 rank”一起归约，通常配 `MPI_2INT` 或 `MPI_DOUBLE_INT`。它们先按第一个分量取最大/最小，平局时取第二个分量较小的那个；第二个分量放 rank，就得到“最小 rank”，放别的值就按那个值排序。

浮点归约的顺序由实现决定。`MPI_SUM` 不保证和串行逐位相同：规范允许实现利用结合律改变求值顺序。

需要可复现结果时，自己控制归约顺序（例如先 Gather 到一处，再按固定顺序加），或者用补偿求和；比较时给容差。

`MPI_Op_create` 注册用户函数，函数必须满足结合律；`commute=false` 时操作数按 rank 升序排列，求值顺序仍可利用结合律改变，`commute=true` 时可以重排，用户函数里不要调用 MPI。

`MPI_Reduce_scatter` 先归约再按块散射，`MPI_Scan`/`MPI_Exscan` 做前缀和。它们都是集合通信，同样要求所有 rank 参与、顺序一致；`MPI_Exscan` 在 rank 0 上的结果未定义。

归约与广播的对照：

| | 作用域 | 顺序 | 确定性 | 原地 | 非阻塞 | 异常 |
|---|---|---|---|---|---|---|
| MPI 集合通信 | communicator 内所有 rank | 同一 communicator 上调用顺序必须一致 | 浮点归约不保证逐位相同 | `MPI_IN_PLACE`，按操作和参数位置 | MPI-3.0 起 `MPI_I*` | 默认 `MPI_ERRORS_ARE_FATAL`；集合错误常表现为挂起 |
| OpenMP `reduction` | 团队或工作共享构造 | 私有副本的合并顺序未指定 | 浮点不保证逐位相同 | 直接更新原变量 | `nowait` 可去掉结束屏障，但归约完成前读原变量是竞争 | 异常必须在同一线程、同一并行区内捕获 |
| `std::reduce(par)` | 算法调用的范围 | 合并顺序未指定 | 浮点不保证逐位相同 | 无，结果写入返回值 | 无，调用返回时结果已就绪 | 元素访问函数抛异常时调用 `std::terminate` |

pthread 没有集合通信，只能自己建树、逐层汇总；线程的创建和汇入见[第 3 章](ch03.md)。系统调用也没有集合通信的对应物，MPI 底层用 socket 或共享内存，不在这里展开。

分布方式决定接口：

- 块划分：每个 rank 连续拿 n/p 个，用 Scatter/Gather/Allgather。

## 30.4 派生数据类型：contiguous、vector、struct 与打包成本

{{#fig ch30/datatype_layout}}

三种构造器：

- `MPI_Type_contiguous(count, oldtype, &newtype)`：连续 count 个旧类型。
- `MPI_Type_vector(count, blocklength, stride, oldtype, &newtype)`：count 块、每块 blocklength 个、块间跨 stride 个旧类型。

派生类型不一定比基本类型慢。连续的 `MPI_Type_contiguous` 通常能直接按块处理；带间隙的 `MPI_Type_create_struct` 可能需要打包，是否变慢取决于实现、消息大小和网络。

不要凭“派生类型一定慢”就把数组拆开，先测。

`MPI_Pack`/`MPI_Unpack` 把数据复制到连续缓冲区，适合“一次发多个不同类型或变长数据”的场景。`MPI_Pack_size` 估算缓冲区大小，`MPI_PACKED` 是打包后的数据类型。打包是显式复制，派生类型是让 MPI 自己决定是否复制。

MPI 不能直接发送指针：接收进程的地址空间不同，指针值只是一个地址。发送结构体里的指针，只会把地址发过去。C++ 的 `std::is_trivially_copyable`、`offsetof`、`alignof` 只能帮你描述本机布局，不能保证跨机器一致。

> **旧资料提示**：旧教程说“派生数据类型一定比基本类型慢，所以把数组拆开”。连续类型通常能高效处理，只有带间隙的结构体才可能需要打包；要用本机测量决定，见[第 40 章](ch40.md)。

## 30.5 性能：计时、加速比与可扩展性

{{#fig ch30/scaling}}

`MPI_Wtime()` 返回墙钟秒数，`MPI_Wtick()` 给分辨率。计时模板是 `MPI_Barrier` 对齐、各 rank 记开始/结束、`MPI_Reduce(MPI_MAX)` 取最慢 rank 的时间：

```cpp
MPI_Barrier(comm);
double t0 = MPI_Wtime();
/* 被测代码 */
double local = MPI_Wtime() - t0;
double slowest = 0.0;
MPI_Reduce(&local, &slowest, 1, MPI_DOUBLE, MPI_MAX, 0, comm);
```

计时按四步做：

- `MPI_Barrier` 对齐所有 rank。
- 各 rank 记自己的开始和结束。
- `MPI_Reduce(MPI_MAX)` 取最慢 rank 的时间。
- 重复运行，报告最小值或中位数。

`MPI_Wtime` 是墙钟，但不同 rank 的时钟不保证同步；不要拿 rank A 的时间减 rank B 的时间。

加速比 `S(n,p)=T串行(n)/T并行(n,p)`，效率 `E=S/p`。强可扩展性固定 n 增加 p，弱可扩展性让 n 随 p 增长。

矩阵-向量乘法在 n 固定、p 很大时，通信占比上升，效率下降；n 随 p 增长时效率能维持，属于弱可扩展。

本机一次运行里，p 从 1 增到 8，加速比远低于 p，效率随 p 一路下降；不同次运行里哪个 p 最高会变。

固定 n 时，Allgather 的通信量是 O(n)，每个 rank 的计算量是 O(n²/p)；p 越大，通信和内存带宽的占比越高，进程争抢也越明显。

p=1 的点受串行版和 MPI 版两次测量的噪声影响；这组数只说明本机这一次，换机器、换绑核方式都会变。

矩阵-向量乘法的 MPI 版按行块划分 A 和 y，每个 rank 算 `local_n` 行；x 需要完整，所以每步 `MPI_Allgather` 的通信量是 O(n)。可以改用 `MPI_Allgatherv` 处理不等长，或把 x 复制到所有 rank 一次、之后只同步变化的元素。

2011 年的性能表不能外推：核数、NUMA、SMT、网络和内存带宽都变了。在本机测时要写清 CPU、编译选项、进程数、绑定方式；`mpirun --bind-to core` 和 `OMP_PROC_BIND` 会影响结果。

> **旧资料提示**：旧资料把 2011 年测出的加速比表当成今天的结论。硬件和运行时都变了，必须在本机重测，见[第 40 章](ch40.md)。

- 创建和保存 request。
- 在 `Wait`/`Test` 里推进通信。
- 管理缓冲区的生命周期。
- 测出重叠是否真的划算。

重叠的收益取决于通信/计算比，必须测。

MPI+OpenMP 的分工是节点间用 MPI、节点内用 OpenMP。`MPI_Init_thread` 的四个级别：

- `MPI_THREAD_SINGLE`：只有一个线程。
- `MPI_THREAD_FUNNELED`：多线程，但只有主线程调用 MPI。
- `MPI_THREAD_SERIALIZED`：多线程可以调 MPI，但不能并发。
- `MPI_THREAD_MULTIPLE`：多线程可以并发调 MPI。

FUNNELED 通常就够；MULTIPLE 允许并发调用，但实现要加锁或内部串行化，开销通常更大。

`MPI_Comm_split_type(..., MPI_COMM_TYPE_SHARED, ...)`（MPI-3.0）按共享内存节点分组，便于做节点内通信。MPI-3.0 的 `MPI_Win_allocate_shared` 可以让同节点 rank 直接读写共享内存，但同步仍要自己保证。

MPI-4.0（2021）加入持久集合通信（`MPI_Bcast_init`、`MPI_Reduce_init`、`MPI_Allreduce_init` 等）、分区通信（`MPI_Psend_init`/`MPI_Precv_init`）和大计数 `_c` 接口。本机 Open MPI 5.0.10 的 `MPI_Get_version` 报 3.1（还没有完整实现 MPI-4.0），但 `mpi.h` 已经声明了持久集合和分区通信接口，第 40 章实测过 `MPI_Allreduce_init`；大计数 `_c` 接口没有。本章只介绍这些接口。

非阻塞不等于“没有开销”：请求对象、进度引擎、缓冲区生命周期都要管；小消息用非阻塞可能不如阻塞。通信与计算重叠的对照：

| | 提交 | 完成 | 缓冲区生命周期 | 进度 |
|---|---|---|---|---|
| MPI 非阻塞 | `MPI_Isend`/`MPI_Irecv` 或 `MPI_I*`，返回 request | `MPI_Wait`/`MPI_Test`/`MPI_Waitall` | 完成前不能复用；发送缓冲区要等到发送完成 | 由 MPI 库在 MPI 调用中推进；实现可能用后台线程，但不保证 |
| `std::async` | 返回 `std::future` | `future::get`/`wait` | 参数复制或移动进共享状态；结果在 `get` 前由共享状态持有 | 由实现调度；`get` 阻塞到就绪 |
| OpenMP `task` | `#pragma omp task` | `taskwait`/`taskgroup` | 任务的数据环境在任务完成前有效；共享变量要自己保证 | 由运行时线程池调度，不保证立即执行 |

> **旧资料提示**：旧写法每个时间步只用阻塞集合通信，`MPI_Allgather` 完再算。MPI-3.0 起有非阻塞集合通信，MPI-4.0 起有持久集合通信，可以把通信和计算重叠；见[第 40 章](ch40.md)。

## 速查

集合通信：

| 接口 | 作用 | 计数单位 | 版本 | 坑 |
|---|---|---|---|---|
| `MPI_Reduce` | 归约到 root | 每进程元素数 | MPI-1.0 | root 只收 `count` 个 |
| `MPI_Allreduce` | 归约到所有 rank | 每进程元素数 | MPI-1.0 | 没有 root |
| `MPI_Reduce_scatter` | 归约后按块散射 | `recvcounts[]` 每块 | MPI-1.0 | `recvcounts` 之和等于 count |
| `MPI_Scan`/`MPI_Exscan` | 前缀和 | 每进程元素数 | MPI-1.0 | Exscan 在 rank 0 未定义 |
| `MPI_Bcast` | 广播 | 元素个数 | MPI-1.0 | root 输入，其他输出 |
| `MPI_Scatter`/`MPI_Gather` | 等长分发/收集 | 每块元素数 | MPI-1.0 | 不是总数 |
| `MPI_Allgather` | 全收集 | 每 rank 元素数 | MPI-1.0 | 结果按 rank 拼 |
| `MPI_Scatterv`/`MPI_Gatherv` | 不等长分发/收集 | `counts[]` 每 rank | MPI-1.0 | `displs` 单位是 extent |
| `MPI_Alltoall` | 全交换 | 每对元素数 | MPI-1.0 | O(p²) |
| `MPI_IN_PLACE` | 原地 | 按操作 | — | 不是所有参数位置都支持 |
| `MPI_Op_create` | 用户归约 | 函数 | MPI-1.0 | 必须结合律；`commute` 决定顺序 |
| `MPI_MAXLOC`/`MPI_MINLOC` | 值 + 下标 | 对类型 | MPI-1.0 | 平局取较小第二分量 |

类型、计时与线程：

| 接口 | 作用 | 计数单位 | 版本 | 坑 |
|---|---|---|---|---|
| `MPI_Type_contiguous` | 连续类型 | 旧类型个数 | MPI-1.0 | 用完 `MPI_Type_free` |
| `MPI_Type_vector` | 等间距块 | 块数/块长/跨步 | MPI-1.0 | `stride` 以旧类型计 |
| `MPI_Type_create_struct` | 异构结构体 | 字段数 | MPI-2.0 | 偏移用 `MPI_Get_address` |
| `MPI_Type_create_resized` | 改 extent | 字节 | MPI-2.0 | 结构体数组必要时用 |

| `MPI_Pack`/`MPI_Unpack` | 显式打包 | 字节 | MPI-1.0 | 多一次复制 |
| `MPI_Wtime`/`MPI_Wtick` | 墙钟/分辨率 | 秒 | MPI-1.0 | 跨节点不同步 |

| `MPI_Comm_split_type` | 按节点分组 | split_type | MPI-3.0 | `MPI_COMM_TYPE_SHARED` |

## 思考题

1. 30.2 的 `MPI_Allreduce` 用“树形归约 + 树形广播”和用蝶形，在 p=8 时各需要几轮？如果 p 不是 2 的幂，蝶形还能直接用吗？

   <details><summary>提示</summary>

   树形归约 3 轮、树形广播 3 轮，合起来 6 轮；蝶形 3 轮，每轮所有 rank 同时交换。教科书的蝶形按 2 的幂写，p 不是 2 的幂时要么补到下一个 2 的幂，要么由实现换成别的算法；MPI 不要求你用某一种结构。

   </details>

2. 30.3 的 `MPI_Scatterv` 如果 `sendtype=MPI_INT`，把 `displacements` 按字节写成 `{0,12,24,32}`，p=4、`counts={3,3,2,2}` 时每个 rank 会收到什么？改成以 `sendtype` 的 extent 为单位后呢？

   <details><summary>提示</summary>

   MPI 会把每个 `displs[i]` 再乘 `extent(MPI_INT)=4`，所以 rank 1 从第 12 个 `int` 开始读，rank 2 从第 24 个，rank 3 从第 32 个；缓冲区只有 10 个元素，后三个 rank 越界，结果是未定义的。改成 `{0,3,6,8}` 才是元素偏移，四个 rank 分别收到 0–2、3–5、6–7、8–9。

   </details>

3. 30.4 的结构体广播，用派生类型一次发、用三次 `MPI_Bcast`、用 `MPI_Pack` 打包，各自在消息大小、可移植性和代码复杂度上怎么取舍？

   <details><summary>提示</summary>

   派生类型只发一条消息，消息里是字段数据（通常不含尾部填充），但收发双方要建相同的类型图，布局换了就要改。三次 Bcast 最直观、跨实现最稳，代价是三次启动开销，字段多时更明显。`MPI_Pack` 只发一条消息且缓冲区连续，适合字段多或变长，代价是多一次复制；三种都要保证接收端知道字段顺序。

   </details>

4. 把 30.6 的 `MPI_Iallgather` 用到 30.5 的矩阵-向量乘法，哪些计算可以放进重叠区间？如果 x 每步都变，缓冲区要怎么管？

   <details><summary>提示</summary>

   `x` 的 Allgather 完成前不能算 `A_local·x`，所以不能用它盖住本轮乘法。可以重叠的是下一轮的 Allgather 和本轮剩下的工作（归一化、校验和、收尾），或者把 Allgather 与 `y` 的归约重叠。x 每步都变时用双缓冲：两个 `x` 缓冲区、两个请求，`Wait` 确认当前缓冲区可读后才切换；请求完成前不要写回该缓冲区。

   </details>
