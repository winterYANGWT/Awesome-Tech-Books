# 月度运营报告

## 何时用

顾客或同事要“某个月的运营月报”“退货率”“这个月卖了多少”时使用。
只做月度汇总；单张订单的退款金额用 `refund-handling`，不要在这里算。

## 步骤

1. 运行脚本，月份写成 `YYYY-MM`：

   ```bash
   python scripts/report.py --month 2026-09
   ```

2. 脚本 stdout 是一行 CSV；stderr 是诊断。不要修改 CSV 里的数字。
3. 只在被问到口径时读 `references/metrics.md`；不要把它整份抄进报告。
4. 按 `assets/report_template.md` 写五节：结论、数据、原因、建议、附录；全文不超过 500 字。
5. 报告里的每个数字都要能在 CSV 里找到；CSV 没有的数字写“未统计”，不要估。

## 坑

- 先排除已取消订单，订单数和退货率的分母都用排除后的数。
- 退货订单按订单去重，不按退货记录数；部分退款也算退货。
- 退货率 = 退货订单数 / 当月订单数（排除已取消），保留一位小数。
- 金额保留两位小数；前三个退货原因按笔数从高到低。
- 快递破损数只统计当月创建订单的物流记录，不要跨月。
- 退货原因笔数加起来可能大于退货订单数：一张订单可以有多条部分退款记录。

## 数据核对

写完报告前逐项核对：

1. CSV 只有一行数据；订单数、实付总额、退货订单数、破损数都能对上。
2. 退货率的分母是订单数，不是退货订单数，也不是 30 天。
3. 前三个原因的笔数从高到低；并列时按原因名称排序。
4. 报告里的金额和 CSV 一样保留两位小数，百分数保留一位小数。

## 输出格式

五节，标题固定；全文不超过 500 字；结论不超过三句；附录只写一行口径和 CSV 原始行。
不要用大表格，不要重复 CSV 里的每一列。
建议要落在可执行的动作上（例如补发、换快递、联系出版社），写清负责人和完成时间，不要写“加强管理”。
按原因排序，先处理笔数最多的那一项，不要把三条建议写成同一件事。
