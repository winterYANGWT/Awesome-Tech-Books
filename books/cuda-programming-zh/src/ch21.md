# 第 21 章 TMA：用描述符搬运多维数据块

上一章结尾，整个 block 合作发起的对齐拷贝被编译成了 `UBLKCP`，由专门的拷贝单元完成。这个单元叫 TMA（Tensor Memory Accelerator），从计算能力 9.0 开始提供，这块 sm_120 的 GPU 上也有。它不只能搬一段连续的字节，还能搬多维数组里的一个矩形块：主机先建立一个描述符，说明这个数组有几维、每维多大、行与行之间隔多少字节；kernel 里一个线程发出一条指令，给出块的起点坐标，剩下的地址计算、越界处理、写进 shared memory，全由硬件完成。

## 21.1 例子：3×3 均值模糊

[tma_blur.cu](code/ch21/tma_blur.cu) 对一幅 8192×8192 的 `float` 图像做 3×3 均值模糊：每个输出像素是它和周围 8 个邻居的平均值，越出图像边界的邻居当作 0。每个 block 负责 32×32 个输出像素，需要连同一圈边框的 34×34 个输入像素，相邻的 block 共用边框。

最简单的写法是每个线程直接从 global memory 读 9 个邻居（靠 L1 缓存复用）。第二种写法是第 9 章的方式，block 里的线程合作把输入块读进 shared memory，每个元素都要自己算地址、自己判断有没有越界：

## 21.2 在主机上描述数据

用 TMA 时，先在主机上用 driver API 的 `cuTensorMapEncodeTiled` 建立描述符（需要链接 `-lcuda`）：

```cpp
{{#include code/ch21/tma_blur.cu:encode}}
```

几个参数的含义：

- 维数和每一维的大小，最内层（变化最快的那一维，这里是 x）放在最前面。
- 除最内层外，每一维加 1 要跨多少字节，必须是 16 字节的整数倍。
- 每次搬的块（box）在每一维上的大小。最内层乘以元素大小也要是 16 字节的整数倍。
- 数据类型、交错方式（interleave）、shared memory 里的排列方式（swizzle，可以打乱排列来避免第 9 章的 bank conflict），以及 L2 预取的粒度。
- 越界怎么填：`CU_TENSOR_MAP_FLOAT_OOB_FILL_NONE` 表示越界的元素填 0。

描述符是一个 128 字节的结构，作为 kernel 参数传进去，参数前要加 `__grid_constant__`，表示它在整个 grid 里只读、不会被拷贝，TMA 硬件要直接从参数所在的内存读它。

## 21.3 在 kernel 里发起 TMA

```cpp
{{#include code/ch21/tma_blur.cu:tma}}
```

和上一章 barrier 版本的结构几乎一样，区别在于由一个线程发起拷贝。`cuda::ptx::cp_async_bulk_tensor` 给出 shared memory 的目标地址、描述符、块的起点坐标和一个 barrier；`barrier_arrive_tx` 在报到的同时告诉 barrier，这一阶段还要等这么多字节到达。其余线程照常报到，然后所有线程一起等。barrier 的这一阶段要等两件事都完成：所有线程都到了，约定的字节数也都写进了 shared memory。坐标可以是负数，也可以超出数组的范围，越界的部分按描述符的规定填 0，kernel 里不需要任何边界判断。

用 `cuobjdump -sass` 看，发起拷贝的就是一条 `UTMALDG.2D` 指令，等待则是几条 `SYNCS` 指令。

## 21.4 一个坑：最内层坐标要对齐

第一版的 TMA kernel 让输入块从 x − 1 开始，和手工加载的版本一样，结果运行时报了 `cudaErrorIllegalInstruction`，出错的正是那条 `UTMALDG.2D`。[tma_align.cu](code/ch21/tma_align.cu) 把问题单独拿出来：从 1024×1024 的矩阵里取一个 32×32 的块，起点坐标从命令行给出（非法指令会让 context 作废，所以每个坐标单独运行一次）：

```text
$ ./tma_align 0 0
块的左上角 (0, 0)：描述符 正常，运行 cudaSuccess
$ ./tma_align 4 0
块的左上角 (4, 0)：描述符 正常，运行 cudaSuccess
$ ./tma_align 1 0
块的左上角 (1, 0)：描述符 正常，运行 cudaErrorIllegalInstruction
$ ./tma_align 3 5
块的左上角 (3, 5)：描述符 正常，运行 cudaErrorIllegalInstruction
$ ./tma_align -4 -1
块的左上角 (-4, -1)：描述符 正常，运行 cudaSuccess
$ ./tma_align -1 0
块的左上角 (-1, 0)：描述符 正常，运行 cudaErrorIllegalInstruction
$ ./tma_align 1000 1000
块的左上角 (1000, 1000)：描述符 正常，运行 cudaSuccess
```

规律很清楚：负坐标、越界都没问题，第二维的坐标也可以随意；但在这块 GPU 和这个驱动上，最内层的坐标必须是 4 的倍数，也就是 16 字节对齐，否则就是非法指令。描述符创建时不会报任何错，问题要到运行时才暴露，而且一出错整个 context 就作废了（第 5 章）。

所以 TMA 版本的输入块改成从 x − 4 开始、宽 40 个元素（覆盖 x − 4 到 x + 35，正好是 160 字节），计算时列号相应地加 3。设计 TMA 的分块时，要让最内层的起点落在 16 字节的边界上，宁可多搬几列。

## 21.5 结果

三种写法的时间：

```text
 1.775 ms    303 GB/s  直接读 global
 1.615 ms    332 GB/s  手工加载到 shared memory
 1.595 ms    337 GB/s  TMA 加载到 shared memory
```

TMA 最快，但三者差得不多：这个 kernel 每个像素只做 9 次加法，读写各一次，完全被显存带宽卡住了（337 GB/s 已经是第 1 章测到的上限）。区别在于完成同样的工作花了多少指令。用 ncu 看一下：

```text
kernel          执行的 warp 指令数   SM 吞吐（占峰值）
blur_global         199,229,440     55.5%
blur_manual         215,154,688     74.0%
blur_tma            148,789,945     71.6%
```

TMA 版本执行的指令比手工加载少了 31%。手工加载时，每个元素都要算一次二维坐标、做四次边界比较、算一次地址；TMA 版本里，这些工作由一条指令交给了硬件，256 个线程里只有一个参与发起拷贝。在这个访存为主的例子里，省下的指令换不来时间；但在计算更重的 kernel 里，省下的指令发射机会和寄存器就能用在计算上。高性能的矩阵乘法 kernel 正是这样用 TMA 的：一个 warp 专门用 TMA 搬数据，其余的 warp 专心计算，配合上一章的多级 barrier 组成流水线。

TMA 还能反过来把 shared memory 里的块写回 global memory（`cp_async_bulk_tensor` 的另一个重载），以及把同一块数据同时送进一个 cluster 里多个 block 的 shared memory（multicast）。后者依赖第 19 章的分布式 shared memory，在这块 GPU 上，那条通路的速度要先量一量再决定用不用。

## 21.6 回头看

TMA 是专门搬运多维数据块的硬件。主机用 `cuTensorMapEncodeTiled` 建立描述符，说明数组的形状、行跨度和每次搬的块大小；kernel 里一个线程用一条指令给出块的起点，硬件负责地址计算、越界填零和写入 shared memory，完成情况由 barrier 跟踪。在访存为主的例子里，它和手工加载一样快，但指令少了三分之一，计算更重的 kernel 才能把这些省下来的资源用上。在这块 GPU 上，块的最内层起点必须 16 字节对齐，否则运行时直接报非法指令。

2. 改写 `blur_tma`，让每个 block 用 grid-stride 循环处理多个输出块，并像第 20 章那样用两块 shared memory 和两个 barrier 做双缓冲：处理当前块的同时，用 TMA 加载下一块。限制每个 SM 只驻留一个 block，和单缓冲的版本比较。
3. 用 TMA 实现第 9 章的矩阵转置：TMA 把 32×32 的块搬进 shared memory，线程从 shared memory 里按列读出来写回。shared memory 里的块是紧密排列的（没有 padding），按列读会有 bank conflict，用 ncu 数一数；再试试 `CU_TENSOR_MAP_SWIZZLE_128B`，读的时候要按 swizzle 的规则换算地址。
4. 在 tma_align.cu 里，把块的宽度改成 36（144 字节），起点坐标仍然取 4 的倍数，还能正常运行吗？
