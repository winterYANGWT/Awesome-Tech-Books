# 第 81 章 cuRAND Host API：随机数生成器、seed 与 device array

## 81.1 问题的由来

很多 GPU 程序需要随机数，但生成随机数和普通的数组初始化不一样。先要分清两条路线：在 host 端通过 cuRAND Host API 创建 generator，把随机数直接生成到 device array；或者在 kernel 中使用 device API。本章的示例走第一条路线，给出 Host API 从创建 generator 到生成随机数的最短完整路径。

## 81.2 核心模型

| 对象 | 作用 |
|---|---|
| `curandGenerator_t` | 随机数生成器对象 |
| RNG type | 选择伪随机或准随机生成器 |
| seed | 控制伪随机序列可复现性 |
| device array | Host API 可以直接把随机数写入 GPU 内存 |
| output copy | 示例把结果拷回 host 求样本均值和标准差，只是为了检查，不属于必需的计算路径 |

## 81.3 详解

示例的核心流程如下，`dSamples` 是一块已经用 `cudaMalloc` 分配好的 device 数组，能放下 `count` 个 `float`：

```cpp
curandGenerator_t rng;
curandCreateGenerator(&rng, CURAND_RNG_PSEUDO_PHILOX4_32_10);   // 选一种伪随机生成器
curandSetPseudoRandomGeneratorSeed(rng, 271828ULL);            // 固定 seed，结果可复现
curandGenerateNormal(rng, dSamples, count, mean, stddev);       // 直接写进 device 数组
curandDestroyGenerator(rng);
```

可以看到，cuRAND Host API 的调用发生在 host 代码中，但生成的结果直接落在 device memory 上。后续 kernel 可以直接使用 `dSamples`，不一定要像示例那样立即拷回 host。

## 81.4 代码示例

一个完整的 Host API 程序大致是：创建 generator → 设置 seed → 分配 device array → 生成随机数 → 交给后续计算（或拷回 host 检查）→ 用 `curandDestroyGenerator` 释放 generator，用 `cudaFree` 释放内存。

下面的程序生成 2^20 个均值为 5、标准差为 2 的正态分布随机数：

```cpp
// normal.cu：nvcc normal.cu -o normal -lcurand
#include <cuda_runtime.h>
#include <curand.h>
#include <cmath>
#include <cstdio>
#include <vector>

int main()
{
    const size_t count = 1 << 20;   // 伪随机生成器产生正态分布时，数量必须是偶数
    const float mean = 5.0f, stddev = 2.0f;

    float* dSamples = nullptr;
    cudaMalloc(&dSamples, sizeof(float) * count);

    curandGenerator_t rng;
    curandCreateGenerator(&rng, CURAND_RNG_PSEUDO_PHILOX4_32_10);
    curandSetPseudoRandomGeneratorSeed(rng, 271828ULL);
    curandGenerateNormal(rng, dSamples, count, mean, stddev);

    // 拷回 host 只是为了检查；cudaMemcpy 会等生成结束再拷贝
    std::vector<float> samples(count);
    cudaMemcpy(samples.data(), dSamples, sizeof(float) * count, cudaMemcpyDeviceToHost);

    double sum = 0.0;
    for (float v : samples) sum += v;
    const double sample_mean = sum / count;
    double sq = 0.0;
    for (float v : samples) sq += (v - sample_mean) * (v - sample_mean);
    const double sample_stddev = std::sqrt(sq / (count - 1));

    printf("samples : %zu\n", count);
    printf("mean    : set %.3f, sample %.4f\n", mean, sample_mean);
    printf("stddev  : set %.3f, sample %.4f\n", stddev, sample_stddev);

    curandDestroyGenerator(rng);
    cudaFree(dSamples);
    return 0;
}
```

样本数超过一百万，样本均值的标准误差约为 2/√(2^20) ≈ 0.002，所以输出的样本均值和标准差应当和设定值非常接近，偏差明显超出这个量级就要回头检查调用。seed 不变时，同一版本 cuRAND 的同一种 generator 每次运行都给出相同的序列。

程序在生成之后把 `dSamples` 拷回 host，算出样本均值和标准差，粗略检查分布。读这个例子时，可以把拷回和统计看作检查手段；更值得关注的是随机数组在 device 端生成后，怎样直接交给后续 kernel 或库调用。为了短，程序省略了错误检查，补法见[第 83 章](ch083.md)。编译时要链接 cuRAND 库（`nvcc` 加 `-lcurand`）。

## 81.5 工程判断

| 场景 | 建议 |
|---|---|
| 批量生成随机数组 | 用 Host API 直接生成到 device array |
| 每个线程需要独立随机状态 | 考虑 device API，并单独管理 per-thread state |
| 需要复现实验 | 显式设置 seed，并记录 generator 类型 |
| 只为了检查分布 | 可以拷回 host 输出，但不要把这当成主计算路径 |

## 81.6 API 与要点速查

| 要点 | 说明 |
|---|---|
| generator 生命周期 | 用完后调用 `curandDestroyGenerator`，和 `cudaFree` 一起写进清理路径 |
| 错误检查 | cuRAND 函数返回 `curandStatus_t`，需要单独检查，只检查 Runtime API 不够（见[第 83 章](ch083.md)） |
| device API 边界 | 本章只讲 Host API；在 kernel 内部生成随机数要用 device API，每个线程维护自己的状态，不适合和 Host API 混在一个最小例子里 |

## 81.7 小结

读完本章，你应该能够写出 cuRAND Host API 的最小路径：创建 generator、设置 seed、分配 device array、生成随机数、把 device array 交给后续计算，并在工程代码中补上状态检查和资源释放。
