# 第 41 章 `cudaMallocAsync`：把 malloc/free 放进 stream 顺序里

传统 `cudaMalloc` 和 `cudaFree` 很容易破坏异步流水线。它们管理全局 device memory 状态，可能引入跨 stream 同步。`cudaMallocAsync` 和 `cudaFreeAsync` 的意义，是把分配和释放也变成 stream 中的有序操作，让内存生命周期能和 GPU work 的顺序对齐。

这不是简单的“异步版本 malloc”，核心对象是 memory pool。

## 41.1 问题的由来

真实程序里，内存分配经常出现在库边界：

- 一个库函数需要临时 workspace。
- 多个库各自维护私有 cache，导致内存占用膨胀。
- 每轮迭代分配释放临时 buffer。
- `cudaFree` 的同步语义打断 stream overlap。

Stream-ordered allocator 把分配和释放排进 stream，让 CUDA 根据 stream order 判断何时可以复用内存。

## 41.2 核心模型

只要 stream order 能证明前一次使用结束，pool 就有机会复用内存。

图 41.1 按时间顺序画出一块内存的经历：在 stream 中用 `cudaMallocAsync` 分配，kernel 使用它，然后在同一个 stream（或通过依赖排在其后的 stream）中 `cudaFreeAsync`。释放之后，这块内存回到 memory pool，可以给后续分配复用。pool 是否把空闲内存还给系统、按什么策略复用、允许哪些 device 访问，分别由 release threshold、reuse policy 和访问权限设置决定。

## 41.3 详解

### 41.3.1 基本语义

```cpp
void* ptr = nullptr;
cudaMallocAsync(&ptr, bytes, stream);
kernel<<<grid, block, 0, stream>>>(ptr);
cudaFreeAsync(ptr, stream);
```

同一 stream 内，kernel 一定在 allocation 之后、free 之前执行。free 不是 host 立即释放，而是排入 stream 的释放操作。

### 41.3.2 Memory pool

每个 device 有默认 memory pool，也可以创建自定义 pool。Pool 可以保留已经释放的物理内存，以便下次快速复用。

要点在于：释放的内存先回到 pool，pool 再根据阈值和策略决定是否还给系统，而不是释放后立刻还给系统。

Graph 里的 memory allocation node（[第 39 章](ch039.md)）不从这些 pool 里分配；在 stream capture 期间调用的 `cudaMallocAsync`/`cudaFreeAsync` 会被录成这种 node，同样如此。每个 device 另有一份专供 graph 分配使用的内存，它的占用用 `cudaDeviceGetGraphMemAttribute` 查询，空闲物理页用 `cudaDeviceGraphMemTrim` 还给系统；`cudaMemPoolGetAttribute`、`cudaMemPoolTrimTo` 看到和管理的只是 stream-ordered allocator 的 pool。排查显存占用时，两边要分别统计。

### 41.3.3 Reuse policy

Pool 可以根据 event dependency、机会式复用、内部依赖等策略复用内存。如果依赖表达不清，CUDA 不能安全复用。

### 41.3.4 跨 device 和跨进程

Memory pool 可以设置其他 device 的访问权限，也可以导出为 shareable handle。跨进程共享 pool allocation 时，仍然需要 IPC event 或其他同步机制表达 ready/finish。

## 41.4 代码示例

默认 pool 使用：

```cpp
cudaStream_t stream;
cudaStreamCreate(&stream);
void* tmp = nullptr;
cudaMallocAsync(&tmp, bytes, stream);
work<<<grid, block, 0, stream>>>(tmp);
cudaFreeAsync(tmp, stream);
cudaStreamSynchronize(stream);
cudaStreamDestroy(stream);
```

查询 pool 统计：

```cpp
cudaMemPool_t pool;
cudaDeviceGetDefaultMemPool(&pool, device);
uint64_t reserved = 0;
cudaMemPoolGetAttribute(pool,
                        cudaMemPoolAttrReservedMemCurrent,
                        &reserved);
uint64_t used = 0;
cudaMemPoolGetAttribute(pool,
cudaMemPoolAttrUsedMemCurrent,
&used);
```

设置 release threshold：

```cpp
uint64_t threshold = 512ull << 20;
cudaMemPoolSetAttribute(pool,
                        cudaMemPoolAttrReleaseThreshold,
                        &threshold);
```

## 41.5 工程判断

| 场景 | 是否适合 async allocator | 注意点 |
|---|---|---|
| stream 中临时 workspace | 适合 | allocation/free 放入同一依赖链 |
| 多库共享 pool | 适合 | 统一 pool 策略减少过量 cache |
| 长生命周期大数组 | 不一定 | 普通 `cudaMalloc` 也清楚 |
| 跨 stream 使用 pointer | 可以 | 必须用 event 建立依赖 |
| 跨 device 访问 pool allocation | 可以 | 需要 `cudaMemPoolSetAccess` |
| 跨进程共享 | 高级用法 | handle + IPC 同步 |

## 41.6 API 与要点速查

Allocator API：

| API | 用途 |
|---|---|
| `cudaMallocAsync` | stream-ordered allocation |
| `cudaFreeAsync` | stream-ordered free |
| `cudaDeviceGetDefaultMemPool` | 获取默认 pool |
| `cudaDeviceSetMemPool` | 设置 device 当前 pool |
| `cudaMemPoolCreate` / `cudaMemPoolDestroy` | 自定义 pool |
| `cudaMemPoolTrimTo` | 主动 trim pool |
| `cudaMemPoolSetAttribute` /`cudaMemPoolGetAttribute` | 设置/查询属性 |
| `cudaMemPoolSetAccess` | 设置跨 device 访问 |
| `cudaMemPoolExportToShareableHandle` | 导出 pool handle |
| `cudaMemPoolImportFromShareableHandle` | 导入 pool handle |
| `cudaMemPoolExportPointer` | 导出 allocation 指针数据 |
| `cudaMemPoolImportPointer` | 导入 allocation 指针 |

Pool 属性：

| 属性 | 含义 |
|---|---|
| `cudaMemPoolAttrReservedMemCurrent` | 当前 reserved memory |
| `cudaMemPoolAttrReservedMemHigh` | reserved 高水位 |
| `cudaMemPoolAttrUsedMemCurrent` | 当前 used memory |
| `cudaMemPoolAttrUsedMemHigh` | used 高水位 |
| `cudaMemPoolAttrReleaseThreshold` | 释放回系统的阈值 |
| `cudaMemPoolReuseFollowEventDependencies` | 根据 event 依赖复用 |
| `cudaMemPoolReuseAllowOpportunistic` | 允许机会式复用 |
| `cudaMemPoolReuseAllowInternalDependencies` | 允许内部依赖帮助复用 |

## 41.7 小结

读完本章，你应该能够：

- 解释 `cudaMallocAsync` 的语义依赖 stream order。
- 区分 graph memory pool 和 stream-ordered memory pool。
- 用 pool 属性观察 reserved/used 高水位。
- 知道跨 stream、跨 device、跨进程共享 allocation 时必须显式表达依赖。
