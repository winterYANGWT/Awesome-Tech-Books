# 第 82 章 cuFFT plan 边界 checklist

## 82.1 问题的由来

FFT 是 CUDA 常用库里很重要的一类能力，信号处理、图像滤波、谱方法和卷积加速都会用到它。cuFFT 的调用步骤并不复杂，难点在于参数组合多：变换维度、batch、数据类型、in-place 还是 out-of-place、归一化约定，任何一项填错，程序往往不会报错，而是输出一组看起来合理、实际错误的结果。

所以本章不给出完整的示例程序，给出的是使用 cuFFT 前后的检查清单：plan 要描述什么，buffer 要满足什么条件，执行和验证时要核对哪些约定。完整的 API 和参数说明以 cuFFT 官方文档为准。

## 82.2 核心模型

| 维度 | 使用 cuFFT 时要弄清什么 |
|---|---|
| plan | FFT 形状、batch、类型和执行配置 |
| buffer | 输入输出是否 in-place、元素类型是否匹配 |
| execution | 需要和其他异步工作排进同一条 stream 时，先把 plan 绑定到该 stream |
| lifetime | plan 创建成本不低，真实工程应复用并显式销毁 |
| validation | 需要说明归一化、频域布局和正反变换约定 |

## 82.3 详解

下面按使用顺序列出检查项。

**创建 plan 之前**

1. 变换维度（1D/2D/3D）和每一维的长度是否确定。多维数据按 C 的 row-major 顺序理解，最后一维变化最快，例如 `cufftPlan2d(&plan, nx, ny, type)` 中 `ny` 是内存里连续的那一维，要确认这与数据在内存里的排列一致。
2. 是否要一次做多个同样长度的变换（batch）。1D 变换可以直接在 `cufftPlan1d` 的 `batch` 参数里给出；2D/3D 要 batch，或者数据不是紧密排列时，需要用能描述 stride 和间距的 plan 接口（`cufftPlanMany`）。
3. 变换类型是复数到复数、实数到复数还是复数到实数，精度是单精度还是双精度。

**准备 buffer**

4. 元素类型与变换类型一致：单精度用 `cufftReal`、`cufftComplex`，双精度用 `cufftDoubleReal`、`cufftDoubleComplex`。
5. 实数到复数的变换只输出非冗余的一半频谱：长度为 N 的实数输入对应 N/2+1 个复数输出（多维时只在最后一维减半）。输出 buffer 的大小和后续 kernel 的下标都要按这个长度计算。
6. 实数与复数之间做 in-place 变换时，实数数组的最后一维要补齐到 2×(N/2+1) 个实数（N 是最后一维的逻辑长度），让它和复数输出占同样的字节数；补齐的位置不参与计算。

**执行**

7. 复数到复数的变换用 `CUFFT_FORWARD` 或 `CUFFT_INVERSE` 指定方向；实数到复数固定是正变换，复数到实数固定是逆变换。
8. 执行调用相对 host 是异步的。需要和前后的 kernel 排在同一条 stream 上时，用 `cufftSetStream` 绑定；读取结果前要同步，或者经由 `cudaMemcpy` 取回。
9. 每个 cuFFT 调用都返回 `cufftResult`，和其他库一样要逐个检查。

**验证**

10. cuFFT 不做归一化：正变换后再做逆变换，结果是原数据乘以变换长度（多维时是各维长度之积），需要自己除回去。
11. 输出频谱按标准顺序排列：下标 0 是零频分量。复数到复数变换的后半段对应负频率，例如长度 16 时下标 15 是频率 −1；实数到复数变换只输出 0 到 N/2 这些非负频率。需要把零频移到中间时要自己处理。
12. 先用答案已知的小输入（例如单一频率的正弦信号）和 CPU 上的 FFT 实现对比，再上真实数据。

## 82.4 代码示例

本章不给出完整程序。一次典型的 cuFFT 调用由四步组成：

1. 创建 plan：规则排列的数据用 `cufftPlan1d`、`cufftPlan2d`、`cufftPlan3d`，更一般的布局用 `cufftPlanMany`；
2. 需要时用 `cufftSetStream` 绑定 stream；
3. 执行变换，例如 `cufftExecC2C`、`cufftExecR2C`、`cufftExecC2R`；
4. 用 `cufftDestroy` 释放 plan。

各函数的参数含义以 cuFFT 官方文档为准。写第一个 cuFFT 程序时，建议对照 82.3 的清单逐条核对。编译时要链接 cuFFT 库（`nvcc` 加 `-lcufft`）。

## 82.5 工程判断

| 现象 | 优先检查 |
|---|---|
| 正变换加逆变换后，数值整体放大了 N 倍 | 没有归一化，逆变换后要除以变换长度 |
| 实数到复数变换的输出后半段越界或是垃圾值 | 输出长度应按 N/2+1 计算 |
| 每次 FFT 都很慢 | 是否每次都重新创建 plan；同样形状的变换应复用 plan |
| 需要做大量小规模 FFT | 用 batch 一次提交，不要在 host 上循环调用 |
| FFT 夹在两个 kernel 之间 | 用 `cufftSetStream` 把 plan 放进同一条 stream，避免多余的同步 |

## 82.6 API 与要点速查

| API | 作用 |
|---|---|
| `cufftPlan1d` / `cufftPlan2d` / `cufftPlan3d` | 为规则排列的 1D/2D/3D 数据创建 plan |
| `cufftPlanMany` | 用 batch、stride 和间距描述更一般的数据布局 |
| `cufftSetStream` | 把 plan 绑定到指定 stream |
| `cufftExecC2C` / `cufftExecR2C` / `cufftExecC2R` | 执行单精度变换；双精度对应 `Z2Z`、`D2Z`、`Z2D` |
| `cufftDestroy` | 释放 plan 及其占用的资源 |

## 82.7 小结

读完本章，你应该能够在写 cuFFT 代码前后逐项核对：plan 描述的形状、batch 和类型是否正确，buffer 的类型和长度是否匹配，执行是否放在了正确的 stream 上，归一化和频谱排列是否按预期处理。完整的 API 用法以 cuFFT 官方文档为准。
