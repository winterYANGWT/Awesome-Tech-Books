# 第 1 章 三个阶段：配置、生成、构建

“改了 CMakeLists.txt 要不要重新跑 cmake？”“`message()` 为什么打印不出 `$<CONFIG>` 的值？”“为什么不能在源码目录里构建？”这几个问题背后是同一件事：CMake 的工作分成三个阶段，每一行写下的东西在不同的阶段生效。先打开一个三行的工程，看一遍完整的过程。

## 1.1 两条命令，三个阶段

上面的查看器顶上有四页：**配置**、**生成**、**构建**、**运行**。它们对应你在终端里敲的两条命令：`cmake -S src -B build` 做了前两件事，`cmake --build build` 做了第三件。

{{#fig ch01/three_phases}}

- **配置**：cmake 从 `CMakeLists.txt` 第一行执行到最后一行。查看器的配置页一共 4 步，第 2 步 `project()` 在 CMake 自带的模块里又执行了六千多条命令（检测编译器），新增了约 300 个变量和 59 个缓存项。这一阶段的结果几乎都在 cmake 的内存里。
- **生成**：配置结束、缓存写进 `CMakeCache.txt` 之后，cmake 把目标 `hello` 翻译成 Ninja 的规则写进 `build.ninja`。查看器的生成页从配置结束开始列文件，所以 `CMakeCache.txt` 也出现在这一页；它是配置结束时写的，不是生成阶段写的。
- **构建**：`cmake --build` 只是替你调用 `ninja`。构建页里能看到 Ninja 真正执行的两条命令：先 `g++ … -c main.cpp`，再把 `main.cpp.o` 链接成 `hello`。

运行页里程序打印 `hello, built with C++17`：工程没有指定 C++ 标准，GCC 15 默认就是 C++17。换一个编译器，这一行可能不同——这类“没写就用默认值”的地方，[第 10 章](ch10.md) 会一一找出来。

## 1.2 构建目录里有什么

源码外构建时，源码目录里只有你写的两个文件，cmake 产生的一切都写在 `-B` 指定的构建目录里。打开上面查看器的“文件”标签（配置页右下），或者生成页的文件列表，能看到这些：

| 文件 | 哪个阶段写的 | 作用 |
|---|---|---|
| `CMakeFiles/4.2.3/` | 配置，`project()` 那一步 | 编译器检测的结果；第二次配置直接读它，不再检测 |
| `CMakeCache.txt` | 配置结束时 | 全部缓存变量；下一次配置从这里读回（[第 5 章](ch05.md)） |
| `build.ninja`、`CMakeFiles/rules.ninja` | 生成 | 每个目标怎样编译、链接；Ninja 只认这个文件 |
| `cmake_install.cmake` | 生成 | `cmake --install` 时执行的脚本（[第 16 章](ch16.md)） |
| `CMakeFiles/hello.dir/main.cpp.o`、`hello` | 构建 | 目标文件和程序 |

既然所有产物都在一个目录里，删掉构建目录就回到干净状态，同一份源码也可以同时有 `build-debug/`、`build-release/` 好几个构建目录。如果把构建目录设成源码目录本身，会怎样？

第一次运行用的是 `cmake -S src -B src`。配置页第 2 步写出的 `CMakeFiles/`、配置结束时写出（在生成页列出）的 `CMakeCache.txt`、生成页的 `build.ninja`、构建页的 `hello` 和 `.o`，全都落在 `src/` 下面，每一条后面都标着“写进了源码目录”。

第二次运行换成独立的 `build/`，这一次不再往源码目录写新文件；运行 1 留下的 `CMakeCache.txt`、`build.ninja`、`CMakeFiles/`、`hello` 等还在 `src/` 里。

源码内构建的麻烦不止是乱：`.gitignore` 要列一长串，清理时分不清哪些是自己写的，而且一个源码目录只能有一套配置。所以几乎所有 CMake 资料的第一条建议都是“源码外构建”（out-of-source build）。

## 1.3 同一个文件，三个阶段

一行 CMake 代码什么时候生效，要看它属于哪个阶段。下面这个文件故意把三个阶段的命令写在一起：

```cmake

```
{{#sidefx ch01/1_3_when}}

逐步点过去：

- 第 3 步 `message()`：输出立刻出现，`${CMAKE_CXX_COMPILER}` 已经被替换成 `/usr/bin/g++`。变量在配置阶段就有值。
- 第 4 步 `file(WRITE)`：“文件”一栏立刻多了 `build/configured.txt`。配置阶段的命令可以直接改磁盘。
- 第 5 步 `file(GENERATE)`：**什么副作用也没有**。它只是登记了一个“生成阶段要写的文件”，内容里的 `$<TARGET_FILE_NAME:app>` 这时还只是一段字符串——何况 `app` 在第 6 步才定义。切到生成页，`build/generated.txt` 出现了，点开能看到 `$<…>` 已经变成了 `app`；运行页最后一条 `cmake -E cat` 也会打出这一行。
- 第 7 步 `add_custom_command(TARGET app POST_BUILD …)`：配置阶段同样什么也没发生。切到构建页，第二条命令（链接）末尾接着执行了 `cmake -E echo`，打印“构建阶段：app 链接好了”。

| 写法 | 执行或求值的阶段 | 副作用出现在 |
|---|---|---|
| `set()`、`message()`、`if()`、`file(WRITE)`、`configure_file()`、`execute_process()` | 配置 | cmake 的内存、终端、配置时的磁盘 |
| `$<…>` 生成器表达式、`file(GENERATE)` | 生成 | 构建规则、生成阶段写的文件 |
| `add_custom_command()`、`add_custom_target()` 里的命令，编译和链接 | 构建 | 构建目录里的产物 |

这张表解释了开头的问题：`message("$<CONFIG>")` 在配置阶段执行，这时生成器表达式还没有求值，打印出来的就是原样的 `$<CONFIG>`。要看它的值，得像第 5 步那样用 `file(GENERATE)` 写到文件里（[第 9 章](ch09.md)）。

> **旧资料提示**：很多老教程在 `CMakeLists.txt` 里用 `execute_process()` 调代码生成器。它在配置阶段执行，只有重新配置时才会再跑；输入文件改了，构建并不会重新生成。这类事应该交给构建阶段的 `add_custom_command()`，见 [第 13 章](ch13.md)。

## 1.4 改了 CMakeLists.txt 之后

先构建一次，然后给 `greet` 加一个宏定义，**不重新执行 cmake**，直接 `cmake --build`：

```cmake
{{#include code/ch01/1_4_rerun/v2/CMakeLists.txt}}
```
{{#sidefx ch01/1_4_rerun run=2}}

第二次运行没有配置页：这一次没有单独执行 cmake。构建页的第一条命令是 `[0/1] /usr/bin/cmake --regenerate-during-build`：Ninja 发现 `build.ninja` 比 `CMakeLists.txt` 旧，先回头让 cmake 重新配置、生成，然后接着构建。下一条编译命令里出现了新加的 `-DGREETING=\"hi\"`，运行页打印 `hi`。

所以日常改 `CMakeLists.txt` 不需要手动重新配置，`cmake --build` 会自己处理。需要手动执行 `cmake` 的是另外几种情况：

| 情况 | 原因 | 做法 |
|---|---|---|
| 想改一个缓存变量 | 缓存只在配置时读写 | `cmake -B build -DX=Y`（[第 5 章](ch05.md)） |
| 用 `file(GLOB)` 收集源文件，又新加了文件 | CMake 不知道目录里多了文件 | 列出源文件，或加 `CONFIGURE_DEPENDS`（[第 25 章](ch25.md)） |
| 换编译器、换生成器 | 编译器检测结果在缓存和 `CMakeFiles/` 里 | 新建构建目录，或 `cmake --fresh` |

`cmake --build` 常用的几个参数：`--target 名字` 只构建一个目标，`-j N` 并行数，`--verbose` 打印完整命令（查看器的构建页就是这样录下来的），`--clean-first` 先清理再构建。

## 速查

| 命令 | 做什么 | 注意 |
|---|---|---|
| `cmake -S 源码 -B 构建目录` | 配置 + 生成 | 构建目录不要和源码目录相同 |
| `cmake -S . -B build -G Ninja` | 指定生成器 | 第一次配置时定下并记进缓存；之后换生成器会报错，要换就新建构建目录 |
| `cmake --build build` | 构建；需要时自动重新配置 | 等价于在构建目录里执行 `ninja` |
| `cmake --build build --verbose` | 打印每条真实命令 | 查参数从哪来时先看这个 |
| `cmake --fresh -B build` | 丢掉缓存重新配置 | 3.24 起才有 |
| 删掉 `build/` | 回到干净状态 | 源码目录不受影响 |
