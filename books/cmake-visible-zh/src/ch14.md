# 第 14 章 find_package：模块模式和配置模式

`find_package(GTest REQUIRED)` 写在 `CMakeLists.txt` 里只有一行，配置却能成功，还能直接链接 `GTest::gtest`。它去了哪些目录、读了谁写的文件、读完留下了什么？先看两个包：一个只有 Find 模块，一个由包自己提供配置文件。

{{#sidefx ch14/14_1_two_modes}}

第 3 步 `find_package(ZLIB REQUIRED)` 在模块里执行了 142 条命令，缓存栏新增 `ZLIB_INCLUDE_DIR:PATH=/usr/include` 和 `ZLIB_LIBRARY_RELEASE:FILEPATH=/usr/lib/x86_64-linux-gnu/libz.so`；第 5 步打印的 `ZLIB_DIR` 是空的。`ZLIB::ZLIB` 是 FindZLIB 模块用这两个值拼出来的导入目标。

第 4 步写的是 `find_package(GTest CONFIG REQUIRED)`：缓存里出现 `GTest_DIR:PATH=/usr/lib/x86_64-linux-gnu/cmake/GTest`，变量栏多了 `GTest_CONFIG` 和 `GTest_VERSION=1.17.0`。这一步执行了 1071 条模块命令，输出里的 `Found Threads: TRUE` 是 GTestConfig.cmake 自己又找了 Threads。

两次都叫 find_package，走的是两条路：

| 模式 | 找的文件 | 谁提供 | 本示例留下的 |
|---|---|---|---|
| 模块模式 | `Find<名>.cmake`，先找 `CMAKE_MODULE_PATH`，再找 CMake 自带的模块 | CMake、操作系统或项目自己 | `ZLIB_INCLUDE_DIR`、`ZLIB_LIBRARY_RELEASE`；`ZLIB_DIR` 空 |
| 配置模式 | `<名>Config.cmake` 或 `<小写名>-config.cmake`；请求版本时还有 `<名>ConfigVersion.cmake` 或 `<小写名>-config-version.cmake` | 包自己安装 | `GTest_DIR`、`GTest_CONFIG`、`GTest_VERSION` |

不带 `CONFIG` 的 `find_package(X)` 先试模块模式；模块里没找到，再退回配置模式。`CONFIG`（或同义的 `NO_MODULE`）跳过模块模式，`MODULE` 则相反，只用模块模式。

模块模式依赖 CMake 或系统维护的 Find 文件，配置模式依赖包安装时写下的 Config 文件。本机的 zlib 没有配置文件；不带 `CONFIG` 的 `find_package(ZLIB)` 先用 FindZLIB 模块，模块模式不写 `<名>_DIR`，所以 `ZLIB_DIR` 是空的。GTest 装了自己的 `GTestConfig.cmake`，明确写 `CONFIG` 时走的就是它，缓存里留下 `GTest_DIR`。

## 14.5 版本、COMPONENTS、REQUIRED 和 QUIET


```cmake
{{#include code/ch14/14_5_components/v2/CMakeLists.txt}}
```
{{#sidefx ch14/14_5_components}}

运行 1 第 3 步 `find_package(Boost 1.80 CONFIG REQUIRED COMPONENTS filesystem)` 执行了 332 条模块命令，缓存多了 `Boost_DIR`，还有 `boost_filesystem_DIR` 这些组件目录项；变量栏里 `Boost_FILESYSTEM_FOUND=1`、`Boost_LIBRARIES=Boost::filesystem`。

构建时链接 `libboost_filesystem.so.1.90.0`，还带上了 `libboost_atomic` 和几个 `-DBOOST_*`。这些是组件目标自己的用法要求，不是 `CMakeLists.txt` 里写的；`COMPONENTS` 后面的名字由包定义，少一个必需组件，整个包就算没找到。Boost 的 Config 也不是只读一个文件：它按组件再找 `boost_filesystem-config.cmake`，这些文件就在 `Boost_DIR` 附近。

运行 2 换成 `find_package(Tiny 9.0 CONFIG REQUIRED)`。第 4 步进入版本文件，第 5 步设 `PACKAGE_VERSION=1.2.3`，第 6 步判断 1.2.3 < 9.0 为真，第 7 步设 `PACKAGE_VERSION_COMPATIBLE=FALSE`，同一步输出报错：找到的配置文件版本是 1.2.3，和请求的 9.0 不兼容。`REQUIRED` 把“找不到”变成了配置失败。

| 写法 | 作用 | 本示例 |
|---|---|---|
| `COMPONENTS filesystem` | 要求一个组件；缺了它整个包不算找到 | `Boost_FILESYSTEM_FOUND=1`，链接 `Boost::filesystem` |
| `9.0` | 请求版本；是否兼容由版本文件判断 | 版本文件返回 FALSE，报错 |
| `REQUIRED` | 找不到就停止配置 | 运行 2 退出码 1 |
| `QUIET` | 关掉“没找到”的信息性输出 | 不改变 `REQUIRED` 的致命错误 |
| `EXACT` | 要求版本完全相等 | 示例没有用；`1.2` 不要求等于 `1.2.3` |

不写 `EXACT` 时，是否兼容由版本文件判断，常见写法是“不低于请求版本”。`QUIET` 只是把提示压下去，包没找到时 `Tiny_FOUND` 仍是 FALSE；后面链接 `Tiny::tiny` 才会在生成阶段报错。`QUIET` 和 `REQUIRED` 可以一起写：找不到时仍然报错，平时的提示更少。

```cmake
{{#include code/ch14/14_6_find_module/cmake/FindFoo.cmake}}
```
{{#sidefx ch14/14_6_find_module}}

第 3 步把 `cmake/` 加进 `CMAKE_MODULE_PATH`，第 4 步 find_package 才在 CMake 自带模块之前读到 `FindFoo.cmake`。模块默认找 `Find<包名>.cmake`，名字不对 find_package 不会读它。第 5 步算出 deps 根，第 6 步 `find_path` 把 `Foo_INCLUDE_DIR:PATH` 写进缓存，第 7 步 `find_library` 写 `Foo_LIBRARY:FILEPATH`。

第 9 步 `find_package_handle_standard_args` 检查两个必需变量，设 `Foo_FOUND` 并打印 `Found Foo: .../libfoo.a`；第 11 到 12 步建 `Foo::Foo`，把库文件和 include 目录挂上去。第 11 步的目标栏里，它后面标着“导入”。构建页两条命令：编译带 `-isystem /work/src/deps/foo/include`，链接直接写 `libfoo.a`，运行输出 `foo=73`。

第二次运行第 6、7 步没有缓存变化，构建页 0 条命令。`find_path` 和 `find_library` 先看同名缓存项，已有非 NOTFOUND 的值就不再搜；要让它们重找，删掉缓存项（`-U 'Foo_*'`）或换构建目录，这和[第 5 章](ch05.md)的缓存是同一套规则。示例的 `deps/foo` 是一个假的安装树：一个头文件和一个事先编好的 `libfoo.a`；用户项目里的 FindMimalloc 也是这个结构，`find_path` 找头文件，`find_library` 找库，`find_package_handle_standard_args` 报结果，最后建一个导入目标。

## 速查

| 写法 | 找什么 | 注意 |
|---|---|---|
| `find_package(X)` | 先模块模式，再配置模式 | 基本签名；模块里没找到才退回配置 |
| `find_package(X CONFIG)` | 只找 `XConfig.cmake` / `x-config.cmake` | 包自己提供配置文件时用 |
| `find_package(X MODULE)` | 只找 `FindX.cmake` | 不会退回配置模式 |
| `find_package(X 1.2 REQUIRED COMPONENTS a)` | 版本 + 组件 | 版本文件先执行，组件由包检查 |
| `find_package(X GLOBAL)` | 按正常顺序找，导入目标全局可见 | 3.24 起；等价于 `CMAKE_FIND_PACKAGE_TARGETS_GLOBAL` |
| `find_package(X QUIET)` | 没找到时不打印提示 | 不改变 `REQUIRED` 的错误 |

| 变量或缓存项 | 谁写 | 作用 |
|---|---|---|
| `X_DIR` | 配置模式找到后写缓存 | 配置文件所在的目录；也可以 `-D` 指定 |
| `X_CONFIG` | 配置模式 | 配置文件的完整路径 |
| `X_CONSIDERED_CONFIGS`、`X_CONSIDERED_VERSIONS` | 配置模式 | 看过的配置文件和对应版本（包括最终采用的那个） |
| `X_FOUND` | find_package | 包是否找到；大小写形式都可能有（本示例是 `Foo_FOUND` 和 `FOO_FOUND`） |
| `X_VERSION` | 版本文件或 Config | 找到的版本；本章的 Tiny 是 `1.2.3` |
| `CMAKE_PREFIX_PATH` | 用户 | 安装树的根，不是配置文件目录 |
| `CMAKE_MODULE_PATH` | 项目 | 先在这里找 `FindX.cmake` |
| `CMAKE_FIND_PACKAGE_PREFER_CONFIG` | 用户 | 为真时先配置模式、再模块模式 |
