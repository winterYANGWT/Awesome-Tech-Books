## 9.1 配置时只是字符串

配置页第 4 步执行 `target_compile_options` 后，目标栏里 `app` 的 `COMPILE_OPTIONS` 是 `$<IF:$<CONFIG:Debug>,-O0,-O2>`，既没有 `-O0` 也没有 `-O2`。这时只是把一段字符串挂到了目标上。

生成页里同一个目标变成了 `-O0`，后面标着来自 `CMakeLists.txt:5` 的 `target_compile_options`；构建页的第一条编译命令里也有 `-O0`。`file(GENERATE)` 写出的 `build/genex.txt` 在运行页被 `cat` 出来：

```text
config=Debug
options=-O0
binary=/work/build/app
```

第二次运行只把 `CMAKE_BUILD_TYPE` 换成 `Release`。第 4 步的属性还是同一段 `$<…>`，生成页里由这条命令贡献的参数却变成 `-O2`（构建类型自带的 `-O3 -DNDEBUG` 仍在前面），`genex.txt` 也跟着变成 `config=Release` 和 `options=-O2`。配置阶段存下的字符串没有变，变的是生成阶段对它的求值结果。

{{#fig ch09/genex_timeline}}

`file(GENERATE)` 写出的文件里，`binary=` 后面是完整路径，`options=` 后面是求值后的编译选项。文件名由 `OUTPUT` 决定，内容由 `CONTENT` 决定。想把表达式和它周围的值一起留下来，这是最直接的办法；写文件发生在生成阶段，不需要构建。

单配置生成器里，`$<CONFIG>` 就是 `CMAKE_BUILD_TYPE` 的值；换一种构建类型，同一份属性就会对另一种配置求值。生成器表达式不是“配置时算好的常量”，而是留给生成阶段、对每个目标和每种配置分别计算的一段描述。

{{#sidefx ch09/9_2_genex_kinds}}

第 6 步的 `file(GENERATE)` 什么也没写；切到生成页，`build/genex.txt` 出现了，运行页的 `cat` 把它逐行打印出来。`$<IF:$<CONFIG:Debug>,yes,no>` 得到 `yes`，`$<$<CONFIG:Debug>:debug-only>` 得到 `debug-only`；`$<CXX_COMPILER_ID>` 是 `GNU`，`$<CXX_COMPILER_ID:GNU,Clang>` 和 `$<COMPILE_LANG_AND_ID:CXX,GNU>` 都是 `1`。

`$<TARGET_FILE:app>` 给出 `/work/build/genex-app`，`$<TARGET_PROPERTY:app,OUTPUT_NAME>` 给出第 4 步设置的 `genex-app`。`$<CXX_COMPILER_ID>` 和 `$<COMPILE_LANG_AND_ID>` 需要二进制目标的上下文，所以 `file(GENERATE)` 末尾写了 `TARGET app`（3.19 起）；没有目标时，`$<CXX_COMPILER_ID>` 会报 “may only be used with binary targets”。

| 类别 | 写法 | GNU / Debug 下 |
|---|---|---|
| 配置 | `$<CONFIG>` | `Debug` |
| 条件 | `$<$<CONFIG:Debug>:debug-only>` | `debug-only` |
| 条件 | `$<IF:$<CONFIG:Debug>,yes,no>` | `yes` |
| 编译器 | `$<CXX_COMPILER_ID:GNU,Clang>` | `1` |
| 编译器 | `$<COMPILE_LANG_AND_ID:CXX,GNU>` | `1`（只对 C++ 源） |
| 目标 | `$<TARGET_FILE:app>` | `/work/build/genex-app` |
| 目标 | `$<TARGET_PROPERTY:app,OUTPUT_NAME>` | `genex-app` |
| 列表 | `$<JOIN:alpha;beta;gamma,\|>` | `alpha\|beta\|gamma` |
| 列表 | `$<LIST:TRANSFORM,alpha;beta,TOUPPER>` | `ALPHA;BETA` |

`$<LIST:…>` 是 3.27 才有的，所以这个示例第一行写 `3.27...4.2`；其余示例仍是 `3.25...4.2`。`$<JOIN:…>` 和 `$<LIST:JOIN,…>` 的差别在空项：`JOIN` 丢掉空项，`LIST:JOIN` 保留。

切到生成页：`app` 的编译参数里有 `-I/work/src/include`，后面标着“来自 greet 的 INTERFACE_INCLUDE_DIRECTORIES”，由第 6 步的 `target_link_libraries` 带过来；`greet` 自己也有同一个 `-I`。构建树里 `BUILD_INTERFACE` 生效，`INSTALL_INTERFACE` 展开成空。

运行页的 `cmake --install` 之后，`grep` 在 `prefix/lib/cmake/Greet/GreetTargets.cmake` 第 62 行找到：

```text
INTERFACE_INCLUDE_DIRECTORIES "${_IMPORT_PREFIX}/include"
```

安装导出时只有 `INSTALL_INTERFACE` 生效，相对路径 `include` 被写成 `${_IMPORT_PREFIX}/include`；`BUILD_INTERFACE` 这时是空的。导出文件的完整用法在 [第 17 章](ch17.md)。

```cmake
{{#include code/ch09/9_4_multi_config/CMakeLists.txt}}
```
{{#sidefx ch09/9_4_multi_config}}

第 3 步打印出可用的配置：`Debug;Release;RelWithDebInfo`，以及当时为空的 `CMAKE_BUILD_TYPE`。生成页里除了 `build.ninja`，还多出 `build-Debug.ninja`、`build-Release.ninja`、`build-RelWithDebInfo.ninja` 各一份；`file(GENERATE)` 也按配置写出 `config-Debug.txt`、`config-Release.txt`、`config-RelWithDebInfo.txt` 三份。

第一次运行默认构建 Debug：编译命令里有 `-DAPP_CONFIG=\"Debug\"`，程序输出 `config=Debug`。运行页的 after 又执行 `cmake --build build --config Release`，再运行 `Release/app`，输出 `config=Release`。

{{#fig ch09/genex_eval_scope}}

生成页的目标卡只列 Debug 这一份，显示 `-DAPP_CONFIG="Debug"`；三份编译规则各自带着对应配置的 `-DAPP_CONFIG`，不过它们在 `CMakeFiles/impl-*.ninja` 里，查看器把 `CMakeFiles/` 下的文件合并成内部文件，不能直接点开。

三份 `config-*.txt` 的内容只有配置名不同；运行页的 `cat` 依次读出 `config=Debug`、`config=Release`、`config=RelWithDebInfo`，和生成页的文件列表对得上。

把查看器切到第二次运行：它加 `-DCMAKE_BUILD_TYPE=Release`，第 3 步的输出里 `CMAKE_BUILD_TYPE=[]` 变成 `[Release]`；随后的构建仍然是 Debug，`--config Debug` 只得到 `ninja: no work to do.`。

多配置生成器用 `CMAKE_CONFIGURATION_TYPES` 列出配置、用 `--config` 选择配置；`CMAKE_BUILD_TYPE` 是单配置生成器的变量。想让 `build.ninja` 默认用别的配置，设 `CMAKE_DEFAULT_BUILD_TYPE`（3.17 起），值必须是 `CMAKE_CONFIGURATION_TYPES` 里的一项。

## 9.5 调试生成器表达式

生成器表达式不能用 `message()` 看到求值结果，最常见的错误是把它塞进 `if()`。这个反例在 Debug 下配置，但 `if()` 比较的是两个字符串：

```cmake
{{#include code/ch09/9_5_genex_in_if/CMakeLists.txt}}
```
{{#sidefx ch09/9_5_genex_in_if}}

第 4 步的 `if()` 拿到的是字符串 `$<CONFIG>`，不是 `Debug`；第 5 步的 `message()` 把它原样打印出来。构建页的编译命令里没有 `DEBUG_BRANCH`，运行结果是 `branch=no`，即使这次配置用的就是 Debug。

运行页最后一条 `cmake --build build --target genexdebug` 构建了一个自定义目标，它的 `cmake -E echo` 在构建阶段执行，打印 `生成时 Debug`。`genexdebug` 默认不构建，只有指定 `--target` 才会执行。这是官方文档给的调试办法之一：把表达式放进构建阶段才执行的命令。

调试生成器表达式有几条路，看到的东西不一样：

| 办法 | 看哪里 | 限制 |
|---|---|---|
| `file(GENERATE)` | 生成页里写出的文件，运行页 `cat` | 只能看写进 `CONTENT` 的值 |
| `add_custom_target` + `cmake -E echo` | 构建页执行 `--target` 时的输出 | 目标默认不构建，要显式指定 |
| `cmake --build --verbose` | 最终编译、链接命令里的参数 | 看不到属性本身，属性要靠 `$<TARGET_PROPERTY>` |

想知道某个属性最后是什么，可以在 `file(GENERATE)` 的 `CONTENT` 里写 `$<TARGET_PROPERTY:目标,属性>`；9.1 的 `options=` 这一行就是这么来的。

所以在 `if()` 里这样判断 `$<CONFIG>` 永远不成立；想按配置分支，就把表达式放进目标属性，或者用 `file(GENERATE)` 写出来再读。单配置生成器里可以用 `CMAKE_BUILD_TYPE` 做 `if()`；多配置下这个变量不参与选择配置，如果仍传了 `-DCMAKE_BUILD_TYPE=Debug`，`if()` 会按这个值走，但它和 `--config` 实际用的配置无关。

## 速查

| 写法 | 求值结果（GNU / Debug） | 注意 |
|---|---|---|
| `$<CONFIG>` | `Debug` | 单配置下取自 `CMAKE_BUILD_TYPE` |
| `$<CONFIG:Debug>` | `1` | 配置名匹配时为 1，否则为 0 |
| `$<$<CONFIG:Debug>:x>` | `x` | 外层是条件表达式，不匹配时为空 |
| `$<IF:cond,a,b>` | `a` 或 `b` | 3.8 起；`cond` 必须是 0 或 1 |
| `$<CXX_COMPILER_ID:GNU,Clang>` | `1` | 多个 ID 用逗号分隔 |
| `$<COMPILE_LANG_AND_ID:CXX,GNU>` | `1` | 需要目标上下文，只对 C++ 源 |
| `$<TARGET_FILE:app>` | `/work/build/app` | 目标产物全路径 |
| `$<TARGET_PROPERTY:app,PROP>` | 属性值 | 属性不存在时为空 |
| `$<JOIN:list,glue>` | `alpha\|beta` | 丢掉空项 |
| `$<LIST:…>` | 见 9.2 | 3.27 起；`LIST:JOIN` 保留空项 |
| `$<BUILD_INTERFACE:…>` | 构建树里生效 | `install(EXPORT)` 时为空 |
| `$<INSTALL_INTERFACE:…>` | 安装导出里生效 | 构建树里为空 |

## 思考题

1. 在 `9_1_genex_string` 里再加一次运行，参数是 `-DCMAKE_BUILD_TYPE=RelWithDebInfo`。预测 `genex.txt` 的 `config` 和 `options` 两行，以及编译命令里 `-O0`、`-O2` 哪个出现。
   <details><summary>提示</summary>`RelWithDebInfo` 不是 `Debug`，条件为假，走 `-O2`；构建类型自己还会加 `-O2 -g -DNDEBUG`。</details>
2. 在 `9_2_genex_kinds` 的 `file(GENERATE)` 里加两行：`find=$<LIST:FIND,alpha;beta;gamma,beta>` 和 `lj=$<LIST:JOIN,alpha;;beta,|>`。预测 `find` 和 `lj` 的值；再把 `LIST:JOIN` 换成 `JOIN`，看空项还在不在。
   <details><summary>提示</summary>`FIND` 返回下标 1；`LIST:JOIN` 保留空项，得到 `alpha||beta`，`JOIN` 会把它丢掉。</details>
3. 把 `9_3_build_install_interface` 的 `$<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>` 删掉，只留 `$<INSTALL_INTERFACE:include>`，重新配置并构建。`app` 的编译会怎样？`cmake --install` 还会成功吗？
   <details><summary>提示</summary>构建树里包含目录为空，`app` 找不到 `greet/greet.h`；安装导出本身不编译代码，仍会写出 `include`。</details>
4. 把 `9_5_genex_in_if` 的 `if("$<CONFIG>" STREQUAL "Debug")` 改成 `if(CMAKE_BUILD_TYPE STREQUAL "Debug")`。单配置下 Debug 和 Release 各是什么结果？换成 `-G Ninja Multi-Config` 呢？
   <details><summary>提示</summary>单配置下 `CMAKE_BUILD_TYPE` 有值，Debug 能进分支；多配置下它不参与选择配置，但如果你仍传 `-DCMAKE_BUILD_TYPE=Debug`，`if()` 还是会进这个分支，只是它和 `--config` 用的配置无关。</details>
