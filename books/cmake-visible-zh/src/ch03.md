# 第 3 章 CMake 语言：一切都是字符串

`set(FLAGS -Wall -Wextra)` 和 `set(FLAGS "-Wall -Wextra")` 差在哪？在 `if()` 里展开 `${X}` 为什么有时安静地变假，有时直接报错？这两个问题都落在同一套规则上：命令先被拆成参数，`${}` 在命令执行前替换，剩下带分号的字符串再当列表拆开。

第 1 章看到 `${CMAKE_CXX_COMPILER}` 在配置阶段就被替换成了路径（[1.3 节](ch01.md)），第 2 章看到 `project()` 一次设下几百个变量；这一章把替换的时机和拆分的边界讲清楚。

## 3.1 命令、参数、引号

先看一个只做一件事的工程：`show()` 打印收到的参数个数和每个参数，下面用不同写法调用它。

```cmake
{{#include code/ch03/3_1_arguments/CMakeLists.txt}}
```
{{#sidefx ch03/3_1_arguments}}

| 调用 | `ARGC` | 函数收到的参数 |
|---|---|---|
| `show(a b c)` | 3 | `a`、`b`、`c` |
| `show("a b c")` | 1 | `a b c` |
| `show(a;b;c)` | 3 | `a`、`b`、`c` |
| `show("a;b;c")` | 1 | `a;b;c` |
| `show(${EMPTY})` | 0 | 没有参数 |
| `show("${EMPTY}")` | 1 | 一个空串 |
| `show("" "")` | 2 | 两个空串 |
| `show(one "two three" four;five)` | 4 | `one`、`two three`、`four`、`five` |

第 5 步进入 `show()` 时，作用域里已经放好 `ARGC=3` 和 `ARGV0..2`；第 16 步换成 `"a b c"`，`ARGC` 变成 1，第 20 步的 `ARGV0` 是 `a b c`。引号不是在值里加引号，它只是让空格和分号留在这一个参数里。

分号也一样：`show(a;b;c)` 在第 23 步仍然收到 3 个参数，`show("a;b;c")` 在第 34 步只收到 1 个，第 38 步的 `ARGV0` 里带着两个分号。空串更绕：`${EMPTY}` 没加引号时，展开后不产生参数，第 41 步 `ARGC=0`；`"${EMPTY}"` 加引号后产生一个空参数，第 46 步 `ARGC=1`，第 50 步打印出 `ARGV0=[]`。

{{#fig ch03/arg_split}}

查看器命令下面那行“展开变量后，命令实际收到的参数”来自 CMake 的调试轨迹，它在按分号拆分之前就记下了参数：`show(${EMPTY})` 在这里显示成 `show("")`，和函数里的 `ARGC=0` 对不上。数参数时看函数作用域里的 `ARGC` 和 `ARGV<i>`。函数作用域本身留给[第 4 章](ch04.md)，这里只看参数。

`set(FLAGS -Wall -Wextra)` 走的是同一条路：`set()` 收到两个值，存成 `-Wall;-Wextra`；`set(FLAGS "-Wall -Wextra")` 收到一个值，里面是一个空格。列表到底是什么，下一节用 `list()` 和构建命令看。

## 3.2 列表就是带分号的字符串

`set(L a b c)` 之后，`L` 不是三个变量，也不是数组，就是一个字符串 `a;b;c`。

```cmake
{{#include code/ch03/3_2_lists/CMakeLists.txt}}
```
{{#sidefx ch03/3_2_lists}}

第 3 步 `set()` 把三个参数用分号连成一个值；第 5 步 `list(APPEND)` 在末尾接上 `;d`，第 6 到 8 步的 `LENGTH`、`GET`、`JOIN` 都只是在这个字符串上按分号数元素、取元素、换连接符。`list()` 没有创造新类型，它只是替你读写这个带分号的字符串。

| 步骤 | 结果 |
|---|---|
| `set(L a b c)` | `L=a;b;c` |
| `list(APPEND L d)` | `L=a;b;c;d` |
| `list(LENGTH L len)` | `len=4` |
| `list(GET L 0 first)` | `first=a` |
| `list(JOIN L " " joined)` | `joined=a b c d` |

`set(FLAGS -Wall -Wextra)` 和 `set(SPACED "-Wall -Wextra")` 的区别在第 11 到 14 步：前者 `LENGTH` 是 2，后者是 1；打印出来，`SPACED` 的值就是 `-Wall -Wextra`，没有分号。

把 `FLAGS` 交给 `target_compile_options()` 时，第 19、20 步读到的属性都是 `-Wall;-Wextra`，不管调用时加没加引号。它写进的是 `COMPILE_OPTIONS` 这个分号分隔的列表属性，所以 `"${FLAGS}"` 里的分号仍是列表项，挡不住拆分；构建页第 1、2 条编译命令也确实都带两个选项。

要在构建命令里看见参数边界，可以换一个不经过 `COMPILE_OPTIONS` 的命令：两个 `add_custom_target()` 分别执行 `cmake -E echo`，构建页第 5、6 条命令一条是 `echo -Wall -Wextra`，另一条是 `echo "-Wall;-Wextra"`。不加引号的 `${FLAGS}` 展开后仍被拆成两个参数，引号里的 `-Wall;-Wextra` 才留在一个参数里；前者打印两个词，后者打印一个带分号的词。

## 3.4 if() 的规则

`if()` 有两套读法：`if(X)` 把 X 当变量名，`if(${X})` 先把值拼进来，再按常量或变量名解释。

```cmake
{{#include code/ch03/3_4_if_truthy/CMakeLists.txt}}
```
{{#sidefx ch03/3_4_if_truthy}}

| `X` 的值 | `if(X)` | `if(${X})` |
|---|---|---|
| `ON` | TRUE | TRUE |
| `OFF` | FALSE | FALSE |
| `TRUE` | TRUE | TRUE |
| `FALSE` | FALSE | FALSE |
| `YES` | TRUE | TRUE |
| `NO` | FALSE | FALSE |
| `Y` | TRUE | TRUE |
| `N` | FALSE | FALSE |
| `IGNORE` | FALSE | FALSE |
| `NOTFOUND` | FALSE | FALSE |
| `1` | TRUE | TRUE |
| `0` | FALSE | FALSE |
| `2` | TRUE | TRUE |
| `-1` | TRUE | TRUE |
| `0.0` | **TRUE** | **FALSE** |
| `abc` | **TRUE** | **FALSE** |
| `foo-NOTFOUND` | FALSE | FALSE |
| 空串 | FALSE | FALSE |

这张表来自第 4 到 112 步的循环：每一轮 `set(X ...)` 后用两种写法各判一次。`if(X)` 只看变量是否定义、值是不是假常量，所以 `abc` 也是真；`if(${X})` 会把值重新按 `if()` 的规则解释：`abc` 变成变量名（未定义，假），`0.0` 变成数字零（假）。`0.0` 这一行就是因为变量形式不把值当数字解析，替换之后才按数字零处理。

`if(${X})` 在 X 为空时变成 `if()`，第 110 步它是假，没有报错。下面的反例里，`if(${X} STREQUAL "abc")` 遇到空值会变成 `if(STREQUAL "abc")`，直接报 `Unknown arguments specified`。

| 写法 | 判断什么 | 示例里的结果 |
|---|---|---|
| `TARGET app` | 目标是否已经定义 | 真，第 115 步 |
| `EXISTS ".../main.cpp"` | 文件是否存在 | 真 |
| `"extra" IN_LIST features` | 元素是否在列表变量里 | 真，`features` 是 `core;extra` |
| `DEFINED CMAKE_CXX_COMPILER` | 变量是否定义 | 真 |
| `"${CMAKE_CXX_COMPILER_ID}" STREQUAL "GNU"` | 字符串相等 | 真 |
| `2 EQUAL 2` | 数字相等 | 真，第 119 步 |

第 115 步把这些条件用 `AND` 串起来，第 116 步给 `app` 加上 `HAVE_EXTRA`；第 117 步的 `STREQUAL` 和版本比较在第 118 步加 `GCC15`；第 119 步的 `EQUAL` 在第 120 步加 `TWO`。运行页三行 `HAVE_EXTRA`、`GCC15`、`TWO` 都打印出来，说明这些判断都走了真分支。

第 5 步的 `if(${name} STREQUAL "abc")` 展开成 `if(MODE STREQUAL abc)`，`if()` 又自动把 `MODE` 解引用成 `abc`，于是第 6 步走进真分支，得到 `wrong-match`。本意是比较 `name` 的值 `MODE` 和 `abc`，应该写 `if("${name}" STREQUAL "abc")`（第 7 步，假）或 `if(name STREQUAL "abc")`。

{{#fig ch03/if_expand}}

第二次运行把 `EMPTY` 展开进比较，第 4 步变成 `if(STREQUAL abc)`，报 `Unknown arguments specified`，配置失败。空值单独放在 `if(${X})` 里只是假，放进二元比较就缺少左操作数。

## 3.5 注释、续行和方括号参数

CMake 的注释和字符串还有几种不常写的形式：块注释、引号里的续行、原样保留的方括号参数。

```cmake
{{#include code/ch03/3_5_bracket/CMakeLists.txt}}
```
{{#sidefx ch03/3_5_bracket}}

| 写法 | 作用 | 注意 |
|---|---|---|
| `# ...` | 行注释 | 到行尾结束 |
| `#[[ ... ]]` | 块注释 | 整段不执行；内容里出现 `]]` 会提前结束 |
| `[=[ ... ]=]` | 方括号参数 | 永远是一个参数；不展开变量、不处理转义 |
| 引号参数里行尾的 `\` | 续行 | 只删掉换行，不插入空格 |

第 4 步的 `RE` 用 `[=[ ... ]=]` 原样保存正则，反斜杠不用写两遍；第 5 步 `MATCHES` 用它匹配 `v1.4.2`，第 6 到 8 步取出三个数字。第 9 步的 `message()` 里有一个引号续行，源码分两行，打印出来是一行，换行被删掉而不是换成空格。

第 10 步的 `META` 也是方括号参数，里面的 `${这里不会展开}` 原样进了 `build/meta.json`（第 11 步的文件），第 12 步的 `message()` 也把它原样打印出来。方括号参数永远是一个参数，不展开变量、不处理转义，写 JSON、正则、代码片段时省事。

块注释 `#[[ ... ]]` 从 `#[[` 到 `]]` 整段都不执行，所以配置页的步数里没有它；它也不能嵌套，内容里出现 `]]` 就提前结束。要包含 `]]` 时用更长的括号：

```cmake
#[=[ 这里可以写 ]] 和 ${不展开} ]=]
```

变量、列表、`if()` 都建立在这些字符串上；`set()` 把值写进当前作用域。下一章看这个作用域在子目录、函数和 `include()` 里怎样复制和销毁。

## 速查

| 写法 | 副作用发生在 | 注意 |
|---|---|---|
| `set(X a b)` | 配置 | 值变成 `a;b`；列表就是带分号的字符串 |
| `set(X "a b")` | 配置 | 一个字符串，里面是一个空格；没有分号 |
| `${X}`、`${${name}}` | 配置，命令执行前 | 未定义展开成空串；嵌套从内向外 |
| `$ENV{X}`、`$CACHE{X}` | 配置，命令执行前 | 只从环境 / 缓存取值；`$CACHE{}` 不看普通变量 |
| `if(X)` | 配置 | 把 X 当变量名；未定义或值是假常量时为假 |
| `if(${X})` | 配置 | 先替换再判断；空值成为 `if()`，为假 |
| `[=[ ... ]=]` | 配置 | 永远一个参数；变量不展开 |

2. 把 `3_2_lists` 里 `target_compile_options(app PRIVATE ${FLAGS})` 改成 `target_compile_options(app PRIVATE "-Wall -Wextra")`。`COMPILE_OPTIONS` 会变成几项？构建页的编译命令会多出什么？

3. 把 `3_4_if_deref` 的 `set(MODE "abc")` 改成 `set(MODE "xyz")`。第一个 `if()` 还走真分支吗？为什么？
   <details><summary>提示</summary>`if(${name} ...)` 展开成 `if(MODE STREQUAL abc)`；`MODE` 被解引用成 `xyz`，和 `abc` 不等，走假分支。</details>
4. 在 `3_4_if_deref` 的第二次运行里，把 `if(${EMPTY} STREQUAL "abc")` 改成 `if("${EMPTY}" STREQUAL "abc")`。还会报错吗？结果是什么？
