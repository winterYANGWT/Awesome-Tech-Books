# 第 25 章 旧写法为什么被取代

Deniz Bahadir 在 Meeting C++ 2018 的演讲 *More Modern CMake* 里，把示例工程从 CMake 2.8 时代的写法改到 3.12。改的多是命令作用的位置：从“这个目录”缩到“这个目标”。下面六组示例各跑新旧两遍；25.3 的 GLOB 组另外多两次只构建的运行，看副作用落在哪里。

## 25.1 include_directories / add_definitions → target_*

`include_directories()` 的名字里没有 target：它写当前目录的属性，当前目录的目标拿到，之后添加的子目录也继承。`add_definitions()` 也写目录属性：目录里的目标不管在命令前还是命令后创建，编译时都带这些宏，之后添加的子目录也继承。


子目录里只有一个和根目录头文件无关的库：

```cmake
{{#include code/ch25/25_1_dir_vs_target/sub/CMakeLists.txt}}
```
{{#sidefx ch25/25_1_dir_vs_target}}

运行 1 第 3、4 步把 `include/common` 和 `OWNER=1` 写进顶层目录属性。第 6 步 `helper` 一创建，目标属性里就带着 `IncludeDirectories=/work/src/include/common`；第 7 步它自己的 `PUBLIC` 目录追加在后面变成了两项。生成页里 `helper` 的编译参数有 `-I/work/src/include/common` 和 `-DOWNER=1`，构建页第 1 条命令就是带着这两个参数编译 `sub/helper.cpp`。

这个库既没包含 `value.h`，也没用过 `OWNER`。它只是恰好建在这个目录下面。

运行 2 换成 `target_include_directories(app ...)` 和 `target_compile_definitions(app ...)`。第 4 步创建的 `helper` 只有自己的 `-I/work/src/sub`；生成页里它的参数列表没有根目录的 `-I`，也没有 `-DOWNER=1`。`app` 仍然通过第 8、9 步拿到需要的东西，运行页输出不变；运行 2 末尾的检查命令用 `ninja -t commands helper` 确认它的编译行只有自己的 `-I`，没有 `-DOWNER=1`。

{{#fig ch25/dir_property_blast}}

`link_directories()` 也是目录属性，但它只对调用之后创建的目标生效，链接行多出 `-L`。本章示例没有用到它；这条结论来自它的[命令文档](https://cmake.org/cmake/help/v4.2/command/link_directories.html)。

新写法里，`link_directories()` 对应 `target_link_directories()`；链接选项用 `target_link_options()`，宏定义用 `target_compile_definitions()`，作用范围都写在目标名后面。这就是[第 8 章](ch08.md)的用法要求：它挂在目标上，不挂在目录上。

## 25.2 改 CMAKE_CXX_FLAGS → target_compile_options / compile features

`CMAKE_CXX_FLAGS` 是语言级变量，在设置它的目录和之后进入的子目录里，所有 C++ 编译调用都带它，链接行也带（子目录在 `add_subdirectory()` 时复制当时的值，见 [10.2 节](ch10.md)）。`add_subdirectory()` 进来的第三方代码同样是 C++，一样躲不开。

```cmake
{{#include code/ch25/25_2_cxx_flags/CMakeLists.txt}}
```
{{#sidefx ch25/25_2_cxx_flags}}

运行 1 第 3 步把 `-Wall -Werror` 拼进 `CMAKE_CXX_FLAGS`。生成页里 `app` 和 `legacy` 的参数都写着 `-Wall -Werror`，后面标着“CMake 自己加的”。构建页第 1 条命令编译 `vendor/legacy.cpp`，`-Werror` 把 `unused variable` 变成错误，构建停在这里，`app` 根本没轮到。

运行 2 第 7 步只给 `app` 加 `target_compile_options(app PRIVATE -Wall -Werror)`。生成页里 `legacy` 的参数是空的，`app` 有两个选项；构建页第 1 条命令编译 `legacy.cpp` 时不带警告选项，第 2 条才给 `app` 加上，程序打印 `legacy=2`。

警告选项应该只跟自己的目标走。语言标准也不要拼进 flags，用 `target_compile_features(app PRIVATE cxx_std_17)`，让 CMake 按编译器决定加不加 `-std=`（[第 10 章](ch10.md)）。第三方目录的警告不归你管，更不该替它开 `-Werror`。

## 25.3 file(GLOB) 收集源文件

`file(GLOB)` 在配置阶段把匹配到的文件名固定成一份列表。列表存进变量以后，目录里再多一个 `.cpp`，构建系统不会知道。

```cmake
{{#include code/ch25/25_3_glob/CMakeLists.txt}}
```
{{#sidefx ch25/25_3_glob}}

运行 1 第 3 步 `SOURCES` 只有 `main.cpp` 和 `registry.cpp`，构建页编译两个文件，程序打印 `units=0`。运行 2 往源码目录里放进了 `extra.cpp`，但只执行 `cmake --build`：没有配置页，构建页一条命令也没有，程序仍是 `units=0`。新文件没有进 `build.ninja`，Ninja 不会去编译它。

运行 3 换成 `file(GLOB SOURCES CONFIGURE_DEPENDS "*.cpp")`。`CONFIGURE_DEPENDS` 从 3.12 起才有；第 3 步的列表里出现了 `extra.cpp`，构建页第 1 条命令变成 `[0/2] cmake -P .../VerifyGlobs.cmake`，检查通过后才编译 `extra.cpp`，程序变成 `units=1`。代价是每次构建都多一步检查，文档也说这个标志在有的生成器上不可靠，更稳的办法仍然是把源文件列出来。

运行 4 再加 `third.cpp`、仍然只构建。检查发现 GLOB 不匹配，先执行 `--regenerate-during-build` 重新配置，再检查一遍，最后编译 `third.cpp`，程序变成 `units=2`。

## 25.4 ${X_LIBRARIES} / ${X_INCLUDE_DIRS} 变量 → 导入目标

`find_package()` 找到包以后，模块模式通常给两套东西：`X_LIBRARIES`、`X_INCLUDE_DIRS` 这些变量，和一个导入目标（imported target）`X::X`。变量是几个字符串，导入目标把包含目录、链接库和编译定义绑在一起。

```cmake
{{#include code/ch25/25_4_vars_vs_targets/CMakeLists.txt}}
```
{{#sidefx ch25/25_4_vars_vs_targets}}

这里用 LibXml2 而不是 ZLIB：本机的 `zlib.h` 就在 `/usr/include`，忘了加 `ZLIB_INCLUDE_DIRS` 也编得过，演示不出差别。libxml2 的头文件在 `/usr/include/libxml2`，不在编译器默认路径里；`LibXml2::LibXml2` 从 3.12 起提供。

运行 1 第 3 步 `find_package(LibXml2 REQUIRED)` 同时定义了变量和导入目标，但第 5 步只链接 `${LIBXML2_LIBRARIES}`。生成页里 `app` 只有链接行，没有包含目录；构建页第 1 条编译命令没有 `-isystem`，停在 `libxml/parser.h: No such file or directory`。

运行 2 第 5 步改成 `target_link_libraries(app PRIVATE LibXml2::LibXml2)`。生成页里 `app` 多了一行 `-I/usr/include/libxml2`，标着来自 `LibXml2::LibXml2` 的 `INTERFACE_INCLUDE_DIRECTORIES`；构建页把这一项写成 `-isystem /usr/include/libxml2`，编译通过，程序打印 `libxml2=2.15.2`。

| 写法 | 链接时带过来的东西 |
|---|---|
| `${LIBXML2_LIBRARIES}` | 只有库文件；包含目录要自己从 `${LIBXML2_INCLUDE_DIRS}` 搬 |
| `LibXml2::LibXml2` | `INTERFACE_INCLUDE_DIRECTORIES` 里的 `/usr/include/libxml2` 和导入位置一起带过来 |

变量写法的问题不在名字，而在它只带了一个列表：用到包的目标要自己把包含目录、编译定义、链接选项逐个搬过去，漏一个就可能在另一台机器上编不过。导入目标把这些放在 `INTERFACE_*` 属性里，链接一次全带过来。

## 25.5 在 CMakeLists.txt 里 set(CMAKE_BUILD_TYPE Release)

单配置生成器下 `CMAKE_BUILD_TYPE` 通常为空（`CMAKE_BUILD_TYPE` 环境变量或工具链可以给默认值）。用户用 `-DCMAKE_BUILD_TYPE=Debug` 把它写进缓存；工程里再 `set(CMAKE_BUILD_TYPE Release)`，建的是普通变量。按[第 5 章](ch05.md)的规则，普通变量遮住同名的缓存项。

```cmake
{{#include code/ch25/25_5_force_build_type/CMakeLists.txt}}
```
{{#sidefx ch25/25_5_force_build_type}}

运行 1 第 3 步把普通变量设成 `Release`。第 4 步打印 `build type: Release`，第 5 步用 `$CACHE{CMAKE_BUILD_TYPE}` 读缓存，打印的却是 `Debug`。生成页里 `app` 的编译选项是 `-O3 -DNDEBUG`，构建页两条命令都带着它们，运行页打印 `NDEBUG=1` 和 `OPTIMIZE=1`——用户要的 Debug 没有生效。

运行 2 把这一行删掉，第 3、4 步都打印 `Debug`。生成页的编译选项变成 `-g`，运行页打印 `NDEBUG=0` 和 `OPTIMIZE=0`。同一个构建目录、同一个 `-D`，差别只在有没有那行 `set()`。

构建类型是用户或预设（preset）的选择，工程不该替用户决定。要设默认值就写进预设，不要用 `set(... CACHE ... FORCE)` 把用户的值强行盖掉（[第 20 章](ch20.md)）。

## 25.6 宏当函数用、全局变量传参

宏不是函数。调用宏时，宏体被原样贴进调用处，里面的 `set()` 改的是调用者的变量；函数会新开一个作用域，变量在返回时消失。

```cmake

```
{{#sidefx ch25/25_6_macro_leak}}

运行 1 第 4 步 `tmp=user-visible`，第 5 步调用宏，第 6 步 `set(tmp ...)` 直接把目录里的 `tmp` 改成 `tool_internal`。第 9 步打印 `after call tmp=tool_internal`，第 11 步给 `app` 的 `MODE` 也跟着变成 `tool_internal`；运行页里 `tool` 和 `app` 都打印 `tool_internal`。

运行 2 把 `macro` 换成 `function`。第 6 步同样看到 `tmp` 变成 `tool_internal`，但这是函数复制出来的作用域；第 8 步外层作用域那一行显示 `tmp` 回到 `user-visible`（查看器把两个作用域都标成目录 `src`，其中一个带“外层作用域”）。第 9 步打印 `after call tmp=user-visible`，`app` 的 `MODE` 是 `user-visible`，`tool` 仍是 `tool_internal`。

所以要给宏或函数传值，用参数，不要靠调用者作用域里的临时变量。函数还有真正的 `ARGV`、`ARGC`，可以用 `return(PROPAGATE ...)` 把结果传回调用者（[第 4 章](ch04.md)、[第 6 章](ch06.md)）。

## 25.7 源码内构建、绝对路径和旧版本号

还有三类旧写法，本章没有给它们单独的录制；它们的后果在前面的章节里已经看过。

| 旧写法 | 现在怎么做 | 后果 |
|---|---|---|
| `cmake -S . -B .` 源码内构建 | `cmake -S . -B build` | 生成物混进源码；一个源码目录只能有一套配置（[1.2 节](ch01.md)） |
| `include_directories(/home/me/proj/include)` | 相对路径 + `$<BUILD_INTERFACE:...>` / `$<INSTALL_INTERFACE:...>` | 换机器或安装后路径失效；导出时容易报错，或把构建机路径带给下游（[9.3 节](ch09.md)、[17.1 节](ch17.md)） |
| `cmake_minimum_required(VERSION 2.8)` | `cmake_minimum_required(VERSION 3.25...4.2)` | CMake 4.0 起，低于 3.5 的兼容已删除，配置第一步就报错（[23.4 节](ch23.md)） |

{{#fig ch25/old_new_map}}

图把其中四组对应画在一起：目录命令、全局 flags、变量和宏。共同点不是命令变新了，而是作用范围从“整个目录、整个工程、调用者”缩到了“这个目标、这次调用”。

## 速查

| 旧写法 | 新写法 | 副作用原来落在哪 |
|---|---|---|
| `include_directories()` / `add_definitions()` | `target_include_directories()` / `target_compile_definitions()` | 当前目录和之后添加的子目录里所有目标 |
| `link_directories()` | `target_link_directories()` 或直接写库的完整路径 | 调用之后创建的目标 |
| 改 `CMAKE_CXX_FLAGS` | `target_compile_options()` | 所有 C++ 编译和链接调用 |
| 把 `-std=` 拼进 flags | `target_compile_features()` | 每个目标自己声明需要什么 |
| 读 `${X_LIBRARIES}`、`${X_INCLUDE_DIRS}` | 链接 `X::X` | 每个使用点都要自己搬一遍 |
| `file(GLOB)` | 列出源文件；或加 `CONFIGURE_DEPENDS`（3.12） | 配置时固定，新文件构建时看不见 |
| `set(CMAKE_BUILD_TYPE Release)` | 交给 `-D` 或预设 | 普通变量遮住用户的缓存值 |
| 宏里 `set()` 临时变量 | 函数 | 调用者的作用域被改写 |

## 思考题

1. 把 25_1 运行 1 的 `include_directories(include/common)` 移到 `add_subdirectory(sub)` 之后。`helper` 还会拿到 `-I` 吗？`app` 呢？
   <details><summary>提示</summary>目录属性在 `add_subdirectory` 时复制给子目录，之后再改顶层目录不会回头改子目录；`app` 在顶层创建，会拿到。</details>
2. 在 25_2 的新写法里，把 `target_compile_options(app ...)` 换成 `add_compile_options(-Wall -Werror)`，并放到 `add_subdirectory(vendor)` 前面。构建会成功吗？如果放在后面呢？
   <details><summary>提示</summary>`add_compile_options()` 写目录属性，只初始化之后创建的目标。放前面时 `legacy` 也会拿到 `-Werror`，重新变成反例。</details>
3. 25_3 运行 4 只执行了 `cmake --build`，构建页为什么出现两次 `VerifyGlobs.cmake`？
   <details><summary>提示</summary>第一次检查发现 GLOB 不匹配，触发重新配置；新生成的构建规则里还有一次检查，然后才编译新文件。</details>
4. 把 25_5 运行 1 的 `set(CMAKE_BUILD_TYPE Release)` 改成 `set(CMAKE_BUILD_TYPE Release CACHE STRING "" FORCE)`，再用 `-DCMAKE_BUILD_TYPE=Debug` 配置。缓存里会是什么？用户还能选 Debug 吗？
   <details><summary>提示</summary>`FORCE` 直接改缓存项，缓存变成 Release；用户的 `-D` 被覆盖，和普通变量遮蔽一样是工程替用户做了决定。</details>
