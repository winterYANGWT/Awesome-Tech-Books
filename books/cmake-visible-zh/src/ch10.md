# 第 10 章 编译选项、语言标准和构建类型

```cmake
set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} -std=c++20 -Wall")
```

这一行在很多工程里都能见到。它看起来只是“加两个参数”，实际改的是一个所有 C++ 目标共享的变量，链接命令也会读它。先看语言标准应该写在哪里，再看这行到底改到了谁。

## 10.1 语言标准的三种写法

`target_compile_features()` 从 CMake 3.1 起就有，但它的行为和“加一个 `-std`”不一样。下面三个子目录各写一种方式，顶层的 `CMakeLists.txt` 只负责 `add_subdirectory()`。

```cmake
{{#include code/ch10/10_1_std/CMakeLists.txt}}
```

`vars/CMakeLists.txt` 用三个变量：

```cmake
{{#include code/ch10/10_1_std/vars/CMakeLists.txt}}
```

`features/CMakeLists.txt` 用 `target_compile_features()`：

```cmake
{{#include code/ch10/10_1_std/features/CMakeLists.txt}}
```

`props/CMakeLists.txt` 用目标属性，故意选一个更早的标准，方便对照：

```cmake
{{#include code/ch10/10_1_std/props/CMakeLists.txt}}
```
{{#sidefx ch10/10_1_std}}

逐个看配置页：

- 第 4–6 步在 `vars/` 里设三个变量，第 7 步 `add_library()` 创建 `std_vars` 时读到了它们。生成页里它的 CXX 标准是 17，编译参数是 `-std=c++17`：`CXX_EXTENSIONS` 为 `OFF`，和默认的 gnu 扩展模式不一致，所以要加这个参数。
- 第 11 步 `target_compile_features(std_features PUBLIC cxx_std_17)` 把 `cxx_std_17` 同时写进 `COMPILE_FEATURES` 和 `INTERFACE_COMPILE_FEATURES`。第 13 步 `app` 链接它；生成阶段写出的 `build/features.txt` 里，`app` 的 `COMPILE_FEATURES` 也是 `cxx_std_17`。
- 第 18 步 `set_target_properties()` 的命令里有 `CXX_STANDARD 14`；生成页里 `std_props` 的编译参数是 `-std=c++14`。

但 `std_features` 和 `app` 的编译命令里没有 `-std`。GCC 15 默认就是 `gnu++17`，`cxx_std_17` 要求的最低标准已经满足，扩展模式也和默认一致，CMake 不会为了写而写。`CXX_STANDARD_REQUIRED ON` 本身也不产生参数，它只决定编译器不支持这个标准时是退回旧标准还是报错。

| 写法 | 谁受影响 | 本例里的编译参数 |
|---|---|---|
| 三个 `CMAKE_CXX_*` 变量 | 变量设置之后创建的目标 | `-std=c++17` |
| `target_compile_features(... PUBLIC cxx_std_17)` | 目标自己和链接它的目标 | 不加 `-std`（默认已满足） |
| `set_target_properties(... CXX_STANDARD 14 ...)` | 只有这个目标 | `-std=c++14` |

{{#fig ch10/std_decision}}

给库声明最低标准时，用 `target_compile_features(x PUBLIC cxx_std_NN)`：`PUBLIC` 让链接它的目标也拿到同一个要求（[第 8 章](ch08.md)），换编译器时由 CMake 决定加不加 `-std`。`CMAKE_CXX_STANDARD` 适合应用或整个目录统一设默认值，但它只对之后创建的目标生效，写在 `add_executable()` 后面就漏掉了（[第 7 章](ch07.md)）。

## 10.2 CMAKE_CXX_FLAGS 的问题

把同一组参数写进 `CMAKE_CXX_FLAGS`，再引入一个不需要它们的第三方子目录：

顶层 `CMakeLists.txt`：

```cmake
{{#include code/ch10/10_2_cxx_flags/CMakeLists.txt}}
```

`third_party/CMakeLists.txt` 只有一行：

```cmake
{{#include code/ch10/10_2_cxx_flags/third_party/CMakeLists.txt}}
```

第二个运行的 `v2/CMakeLists.txt` 换成 `target_compile_options()`，只改 `app`：

```cmake
{{#include code/ch10/10_2_cxx_flags/v2/CMakeLists.txt}}
```
{{#sidefx ch10/10_2_cxx_flags}}

运行 1 第 3 步 `set()` 把值放进顶层目录作用域，第 4 步 `add_subdirectory(third_party)` 建子目录时带了进去。生成页里 `tiny` 和 `app` 都有 `-Wall -DFROM_TOP_FLAGS`，`app` 多一行 `-Wextra`。构建页里 `tiny` 的编译命令以 `-Wall -DFROM_TOP_FLAGS` 开头，`app` 的链接命令也带着它。

{{#fig ch10/flags_order}}

运行 2 换成 `target_compile_options(app PRIVATE ...)`：第 7 步只有 `app` 的 `COMPILE_OPTIONS` 多了三个参数，`tiny` 的目标页和编译命令都空了；运行页的 `app: macro=yes tiny=0` 说明宏没有漏过去。`CMAKE_CXX_FLAGS` 是给用户在命令行或工具链文件里设的，从 `CXXFLAGS` 环境变量初始化；工程在 CMakeLists.txt 里 `set()` 会把用户的缓存值遮住，要加项目自己的参数就用 `target_compile_options()` 或接口库。

它按目录作用域生效：把 `set(CMAKE_CXX_FLAGS ...)` 挪到 `add_subdirectory(third_party)` 后面，`tiny` 读不到这份值，`app` 仍然有。子目录在 `add_subdirectory()` 时复制当时的作用域，细节见 [8.5 节](ch08.md)。

## 10.3 构建类型

同一个工程，四次运行：不设、Debug、Release，最后换成带默认值的 CMakeLists。

`CMakeLists.txt`：

```cmake
{{#include code/ch10/10_3_build_type/CMakeLists.txt}}
```

`v2/CMakeLists.txt` 加上默认值：

```cmake
{{#include code/ch10/10_3_build_type/v2/CMakeLists.txt}}
```
{{#sidefx ch10/10_3_build_type}}

运行 1 不传 `CMAKE_BUILD_TYPE`：第 2 步 `project()` 之后缓存里这一项是空的，生成页的 `app` 下面没有编译参数，构建页第一条是 `g++    -MD`，没有任何 `-O` 或 `-g`。运行 2 加 `-DCMAKE_BUILD_TYPE=Debug`，第 2 步 `project()` 把命令行带来的 `UNINITIALIZED` 补成 `STRING`，构建页出现 `-g`，链接命令也带 `-g`。运行 3 换成 `Release`，编译命令变成 `-O3 -DNDEBUG`，运行页打印 `NDEBUG is defined`。

| 构建类型 | `CMAKE_CXX_FLAGS_<CONFIG>` | 编译命令里 |
|---|---|---|
| 不设 | （空） | 没有 `-O`、`-g` |
| Debug | `-g` | `-g` |
| Release | `-O3 -DNDEBUG` | `-O3 -DNDEBUG` |
| RelWithDebInfo | `-O2 -g -DNDEBUG` | `-O2 -g -DNDEBUG` |
| MinSizeRel | `-Os -DNDEBUG` | `-Os -DNDEBUG` |

不设时不是“默认 Release”，而是什么优化参数都没有。工程想要默认值时，运行 4 的 `v2/CMakeLists.txt` 在 `project()` 之前把值写进缓存：第 2 步的 `if` 只在顶层、缓存为空、且不是多配置生成器时执行；第 3 步 `set(... CACHE STRING ...)` 写出 `CMAKE_BUILD_TYPE=RelWithDebInfo`；第 4 步 `project()` 才读到它。构建页因此是 `-O2 -g -DNDEBUG`。

这段顺序不能反：`project()` 会先建一个空的 `CMAKE_BUILD_TYPE` 缓存项，放在它后面的 `set(... CACHE ...)` 不带 `FORCE` 就改不动这个空值。多配置生成器（Ninja Multi-Config）不用 `CMAKE_BUILD_TYPE`，默认配置由 `CMAKE_DEFAULT_BUILD_TYPE`（3.17 起）指定，值必须是 `CMAKE_CONFIGURATION_TYPES` 里的一项。

## 10.4 按编译器加选项：警告做成一个接口库

`-Wall` 给 GCC/Clang，`/W4` 给 MSVC。把选择写进一个 INTERFACE 库，谁链接谁才拿到：

`CMakeLists.txt`：

```cmake
{{#include code/ch10/10_4_warnings/CMakeLists.txt}}
```
{{#sidefx ch10/10_4_warnings}}

第 3 步写出 `build/compiler.txt`，内容是 `id=GNU`、`frontend=GNU`；第 5 步把两个生成器表达式（[第 9 章](ch09.md)）写进 `proj_warnings` 的 `INTERFACE_COMPILE_OPTIONS`，第 7 步 `app` 链接它。生成页里 `app` 的三行参数都标着 `← CMakeLists.txt:13 target_link_libraries`，后面注明 `· 来自 proj_warnings 的 INTERFACE_COMPILE_OPTIONS`，`tool` 一行也没有。构建页里 `tool` 的编译命令是 `g++    -MD`，和 10.3 运行 1 一样干净。

| 编译器 | `COMPILER_ID` | `SIMULATE_ID` | `FRONTEND_VARIANT` |
|---|---|---|---|
| GCC 15 | GNU | 空 | GNU |
| Clang 21 | Clang | 空 | GNU |
| MSVC | MSVC | 空 | MSVC |
| clang-cl | Clang | MSVC | MSVC |

运行 2 另建 `build-clang`，用 `-DCMAKE_CXX_COMPILER=clang++` 配置：第 2 步 `project()` 的输出变成 Clang，第 3 步的 `compiler.txt` 是 `id=Clang`、`frontend=GNU`，所以 `$<CXX_COMPILER_ID:MSVC>` 为假，还是走 GNU 那组参数。前两行表格来自本机录制，后两行来自文档；本机没有 MSVC 和 clang-cl。文档说 Clang-Cl 是 Clang 在 Windows 上使用 MSVC 兼容前端的形态，它的 `COMPILER_ID` 还是 Clang，`SIMULATE_ID` 和 `FRONTEND_VARIANT` 是 MSVC。

判断“MSVC 风格参数”要看 `CMAKE_CXX_COMPILER_FRONTEND_VARIANT`（3.14 起），不是 `COMPILER_ID`。示例为了保持 3.25 的最低版本用了 `$<CXX_COMPILER_ID:MSVC>`，在 clang-cl 上它会走错分支，加上 GNU 的 `-Wall`。要覆盖它，可以用 3.30 起的 `$<CXX_COMPILER_FRONTEND_VARIANT:MSVC>`，或者在配置阶段判断 `CMAKE_CXX_COMPILER_FRONTEND_VARIANT`；接口库的好处是作用范围跟着链接关系走。

## 10.5 C++20 模块扫描

`cxx_std_20` 的目标在 Ninja 下会多出两类命令。工程里只有一个 C++20 目标和一个默认标准的目标：

`CMakeLists.txt`：

```cmake
{{#include code/ch10/10_5_cxx20_scan/CMakeLists.txt}}
```

第二个运行的 `v2/CMakeLists.txt` 关掉扫描：

```cmake
{{#include code/ch10/10_5_cxx20_scan/v2/CMakeLists.txt}}
```
{{#sidefx ch10/10_5_cxx20_scan}}

运行 1 的构建页有 6 条命令。第 1 条是扫描：`g++ -std=gnu++20 -E -x c++ ... -fmodules-ts -fdeps-format=p1689r5`，只处理 `app` 的 `main.cpp`；第 2 条是 `cmake -E cmake_ninja_dyndep`，把扫描结果变成 Ninja 的模块依赖；第 3 条才是 `app` 的编译。`plain` 没有设标准，第 4 条编译它时没有这些命令，运行页打印 `plain: __cplusplus=201703`，说明它走的是编译器默认的 C++17。

运行 2 第 3 步把 `CMAKE_CXX_SCAN_FOR_MODULES` 设为 `OFF`，构建页只剩 4 条命令：`app` 的编译直接执行，扫描和 `cmake_ninja_dyndep` 都消失了。只想关一个目标时，用目标属性 `CXX_SCAN_FOR_MODULES OFF`。

这是 CMP0155（3.28 起）的行为：C++20 及以上的目标里的 C++ 源文件可能 `import` 模块，Ninja 要在编译前扫描。`cmake_minimum_required(VERSION 3.25...4.2)` 把策略设到 4.2，CMP0155 是 NEW；只写到 3.25 的工程不会自动打开它。下一章换到库：同一个 `add_library()` 不写类型时，`BUILD_SHARED_LIBS` 决定它是静态还是动态（[第 11 章](ch11.md)）。

## 速查

| 写法 | 作用范围 | 注意 |
|---|---|---|
| `target_compile_features(x PUBLIC cxx_std_17)` | `x` 和链接它的目标 | 只声明最低标准；默认满足且扩展设置一致时通常不加，`CXX_EXTENSIONS OFF` 时会加 `-std=c++NN` |
| `set(CMAKE_CXX_STANDARD 17)` 等三个变量 | 之后创建的目标 | 三个变量都要在 `add_*` 之前；`CXX_EXTENSIONS OFF` 时才是 `-std=c++17` |
| `set_target_properties(x PROPERTIES CXX_STANDARD 17 ...)` | 单个目标 | 目标已存在也能改 |
| `target_compile_options(x PRIVATE ...)` | `x` | 不进 `INTERFACE_*`，下游拿不到 |
| `add_library(w INTERFACE)` + `target_compile_options(w INTERFACE ...)` | 链接 `w` 的目标 | 按编译器或前端选参数时用生成器表达式 |
| `CMAKE_CXX_FLAGS` | 当前目录及之后进入的子目录里的编译和链接（设置前已进入的子目录不受影响） | 留给用户或工具链；工程里写会波及这些目标和链接命令 |
| `CMAKE_BUILD_TYPE` | 单配置生成器 | 空值表示不加优化或调试参数；多配置用 `CMAKE_CONFIGURATION_TYPES` |
| `CMAKE_CXX_SCAN_FOR_MODULES` | 之后创建的目标 | CMP0155 为 NEW 时，C++20 及以上的目标默认扫描；3.28 起 |

3. 把 10.3 的默认值块从 `project()` 前面挪到后面，再从头配置一次。缓存里的 `CMAKE_BUILD_TYPE` 是什么？构建命令还有 `-O2` 吗？

4. 假设用 clang-cl 配置 10.4。`COMPILER_ID`、`SIMULATE_ID`、`FRONTEND_VARIANT` 分别是什么？示例里的 `$<CXX_COMPILER_ID:MSVC>` 会选哪组参数？
