# 第 7 章 目标和属性

“现代 CMake 以目标为中心。”这句话几乎每篇教程都写，但目标到底是什么？一个 `add_library` 执行完，查看器的“目标”栏里就挂上了一串属性，它们又是什么？

下面这个工程一次建了六种目标。配置完点开“目标”栏，再取消“只看改过的属性”。

{{#sidefx ch07/7_1_target_kinds}}

第 3 到 6 步连续建了四个库：`stat` 是静态库，`shared` 是动态库，`obj` 是对象库，`iface` 是接口库、没有源文件。第 8 步的 `app` 是可执行文件，第 10 步的 `notes` 是自定义目标。取消“只看改过的属性”后，刚建好的 `stat` 有 16 行属性，其中大多是 CMake 给的默认值。

切到生成页，每个目标卡片标题后面跟着产物：`stat` 是 `libstat.a`，`shared` 是 `libshared.so`，`app` 是 `app`。`obj` 后面是 `CMakeFiles/obj.dir/./obj.cpp.o`，不是一个库文件；`notes` 后面什么也没有。目标的名字和产物的名字是两件事。

| 目标 | 写法 | 生成页的产物 | 构建页里做什么 |
|---|---|---|---|
| `stat` | `STATIC` | `libstat.a` | 编译 `.o`，再 `ar qc` 打包 |
| `shared` | `SHARED` | `libshared.so` | 编译带 `-fPIC`，链接带 `-shared` |
| `obj` | `OBJECT` | 只有 `.o` | 只编译，不打包 |
| `iface` | `INTERFACE` | 没有 | 什么也不构建 |
| `app` | `add_executable` | `app` | 编译、链接 |
| `notes` | `add_custom_target` | 没有 | 每次构建都执行 `echo` |

{{#fig ch07/target_anatomy}}

{{#figref ch07/target_anatomy}} 左边三项里，类型和初始源文件在 `add_*` 时给出；属性先取默认值或 `CMAKE_*` 初值，之后还能改。右边是结果：构建出的产物，以及 `INTERFACE_*` 属性——它们不参与自己的构建，只在别的目标链接它时被读走。

构建页一共 8 条命令。第 1、3 条是 `stat` 的编译和 `ar qc`；第 2、4 条是 `shared` 的 `-fPIC` 编译和 `-shared` 链接；第 5 条只编译 `obj` 的 `.o`；第 7 条链接 `app` 时，`obj` 的 `.o` 被直接列在命令里。接口库没有命令，自定义目标每次都会执行。

## 7.2 属性和 set_target_properties / get_target_property

```cmake
{{#include code/ch07/7_2_properties/CMakeLists.txt}}
```
{{#sidefx ch07/7_2_properties}}

第 3 步建出 `app` 时，`OUTPUT_NAME` 还没有设置。第 5 步 `set_target_properties` 一次写两个属性：目标栏里 `OUTPUT_NAME` 变成 `demo`，`RUNTIME_OUTPUT_DIRECTORY` 变成 `/work/build/bin`。目标名仍然是 `app`，变的只是产物的名字和目录。

第 6 步 `get_target_property` 把属性读进变量 `app_out`，第 7 步打印出 `demo`。没有设置的属性会读出 `变量名-NOTFOUND`，下一节会看到。第 8 步用 `set_property(... APPEND ...)` 往 `COMPILE_DEFINITIONS` 里追加 `EXTRA=2`；目标栏里这个属性成了 `EXTRA=2;MODE=1`。

构建页第 1 条命令里两个宏都在：`-DEXTRA=2 -DMODE=1`。第 2 条链接命令的输出文件是 `-o bin/demo`，运行页打印 `MODE=1 EXTRA=2`。`set_target_properties` 每次覆盖属性的值，`APPEND` 只对 `COMPILE_DEFINITIONS` 这样的列表属性有意义。

## 7.3 属性的初值来自 `CMAKE_<PROP>` 变量：顺序很重要

```cmake
{{#include code/ch07/7_3_init_order/CMakeLists.txt}}
```
{{#sidefx ch07/7_3_init_order}}

第 3 步创建 `before` 时，`CMAKE_CXX_STANDARD` 还没有设；第 4 到 8 步才设置 `CMAKE_CXX_STANDARD` 等变量。第 9 步创建 `after`，这些值被复制成它的属性。`CXX_STANDARD` 不在这次的目标属性表里，第 10、11 步改用 `get_target_property` 读它：`before` 读到 `before_std-NOTFOUND`，`after` 读到 `20`。

{{#fig ch07/prop_init}}

变量面板默认隐藏 `CMAKE_*`，取消“隐藏 CMAKE_* 等内置变量”才能看到第 4 到 8 步的改变。取消“只看改过的属性”后，`after` 的属性表里多出 `CXX_STANDARD_REQUIRED=ON`、`POSITION_INDEPENDENT_CODE=ON`、`CXX_VISIBILITY_PRESET=hidden` 和 `RUNTIME_OUTPUT_DIRECTORY=/work/build/bin`；`before` 没有这四项。

| 变量 | 创建目标时复制到 | 本示例里 |
|---|---|---|
| `CMAKE_CXX_STANDARD` | `CXX_STANDARD` | `after` 是 20，`before` 没有设置 |
| `CMAKE_CXX_STANDARD_REQUIRED` | `CXX_STANDARD_REQUIRED` | `after` 是 ON，`before` 没有设置 |
| `CMAKE_POSITION_INDEPENDENT_CODE` | `POSITION_INDEPENDENT_CODE` | `after` 的编译命令多 `-fPIE` |
| `CMAKE_<LANG>_VISIBILITY_PRESET` | `<LANG>_VISIBILITY_PRESET` | `after` 多 `-fvisibility=hidden` |
| `CMAKE_RUNTIME_OUTPUT_DIRECTORY` | `RUNTIME_OUTPUT_DIRECTORY` | `after` 落在 `build/bin` |
| `CMAKE_ARCHIVE_OUTPUT_DIRECTORY` | `ARCHIVE_OUTPUT_DIRECTORY` | 本示例没有设 |

构建页第 3 条是 `before` 的编译，没有 `-std=`；第 1、4 条是 `after` 的模块扫描和编译，都带 `-std=gnu++20 -fPIE -fvisibility=hidden`。第 5、6 条链接出的文件分别是 `build/before` 和 `build/bin/after`。C++20 目标多出的模块扫描命令属于[第 10 章](ch10.md)，这里只看属性的差别。

规律是：`CMAKE_<PROP>` 只在**创建目标的那一刻**用来初始化同名属性，之后再改变量，已有目标不变。属性页写着 “initialized by ... when a target is created” 的，才属于这一类；不是每个属性都有对应的 `CMAKE_` 变量。

## 7.4 ALIAS 目标

```cmake
{{#include code/ch07/7_4_alias/CMakeLists.txt}}
```
{{#sidefx ch07/7_4_alias}}

运行 1 的第 5 步是 `add_library(acme::greet ALIAS greet)`。目标栏里多出一个类型为“别名”的条目，录制器从这条命令还原出它的只读属性 `ALIASED_TARGET=greet`。它可以链接、可以读原目标的属性，但不是可构建目标，没有源文件，也不能改属性、安装或导出。

第 7 步 `app` 的 `LINK_LIBRARIES` 里写的是 `acme::greet`，构建页第 4 条链接命令里出现的却是 `libgreet.a`：别名在生成阶段已经被换成了真目标，生成页里没有它的卡片，它自己不产生任何构建规则。

两个反例只改最后一行：

```cmake
# v2/CMakeLists.txt
target_link_libraries(app PRIVATE acme::gret)
```

```cmake
# v3/CMakeLists.txt
target_link_libraries(app PRIVATE gret)
```

运行 2 的第 7 步看起来只是把 `acme::gret` 写进属性，配置结束后的输出里才报错：`Target "app" links to: acme::gret but the target was not found.` 带 `::` 的名字被当作 ALIAS 或导入目标，找不到就在生成阶段停下（CMP0028 的规则；CMake 4.0 起旧行为已经删掉）。

运行 3 用的是不带 `::` 的 `gret`，配置和生成都成功。目标栏里 `app` 的 `LINK_LIBRARIES` 是 `gret`，生成页里也没有 `greet` 的 `-I`。

`main.cpp` 没有包含 `greet` 的头文件，所以编译过了；构建页第 2 条链接命令成了 `-lgret`，链接器报 `cannot find -lgret`。这时错误已经离写错的那一行很远了。“为什么都用 `xxx::xxx`”的答案有两点：

- 双冒号让拼错的名字在生成阶段就暴露；
- 不带双冒号的名字会被当成普通的 `-l` 参数，一路拖到链接；系统里如果正好有一个同名库，链接还可能悄悄成功。

## 7.5 导入目标：别人造好的目标

```cmake
{{#include code/ch07/7_5_imported/CMakeLists.txt}}
```
{{#sidefx ch07/7_5_imported}}

第 3 步 `find_package(ZLIB)` 打印 `Found ZLIB: /usr/lib/x86_64-linux-gnu/libz.so`，并定义了一个叫 `ZLIB::ZLIB` 的目标。第 5 步 `target_link_libraries` 把这个目标写进 `app` 的 `LINK_LIBRARIES`；构建页只有两条命令，都是 `app` 的。

`ZLIB::ZLIB` 是导入目标（imported target）：由别人建好、指向一个已经存在的库文件的目标。它由 CMake 自带的 FindZLIB 模块定义（模块模式和 142 条命令见 [14.1 节](ch14.md)）。打开第 3 步的“目标”一栏，能看到这个导入目标和它的三个属性：

| 属性 | 值 | 作用 |
|---|---|---|
| `INTERFACE_INCLUDE_DIRECTORIES` | `/usr/include` | 用这个库的目标该加的头文件目录（下一章展开） |
| `IMPORTED_CONFIGURATIONS` | `RELEASE` | 这个库提供了哪几种配置的文件 |
| `IMPORTED_LOCATION_RELEASE` | `/usr/lib/x86_64-linux-gnu/libz.so` | Release 配置下库文件的位置 |

查看器注明这些属性是“从执行过的命令里还原的”：CMake 的调试器不列出导入目标，录制器根据 FindZLIB 执行的 `set_target_properties`、`set_property` 把它们拼了回来（[附录 C](appc.md)）。构建页第 2 条链接命令里，`ZLIB::ZLIB` 已经变成 `/usr/lib/x86_64-linux-gnu/libz.so`；没有一条命令去构建 ZLIB，运行页打印 `zlib 1.3.1`。

导入目标默认只在定义它的目录及其子目录可见，`GLOBAL` 和查找顺序留给[第 14 章](ch14.md)。

## 速查

| 写法 | 副作用发生在 | 注意 |
|---|---|---|
| `add_library` / `add_executable` | 配置：建目标；生成：写规则 | 目标名全局唯一，产物名由 `OUTPUT_NAME` 决定 |
| `add_library(x INTERFACE)` | 配置：只建目标 | 没有源文件，也没有产物 |
| `add_custom_target` | 配置：建目标；构建：每次执行命令 | 没有产物文件，默认不参与 `all`，要写 `ALL` |
| `set_target_properties` | 配置：改属性 | 一次可写多个，同名属性被覆盖 |
| `set_property(TARGET ... APPEND ...)` | 配置：往列表属性追加 | 只对列表属性合适 |
| `get_target_property` | 配置：读进变量 | 没有设置时得到 `变量名-NOTFOUND` |
| `add_library(a::b ALIAS b)` | 配置：只登记别名 | 别名不是可构建目标，不能改属性、安装或导出 |
| `add_library(a::b UNKNOWN IMPORTED)` | 配置：登记已有库 | 不产生构建命令；`IMPORTED_LOCATION` 指向库文件 |
| `set(CMAKE_<PROP> ...)` | 配置：只影响之后创建的目标 | 已有目标的属性不会跟着变 |

## 思考题

1. 在 `7_1_target_kinds` 里给 `obj` 加一句 `set_target_properties(obj PROPERTIES OUTPUT_NAME thing)`。生成页里 `obj` 的产物会变成 `libthing.a` 吗？构建页会多出打包命令吗？
   <details><summary>提示</summary>对象库没有自己的库文件；`OUTPUT_NAME` 不会凭空造出一个归档步骤。</details>
2. 把 `7_2_properties` 第 8 步的 `APPEND` 删掉，只留 `set_property(TARGET app PROPERTY COMPILE_DEFINITIONS EXTRA=2)`。预测目标栏里 `COMPILE_DEFINITIONS` 的值、编译命令和运行结果。
   <details><summary>提示</summary>不带 `APPEND` 是覆盖，`MODE=1` 会消失；`main.cpp` 里还在用 `MODE`。</details>
3. 把 `7_3_init_order` 里的 `set(CMAKE_CXX_STANDARD 20)` 挪到 `add_executable(before ...)` 之前。两个目标的 `CXX_STANDARD` 和构建命令会怎样变？
   <details><summary>提示</summary>变量只在创建目标时复制；先设变量，`before` 也会拿到 20。</details>
4. 在 `7_4_alias` 里把 `acme::greet` 改成 `acme::gret`，同时把 `app` 的链接也改成 `acme::gret`。为什么这次配置不会报错，而运行 2 会？
   <details><summary>提示</summary>报错的是“名字带 `::` 但目标不存在”；如果别名和引用一起拼错，目标仍然存在。</details>
