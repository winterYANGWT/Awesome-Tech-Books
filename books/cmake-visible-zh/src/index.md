# 前言：这本书怎么读

CMake 的建议大多不难背：“用 `target_include_directories`，别用 `include_directories`”“库要 `PUBLIC` 链接”“别改 `CMAKE_CXX_FLAGS`”“缓存变量改了要 `--fresh`”。难的是理解它们为什么对。原因是 CMake 的副作用几乎都看不见：变量活在某个作用域里，缓存悄悄写进文件，属性挂在目标上，生成器表达式要等到生成阶段才求值，命令到构建时才执行。

所以这本书的每个示例都真实运行过一遍。CMake 在自己的调试器下逐条命令停下来，录下当时的变量、缓存、目标和磁盘上的文件。读者在弹出的界面里一行一行回放，亲眼看到每一行留下了什么。

## 查看器

每个示例的代码下面有一条启动条：

```text
▶ 逐行执行，看副作用   配置 8 步   新目标 1   配置时写文件 1   构建命令 2
```

点开以后，顶上是四页：

| 页 | 看什么 | 数据从哪来 |
|---|---|---|
| **配置** | 左边是代码，当前行高亮；右上是“这一行做了什么”：变量（分作用域）、缓存、目标、文件、输出、进入或离开的作用域；右下是执行完这一行之后的完整状态 | 调试器每次停下时记下的状态，相邻两次的差 |
| **生成** | 生成阶段写出的文件（点名字看内容）；每个目标最终的编译参数和链接参数，每一项后面的“←”指出是哪一行加的，从依赖传来的还会标出“来自哪个目标的哪个属性” | CMake 的 file API |
| **构建** | Ninja 真正执行的每一条命令，参数按来源着色，鼠标停在上面看出处 | `cmake --build --verbose -j 1` 的输出 |
| **运行** | 构建之后执行的命令（运行程序、`ctest`、`cmake --install`）和它们改动的文件 | 录制时的实际输出 |

一个示例有好几次运行时（例如“改了缓存再配置一次”），顶上左边还有运行的标签。

| 操作 | 作用 |
|---|---|
| `→` / `←`（或 `j` / `k`） | 下一步 / 上一步 |
| 空格 | 自动播放 / 暂停 |
| `Home` / `End` | 第一步 / 最后一步 |
| 点代码里的某一行 | 跳到执行这一行的那一步 |
| 点“←”后面的位置 | 从生成页跳回配置页里对应的那一步 |
| `Esc` | 关闭文件内容，再按一次关闭查看器 |

右下的状态面板默认隐藏 CMake 自己设置的 `CMAKE_*` 变量和高级缓存项，取消勾选就能看到全部。

## 环境

示例全部在同一个环境里录制：Ubuntu，CMake 4.2.3，Ninja 1.13，GCC 15.2。录制时把工作目录统一写成 `/work`：`/work/src` 是示例的源码，`/work/build` 是构建目录，`/work/prefix` 是安装前缀。你用别的版本或编译器，变量的个数和编译参数的细节会有出入，但书里讲的规则不变。

所有示例都写 `cmake_minimum_required(VERSION 3.25...4.2)`，原因在 [第 23 章](ch23.md)。

## 怎么读

- 第一、二部分（第 1–6 章）讲 CMake 怎样执行一个工程：阶段、语言、作用域、缓存。后面所有内容都建立在这里。
- 第三部分（第 7–11 章）讲目标和用法要求，回答“PUBLIC/PRIVATE 到底给了谁”。写过库的读者可以从第 8 章开始。
- 第四、五、六部分讲生成代码、依赖、安装和导出。要发布一个能被 `find_package` 的库，读第 14–18 章。
- 第七、八部分是工程化和排错：测试、预设、质量工具、工具链、策略、调试，以及旧写法为什么被换掉。最后一章把全书串成一个完整的库工程骨架。

## 用在你自己的项目上

录制器和查看器在本书的源码目录里：GitHub 上 Awesome-Tech-Books 仓库的 [`books/cmake-visible-zh/`](https://github.com/winterYANGWT/Awesome-Tech-Books/tree/main/books/cmake-visible-zh)，工具在其中的 `tools/sidefx/`。它只依赖 Python 标准库、CMake 3.27 以上（需要 `--debugger`）和 Ninja。在这个目录下运行：

```sh
python3 tools/sidefx/sidefx.py ~/code/mylib                 # 生成 ~/code/mylib.sidefx.html
python3 tools/sidefx/sidefx.py ~/code/mylib --serve 3001    # 同时在 3001 端口打开
python3 tools/sidefx/sidefx.py ~/code/mylib -- -DBUILD_TESTING=ON
```

它先把项目复制到临时目录再运行，不会碰你的源码和构建目录。原理和局限见 [附录 C](appc.md)。
