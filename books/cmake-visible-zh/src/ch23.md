# 第 23 章 策略和版本

第 1 章的每个示例第一行都是 `cmake_minimum_required(VERSION 3.25...4.2)`；两个数字不是重复：第一个说“CMake 比 3.25 老就别配置”，第二个说“按 4.2 的规则解释这份工程”。只写 `VERSION 3.25` 时，3.25 之后才有的策略就落在“未设置”里。先看只改这一行的工程。

## 23.1 策略是什么

策略（policy）给 CMake 的每一次行为改变编一个号：CMP0156 是链接行去重，CMP0181 是链接参数解析。每条策略有 `OLD` 和 `NEW` 两种行为，工程用版本范围或 `cmake_policy()` 选一种。

`23_1_policy_warning` 两次运行的 `CMakeLists.txt` 只差第 1 行；第 3、4 步建了 `core` 和 `app`，第 5 步把 `core` 链接进 `app`。

```cmake
{{#include code/ch23/23_1_policy_warning/CMakeLists.txt}}
```
{{#sidefx ch23/23_1_policy_warning}}

运行 1 走完第 6 步，生成页的“输出”里出现 `CMake Warning (dev)`：第 3 步的 `add_library(core)` 和第 4 步的 `add_executable(app)` 都提到 CMP0156，后者还提到 CMP0181。两个策略都比 3.25 新：CMP0156 从 3.29 起，CMP0181 从 4.0 起，所以只写 3.25 时它们没有被设置。

这类警告默认不打印；示例用 `-DCMAKE_POLICY_WARNING_CMP0156=ON` 和 `-DCMAKE_POLICY_WARNING_CMP0181=ON` 只是把它们显示出来。不管警告开不开，未设置的策略都按 `OLD` 执行：CMP0156 用旧的链接行去重方式，CMP0181 把链接参数原样使用。

| 运行 | `CMakeLists.txt` 第 1 行 | 生成阶段的开发者警告 |
|---|---|---|
| 1 | `VERSION 3.25` | CMP0156、CMP0181 都出现 |
| 2 | `VERSION 3.25...4.2` | 没有 |

运行 2 的 `CMakeLists.txt` 只把第 1 行换成 `3.25...4.2`，再走同样的第 3 到 5 步；运行 1 打开的两个 warning 变量还留在缓存里，这次又加了 `-Werror=dev`，任何开发者警告都会让配置失败，而配置通过了，生成页的输出是干净的。构建页这次是 `ninja: no work to do`，运行页仍打印 `core = 7`。策略版本提高没有改代码，只改了 CMake 解释代码的规则。

`cmake --help-policy CMP0156` 开头是 `.. versionadded:: 3.29`，正文说它按链接器的能力决定链接行上的库怎么去重；`cmake --help-policy CMP0181` 开头是 `.. versionadded:: 4.0`，讲 `CMAKE_*_LINKER_FLAGS` 这些变量怎么重新解析、加引号。两个策略的 `OLD` 行为都写着 deprecated by definition。

## 23.2 VERSION min...max

`cmake_minimum_required(VERSION min...max)` 等价于 `cmake_policy(VERSION min...max)`，外面再加一道最低版本检查。

- **min**：正在运行的 CMake 比它低，就在这一行报错，后面的命令都不执行；`CMAKE_MINIMUM_REQUIRED_VERSION` 记的也是 min。
- **max**：策略版本。运行中的 CMake 认得、并且是在 max 或更早引入的策略，全部设为 `NEW`；比 max 新的策略不设置。
- **不写 max**：策略版本就是 min，效果和只写一个版本相同。
- **`CMAKE_POLICY_VERSION_MINIMUM`**：如果它比上面算出的策略版本高，就取它；默认不设。
- 范围写法从 3.12 起才有；更老的 CMake 会把 `...` 当成版本分隔符，只按 min 处理。

运行 1 第 3 到 5 步，三个 `cmake_policy(GET …)` 分别把 `cmp0156`、`cmp0181`、`cmp0077` 设成 `NEW`；第 10 步的 `message()` 打印同一组值。运行 2 第 1 行只写 3.25，第 3、4 步读出来的 `cmp0156`、`cmp0181` 是空字符串，第 5 步的 `cmp0077` 仍是 `NEW`。

空不是 `OLD`：`GET` 的文档说只有设置过（包括 `cmake_minimum_required()` 的版本范围设置的）才是 `OLD` 或 `NEW`，没设置就是空。运行 2 的第 8、10 步把两个空值改成 `unset`，是为了让 `message()` 和生成的头文件显示 `unset`；第 12 步打印 `CMP0156=unset CMP0181=unset CMP0077=NEW`，构建出的 `policy_demo` 再打印一遍。3.25 及以前引入的策略仍是 `NEW`，只有 3.25 之后的新策略空着。

{{#fig ch23/policy_range}}

图里的三种情况：运行中的 CMake 低于 min 会报错；策略只要在 max 或更早引入（包括 min 以前引入的）就设为 `NEW`；max 之后引入的策略未设置，CMake 用到时按 `OLD` 执行，是否警告由具体策略决定。

## 23.3 某个策略的 OLD 和 NEW

同一个工程，把 CMP0077 显式设成 `NEW` 和 `OLD`，`option()` 对普通变量的处理不一样。

```cmake
{{#include code/ch23/23_3_cmp0077/CMakeLists.txt}}
```
{{#sidefx ch23/23_3_cmp0077}}

运行 1 第 4 步 `set(WANT_FAST OFF)` 先建普通变量；第 5 步 `option()` 什么也没做，第 7 步确认缓存里没有 `WANT_FAST`，第 8 步打印 `WANT_FAST=OFF`，运行页走普通路径。

运行 2 第 3 步改成 `OLD` 时先出现一条 `CMake Deprecation Warning`：`The OLD behavior for policy CMP0077 will be removed`。第 5 步 `option()` 删掉了普通变量 `WANT_FAST`，同时在缓存里建了 `WANT_FAST:BOOL=ON`；第 7、8 步都变成 ON，运行页走快速路径。差别只在策略：同一行 `option()`、同一个 `set()`、同一个构建目录。

| CMP0077 | `option()` 看到普通变量 OFF | 缓存 | 程序看到 |
|---|---|---|---|
| `NEW` | 什么也不做 | 不建 | OFF |
| `OLD` | 删普通变量，建缓存 ON | `WANT_FAST=ON` | ON |
| 未设置 | 按 `OLD` 执行 | 建缓存 ON | ON，并警告 |

`option()` 的 `OLD` 行为是 CMake 3.12 及以前的规则。工程写 `cmake_minimum_required(VERSION 3.12)` 时，3.13 才出现的 CMP0077 是“未设置”，CMake 仍按 `OLD` 执行并警告；把最低版本抬到 3.13，或者把 max 写成 3.13 以上，它才变成 `NEW`，`option()` 不再覆盖普通变量。所谓“升级 CMake 后行为变了”，多半是策略版本跟着抬了，或者旧策略被删掉了。

把 `cmake_policy(SET CMP0077 OLD)` 写进工程，等于让 CMake 保留一段计划删除的行为；这一行自己就会打出弃用警告，未来版本可能直接删掉 `OLD`。临时兼容可以，长期应该改代码：要么别在 `option()` 之前设同名普通变量，要么把值直接做成缓存项。

## 23.4 CMake 4.0 删掉的旧兼容

`cmake_minimum_required(VERSION 3.1)` 在 CMake 4.2 下连第一步都过不去。

```cmake
{{#include code/ch23/23_4_old_minimum/CMakeLists.txt}}
```
{{#sidefx ch23/23_4_old_minimum}}

运行 1 第 1 步就报错：`Compatibility with CMake < 3.5 has been removed from CMake.`，配置在第一条命令就报错停下，没有完成（`build/CMakeCache.txt` 已经写出来）。CMake 4.0 的发布说明把这条放在 `Deprecated and Removed Features`：低于 3.5 的兼容被删掉，`cmake_minimum_required()` 和 `cmake_policy()` 把策略版本设到 3.5 以下都会报错，错误信息最后一行给出的正是 `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`。

运行 2 用 `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` 再配置：报错变成 `CMake Deprecation Warning`，说低于 3.10 的兼容会在未来版本删掉，但工程能配置、能构建、能运行。这个变量是 4.0 才有的，文档明确说它是给用户、或者给包含第三方工程的项目救急用的，不应该由工程自己写进 CMake 代码。

运行 2 里还有开发者警告：`project()` 检测编译器时出现 CMP0066，生成阶段出现 CMP0156 和 CMP0181（CMP0181 在生成前后各出现一次）。原因是策略版本只抬到 3.5，4.2 认得的那些新策略仍然是“未设置”。救急变量只把报错降成警告，没有把工程更新到 4.2 的规则。

| 警告 | 出现的地方 | 3.5 的策略版本下 |
|---|---|---|
| CMP0066 | `project()` 的编译器检测 | 未设置，按 `OLD` |
| CMP0156 | 生成阶段的 `add_executable` | 未设置，按 `OLD` |
| CMP0181 | 生成阶段，出现两次 | 未设置，按 `OLD` |

要修自己的工程，应该把第 1 行改成至少 3.5，最好直接写 `3.5...4.2` 或更高。`3.1...4.2` 也能过 4.0 的检查，因为策略版本是 4.2；但最低版本仍写着 3.1，会让 3.1 到 3.11 的 CMake 只按 3.1 的规则解释工程。

## 23.5 选最低版本

选最低版本是在“用户能装上的 CMake”和“你想要的新行为”之间取平衡。先看用户群里最老的系统：Ubuntu 24.04 LTS 自带 3.28.3，Ubuntu 26.04 LTS 自带 4.2.3；其他发行版去它的包页面查 `cmake` 的版本，或者让用户运行 `cmake --version`。

| 系统 | 自带的 cmake |
|---|---|
| Ubuntu 24.04 LTS | 3.28.3 |
| Ubuntu 26.04 LTS | 4.2.3 |

如果你要求 3.31，24.04 的用户得自己装新 CMake；如果只写 `VERSION 3.10`，3.10 之后引入的策略都会留在未设置状态。它们用到时按 `OLD` 执行：像 CMP0077 这样的默认会警告，CMP0156、CMP0181 默认不警告，要看警告得手动打开 `CMAKE_POLICY_WARNING_*`。我的建议是：min 写用户群里最老的、你能接受的那条线，max 写你实际测试过的最新版本。

本书写 `3.25...4.2`，是因为正文用到 3.25 的 `block()`、`return(PROPAGATE)` 和 `SYSTEM`，而本书按 4.2 核对。

| 最低版本 | 带来的关键功能 |
|---|---|
| 3.21 | `PROJECT_IS_TOP_LEVEL` 变量，判断是不是顶层工程 |
| 3.23 | `FILE_SET`：`target_sources` 和 `install(TARGETS)` 的头文件集合 |
| 3.24 | `FetchContent_Declare` 的 `FIND_PACKAGE_ARGS`；`cmake --fresh` |
| 3.25 | `block()`/`endblock()`；`SYSTEM` 目录和目标属性；`return(PROPAGATE)` |
| 3.28 | Ninja 和 Visual Studio 17 2022 及更新的生成器支持 C++20 命名模块 |
| 4.0 | 删除 3.5 以前的兼容；CMP0181 等新策略 |

这些版本号都能在对应版本的发布说明里查到；`FIND_PACKAGE_ARGS` 在 `FetchContent` 模块页标着 `.. versionadded:: 3.24`。

{{#fig ch23/policy_states}}

图把一次 `cmake_minimum_required()`、一次 `set(FOO OFF)` 和后面一次 `option()` 连起来：第 1 行先填策略表，`set()` 建好普通变量，`option()` 执行时再查表；`NEW`、`OLD`、未设置三种状态对应三种结果。

策略问题最后常常表现成“这个参数是从哪来的”“这个变量为什么是空的”。下一章换一组工具，从 `message()` 的级别看到 `--trace`、`--debug-find`，再到 CMake 自己的调试器。

## 速查

| 写法 | 效果 | 注意 |
|---|---|---|
| `cmake_minimum_required(VERSION 3.25)` | min 和策略版本都是 3.25 | 3.25 之后的策略未设置 |
| `cmake_minimum_required(VERSION 3.25...4.2)` | 最低 3.25，策略到 4.2 全设为 `NEW` | 3.25 的 CMake 也能配置 |
| `cmake_policy(GET CMP0077 v)` | `v` 为 `NEW`、`OLD` 或空 | 空表示没设置，不是 `OLD` |
| `cmake_policy(SET CMP0077 OLD)` | 强制旧行为 | 自己就会打弃用警告，OLD 可能被删 |
| `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` | 把策略版本抬到 3.5，救老工程 | 4.0 起才有；只降级报错，不更新规则 |
| `cmake --help-policy CMP0156` | 查一个策略的 OLD/NEW 和引入版本 | 也看 `.. versionadded::` |

## 思考题

1. 把 23_2 第二次运行的 `VERSION 3.25` 改成 `VERSION 3.29`，重新配置。`CMP0156`、`CMP0181`、`CMP0077` 各读出什么？
   <details><summary>提示</summary>CMP0156 从 3.29 起，变成 `NEW`；CMP0181 从 4.0 起，仍是空；CMP0077 早就有，仍是 `NEW`。</details>
2. 把 23_3 的 `set(WANT_FAST OFF)` 改成 `set(WANT_FAST OFF CACHE BOOL "")`，再跑 `NEW` 和 `OLD` 两次。`option()` 还会删掉普通变量吗？缓存会变成 ON 吗？
   <details><summary>提示</summary>缓存项已经有 `BOOL` 类型，`NEW` 和 `OLD` 都不再动它，值保持 OFF；这一行只建缓存项，没有同名普通变量可删。</details>
3. 把 23_4 的 `VERSION 3.1` 改成 `VERSION 3.1...4.2`，不加 `CMAKE_POLICY_VERSION_MINIMUM` 能配置吗？`CMAKE_MINIMUM_REQUIRED_VERSION` 是多少？
   <details><summary>提示</summary>能，策略版本是 4.2，4.0 的检查看的是策略版本；最低版本仍是 3.1。3.1 到 3.11 的 CMake 会忽略 max，只按 3.1 处理。</details>
4. 把 23_1 第二次运行的 max 从 4.2 改成 3.29，两个警告哪个回来？
   <details><summary>提示</summary>CMP0156 在 3.29 已经引入，设为 `NEW`，不再警告；CMP0181 是 4.0 的，仍然未设置，警告回来。</details>
