Rust 程序设计语言

异步编程基础：async、await、future 与流

我们让计算机执行的许多操作都可能需要一段时间才能完成。如果在等待这些耗时较长的过程完成时，我们能去做点别的事情，那就太好了。现代计算机提供了两种同时处理多个操作的技术：并行和并发。然而，我们编写的程序逻辑大多是线性的。我们希望能够指定程序要执行的操作，以及函数可以在哪些位置暂停、转而让程序的其他部分运行，而不必事先精确规定每段代码运行的顺序和方式。异步编程（asynchronous programming）就是这样一种抽象：它让我们能够用可能的暂停点和最终结果来表达代码，并替我们处理好协调方面的细节。

第 16 章使用线程来实现并行和并发，本章在此基础上介绍另一种编写代码的方式：Rust 的 future、流，以及让我们能够表达操作可以如何异步进行的 async 和 await 语法；此外还有实现了异步运行时的第三方 crate，所谓异步运行时，就是管理和协调异步操作执行的代码。

我们来看一个例子。假设你正在导出一段自己制作的家庭聚会视频，这个操作可能需要几分钟到几个小时不等。视频导出会尽可能多地占用 CPU 和 GPU 的算力。如果你只有一个 CPU 核心，而操作系统在导出完成之前不会暂停它——也就是说，它以同步（synchronously）的方式执行导出——那么在这个任务运行期间，你就无法在电脑上做任何其他事情。那种体验会相当令人沮丧。幸运的是，你电脑上的操作系统能够、而且确实会在你察觉不到的情况下频繁地中断导出，让你可以同时完成其他工作。

再假设你正在下载别人分享的一段视频，这同样可能需要一段时间，但并不会占用那么多 CPU 时间。在这种情况下，CPU 必须等待数据从网络上到达。虽然数据一开始到达你就可以开始读取，但所有数据全部到齐可能还需要一些时间。即便数据全部到齐，如果视频相当大，把它全部加载完也可能至少需要一两秒钟。这听起来也许不算多，但对于每秒能执行数十亿次操作的现代处理器来说，这是非常漫长的一段时间。同样，操作系统会在你察觉不到的情况下中断你的程序，让 CPU 在等待网络调用完成的同时执行其他工作。

视频导出是 CPU 密集型（CPU-bound）或者说计算密集型（compute-bound）操作的一个例子。它受限于计算机在 CPU 或 GPU 中可能达到的数据处理速度，以及其中有多少速度可以分配给这个操作。视频下载则是 I/O 密集型（I/O-bound）操作的一个例子，因为它受限于计算机输入和输出（input and output）的速度；数据在网络上传输得有多快，它就只能有多快。

在这两个例子中，操作系统那些察觉不到的中断提供了某种形式的并发。不过，这种并发只发生在整个程序的层面上：操作系统中断一个程序，好让其他程序完成工作。在很多情况下，由于我们对自己程序的理解比操作系统要细致得多，我们能够发现操作系统看不到的并发机会。

例如，如果我们正在构建一个管理文件下载的工具，就应该能够把程序写成这样：开始一个下载时不会让 UI 卡住，而且用户应该能够同时开始多个下载。然而，许多用于与网络交互的操作系统 API 都是阻塞（blocking）的；也就是说，在它们正在处理的数据完全就绪之前，它们会阻止程序继续推进。

注意：仔细想想，大多数函数调用都是这样工作的。不过，阻塞这个词通常专门用于那些与文件、网络或计算机上其他资源进行交互的函数调用，因为在这些场景下，单个程序才能从非阻塞的操作中获益。

我们可以为每个文件的下载生成一个专门的线程，从而避免阻塞主线程。然而，这些线程所占用的系统资源开销最终会成为一个问题。更好的做法是让调用从一开始就不阻塞，取而代之的是，我们可以定义一些希望程序完成的任务，并让运行时选择运行它们的最佳顺序和方式。

这正是 Rust 的 async（asynchronous 的缩写，即异步）抽象所提供的。在本章中，你将通过以下主题全面了解 async：

  • 如何使用 Rust 的 async 和 await 语法，并借助运行时执行异步函数
  • 如何使用 async 模型解决我们在第 16 章中看到的一些同样的挑战
  • 多线程和 async 如何提供互补的解决方案，以及如何在许多场景下将二者结合起来

不过，在了解 async 在实践中如何工作之前，我们需要先稍微绕个路，讨论一下并行和并发之间的区别。

并行与并发

到目前为止，我们基本上把并行和并发当作可以互换的概念来对待。现在我们需要更精确地区分它们，因为在我们开始动手之后，二者的区别就会显现出来。

想一想一个团队在软件项目中分配工作的不同方式。你可以给一个成员分配多个任务，也可以给每个成员分配一个任务，或者把这两种方式结合起来。

当一个人在几个不同的任务中的任何一个完成之前就同时处理它们时，这就是并发（concurrency）。实现并发的一种方式类似于在电脑上签出了两个不同的项目，当你对其中一个项目感到厌倦或者卡住时，就切换到另一个。你只有一个人，所以无法在完全相同的时刻同时推进两个任务，但你可以多任务处理，通过在任务之间来回切换，每次推进其中一个（见图 17-1）。

当团队把一组任务分开，让每个成员各自领取一个任务并独立完成时，这就是并行（parallelism）。团队中的每个人都可以在完全相同的时刻推进工作（见图 17-2）。

在这两种工作流中，你都可能需要在不同的任务之间进行协调。也许你原以为分配给某个人的任务完全独立于其他所有人的工作，但实际上它需要团队里的另一个人先完成他们的任务。有些工作可以并行完成，但有些工作实际上是串行（serial）的：它只能按顺序一个接一个地进行，如图 17-3 所示。

同样，你可能会发现自己的某个任务依赖于你的另一个任务。这时，你的并发工作也变成了串行的。

并行和并发也可能彼此交织。如果你得知一位同事要等你完成某个任务才能继续，你很可能会把全部精力都集中到这个任务上，好为同事“解除阻塞”。这时，你和同事就不能再并行工作了，你也不能再并发地处理自己的各项任务了。

同样的基本规律也适用于软件和硬件。在只有一个 CPU 核心的机器上，CPU 一次只能执行一个操作，但它仍然可以并发地工作。借助线程、进程和 async 等工具，计算机可以暂停一项活动，切换到其他活动，最终再轮回到第一项活动。在拥有多个 CPU 核心的机器上，它还可以并行地工作。一个核心可以执行一个任务，而另一个核心同时执行一个完全无关的任务，这些操作是真正同时发生的。

在 Rust 中运行异步代码通常是并发进行的。取决于硬件、操作系统以及我们所使用的异步运行时（稍后会详细介绍异步运行时），这种并发在底层也可能用到并行。
