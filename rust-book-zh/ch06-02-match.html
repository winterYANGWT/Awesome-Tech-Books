Rust 程序设计语言

match 控制流结构

Rust 有一个极其强大的控制流结构，叫作 match，它允许你将一个值与一系列模式进行比较，并根据匹配上的模式执行相应的代码。模式可以由字面量、变量名、通配符以及许多其他内容构成；第 19 章会介绍所有不同种类的模式及其作用。match 的强大之处在于模式的表达能力，以及编译器会确认所有可能的情况都得到了处理。

可以把 match 表达式想象成一台硬币分类机：硬币沿着一条轨道滑下，轨道上分布着大小不一的孔，每枚硬币都会从它遇到的第一个能容纳它的孔中落下。同样地，值会依次经过 match 中的每个模式，一旦遇到第一个“合适”的模式，值就会落入与之相关联的代码块，并在执行过程中被使用。

说到硬币，我们就用它们来举一个使用 match 的例子吧！我们可以编写一个函数，它接收一枚未知的美国硬币，像计数机那样判断出它是哪种硬币，然后返回它以美分为单位的面值，如示例 6-3 所示。

我们来拆解一下 value_in_cents 函数中的 match。首先，我们写出 match 关键字，后面跟着一个表达式，在这个例子中就是 coin 这个值。这看起来与 if 所使用的条件表达式非常相似，但二者有一个很大的区别：对于 if，条件的求值结果必须是布尔值，而这里可以是任何类型。这个例子中 coin 的类型是我们在第一行定义的 Coin 枚举。

接下来是 match 的各个分支。一个分支由两部分组成：一个模式和一些代码。这里第一个分支的模式是值 Coin::Penny，然后是 => 运算符，它将模式与要运行的代码分隔开。这里的代码就只是值 1。各个分支之间用逗号隔开。

当 match 表达式执行时，它会按顺序将结果值与每个分支的模式进行比较。如果某个模式与该值匹配，就执行与该模式相关联的代码；如果该模式与该值不匹配，就继续执行下一个分支，就像硬币分类机一样。我们可以根据需要设置任意多个分支：在示例 6-3 中，我们的 match 有四个分支。

与每个分支相关联的代码是一个表达式，而匹配上的那个分支中表达式的结果值，就是整个 match 表达式的返回值。

如果分支代码很短，比如在示例 6-3 中每个分支都只是返回一个值，我们通常不使用大括号。如果你想在一个分支中运行多行代码，就必须使用大括号，此时分支后面的逗号是可选的。例如，下面的代码在每次使用 Coin::Penny 调用该函数时都会打印“Lucky penny!”，但仍然会返回代码块的最后一个值 1：

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => {
            println!("Lucky penny!");
            1
        }
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter => 25,
    }
}

fn main() {}

绑定值的模式

分支的另一个有用功能是，它们可以绑定到值中与模式相匹配的部分。我们正是通过这种方式从枚举变体中提取值的。

举个例子，我们来修改其中一个枚举变体，让它在内部存放数据。从 1999 年到 2008 年，美国铸造了一批 25 美分硬币，其一面针对 50 个州分别采用了不同的设计。其他硬币都没有州的设计，所以只有 25 美分硬币才有这个额外的值。我们可以修改 Quarter 变体，让它在内部存储一个 UsState 值，从而把这一信息添加到我们的 enum 中，如示例 6-4 所示。

假设有一个朋友正在尝试收集全部 50 个州的 25 美分硬币。在按硬币种类整理零钱的同时，我们还会报出每枚 25 美分硬币所对应的州名，这样如果遇到朋友还没有的那一枚，他们就可以把它加入自己的收藏。

在这段代码的 match 表达式中，我们在匹配 Coin::Quarter 变体值的模式中添加了一个名为 state 的变量。当匹配到 Coin::Quarter 时，state 变量就会绑定到这枚 25 美分硬币所对应州的值上。然后，我们就可以在该分支的代码中使用 state 了，就像这样：

#[derive(Debug)]
enum UsState {
    Alabama,
    Alaska,
    // --snip--
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter(UsState),
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter(state) => {
            println!("State quarter from {state:?}!");
            25
        }
    }
}

fn main() {
    value_in_cents(Coin::Quarter(UsState::Alaska));
}

如果我们调用 value_in_cents(Coin::Quarter(UsState::Alaska))，coin 就是 Coin::Quarter(UsState::Alaska)。当我们将这个值与每个分支进行比较时，直到遇到 Coin::Quarter(state) 之前，没有任何分支能够匹配。此时，state 绑定的值就是 UsState::Alaska。然后，我们就可以在 println! 表达式中使用这个绑定，从而从 Quarter 所对应的 Coin 枚举变体中取出内部的州值。

Option<T> 的 match 模式

在上一节中，我们想要在使用 Option<T> 时从 Some 中取出内部的 T 值；我们同样可以使用 match 来处理 Option<T>，就像处理 Coin 枚举那样！我们比较的不再是硬币，而是 Option<T> 的变体，但 match 表达式的工作方式保持不变。

假设我们想要编写一个函数，它接收一个 Option<i32>，如果其中有值，就将该值加 1；如果其中没有值，函数就应该返回 None 值，并且不尝试执行任何操作。

得益于 match，这个函数写起来非常简单，如示例 6-5 所示。

我们来更详细地分析一下 plus_one 的第一次执行。当我们调用 plus_one(five) 时，plus_one 函数体中的变量 x 的值是 Some(5)。接着我们将它与每个分支进行比较：

fn main() {
    fn plus_one(x: Option<i32>) -> Option<i32> {
        match x {
            None => None,
            Some(i) => Some(i + 1),
        }
    }

    let five = Some(5);
    let six = plus_one(five);
    let none = plus_one(None);
}

Some(5) 值与模式 None 不匹配，所以我们继续检查下一个分支：

fn main() {
    fn plus_one(x: Option<i32>) -> Option<i32> {
        match x {
            None => None,
            Some(i) => Some(i + 1),
        }
    }

    let five = Some(5);
    let six = plus_one(five);
    let none = plus_one(None);
}

Some(5) 与 Some(i) 匹配吗？匹配！它们是相同的变体。i 绑定到 Some 中包含的值上，所以 i 的值是 5。然后执行该分支中的代码，也就是将 i 的值加 1，并创建一个包含总和 6 的新 Some 值。

现在我们来看示例 6-5 中 plus_one 的第二次调用，这次 x 是 None。我们进入 match，并与第一个分支进行比较：

fn main() {
    fn plus_one(x: Option<i32>) -> Option<i32> {
        match x {
            None => None,
            Some(i) => Some(i + 1),
        }
    }

    let five = Some(5);
    let six = plus_one(five);
    let none = plus_one(None);
}

匹配上了！没有可以相加的值，所以程序停下来，并返回 => 右侧的 None 值。因为第一个分支已经匹配，所以不会再与其他分支进行比较。

将 match 与枚举结合起来，在很多场景下都很有用。你会在 Rust 代码中频繁地看到这种模式：对一个枚举进行 match，将一个变量绑定到其中的数据上，然后根据它执行相应的代码。一开始这可能有点棘手，但一旦习惯了，你会希望所有语言都有这个功能。它一直深受用户喜爱。

匹配是穷尽的

match 还有一个方面需要讨论：分支的模式必须覆盖所有可能的情况。考虑下面这个版本的 plus_one 函数，它有一个 bug，无法编译：

fn main() {
    fn plus_one(x: Option<i32>) -> Option<i32> {
        match x {
            Some(i) => Some(i + 1),
        }
    }

    let five = Some(5);
    let six = plus_one(five);
    let none = plus_one(None);
}

我们没有处理 None 的情况，所以这段代码会导致 bug。幸运的是，这是一个 Rust 知道如何捕获的 bug。如果我们尝试编译这段代码，会得到如下错误：

Rust 知道我们没有覆盖所有可能的情况，甚至知道我们遗漏了哪个模式！Rust 中的匹配是穷尽的（exhaustive）：我们必须穷尽每一种可能性，代码才是有效的。特别是在 Option<T> 的情况下，Rust 会防止我们忘记显式处理 None 的情况，从而避免我们在可能是空值的时候误以为自己拥有一个值，这就让前面讨论过的那个十亿美元错误不可能发生。

通配模式和 _ 占位符

使用枚举，我们还可以对少数几个特定的值采取特殊操作，而对其他所有值采取一个默认操作。设想我们正在实现一个游戏：如果你掷骰子掷出了 3，你的角色不会移动，而是会得到一顶漂亮的新帽子；如果掷出了 7，你的角色会失去一顶漂亮的帽子；对于其他所有的值，你的角色会在游戏棋盘上移动相应的格数。下面是实现这一逻辑的 match，其中掷骰子的结果是硬编码的，而不是随机值，其他逻辑则用没有函数体的函数来表示，因为真正实现它们超出了这个例子的范围：

fn main() {
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        other => move_player(other),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
    fn move_player(num_spaces: u8) {}
}

对于前两个分支，模式是字面量 3 和 7。对于覆盖其他所有可能值的最后一个分支，模式是我们选择命名为 other 的变量。other 分支运行的代码将这个变量传递给 move_player 函数，以此来使用它。

即使我们没有列出 u8 所有可能的值，这段代码也能编译，因为最后一个模式会匹配所有没有被明确列出的值。这种通配模式满足了 match 必须穷尽的要求。注意，我们必须把通配分支放在最后，因为模式是按顺序求值的。如果把通配分支放在前面，其他分支就永远不会运行，所以如果我们在通配分支之后添加分支，Rust 会发出警告！

当我们需要通配，但又不想使用通配模式中的值时，Rust 也提供了一种可用的模式：_ 是一个特殊的模式，它可以匹配任意值，并且不会绑定到该值。这就告诉了 Rust 我们不会使用这个值，所以 Rust 也不会警告我们存在未使用的变量。

我们来修改一下游戏规则：现在，如果你掷出的不是 3 或 7，就必须重新掷一次。我们不再需要使用通配的值，所以可以修改代码，用 _ 代替名为 other 的变量：

fn main() {
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        _ => reroll(),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
    fn reroll() {}
}

这个例子同样满足穷尽性要求，因为我们在最后一个分支中显式地忽略了其他所有值；我们没有遗漏任何情况。

最后，我们再修改一次游戏规则：如果你掷出的不是 3 或 7，在你的回合中就什么都不会发生。我们可以使用单元值（即我们在“元组类型”部分提到过的空元组类型）作为 _ 分支的代码来表达这一点：

fn main() {
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        _ => (),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
}

在这里，我们显式地告诉 Rust：我们不会使用任何与前面分支的模式不匹配的其他值，并且在这种情况下我们不想运行任何代码。
