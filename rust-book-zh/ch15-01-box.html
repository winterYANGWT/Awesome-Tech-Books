使用 Box<T> 指向堆上的数据

最简单直接的智能指针是 box，其类型写作 Box<T>。box 允许你把数据存储在堆上而不是栈上，留在栈上的是指向堆数据的指针。如需回顾栈和堆的区别，请参阅第 4 章。

除了把数据存储在堆上而不是栈上之外，box 没有性能开销，不过它们也没有太多额外的功能。你最常在以下场景中使用它们：

  • 当你有一个在编译时无法确定大小的类型，而又想在需要确切大小的上下文中使用这个类型的值时
  • 当你有大量数据，并希望转移所有权，同时确保转移时数据不会被复制时
  • 当你希望拥有一个值，并且只关心它是否实现了某个特定 trait，而不关心它的具体类型时

我们会在“使用 box 实现递归类型”中演示第一种情况。在第二种情况下，转移大量数据的所有权可能会花费很长时间，因为这些数据会在栈上被来回复制。为了改善这种情况下的性能，我们可以把大量数据存储在堆上的 box 中。这样，在栈上来回复制的只有少量的指针数据，而它所引用的数据则留在堆上的同一个位置。第三种情况被称为 trait 对象（trait object），第 18 章的“使用 trait 对象抽象共同行为”一节专门讨论这个主题。所以，你在这里学到的内容会在那一节再次用到！

把单个值放在堆上并没有多大用处，所以你不会经常像这样单独使用 box。在大多数情况下，把单个 i32 这样的值放在默认存储它们的栈上更为合适。下面我们来看一个场景：如果没有 box，我们就无法定义某些类型，而 box 让我们能够定义它们。

使用 box 实现递归类型

递归类型（recursive type）的值可以将另一个相同类型的值作为自身的一部分。递归类型会带来一个问题，因为 Rust 需要在编译时知道一个类型占用多少空间。然而，递归类型的值的嵌套理论上可以无限进行下去，因此 Rust 无法知道这个值需要多少空间。由于 box 的大小是已知的，我们可以通过在递归类型的定义中插入 box 来实现递归类型。

作为递归类型的一个例子，我们来探究一下 cons list。这是函数式编程语言中常见的一种数据类型。除了递归之外，我们将要定义的 cons list 类型非常简单直接；因此，在这个例子中用到的概念，在你以后遇到涉及递归类型的更复杂情况时都会派上用场。

理解 cons list

cons list 是一种源自 Lisp 编程语言及其方言的数据结构，由嵌套的序对（pair）组成，相当于 Lisp 版本的链表。它的名字来源于 Lisp 中的 cons 函数（construct function 的缩写，即“构造函数”），该函数用它的两个参数构造出一个新的序对。对一个由某个值和另一个序对组成的序对调用 cons，我们就能构造出由递归序对组成的 cons list。

例如，下面是一个包含列表 1, 2, 3 的 cons list 的伪代码表示，每个序对都用圆括号括起来：

(1, (2, (3, Nil)))

cons list 中的每一项都包含两个元素：当前项的值和下一项。列表的最后一项只包含一个名为 Nil 的值，没有下一项。cons list 是通过递归调用 cons 函数生成的。表示递归基准情形的规范名称是 Nil。注意，这与第 6 章讨论的“null”或“nil”概念不同，后者指的是无效或缺失的值。

cons list 在 Rust 中并不是常用的数据结构。大多数时候，当你在 Rust 中需要一个项的列表时，Vec<T> 是更好的选择。其他更复杂的递归数据类型在各种场景中确实很有用，但本章从 cons list 入手，可以让我们不受太多干扰地探究 box 是如何让我们定义递归数据类型的。

计算非递归类型的大小

回想一下第 6 章讨论枚举定义时，我们在示例 6-2 中定义的 Message 枚举：

enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}

fn main() {}

为了确定要为一个 Message 值分配多少空间，Rust 会逐一检查每个变体，看哪个变体需要的空间最多。Rust 发现 Message::Quit 不需要任何空间，Message::Move 需要足够存储两个 i32 值的空间，依此类推。因为同一时间只会使用一个变体，所以一个 Message 值所需的最大空间就是存储其最大变体所需的空间。

与此形成对比的是，当 Rust 尝试确定像示例 15-2 中 List 枚举这样的递归类型需要多少空间时会发生什么。编译器先查看 Cons 变体，它存储了一个 i32 类型的值和一个 List 类型的值。因此，Cons 需要的空间等于一个 i32 的大小加上一个 List 的大小。为了计算出 List 类型需要多少内存，编译器又会查看它的各个变体，从 Cons 变体开始。Cons 变体存储了一个 i32 类型的值和一个 List 类型的值，这个过程会无限地进行下去，如图 15-1 所示。

获得一个大小已知的递归类型

由于 Rust 无法计算出要为递归定义的类型分配多少空间，编译器会给出一个错误，并附带这条有用的建议：

help: insert some indirection (e.g., a `Box`, `Rc`, or `&`) to break the cycle
  |
2 |     Cons(i32, Box<List>),
  |               ++++    +

在这条建议中，间接（indirection）指的是不直接存储一个值，而是修改数据结构，转而存储一个指向该值的指针，从而间接地存储这个值。

因为 Box<T> 是一个指针，所以 Rust 总是知道一个 Box<T> 需要多少空间：指针的大小不会因为它所指向的数据量而改变。这意味着我们可以在 Cons 变体中放入一个 Box<T>，而不是直接放入另一个 List 值。Box<T> 会指向下一个 List 值，这个值位于堆上，而不是在 Cons 变体内部。从概念上讲，我们仍然拥有一个由“列表包含其他列表”所构成的列表，但现在这种实现更像是把各个项一个挨一个地排列，而不是一个套一个地嵌套。

我们可以把示例 15-2 中 List 枚举的定义以及示例 15-3 中对 List 的使用修改为示例 15-5 中的代码，这样就可以通过编译了。

Cons 变体需要的空间是一个 i32 的大小加上存储 box 指针数据的空间。Nil 变体不存储任何值，因此它在栈上需要的空间比 Cons 变体少。现在我们知道，任何 List 值所占用的空间都是一个 i32 的大小加上一个 box 指针数据的大小。通过使用 box，我们打破了无限的递归链，因此编译器能够计算出存储一个 List 值所需的大小。图 15-2 展示了现在 Cons 变体的样子。

box 只提供间接存储和堆分配的功能；它们没有任何其他特殊功能，比如我们将在其他智能指针类型中看到的那些功能。它们也没有这些特殊功能所带来的性能开销，因此在像 cons list 这样只需要间接存储这一个特性的场景中，它们会很有用。我们会在第 18 章看到更多 box 的使用场景。

Box<T> 类型之所以是智能指针，是因为它实现了 Deref trait，这使得 Box<T> 值可以被当作引用来对待。当一个 Box<T> 值离开作用域时，由于 Drop trait 的实现，box 所指向的堆数据也会被清理。对于本章余下部分将要讨论的其他智能指针类型所提供的功能来说，这两个 trait 甚至更为重要。下面我们来更详细地探究这两个 trait。
