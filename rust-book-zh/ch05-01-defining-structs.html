Rust 程序设计语言

定义并实例化结构体

结构体与“元组类型”部分讨论过的元组类似，二者都可以存放多个相关联的值。和元组一样，结构体的各个部分可以是不同的类型。但与元组不同的是，在结构体中你需要为每一部分数据命名，以清楚地表明这些值的含义。有了这些名字，结构体就比元组更加灵活：你不必依赖数据的顺序来指定或访问实例中的值。

定义结构体时，我们输入关键字 struct，并为整个结构体命名。结构体的名字应当描述被组合在一起的这些数据的意义。接着，在大括号中定义每一部分数据的名字和类型，我们称之为字段（field）。例如，示例 5-1 展示了一个存储用户账号信息的结构体。

定义好结构体之后，为了使用它，我们需要为每个字段指定具体的值，以创建该结构体的实例（instance）。创建实例时，先写出结构体的名字，然后加上一对大括号，里面是若干 key: value 键值对，其中键是字段的名字，值是我们想要存储在这些字段中的数据。我们不必按照字段在结构体中声明的顺序来指定它们。换句话说，结构体定义就像是这个类型的通用模板，而实例则是用具体的数据填充这个模板，从而创建出该类型的值。例如，我们可以像示例 5-2 那样声明一个特定的用户。

要从结构体中获取某个特定的值，可以使用点号表示法。例如，要访问这个用户的电子邮件地址，我们使用 user1.email。如果实例是可变的，我们还可以使用点号表示法为某个特定字段赋值，从而修改它的值。示例 5-3 展示了如何修改一个可变 User 实例中 email 字段的值。

注意，整个实例必须是可变的；Rust 不允许只将某些字段标记为可变。与任何表达式一样，我们可以在函数体的最后一个表达式中构造一个新的结构体实例，从而隐式地返回这个新实例。

示例 5-4 展示了一个 build_user 函数，它根据给定的电子邮件和用户名返回一个 User 实例。其中 active 字段的值为 true，sign_in_count 的值为 1。

把函数参数起成与结构体字段相同的名字是合理的，但不得不重复写 email 和 username 这些字段名和变量名，就有点乏味了。如果结构体的字段更多，逐个重复这些名字就会更加烦人。幸运的是，有一种方便的简写方式！

使用结构体更新语法创建实例

基于同类型的另一个实例来创建新的结构体实例，沿用其中的大部分值，只修改其中一部分，这种需求很常见。你可以使用结构体更新语法（struct update syntax）来做到这一点。

首先，在示例 5-6 中，我们展示了不使用更新语法、按常规方式在 user2 中创建一个新 User 实例的做法。我们为 email 设置了新值，其余的值则沿用示例 5-2 中创建的 user1 的值。

使用结构体更新语法，我们可以用更少的代码达到同样的效果，如示例 5-7 所示。.. 语法指定了其余未显式设置的字段应当与给定实例中对应字段的值相同。

示例 5-7 中的代码同样在 user2 中创建了一个实例，它的 email 值与 user1 不同，但 username、active 和 sign_in_count 字段的值都与 user1 相同。..user1 必须放在最后，以指定其余所有字段都从 user1 的对应字段中获取值；不过我们可以按任意顺序为任意多个字段指定值，而不必考虑结构体定义中字段的顺序。

注意，结构体更新语法像赋值一样使用了 =，这是因为它会移动数据，正如我们在“变量与数据交互的方式：移动”部分看到的那样。在这个例子中，创建 user2 之后我们就不能再使用 user1 了，因为 user1 的 username 字段中的 String 已被移动到 user2 中。如果我们为 user2 的 email 和 username 都赋予了新的 String 值，从而只使用了 user1 中的 active 和 sign_in_count 值，那么在创建 user2 之后 user1 仍然有效。active 和 sign_in_count 的类型都实现了 Copy trait，因此适用我们在“只在栈上的数据：Copy”部分讨论过的行为。在这个例子中，我们也仍然可以使用 user1.email，因为它的值并没有从 user1 中移出。

使用元组结构体创建不同的类型

Rust 还支持一种看起来与元组类似的结构体，称为元组结构体（tuple struct）。元组结构体具有结构体名称所赋予的额外含义，但它的字段没有名字，只有字段的类型。当你想给整个元组起一个名字，使它成为一个有别于其他元组的类型，并且像常规结构体那样为每个字段命名又会显得冗长或多余时，元组结构体就很有用。

结构体数据的所有权

在示例 5-1 的 User 结构体定义中，我们使用了拥有所有权的 String 类型，而不是 &str 字符串切片类型。这是一个有意为之的选择，因为我们希望这个结构体的每个实例都拥有它的全部数据，并且只要整个结构体有效，这些数据就有效。
