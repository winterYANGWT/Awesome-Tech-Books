Rust 程序设计语言

使用 use 关键字将路径引入作用域

每次调用函数都要写出完整路径，可能会让人觉得既不方便又重复。在示例 7-7 中，无论我们为 add_to_waitlist 函数选择绝对路径还是相对路径，每次想调用 add_to_waitlist 时，都还得指定 front_of_house 和 hosting。幸运的是，有一种方法可以简化这个过程：我们可以用 use 关键字为路径创建一次快捷方式，然后在该作用域中的其他任何地方使用这个更短的名称。

在示例 7-11 中，我们将 crate::front_of_house::hosting 模块引入 eat_at_restaurant 函数的作用域，这样在 eat_at_restaurant 中调用 add_to_waitlist 函数时，只需指定 hosting::add_to_waitlist 即可。

在作用域中添加 use 和路径，类似于在文件系统中创建一个符号链接。通过在 crate 根中添加 use crate::front_of_house::hosting，hosting 现在就成了该作用域中的一个有效名称，就好像 hosting 模块是在 crate 根中定义的一样。与其他任何路径一样，通过 use 引入作用域的路径也会检查私有性。

注意，use 只会为它所在的那个特定作用域创建快捷方式。示例 7-12 将 eat_at_restaurant 函数移动到了一个名为 customer 的新子模块中，这个子模块与 use 语句处于不同的作用域，因此函数体将无法编译。

创建惯用的 use 路径

在示例 7-11 中，你可能会好奇，为什么我们指定的是 use crate::front_of_house::hosting，然后在 eat_at_restaurant 中调用 hosting::add_to_waitlist，而不是像示例 7-13 那样，把 use 路径一直指定到 add_to_waitlist 函数，以达到同样的效果。

虽然示例 7-11 和示例 7-13 完成的是同样的任务，但示例 7-11 才是使用 use 将函数引入作用域的惯用方式。使用 use 将函数的父模块引入作用域，意味着我们在调用函数时必须指定父模块。在调用函数时指定父模块，可以清楚地表明该函数不是在本地定义的，同时又能尽量减少完整路径的重复。而示例 7-13 中的代码则让人搞不清 add_to_waitlist 是在哪里定义的。

另一方面，使用 use 引入结构体、枚举和其他项时，惯用的做法是指定完整路径。示例 7-14 展示了将标准库的 HashMap 结构体引入二进制 crate 作用域的惯用方式。

这种惯用法背后并没有什么充分的理由：它只是逐渐形成的一种约定，大家已经习惯了以这种方式阅读和编写 Rust 代码。

这种惯用法的一个例外是：使用 use 语句将两个同名的项引入作用域时，因为 Rust 不允许这样做。示例 7-15 展示了如何将两个名称相同但父模块不同的 Result 类型引入作用域，以及如何引用它们。

如你所见，使用父模块可以区分这两个 Result 类型。如果我们改为指定 use std::fmt::Result 和 use std::io::Result，同一个作用域中就会有两个 Result 类型，当我们使用 Result 时，Rust 就不知道我们指的是哪一个了。

使用 as 关键字提供新的名称

对于使用 use 将两个同名类型引入同一作用域的问题，还有另一种解决办法：在路径后面，我们可以指定 as 以及该类型的一个新的本地名称，即别名（alias）。示例 7-16 展示了示例 7-15 中代码的另一种写法：使用 as 对两个 Result 类型中的一个进行重命名。

在第二条 use 语句中，我们为 std::io::Result 类型选择了新名称 IoResult，它不会与同样被我们引入作用域的、来自 std::fmt 的 Result 发生冲突。示例 7-15 和示例 7-16 都被认为是惯用的写法，所以选择哪一种取决于你！

使用 pub use 重导出名称

当我们使用 use 关键字将一个名称引入作用域时，这个名称对于导入它的那个作用域来说是私有的。为了让该作用域之外的代码也能像这个名称是在该作用域中定义的那样引用它，我们可以将 pub 和 use 结合起来。这种技术被称为重导出（re-exporting），因为我们不仅把一个项引入了作用域，还让其他人也可以把这个项引入他们自己的作用域。

示例 7-17 展示了把示例 7-11 中根模块里的 use 改为 pub use 后的代码。

在这个修改之前，外部代码必须使用路径 restaurant::front_of_house::hosting::add_to_waitlist() 来调用 add_to_waitlist 函数，而这还要求 front_of_house 模块被标记为 pub。现在，这条 pub use 已经从根模块重导出了 hosting 模块，外部代码就可以改用路径 restaurant::hosting::add_to_waitlist() 了。

当代码的内部结构与调用你代码的程序员对该领域的思考方式不同时，重导出就很有用。例如，在这个餐厅的比喻中，经营餐厅的人会从“前台”和“后台”的角度来思考。但光顾餐厅的顾客可能不会用这些术语来看待餐厅的各个部分。有了 pub use，我们就可以用一种结构编写代码，却对外暴露另一种结构。这样做能让我们的库对于开发该库的程序员和调用该库的程序员来说，都组织得井井有条。我们会在第 14 章“导出便于使用的公有 API”部分中，看到 pub use 的另一个示例，以及它会如何影响 crate 的文档。

在第 2 章中，我们编写了一个猜数字游戏项目，它使用了一个名为 rand 的外部包来获取随机数。为了在项目中使用 rand，我们在 Cargo.toml 中添加了这一行：

在 Cargo.toml 中添加 rand 作为依赖，会告诉 Cargo 从 crates.io 下载 rand 包及其所有依赖，并让 rand 可供我们的项目使用。

接着，为了将 rand 的定义引入我们包的作用域，我们添加了一行以 crate 名 rand 开头的 use 语句，并列出了想要引入作用域的项。回想一下，在第 2 章“生成随机数”部分中，我们将 rand::prelude 模块中的项引入了作用域，并调用了 rand::rng 函数：

use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    println!("The secret number is: {secret_number}");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

Rust 社区的成员已经在 crates.io 上发布了许多包，将其中任何一个引入你的包都需要同样的步骤：在包的 Cargo.toml 文件中列出它们，然后使用 use 将它们 crate 中的项引入作用域。

注意，标准库 std 也是一个位于我们包外部的 crate。因为标准库是随 Rust 语言一起发布的，所以我们不需要修改 Cargo.toml 来引入 std。但我们确实需要通过 use 来引用它，才能把其中的项引入我们包的作用域。例如，对于 HashMap，我们会使用这一行：

#![allow(unused)]
fn main() {
use std::collections::HashMap;
}

这是一个以 std 开头的绝对路径，std 是标准库 crate 的名称。

使用 glob 运算符导入项

如果我们想将某个路径下定义的所有公有项都引入作用域，可以在指定该路径后加上 * glob 运算符：

#![allow(unused)]
fn main() {
use std::collections::*;
}

这条 use 语句将 std::collections 中定义的所有公有项都引入了当前作用域。使用 glob 运算符时要小心！glob 会让人更难分辨作用域中有哪些名称，以及程序中使用的某个名称是在哪里定义的。此外，如果依赖修改了它的定义，你导入的内容也会随之改变。例如，当你升级依赖时，如果该依赖新增了一个定义，与你在同一作用域中的某个定义同名，就可能导致编译器错误。

glob 运算符经常在测试时使用，用来将所有被测试的内容引入 tests 模块；我们会在第 11 章“如何编写测试”部分中讨论这一点。glob 运算符有时也会作为 prelude 模式的一部分来使用：关于这种模式的更多信息，请参阅标准库文档。
