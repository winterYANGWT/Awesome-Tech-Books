Rust 程序设计语言

切片类型

切片（slice）让你可以引用集合中一段连续的元素序列。切片是一种引用，所以它没有所有权。

这里有一个小小的编程问题：编写一个函数，它接收一个由空格分隔的单词组成的字符串，并返回在该字符串中找到的第一个单词。如果函数在字符串中没有找到空格，那么整个字符串就一定是一个单词，所以应该返回整个字符串。

注意：为了介绍切片，本节中我们只考虑 ASCII 的情况；关于 UTF-8 处理的更全面的讨论，请参见第 8 章“使用字符串存储 UTF-8 编码的文本”部分。

我们先来看看在不使用切片的情况下该如何编写这个函数的签名，从而理解切片要解决的问题：

fn first_word(s: &String) -> ?

first_word 函数有一个类型为 &String 的参数。我们并不需要所有权，所以这样没问题。（在惯用的 Rust 中，函数除非确实需要，否则不会获取其参数的所有权，随着我们继续学习，这样做的原因会逐渐清晰。）但我们应该返回什么呢？我们其实没有办法描述字符串的一部分。不过，我们可以返回单词结尾的索引，也就是空格所在的位置。我们来试试这种做法，如示例 4-7 所示。

因为我们需要逐个元素地遍历 String，并检查值是否为空格，所以我们使用 as_bytes 方法把 String 转换为一个字节数组。

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

fn main() {}

接下来，我们使用 iter 方法在字节数组上创建一个迭代器：

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

fn main() {}

我们会在第 13 章中更详细地讨论迭代器。现在只需要知道，iter 是一个返回集合中每个元素的方法，而 enumerate 会包装 iter 的结果，把每个元素作为元组的一部分返回。enumerate 返回的元组中，第一个元素是索引，第二个元素是指向集合元素的引用。这比我们自己计算索引要方便一些。

因为 enumerate 方法返回的是一个元组，所以我们可以使用模式来解构这个元组。我们会在第 6 章中进一步讨论模式。在 for 循环中，我们指定了一个模式，其中 i 对应元组中的索引，&item 对应元组中的单个字节。因为我们从 .iter().enumerate() 中得到的是指向元素的引用，所以在模式中使用了 &。

在 for 循环内部，我们使用字节字面量语法来查找表示空格的字节。如果找到了空格，就返回它的位置；否则，就使用 s.len() 返回字符串的长度。

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

fn main() {}

现在我们有了一种找出字符串中第一个单词结尾索引的方法，但还存在一个问题。我们单独返回了一个 usize，但它只有在 &String 的上下文中才是一个有意义的数字。换句话说，因为它是一个与 String 相分离的值，所以无法保证它在将来仍然有效。请看示例 4-8 中的程序，它使用了示例 4-7 中的 first_word 函数。

这个程序可以编译通过，没有任何错误；即使我们在调用 s.clear() 之后再使用 word，它也同样能编译通过。因为 word 与 s 的状态完全没有关联，所以 word 仍然包含值 5。我们可以用这个值 5 和变量 s 来尝试提取第一个单词，但这将是一个 bug，因为自从我们把 5 保存到 word 之后，s 的内容已经改变了。

还得操心 word 中的索引与 s 中的数据失去同步，这既烦琐又容易出错！如果我们再编写一个 second_word 函数，管理这些索引就会变得更加脆弱。它的签名将不得不像这样：

fn second_word(s: &String) -> (usize, usize) {

现在我们要跟踪一个起始索引和一个结束索引，而且有了更多根据特定状态下的数据计算出来、却又与该状态毫无关联的值。我们有三个互不相关的变量四处游离，还需要让它们保持同步。

幸运的是，Rust 为这个问题提供了一个解决方案：字符串切片。

字符串切片

字符串切片（string slice）是对 String 中一段连续元素序列的引用，它看起来是这样的：

fn main() {
    let s = String::from("hello world");

    let hello = &s[0..5];
    let world = &s[6..11];
}

hello 不是对整个 String 的引用，而是对 String 中一部分的引用，这部分由额外的 [0..5] 指定。我们使用方括号中的范围来创建切片，写法是 [starting_index..ending_index]，其中 starting_index 是切片的第一个位置，ending_index 则比切片的最后一个位置多 1。在内部，切片数据结构存储了切片的起始位置和长度，长度对应于 ending_index 减去 starting_index 的值。所以，对于 let world = &s[6..11]; 而言，world 将是一个切片，它包含一个指向 s 中索引 6 处字节的指针，长度值为 5。

图 4-7 用示意图展示了这一点。

图 4-7：引用 String 一部分的字符串切片

使用 Rust 的 .. 范围语法时，如果想从索引 0 开始，可以省略两个点之前的值。换句话说，下面两种写法是等价的：

#![allow(unused)]
fn main() {
let s = String::from("hello");

let slice = &s[0..2];
let slice = &s[..2];
}

同理，如果你的切片包含 String 的最后一个字节，也可以省略末尾的数字。这意味着下面两种写法是等价的：

#![allow(unused)]
fn main() {
let s = String::from("hello");

let len = s.len();

let slice = &s[3..len];
let slice = &s[3..];
}

你还可以同时省略两个值，从而获取整个字符串的切片。所以，下面两种写法是等价的：

#![allow(unused)]
fn main() {
let s = String::from("hello");

let len = s.len();

let slice = &s[0..len];
let slice = &s[..];
}

注意：字符串切片的范围索引必须位于有效的 UTF-8 字符边界上。如果你试图在一个多字节字符的中间创建字符串切片，程序将会因错误而退出。

我们用与示例 4-7 相同的方式获取单词结尾的索引，即查找第一个出现的空格。当找到空格时，我们以字符串的开头和空格的索引作为起始和结束索引，返回一个字符串切片。

现在，当我们调用 first_word 时，会得到一个与底层数据绑定在一起的单一值。这个值由指向切片起点的引用和切片中元素的数量组成。

返回切片对于 second_word 函数同样适用：

fn second_word(s: &String) -> &str {

现在我们有了一个简单直接的 API，而且它更难被用错，因为编译器会确保指向 String 的引用始终有效。还记得示例 4-8 程序中的那个 bug 吗？我们获取了第一个单词结尾的索引，但随后清空了字符串，导致索引失效。那段代码在逻辑上是错误的，却没有立即显示任何错误。如果我们继续对一个已清空的字符串使用第一个单词的索引，问题会在之后才暴露出来。切片使这种 bug 不可能发生，并让我们更早地知道代码出了问题。使用切片版本的 first_word 会产生一个编译时错误：

编译器错误如下：

  --> src/main.rs:18:5
   |

   |                           -- immutable borrow occurs here

   |     ^^^^^^^^^ mutable borrow occurs here

   |                                   ---- immutable borrow later used here

For more information about this error, try `rustc --explain E0502`.
error: could not compile `ownership` (bin "ownership") due to 1 previous error

回忆一下借用规则：如果我们拥有某个东西的不可变引用，就不能再获取它的可变引用。因为 clear 需要截断 String，所以它需要获取一个可变引用。调用 clear 之后的 println! 使用了 word 中的引用，所以此时这个不可变引用必须仍然有效。Rust 不允许 clear 中的可变引用和 word 中的不可变引用同时存在，因此编译失败。Rust 不仅让我们的 API 更易于使用，还在编译时就消除了一整类错误！

字符串字面量就是切片

回想一下，我们讲过字符串字面量是存储在二进制文件中的。现在我们了解了切片，就能正确地理解字符串字面量了：

#![allow(unused)]
fn main() {
let s = "Hello, world!";
}

这里 s 的类型是 &str：它是一个指向二进制文件中那个特定位置的切片。这也是字符串字面量不可变的原因；&str 是一个不可变引用。

字符串切片作为参数

知道了可以获取字面量和 String 值的切片之后，我们就可以对 first_word 再做一项改进，那就是它的签名：

fn first_word(s: &String) -> &str {

更有经验的 Rustacean 会改写成示例 4-9 中所示的签名，因为它让我们可以对 &String 值和 &str 值使用同一个函数。

如果我们有一个字符串切片，可以直接传递它。如果我们有一个 String，则可以传递该 String 的切片或对该 String 的引用。这种灵活性利用了解引用强制转换，我们会在第 15 章“在函数和方法中使用解引用强制转换”部分介绍这一特性。

其他类型的切片

你可能已经想到，字符串切片是专门针对字符串的。不过还有一种更通用的切片类型。考虑下面这个数组：

#![allow(unused)]
fn main() {
let a = [1, 2, 3, 4, 5];
}

就像我们可能想引用字符串的一部分一样，我们也可能想引用数组的一部分。可以这样做：

#![allow(unused)]
fn main() {
let a = [1, 2, 3, 4, 5];

let slice = &a[1..3];

assert_eq!(slice, &[2, 3]);
}

这个切片的类型是 &[i32]。它的工作方式与字符串切片相同，都是存储一个指向第一个元素的引用和一个长度。你会在各种其他集合中使用这种切片。我们会在第 8 章讨论 vector 时详细介绍这些集合。

总结

所有权、借用和切片这些概念，在编译时就确保了 Rust 程序的内存安全。Rust 语言像其他系统编程语言一样，让你能够控制内存的使用。但由于数据的所有者会在离开作用域时自动清理这些数据，你无需编写和调试额外的代码就能获得这种控制能力。

所有权影响着 Rust 中许多其他部分的工作方式，所以在本书的其余部分，我们还会进一步讨论这些概念。让我们进入第 5 章，看看如何把多个数据片段组合到一个 struct 中。
