Rust 程序设计语言

定义枚举

结构体为你提供了一种将相关字段和数据组合在一起的方式，比如带有 width 和 height 的 Rectangle；而枚举则为你提供了一种表达“某个值是一组可能的值之一”的方式。例如，我们可能想要表达 Rectangle 是一组可能的形状之一，这组形状还包括 Circle 和 Triangle。为此，Rust 允许我们把这些可能性编码为一个枚举。

我们来看一个可能需要用代码表达的场景，看看为什么在这种情况下枚举比结构体更有用、更合适。假设我们需要处理 IP 地址。目前，IP 地址有两个主要标准：第四版和第六版。因为这是程序会遇到的 IP 地址仅有的两种可能，所以我们可以把所有可能的变体都列举（enumerate）出来，这也正是枚举（enumeration）这个名字的由来。

任何一个 IP 地址要么是第四版地址，要么是第六版地址，但不可能同时是两者。IP 地址的这一特性让枚举这种数据结构非常合适，因为一个枚举值只能是其变体中的一个。第四版和第六版地址本质上都仍然是 IP 地址，所以当代码处理适用于任何类型 IP 地址的情况时，应当把它们视为同一种类型。

我们可以在代码中定义一个 IpAddrKind 枚举，并列出 IP 地址可能的类别 V4 和 V6，以此来表达这个概念。它们就是这个枚举的变体：

enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;

    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}

fn route(ip_kind: IpAddrKind) {}

现在，IpAddrKind 就是一个自定义数据类型了，我们可以在代码的其他地方使用它。

枚举值

我们可以像这样分别创建 IpAddrKind 两个变体的实例：

enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;

    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}

fn route(ip_kind: IpAddrKind) {}

注意，枚举的变体位于其标识符的命名空间之下，我们使用双冒号将二者隔开。这样做很有用，因为现在 IpAddrKind::V4 和 IpAddrKind::V6 这两个值都属于同一个类型：IpAddrKind。于是，我们就可以定义一个接收任意 IpAddrKind 的函数，例如：

enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;

    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}

fn route(ip_kind: IpAddrKind) {}

并且可以使用任意一个变体来调用这个函数：

enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;

    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}

fn route(ip_kind: IpAddrKind) {}

使用枚举还有更多好处。进一步思考我们的 IP 地址类型，目前我们还无法存储实际的 IP 地址数据，只知道它属于哪一类。考虑到你刚刚在第 5 章学习了结构体，你可能会想用结构体来解决这个问题，如示例 6-1 所示。

这里我们定义了一个结构体 IpAddr，它有两个字段：一个是类型为 IpAddrKind（即我们之前定义的枚举）的 kind 字段，另一个是类型为 String 的 address 字段。我们创建了这个结构体的两个实例。第一个是 home，它的 kind 值为 IpAddrKind::V4，关联的地址数据为 127.0.0.1。第二个实例是 loopback，它的 kind 值是 IpAddrKind 的另一个变体 V6，关联的地址为 ::1。我们使用结构体将 kind 和 address 的值捆绑在一起，这样变体就与值关联起来了。

不过，仅用枚举来表达同样的概念会更加简洁：我们可以直接把数据放进每个枚举变体中，而不必把枚举放在结构体里。IpAddr 枚举的这个新定义表明，V4 和 V6 变体都会关联 String 值：

fn main() {
    enum IpAddr {
        V4(String),
        V6(String),
    }

    let home = IpAddr::V4(String::from("127.0.0.1"));

    let loopback = IpAddr::V6(String::from("::1"));
}

我们直接将数据附加到枚举的每个变体上，因此不再需要额外的结构体。在这里也更容易看出枚举工作方式的另一个细节：我们定义的每个枚举变体的名字，也会成为一个用来构造该枚举实例的函数。也就是说，IpAddr::V4() 是一个函数调用，它接收一个 String 实参，并返回一个 IpAddr 类型的实例。定义了枚举之后，我们就自动获得了这些构造函数。

使用枚举而不是结构体还有另一个好处：每个变体可以拥有不同类型和数量的关联数据。第四版 IP 地址总是由四个数字部分组成，每个部分的值都在 0 到 255 之间。如果我们想把 V4 地址存储为四个 u8 值，同时仍将 V6 地址表示为一个 String 值，用结构体就做不到了。而枚举可以轻松应对这种情况：

fn main() {
    enum IpAddr {
        V4(u8, u8, u8, u8),
        V6(String),
    }

    let home = IpAddr::V4(127, 0, 0, 1);

    let loopback = IpAddr::V6(String::from("::1"));
}

我们已经展示了几种不同的方式来定义存储第四版和第六版 IP 地址的数据结构。然而事实证明，存储 IP 地址并编码其类别的需求实在太常见了，以至于标准库已经提供了一个可供我们使用的定义！我们来看看标准库是如何定义 IpAddr 的。它拥有与我们定义和使用的完全相同的枚举和变体，但它以两个不同结构体的形式将地址数据嵌入变体中，而这两个结构体针对各自的变体有着不同的定义：

#![allow(unused)]
fn main() {
struct Ipv4Addr {
    // --snip--
}

struct Ipv6Addr {
    // --snip--
}

enum IpAddr {
    V4(Ipv4Addr),
    V6(Ipv6Addr),
}
}

这段代码说明，你可以把任何类型的数据放进枚举变体中，例如字符串、数字类型或结构体，甚至还可以包含另一个枚举！另外，标准库中的类型通常并不比你自己可能想出来的复杂多少。

注意，尽管标准库中包含了 IpAddr 的定义，我们仍然可以创建并使用自己的定义而不会产生冲突，因为我们并没有将标准库中的定义引入作用域。我们会在第 7 章进一步讨论如何将类型引入作用域。

我们来看示例 6-2 中另一个枚举的例子：这个枚举的变体中嵌入了多种多样的类型。

这个枚举有四个不同类型的变体：

  • Quit：没有关联任何数据
  • Move：像结构体一样拥有命名字段
  • Write：包含一个 String
  • ChangeColor：包含三个 i32 值

定义一个像示例 6-2 那样带有多种变体的枚举，与定义多个不同种类的结构体类似，区别在于枚举不使用 struct 关键字，而且所有变体都被组合在 Message 类型之下。下面这些结构体可以存放与前面的枚举变体相同的数据：

struct QuitMessage; // unit struct
struct MoveMessage {
    x: i32,
    y: i32,
}
struct WriteMessage(String); // tuple struct
struct ChangeColorMessage(i32, i32, i32); // tuple struct

fn main() {}

但如果我们使用这些各自拥有独立类型的不同结构体，就无法像使用示例 6-2 中定义的 Message 枚举（它是单一类型）那样，轻松地定义一个能接收其中任意一种消息的函数。

枚举和结构体还有一个相似之处：就像可以使用 impl 在结构体上定义方法一样，我们也可以在枚举上定义方法。下面是一个可以定义在 Message 枚举上的名为 call 的方法：

fn main() {
    enum Message {
        Quit,
        Move { x: i32, y: i32 },
        Write(String),
        ChangeColor(i32, i32, i32),
    }

    impl Message {
        fn call(&self) {
            // method body would be defined here
        }
    }

    let m = Message::Write(String::from("hello"));
    m.call();
}

方法体会使用 self 来获取调用该方法的值。在这个例子中，我们创建了一个值为 Message::Write(String::from("hello")) 的变量 m，当 m.call() 运行时，call 方法体中的 self 就是这个值。

我们再来看看标准库中另一个非常常见且有用的枚举：Option。

Option 枚举

本节将以 Option 为例进行研究，它是标准库定义的另一个枚举。Option 类型编码了一种非常常见的场景：一个值可能是某个值，也可能什么都没有。

例如，如果你请求一个非空列表中的第一项，就会得到一个值；如果你请求一个空列表中的第一项，就什么也得不到。用类型系统来表达这个概念，意味着编译器可以检查你是否处理了所有应该处理的情况；这一功能可以防止在其他编程语言中极其常见的 bug。

人们通常从包含了哪些功能的角度来看待编程语言的设计，但排除了哪些功能也同样重要。Rust 没有许多其他语言都有的空值功能。空值（null）是一个表示“此处没有值”的值。在有空值的语言中，变量总是处于两种状态之一：空值或非空值。

空值的发明者 Tony Hoare 在他 2009 年的演讲“空引用：价值十亿美元的错误”（Null References: The Billion Dollar Mistake）中这样说道：

我称之为我的十亿美元错误。当时，我正在为一门面向对象语言设计第一个全面的引用类型系统。我的目标是确保所有对引用的使用都绝对安全，并由编译器自动执行检查。但我没能抵挡住加入空引用的诱惑，仅仅因为它实在太容易实现了。这导致了数不清的错误、漏洞和系统崩溃，在过去四十年里可能造成了十亿美元的痛苦和损失。

空值的问题在于，如果你试图把空值当作非空值来使用，就会得到某种错误。由于空或非空这种属性无处不在，犯这类错误极其容易。

然而，空值想要表达的概念仍然是有用的：空值是一个因为某种原因而当前无效或缺失的值。

问题其实不在于这个概念，而在于具体的实现。因此，Rust 没有空值，但它确实有一个可以编码“值存在或缺失”这一概念的枚举。这个枚举就是 Option<T>，它由标准库定义如下：

#![allow(unused)]
fn main() {
enum Option<T> {
    None,
    Some(T),
}
}

Option<T> 枚举非常有用，以至于它被包含在了 prelude 中；你不需要显式地将它引入作用域。它的变体也包含在 prelude 中：你可以不加 Option:: 前缀，直接使用 Some 和 None。Option<T> 枚举仍然只是一个普通的枚举，Some(T) 和 None 仍然是 Option<T> 类型的变体。

<T> 语法是一个我们还没有讲到的 Rust 功能。它是一个泛型类型参数，我们会在第 10 章更详细地介绍泛型。目前，你只需要知道：<T> 意味着 Option 枚举的 Some 变体可以存放一个任意类型的数据，而每一个用来替代 T 的具体类型都会让整个 Option<T> 成为一个不同的类型。下面是一些使用 Option 值来存放数字类型和字符类型的例子：

fn main() {
    let some_number = Some(5);
    let some_char = Some('e');

    let absent_number: Option<i32> = None;
}

some_number 的类型是 Option<i32>。some_char 的类型是 Option<char>，这是另一个不同的类型。因为我们在 Some 变体中指定了一个值，所以 Rust 可以推断出这些类型。对于 absent_number，Rust 要求我们注解整个 Option 的类型：仅凭一个 None 值，编译器无法推断出对应的 Some 变体会存放什么类型。这里，我们告诉 Rust，我们希望 absent_number 的类型是 Option<i32>。

当我们有一个 Some 值时，我们知道存在一个值，并且这个值就存放在 Some 中。当我们有一个 None 值时，从某种意义上说，它与空值的含义相同：我们没有一个有效的值。那么，为什么 Option<T> 会比空值更好呢？

简而言之，因为 Option<T> 和 T（这里的 T 可以是任何类型）是不同的类型，所以编译器不会允许我们像使用一个肯定有效的值那样去使用 Option<T> 值。例如，下面这段代码无法编译，因为它试图将一个 i8 与一个 Option<i8> 相加：

fn main() {
    let x: i8 = 5;
    let y: Option<i8> = Some(5);

    let sum = x + y;
}

真够吓人的！实际上，这条错误信息的意思是 Rust 不知道该如何将 i8 与 Option<i8> 相加，因为它们是不同的类型。在 Rust 中，当我们拥有一个像 i8 这样类型的值时，编译器会确保我们总是拥有一个有效的值。我们可以放心地使用它，而无须在使用之前检查它是否为空值。只有当我们拥有一个 Option<i8>（或者我们正在处理的任何类型的值）时，才需要担心可能没有值的情况，而编译器会确保我们在使用该值之前处理了这种情况。

换句话说，在对 Option<T> 执行 T 的运算之前，你必须先将它转换为 T。通常，这有助于捕获空值最常见的问题之一：假设某个值不为空，而实际上它为空。

消除了错误地假设某个值非空的风险，能让你对自己的代码更有信心。为了拥有一个可能为空的值，你必须显式地选择启用，将这个值的类型设为 Option<T>。然后，在使用这个值时，你必须显式地处理值为空的情况。只要一个值的类型不是 Option<T>，你就可以放心地认为该值不为空。这是 Rust 有意为之的设计决策，用来限制空值的泛滥，并提高 Rust 代码的安全性。

那么，当你有一个 Option<T> 类型的值时，如何从 Some 变体中取出 T 值来使用呢？Option<T> 枚举拥有大量在各种情况下都很有用的方法；你可以在它的文档中查看这些方法。熟悉 Option<T> 上的方法，会在你的 Rust 之旅中让你受益匪浅。

一般来说，为了使用 Option<T> 值，你需要编写处理每个变体的代码。你希望有一些代码只在拥有 Some(T) 值时运行，并且这些代码可以使用其中的 T；你还希望另一些代码只在拥有 None 值时运行，而这些代码没有可用的 T 值。match 表达式就是这样一种控制流结构，与枚举一起使用时，它恰好能做到这一点：它会根据枚举的不同变体运行不同的代码，并且这些代码可以使用匹配到的值中的数据。
