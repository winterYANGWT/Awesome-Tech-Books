用 Result 处理可恢复错误

大多数错误并没有严重到需要让程序完全停止的地步。有时函数失败的原因是你可以很容易地理解并加以应对的。例如，如果你试图打开一个文件，而该操作因为文件不存在而失败，你可能会想创建这个文件，而不是终止进程。

回忆一下第 2 章“使用 Result 处理潜在的失败”部分，Result 枚举被定义为拥有 Ok 和 Err 两个变体，如下所示：

#![allow(unused)]
fn main() {
enum Result<T, E> {
    Ok(T),
    Err(E),
}
}

T 和 E 是泛型类型参数：我们会在第 10 章更详细地讨论泛型。现在你需要知道的是，T 代表成功时在 Ok 变体中返回的值的类型，而 E 代表失败时在 Err 变体中返回的错误的类型。因为 Result 带有这些泛型类型参数，所以在我们想返回的成功值和错误值可能各不相同的许多场景中，都可以使用 Result 类型以及定义在它上面的函数。

我们来调用一个返回 Result 值的函数，因为这个函数可能会失败。在示例 9-3 中，我们尝试打开一个文件。

File::open 的返回类型是 Result<T, E>。泛型参数 T 已由 File::open 的实现填入了成功值的类型 std::fs::File，它是一个文件句柄。错误值所用的 E 的类型是 std::io::Error。这个返回类型意味着对 File::open 的调用可能成功，并返回一个可供我们读取或写入的文件句柄；这个函数调用也可能失败，例如文件可能不存在，或者我们可能没有访问该文件的权限。File::open 函数需要有一种方式来告诉我们它是成功还是失败，同时给出文件句柄或错误信息。这正是 Result 枚举所传达的信息。

当 File::open 成功时，变量 greeting_file_result 中的值将是一个包含文件句柄的 Ok 实例。当它失败时，greeting_file_result 中的值将是一个 Err 实例，其中包含关于所发生错误种类的更多信息。

我们需要在示例 9-3 的代码基础上添加一些内容，以便根据 File::open 返回的值采取不同的操作。示例 9-4 展示了使用一个基础工具来处理 Result 的方法，这个工具就是我们在第 6 章讨论过的 match 表达式。

注意，与 Option 枚举一样，Result 枚举及其变体已经由 prelude 引入了作用域，所以我们不需要在 match 分支中的 Ok 和 Err 变体前面写上 Result::。

当结果是 Ok 时，这段代码会从 Ok 变体中取出内部的 file 值并返回，然后我们把这个文件句柄值赋给变量 greeting_file。在 match 之后，我们就可以使用这个文件句柄进行读取或写入了。

match 的另一个分支处理从 File::open 得到 Err 值的情况。在这个例子中，我们选择调用 panic! 宏。如果当前目录下没有名为 hello.txt 的文件，运行这段代码时，我们会看到来自 panic! 宏的如下输出：

匹配不同的错误

不管 File::open 因为什么原因失败，示例 9-4 中的代码都会 panic!。然而，我们希望针对不同的失败原因采取不同的操作。如果 File::open 是因为文件不存在而失败，我们想创建这个文件并返回新文件的句柄。如果 File::open 是因为其他任何原因失败（例如我们没有打开该文件的权限），我们仍然希望代码像示例 9-4 那样 panic!。为此，我们添加一个内层的 match 表达式，如示例 9-5 所示。

File::open 在 Err 变体中返回的值的类型是 io::Error，这是标准库提供的一个结构体。这个结构体有一个方法 kind，调用它可以得到一个 io::ErrorKind 值。io::ErrorKind 枚举由标准库提供，它的各个变体代表 io 操作可能产生的不同种类的错误。我们要用的变体是 ErrorKind::NotFound，它表示我们试图打开的文件还不存在。所以，我们对 greeting_file_result 进行匹配，同时还对 error.kind() 进行了一次内层匹配。

在内层匹配中，我们要检查的条件是 error.kind() 返回的值是否为 ErrorKind 枚举的 NotFound 变体。如果是，我们就尝试用 File::create 创建该文件。然而，由于 File::create 也可能失败，我们需要在内层 match 表达式中添加第二个分支。当文件无法创建时，会打印一条不同的错误信息。外层 match 的第二个分支保持不变，因此除了文件缺失错误之外，程序遇到任何错误都会 panic。

将 match 与 Result<T, E> 搭配使用的替代方案

match 真是太多了！match 表达式非常有用，但也非常原始。在第 13 章中，你将学习闭包，Result<T, E> 上定义的许多方法都要配合闭包使用。在代码中处理 Result<T, E> 值时，这些方法可能比使用 match 更加简洁。

例如，下面是实现示例 9-5 中相同逻辑的另一种写法，这次使用了闭包和 unwrap_or_else 方法：

use std::fs::File;
use std::io::ErrorKind;

fn main() {
    let greeting_file = File::open("hello.txt").unwrap_or_else(|error| {
        if error.kind() == ErrorKind::NotFound {
            File::create("hello.txt").unwrap_or_else(|error| {
                panic!("Problem creating the file: {error:?}");
            })
        } else {
            panic!("Problem opening the file: {error:?}");
        }
    });
}

虽然这段代码的行为与示例 9-5 相同，但它不包含任何 match 表达式，读起来也更清晰。读完第 13 章后，再回来看看这个例子，并在标准库文档中查阅 unwrap_or_else 方法。在处理错误时，还有许多这类方法可以简化庞大的嵌套 match 表达式。

传播错误

当函数的实现中调用了某个可能失败的操作时，你可以不在函数内部处理这个错误，而是把错误返回给调用者，让它来决定如何处理。这被称为传播（propagating）错误，它把更多的控制权交给了调用代码，因为比起你的代码所处的上下文，调用代码那里可能有更多的信息或逻辑来决定应该如何处理这个错误。

例如，示例 9-6 展示了一个从文件中读取用户名的函数。如果文件不存在或无法读取，这个函数会把这些错误返回给调用它的代码。

这个函数可以写得短得多，但为了探索错误处理，我们先手动完成大部分工作；最后我们再展示更简短的写法。我们先来看函数的返回类型：Result<String, io::Error>。这意味着该函数返回一个 Result<T, E> 类型的值，其中泛型参数 T 被填入了具体类型 String，泛型类型 E 被填入了具体类型 io::Error。

如果这个函数顺利成功，调用它的代码会收到一个存放着 String 的 Ok 值，这个 String 就是该函数从文件中读到的 username。如果这个函数遇到了任何问题，调用代码会收到一个 Err 值，其中存放着一个 io::Error 实例，包含了关于问题所在的更多信息。我们选择 io::Error 作为这个函数的返回类型，是因为它恰好是函数体中调用的两个可能失败的操作（File::open 函数和 read_to_string 方法）所返回的错误值的类型。

函数体首先调用 File::open 函数。然后，我们用一个类似于示例 9-4 中的 match 来处理 Result 值。如果 File::open 成功，模式变量 file 中的文件句柄就会成为可变变量 username_file 的值，函数继续执行。在 Err 的情况下，我们不调用 panic!，而是使用 return 关键字从整个函数中提前返回，并把来自 File::open 的错误值（现在位于模式变量 e 中）作为这个函数的错误值传回给调用代码。

所以，如果 username_file 中有一个文件句柄，函数接下来会在变量 username 中创建一个新的 String，并对 username_file 中的文件句柄调用 read_to_string 方法，把文件内容读入 username。read_to_string 方法也返回一个 Result，因为即使 File::open 成功了，它也可能失败。所以我们需要另一个 match 来处理这个 Result：如果 read_to_string 成功，我们的函数就成功了，于是我们把文件中读到、现在位于 username 中的用户名包装在 Ok 中返回。如果 read_to_string 失败，我们就以与处理 File::open 返回值的那个 match 中相同的方式返回错误值。不过，我们不需要显式地写 return，因为这是函数中的最后一个表达式。

调用这段代码的代码将会处理得到的值：要么是包含用户名的 Ok 值，要么是包含 io::Error 的 Err 值。如何处理这些值由调用代码决定。例如，如果调用代码得到一个 Err 值，它可以调用 panic! 让程序崩溃，也可以使用一个默认用户名，或者从文件以外的其他地方查找用户名。我们并不掌握足够的信息来了解调用代码实际想做什么，所以我们把所有的成功或错误信息向上传播，让它来恰当地处理。

这种传播错误的模式在 Rust 中如此常见，以至于 Rust 提供了问号运算符 ? 来简化这一过程。

? 运算符快捷方式

示例 9-7 展示了 read_username_from_file 的另一种实现，它的功能与示例 9-6 相同，但使用了 ? 运算符。

放在 Result 值之后的 ?，其工作方式被定义为与示例 9-6 中我们为处理 Result 值而定义的 match 表达式几乎相同。如果 Result 的值是 Ok，Ok 中的值就会作为这个表达式的结果返回，程序继续执行。如果值是 Err，这个 Err 就会像使用了 return 关键字那样从整个函数中返回，从而把错误值传播给调用代码。

示例 9-6 中的 match 表达式与 ? 运算符所做的事情有一个区别：被 ? 运算符作用的错误值会经过 from 函数，该函数定义在标准库的 From trait 中，用于把值从一种类型转换为另一种类型。当 ? 运算符调用 from 函数时，收到的错误类型会被转换为当前函数返回类型中所定义的错误类型。当一个函数用同一种错误类型来代表它可能失败的所有方式时，即使其中的各个部分可能因为许多不同的原因而失败，这一特性也非常有用。

例如，我们可以修改示例 9-7 中的 read_username_from_file 函数，让它返回一个我们自己定义的、名为 OurError 的自定义错误类型。如果我们再定义 impl From<io::Error> for OurError，以便从 io::Error 构造出 OurError 的实例，那么 read_username_from_file 函数体中的 ? 运算符调用就会调用 from 并转换错误类型，而无需在函数中添加任何额外的代码。

在示例 9-7 的上下文中，File::open 调用末尾的 ? 会把 Ok 中的值返回给变量 username_file。如果发生错误，? 运算符会从整个函数中提前返回，并把 Err 值交给调用代码。read_to_string 调用末尾的 ? 也是同样的道理。

? 运算符消除了大量样板代码，让这个函数的实现更加简单。我们甚至可以在 ? 之后直接链式调用方法，从而进一步缩短这段代码，如示例 9-8 所示。

我们把在 username 中创建新 String 的操作移到了函数开头，这部分没有变化。我们没有创建变量 username_file，而是把对 read_to_string 的调用直接链接到 File::open("hello.txt")? 的结果上。read_to_string 调用的末尾仍然有一个 ?，并且当 File::open 和 read_to_string 都成功而没有返回错误时，我们仍然返回一个包含 username 的 Ok 值。其功能依然与示例 9-6 和示例 9-7 相同，这只是另一种更符合人体工程学的写法。

示例 9-9 展示了使用 fs::read_to_string 让代码变得更短的方法。

把文件读入字符串是相当常见的操作，所以标准库提供了方便的 fs::read_to_string 函数，它会打开文件、新建一个 String、读取文件内容、把内容放入这个 String 并将其返回。当然，使用 fs::read_to_string 就没有机会讲解所有的错误处理了，所以我们先用了较长的写法。

在哪里使用 ? 运算符

? 运算符只能用在返回类型与 ? 所作用的值相兼容的函数中。这是因为 ? 运算符被定义为从函数中提前返回一个值，其方式与我们在示例 9-6 中定义的 match 表达式相同。在示例 9-6 中，match 作用于一个 Result 值，提前返回的分支返回了一个 Err(e) 值。函数的返回类型必须是 Result，才能与这个 return 相兼容。

在示例 9-10 中，我们来看看，如果在一个返回类型与 ? 所作用的值的类型不兼容的 main 函数中使用 ? 运算符，会得到什么错误。

这段代码打开一个文件，这可能会失败。? 运算符跟在 File::open 返回的 Result 值之后，但这个 main 函数的返回类型是 () 而不是 Result。编译这段代码时，我们会得到如下错误信息：

$ cargo run

error[E0277]: the `?` operator can only be used in a function that returns `Result` or `Option` (or another type that implements `FromResidual`)
 --> src/main.rs:4:48
  |
3 | fn main() {
  | --------- this function should return `Result` or `Option` to accept `?`
4 |     let greeting_file = File::open("hello.txt")?;
  |                                                ^ cannot use the `?` operator in a function that returns `()`
  |

  |
3 ~ fn main() -> Result<(), Box<dyn std::error::Error>> {
4 |     let greeting_file = File::open("hello.txt")?;
5 +     Ok(())
  |

For more information about this error, try `rustc --explain E0277`.
error: could not compile `error-handling` (bin "error-handling") due to 1 previous error

这个错误指出，我们只能在返回 Result、Option 或其他实现了 FromResidual 的类型的函数中使用 ? 运算符。

要修复这个错误，你有两种选择。一种是修改函数的返回类型，使其与你使用 ? 运算符的值相兼容，前提是没有什么限制阻止你这样做。另一种是使用 match 或 Result<T, E> 的某个方法，以合适的方式处理 Result<T, E>。

错误信息还提到，? 也可以用于 Option<T> 值。与在 Result 上使用 ? 一样，你只能在返回 Option 的函数中对 Option 使用 ?。在 Option<T> 上调用 ? 运算符时，其行为与在 Result<T, E> 上调用时类似：如果值是 None，这个 None 会在此处从函数中提前返回；如果值是 Some，Some 中的值就是这个表达式的结果值，函数继续执行。示例 9-11 中的函数会找出给定文本中第一行的最后一个字符。

这个函数返回 Option<char>，因为那里可能有一个字符，也可能没有。这段代码接收字符串切片参数 text，并对它调用 lines 方法，该方法返回一个遍历字符串中各行的迭代器。因为这个函数想检查第一行，所以它对迭代器调用 next 来获取迭代器中的第一个值。如果 text 是空字符串，这次 next 调用将返回 None，此时我们用 ? 来停止并从 last_char_of_first_line 返回 None。如果 text 不是空字符串，next 将返回一个 Some 值，其中包含 text 第一行的字符串切片。

? 会提取出这个字符串切片，然后我们可以对它调用 chars 来获取其字符的迭代器。我们关心的是第一行的最后一个字符，所以调用 last 来返回迭代器中的最后一项。这是一个 Option，因为第一行可能是空字符串，例如 text 以空行开头、但其他行有字符，比如 "\nhi"。不过，如果第一行确实有最后一个字符，它就会被放在 Some 变体中返回。中间的 ? 运算符为我们提供了一种表达这一逻辑的简洁方式，让我们只用一行就能实现这个函数。如果不能在 Option 上使用 ? 运算符，我们就不得不用更多的方法调用或一个 match 表达式来实现这一逻辑。

注意，你可以在返回 Result 的函数中对 Result 使用 ? 运算符，也可以在返回 Option 的函数中对 Option 使用 ? 运算符，但不能混用。? 运算符不会自动把 Result 转换为 Option，反之亦然；在这些情况下，你可以使用 Result 上的 ok 方法或 Option 上的 ok_or 方法等来显式地进行转换。

到目前为止，我们使用的所有 main 函数都返回 ()。main 函数比较特殊，因为它是可执行程序的入口点和出口点，为了让程序按预期运行，它的返回类型受到一些限制。

幸运的是，main 也可以返回 Result<(), E>。示例 9-12 使用了示例 9-10 中的代码，但我们把 main 的返回类型改成了 Result<(), Box<dyn Error>>，并在末尾添加了返回值 Ok(())。现在这段代码可以编译了。

Box<dyn Error> 类型是一个 trait 对象，我们将在第 18 章“使用 trait 对象抽象共同行为”部分讨论它。目前，你可以把 Box<dyn Error> 理解为“任何类型的错误”。在错误类型为 Box<dyn Error> 的 main 函数中对 Result 值使用 ? 是允许的，因为它允许任何 Err 值被提前返回。尽管这个 main 函数的函数体只会返回 std::io::Error 类型的错误，但通过指定 Box<dyn Error>，即使以后在 main 的函数体中添加了更多返回其他错误的代码，这个签名也依然正确。

当 main 函数返回 Result<(), E> 时，如果 main 返回 Ok(())，可执行程序会以 0 值退出；如果 main 返回 Err 值，则会以非零值退出。用 C 编写的可执行程序在退出时会返回整数：成功退出的程序返回整数 0，出错的程序返回某个非 0 的整数。Rust 也从可执行程序返回整数，以兼容这一约定。

main 函数可以返回任何实现了 std::process::Termination trait 的类型，该 trait 包含一个返回 ExitCode 的函数 report。关于如何为你自己的类型实现 Termination trait，请查阅标准库文档以了解更多信息。
