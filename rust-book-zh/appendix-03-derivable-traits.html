Rust 程序设计语言

附录 C：可派生的 trait

在本书的多个地方，我们都讨论过 derive 属性，它可以应用于结构体或枚举的定义。derive 属性会生成代码，在你用 derive 语法标注的类型上，以该 trait 自带的默认实现来实现这个 trait。

在本附录中，我们提供了一份参考，列出标准库中所有可以与 derive 一起使用的 trait。每一节都涵盖以下内容：

  • 派生该 trait 后可以使用哪些运算符和方法
  • derive 所提供的 trait 实现做了什么
  • 实现该 trait 对类型意味着什么
  • 在什么条件下允许或不允许实现该 trait
  • 需要该 trait 的操作示例

如果你想要的行为与 derive 属性提供的不同，可以查阅各个 trait 的标准库文档，了解如何手动实现它们的详细信息。

这里列出的 trait 是标准库中仅有的、可以用 derive 在你的类型上实现的 trait。标准库中定义的其他 trait 没有合理的默认行为，因此需要由你根据想要实现的目标，以合理的方式自行实现它们。

一个不能派生的 trait 的例子是 Display，它负责为最终用户进行格式化。你始终应该考虑以什么样的方式向最终用户展示一个类型才合适：类型的哪些部分应该允许最终用户看到？哪些部分是他们关心的？什么样的数据格式对他们来说最有用？Rust 编译器并不具备这些判断力，所以无法为你提供合适的默认行为。

本附录给出的可派生 trait 列表并不完整：库可以为它们自己的 trait 实现 derive，因此可以使用 derive 的 trait 列表实际上是完全开放的。实现 derive 需要用到过程宏，这部分内容在第 20 章“自定义 derive 宏”部分中介绍。

用于程序员输出的 Debug

Debug trait 让格式化字符串可以进行调试格式化，你可以通过在 {} 占位符中加上 :? 来指定使用调试格式。

Debug trait 允许你出于调试目的打印某个类型的实例，这样你和其他使用该类型的程序员就可以在程序执行的某个特定时刻检查一个实例。

例如，使用 assert_eq! 宏时就需要 Debug trait。如果相等断言失败，这个宏会打印作为参数传入的实例的值，以便程序员看清这两个实例为什么不相等。

用于相等比较的 PartialEq 和 Eq

PartialEq trait 允许你比较某个类型的实例是否相等，并且让你可以使用 == 和 != 运算符。

派生 PartialEq 会实现 eq 方法。当在结构体上派生 PartialEq 时，只有所有字段都相等，两个实例才相等；只要有任何字段不相等，这两个实例就不相等。当在枚举上派生时，每个变体都与自身相等，而与其他变体不相等。

例如，使用 assert_eq! 宏时就需要 PartialEq trait，因为这个宏需要能够比较某个类型的两个实例是否相等。

Eq trait 没有任何方法。它的作用是表明：对于被标注类型的每一个值，该值都等于它自身。Eq trait 只能应用于同时实现了 PartialEq 的类型，不过并不是所有实现了 PartialEq 的类型都能实现 Eq。浮点数类型就是一个例子：浮点数的实现规定，两个非数字（NaN）值的实例彼此不相等。

需要 Eq 的一个例子是 HashMap<K, V> 中的键，这样 HashMap<K, V> 才能判断两个键是否相同。

用于排序比较的 PartialOrd 和 Ord

PartialOrd trait 允许你为了排序而比较某个类型的实例。实现了 PartialOrd 的类型可以使用 <、>、<= 和 >= 运算符。PartialOrd trait 只能应用于同时实现了 PartialEq 的类型。

派生 PartialOrd 会实现 partial_cmp 方法，它返回一个 Option<Ordering>，当给定的值无法确定顺序时，结果为 None。浮点数值 NaN 就是一个无法确定顺序的值的例子，尽管该类型的大多数值都可以进行比较。用任何浮点数和浮点数值 NaN 调用 partial_cmp，都会返回 None。

当在结构体上派生时，PartialOrd 会按照字段在结构体定义中出现的顺序，依次比较每个字段的值，以此来比较两个实例。当在枚举上派生时，在枚举定义中先声明的变体被认为小于后列出的变体。

例如，rand crate 中的 gen_range 方法就需要 PartialOrd trait，该方法会在由范围表达式指定的范围内生成一个随机值。

Ord trait 让你知道，对于被标注类型的任意两个值，总是存在一个有效的顺序。Ord trait 实现了 cmp 方法，它返回的是 Ordering 而不是 Option<Ordering>，因为总是可以得到一个有效的顺序。Ord trait 只能应用于同时实现了 PartialOrd 和 Eq 的类型（而 Eq 又要求实现 PartialEq）。当在结构体和枚举上派生时，cmp 的行为与 PartialOrd 中派生实现的 partial_cmp 的行为相同。

需要 Ord 的一个例子是将值存储在 BTreeSet<T> 中，这是一种根据值的排列顺序来存储数据的数据结构。

用于复制值的 Clone 和 Copy

Clone trait 允许你显式地创建一个值的深拷贝，这个复制过程可能会运行任意代码并复制堆上的数据。有关 Clone 的更多信息，请参阅第 4 章“变量与数据交互的方式：克隆”部分。

派生 Clone 会实现 clone 方法，当为整个类型实现该方法时，它会对类型的每个组成部分调用 clone。这意味着类型中的所有字段或值也都必须实现 Clone，才能派生 Clone。

需要 Clone 的一个例子是在切片上调用 to_vec 方法。切片并不拥有它所包含的类型实例，但 to_vec 返回的 vector 需要拥有其中的实例，因此 to_vec 会对每一项调用 clone。所以，存储在切片中的类型必须实现 Clone。

Copy trait 允许你只通过复制存储在栈上的位来复制一个值，而无需运行任意代码。有关 Copy 的更多信息，请参阅第 4 章“只在栈上的数据：Copy”部分。

Copy trait 没有定义任何方法，这是为了防止程序员重载这些方法，从而违背“不会运行任意代码”这一假设。这样一来，所有程序员都可以认为复制一个值会非常快。

你可以在任何其所有组成部分都实现了 Copy 的类型上派生 Copy。实现了 Copy 的类型也必须实现 Clone，因为实现了 Copy 的类型有一个平凡的 Clone 实现，它执行的任务与 Copy 相同。

很少有地方必须要求 Copy trait；实现了 Copy 的类型可以享受一些优化，也就是说你不必调用 clone，这会让代码更简洁。

凡是 Copy 能做到的事情，你也都可以用 Clone 来完成，只不过代码可能会更慢，或者需要在某些地方调用 clone。

用于将值映射为固定大小的值的 Hash

Hash trait 允许你获取一个任意大小的类型的实例，并使用哈希函数将该实例映射为一个固定大小的值。派生 Hash 会实现 hash 方法。派生出的 hash 方法实现会把对类型的每个组成部分调用 hash 的结果组合起来，这意味着所有字段或值也都必须实现 Hash，才能派生 Hash。

需要 Hash 的一个例子是在 HashMap<K, V> 中存储键，以便高效地存储数据。

用于默认值的 Default

Default trait 允许你为一个类型创建默认值。派生 Default 会实现 default 函数。派生出的 default 函数实现会对类型的每个组成部分调用 default 函数，这意味着类型中的所有字段或值也都必须实现 Default，才能派生 Default。

Default::default 函数通常与第 5 章“使用结构体更新语法创建实例”部分中讨论过的结构体更新语法结合使用。你可以自定义结构体的少数几个字段，然后使用 ..Default::default() 为其余字段设置并使用默认值。

例如，当你在 Option<T> 实例上使用 unwrap_or_default 方法时，就需要 Default trait。如果 Option<T> 是 None，unwrap_or_default 方法将返回 Option<T> 中所存储的类型 T 的 Default::default 结果。
