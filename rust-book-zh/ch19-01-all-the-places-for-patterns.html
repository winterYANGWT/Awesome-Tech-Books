Rust 程序设计语言

所有可以使用模式的位置

模式在 Rust 中的许多地方都会出现，你其实已经在不知不觉中大量使用它们了！本节将讨论所有可以使用模式的位置。

match 分支

正如第 6 章所讨论的，我们在 match 表达式的分支中使用模式。从形式上看，match 表达式由以下部分组成：关键字 match、一个要匹配的值，以及一个或多个分支；每个分支由一个模式和一个表达式组成，当值与该分支的模式匹配时就运行这个表达式，如下所示：

match VALUE {
    PATTERN => EXPRESSION,
    PATTERN => EXPRESSION,
    PATTERN => EXPRESSION,
}

例如，下面是示例 6-5 中的 match 表达式，它对变量 x 中的 Option<i32> 值进行匹配：

match x {
    None => None,
    Some(i) => Some(i + 1),
}

这个 match 表达式中的模式，就是每个箭头左边的 None 和 Some(i)。

match 表达式的一个要求是必须是穷尽的（exhaustive），也就是说，必须考虑到 match 表达式中的值的所有可能情况。确保覆盖了所有可能情况的一种方法是在最后一个分支中使用一个通配模式：例如，一个能匹配任何值的变量名永远不会匹配失败，因此可以覆盖所有剩余的情况。

特殊的模式 _ 可以匹配任何东西，但它永远不会绑定到变量，所以常常用在最后一个匹配分支中。例如，当你想忽略任何未指定的值时，_ 模式就很有用。我们会在本章后面的“在模式中忽略值”部分更详细地介绍 _ 模式。

let 语句

在本章之前，我们只明确讨论过在 match 和 if let 中使用模式，但实际上我们在其他地方也用过模式，包括在 let 语句中。例如，考虑下面这个使用 let 的简单变量赋值：

#![allow(unused)]
fn main() {
let x = 5;
}

每次你像这样使用 let 语句时，其实都在使用模式，尽管你可能没有意识到！更正式地说，let 语句的形式如下：

let PATTERN = EXPRESSION;

在像 let x = 5; 这样在 PATTERN 位置上放一个变量名的语句中，变量名只是一种特别简单的模式形式。Rust 会将表达式与模式进行比较，并对它找到的所有名称进行赋值。所以，在 let x = 5; 这个例子中，x 是一个模式，它的意思是“把这里匹配到的东西绑定到变量 x”。因为名称 x 就是整个模式，所以这个模式实际上的意思是“无论值是什么，都把它整个绑定到变量 x”。

为了更清楚地看到 let 的模式匹配特性，请看示例 19-1，它在 let 中使用模式来解构一个元组。

这里，我们将一个元组与一个模式进行匹配。Rust 将值 (1, 2, 3) 与模式 (x, y, z) 进行比较，发现该值与模式匹配——也就是说，它发现两者的元素数量相同——于是 Rust 把 1 绑定到 x，把 2 绑定到 y，把 3 绑定到 z。你可以把这个元组模式看作在其中嵌套了三个独立的变量模式。

如果模式中的元素数量与元组中的元素数量不一致，那么整体类型就不会匹配，我们会得到一个编译器错误。例如，示例 19-2 展示了尝试把一个有三个元素的元组解构到两个变量中，这是行不通的。

尝试编译这段代码会产生如下类型错误：

error[E0308]: mismatched types
 --> src/main.rs:2:9
  |
2 |     let (x, y) = (1, 2, 3);
  |         ^^^^^^   --------- this expression has type `({integer}, {integer}, {integer})`
  |         |
  |         expected a tuple with 3 elements, found one with 2 elements
  |

要修复这个错误，我们可以使用 _ 或 .. 来忽略元组中的一个或多个值，你会在“在模式中忽略值”部分看到具体做法。如果问题在于模式中的变量太多，那么解决办法就是移除一些变量，让变量的数量等于元组中元素的数量，从而使类型匹配。

条件 if let 表达式

在第 6 章中，我们讨论了如何使用 if let 表达式，它主要是一种更简短的写法，相当于只匹配一种情况的 match。if let 还可以选择性地带有一个对应的 else，其中包含在 if let 中的模式不匹配时要运行的代码。

示例 19-3 展示了也可以混合使用 if let、else if 和 else if let 表达式。与 match 表达式相比，这样做能给我们带来更大的灵活性，因为在 match 表达式中只能用一个值去和各个模式进行比较。此外，Rust 并不要求一系列 if let、else if 和 else if let 分支中的条件彼此相关。

示例 19-3 中的代码会根据对几个条件的一系列检查，来决定把背景设置成什么颜色。在这个例子中，我们创建了一些带有硬编码值的变量，而真实的程序可能会从用户输入中获取这些值。

如果用户指定了最喜欢的颜色，就用该颜色作为背景色。如果没有指定最喜欢的颜色，并且今天是星期二，背景色就是绿色。否则，如果用户以字符串形式指定了自己的年龄，并且我们能够成功地将其解析为数字，那么颜色就会根据该数字的值，要么是紫色，要么是橙色。如果以上条件都不满足，背景色就是蓝色。

这种条件结构让我们能够支持复杂的需求。根据这里的硬编码值，这个例子会打印 Using purple as the background color。

可以看到，if let 也可以像 match 分支那样引入新的变量来遮蔽已有的变量：if let Ok(age) = age 这一行引入了一个新的 age 变量，它包含 Ok 变体中的值，遮蔽了原有的 age 变量。这意味着我们需要把 if age > 30 这个条件放在该代码块内部：不能把这两个条件合并成 if let Ok(age) = age && age > 30。我们想要与 30 进行比较的那个新的 age，要等到以大括号开始的新作用域时才有效。

使用 if let 表达式的缺点在于，编译器不会检查穷尽性，而对于 match 表达式则会检查。如果我们省略了最后的 else 块，从而遗漏了对某些情况的处理，编译器也不会提醒我们这里可能存在逻辑 bug。
