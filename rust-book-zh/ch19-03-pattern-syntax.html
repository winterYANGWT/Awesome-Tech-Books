Rust 程序设计语言

模式语法

在本节中，我们会汇总所有在模式中有效的语法，并讨论为什么以及在什么时候你可能会想要使用它们。

匹配字面量

正如你在第 6 章中看到的，可以直接将模式与字面量进行匹配。下面的代码给出了一些例子：

fn main() {
    let x = 1;

    match x {
        1 => println!("one"),
        2 => println!("two"),
        3 => println!("three"),
        _ => println!("anything"),
    }
}

这段代码会打印 one，因为 x 中的值是 1。当你希望代码在得到某个特定的具体值时执行某个操作，这种语法就很有用。

匹配命名变量

命名变量是可以匹配任何值的不可反驳模式，我们在本书中已经多次使用过它们。不过，在 match、if let 或 while let 表达式中使用命名变量时，会有一个复杂之处。因为这几种表达式都会开启一个新的作用域，所以在这些表达式内部作为模式的一部分声明的变量，会遮蔽这些结构之外的同名变量，所有变量都是如此。在示例 19-11 中，我们声明了一个值为 Some(5) 的变量 x 和一个值为 10 的变量 y。然后我们对值 x 创建了一个 match 表达式。看一看各个匹配分支中的模式以及最后的 println!，在运行这段代码或继续往下读之前，试着推断一下这段代码会打印什么。

让我们逐步看看 match 表达式运行时会发生什么。第一个匹配分支中的模式与 x 所定义的值不匹配，所以代码继续执行。

第二个匹配分支中的模式引入了一个名为 y 的新变量，它会匹配 Some 值中的任何值。因为我们处在 match 表达式内部的新作用域中，所以这是一个新的 y 变量，而不是我们在开头声明的那个值为 10 的 y。这个新的 y 绑定会匹配 Some 中的任何值，而 x 中正是这样的值。因此，这个新的 y 会绑定到 x 中 Some 的内部值。这个值是 5，于是该分支的表达式被执行，打印出 Matched, y = 5。

如果 x 是 None 值而不是 Some(5)，那么前两个分支中的模式都不会匹配，于是该值会与下划线匹配。我们没有在下划线分支的模式中引入 x 变量，所以表达式中的 x 仍然是外部那个没有被遮蔽的 x。在这种假设的情况下，match 会打印 Default case, x = None。

当 match 表达式执行完毕时，它的作用域就结束了，内部 y 的作用域也随之结束。最后的 println! 会输出 at the end: x = Some(5), y = 10。

如果要创建一个比较外部 x 和 y 的值的 match 表达式，而不是引入一个遮蔽已有 y 变量的新变量，我们就需要改用匹配守卫条件。我们会在后面的“使用匹配守卫添加条件”部分讨论匹配守卫。

匹配多个模式

在 match 表达式中，可以使用 | 语法来匹配多个模式，它是模式的或（or）运算符。例如，在下面的代码中，我们将 x 的值与各个匹配分支进行匹配，其中第一个分支有一个或选项，意思是只要 x 的值与该分支中的任意一个值匹配，就会运行该分支的代码：

fn main() {
    let x = 1;

    match x {
        1 | 2 => println!("one or two"),
        3 => println!("three"),
        _ => println!("anything"),
    }
}

这段代码会打印 one or two。

使用 ..= 匹配值的范围

..= 语法让我们可以匹配一个闭区间范围内的值。在下面的代码中，当模式匹配给定范围内的任意值时，该分支就会执行：

fn main() {
    let x = 5;

    match x {
        1..=5 => println!("one through five"),
        _ => println!("something else"),
    }
}

如果 x 是 1、2、3、4 或 5，第一个分支就会匹配。对于多个匹配值来说，这种语法比用 | 运算符表达同样的意思更方便；如果使用 |，我们就必须写出 1 | 2 | 3 | 4 | 5。指定一个范围要简短得多，尤其是当我们想要匹配比如 1 到 1,000 之间的任意数字时！

编译器会在编译时检查范围是否为空，而由于 Rust 只能判断 char 和数值类型的范围是否为空，所以范围只允许用于数值或 char 值。

下面是一个使用 char 值范围的例子：

fn main() {
    let x = 'c';

    match x {
        'a'..='j' => println!("early ASCII letter"),
        'k'..='z' => println!("late ASCII letter"),
        _ => println!("something else"),
    }
}

Rust 能够判断出 'c' 位于第一个模式的范围之内，并打印 early ASCII letter。

嵌套的结构体和枚举

结构体和元组

我们可以用更复杂的方式来混合、匹配和嵌套解构模式。下面的例子展示了一个复杂的解构：我们在一个元组中嵌套了结构体和元组，并把所有的基本类型值都解构出来：

fn main() {
    struct Point {
        x: i32,
        y: i32,
    }

    let ((feet, inches), Point { x, y }) = ((3, 10), Point { x: 3, y: -10 });
}

这段代码让我们可以把复杂的类型拆分成各个组成部分，从而分别使用我们感兴趣的值。

使用模式进行解构是一种方便的方式，可以让我们分别使用值的各个部分，比如结构体中每个字段的值。

在模式中忽略值

你已经看到，有时在模式中忽略某些值是很有用的，比如在 match 的最后一个分支中，用来实现一个通配，它实际上什么都不做，但确实涵盖了所有剩余的可能值。有几种方式可以在模式中忽略整个值或值的一部分：使用 _ 模式（你已经见过了）、在另一个模式中使用 _ 模式、使用以下划线开头的名称，或者使用 .. 来忽略值的剩余部分。让我们来探讨如何以及为什么使用这些模式。

使用 _ 忽略整个值

我们已经把下划线用作通配模式，它会匹配任何值，但不会绑定到该值。这在 match 表达式的最后一个分支中特别有用，不过我们也可以在任何模式中使用它，包括函数参数，如示例 19-17 所示。

在大多数情况下，当你不再需要某个函数参数时，你会修改函数签名，使其不再包含这个未使用的参数。忽略函数参数在某些情况下尤其有用，例如，当你在实现一个 trait 时，需要某种特定的类型签名，但你的实现中的函数体并不需要其中某个参数。这样你就可以避免收到关于未使用函数参数的编译器警告，而如果你使用的是一个名称，就会收到这种警告。

使用匹配守卫添加条件

匹配守卫（match guard）是一个额外的 if 条件，它指定在 match 分支的模式之后，必须同时满足这个条件，该分支才会被选中。匹配守卫适合用来表达比单独使用模式更复杂的逻辑。不过请注意，它们只能用在 match 表达式中，而不能用在 if let 或 while let 表达式中。

这个条件可以使用模式中创建的变量。示例 19-26 展示了一个 match，其中第一个分支的模式是 Some(x)，并且还带有一个 if x % 2 == 0 的匹配守卫（如果数字是偶数，它就为 true）。

这个例子会打印 The number 4 is even。当 num 与第一个分支中的模式进行比较时，它是匹配的，因为 Some(4) 与 Some(x) 匹配。然后，匹配守卫会检查 x 除以 2 的余数是否等于 0，因为确实如此，所以第一个分支被选中。

如果 num 是 Some(5)，那么第一个分支中的匹配守卫就会为 false，因为 5 除以 2 的余数是 1，不等于 0。接着 Rust 会转到第二个分支，这个分支会匹配，因为它没有匹配守卫，所以能匹配任何 Some 变体。

在模式中无法表达 if x % 2 == 0 这个条件，而匹配守卫让我们能够表达这种逻辑。这种额外表达能力的缺点在于，当涉及匹配守卫表达式时，编译器不会尝试检查穷尽性。

使用 @ 绑定

at 运算符 @ 让我们可以在检测一个值是否与模式匹配的同时，创建一个存放该值的变量。在示例 19-29 中，我们想要检测 Message::Hello 的 id 字段是否在范围 3..=7 之内。我们还想把这个值绑定到变量 id 上，以便在与该分支关联的代码中使用它。

使用 @ 让我们可以在一个模式中既检测一个值，又把它保存到变量中。

总结

Rust 的模式在区分不同种类的数据时非常有用。在 match 表达式中使用模式时，Rust 会确保你的模式覆盖了所有可能的值，否则程序将无法编译。let 语句和函数参数中的模式让这些结构更加有用，使我们能够把值解构成更小的部分，并把这些部分赋值给变量。我们可以根据需要创建简单或复杂的模式。
