Rust 程序设计语言

面向对象语言的特征

对于一门语言必须具备哪些特性才算面向对象，编程社区并没有达成共识。Rust 受到许多编程范式的影响，其中也包括 OOP；例如，我们在第 13 章探讨过源自函数式编程的那些特性。可以说，OOP 语言都具有一些共同的特征，即对象、封装和继承。让我们来看看这些特征各自意味着什么，以及 Rust 是否支持它们。

对象包含数据和行为

由 Erich Gamma、Richard Helm、Ralph Johnson 和 John Vlissides 合著的《设计模式：可复用面向对象软件的基础》（Design Patterns: Elements of Reusable Object-Oriented Software，Addison-Wesley，1994）一书，俗称“四人帮”（The Gang of Four）之书，是一部面向对象设计模式的目录。书中这样定义 OOP：

面向对象的程序由对象组成。一个对象包含数据以及操作这些数据的过程。这些过程通常被称为方法或操作。

按照这个定义，Rust 是面向对象的：结构体和枚举包含数据，而 impl 块为结构体和枚举提供方法。虽然带有方法的结构体和枚举并不叫作对象，但按照“四人帮”对对象的定义，它们提供了同样的功能。

隐藏实现细节的封装

另一个通常与 OOP 联系在一起的概念是封装（encapsulation），意思是对象的实现细节对于使用该对象的代码来说是不可访问的。因此，与对象交互的唯一方式是通过它的公有 API；使用对象的代码不应该能够深入对象内部、直接修改数据或行为。这使得程序员能够修改和重构对象的内部实现，而无需修改使用该对象的代码。

我们在第 7 章讨论过如何控制封装：可以使用 pub 关键字来决定代码中的哪些模块、类型、函数和方法应当是公有的，而其他一切默认都是私有的。例如，我们可以定义一个结构体 AveragedCollection，它有一个字段存放由 i32 值组成的 vector。这个结构体还可以有一个字段存放 vector 中所有值的平均值，这样就不必在每次有人需要平均值时再临时计算。换句话说，AveragedCollection 会为我们缓存计算出的平均值。示例 18-1 给出了 AveragedCollection 结构体的定义。

这个结构体被标记为 pub，以便其他代码可以使用它，但结构体中的字段仍然是私有的。这在本例中很重要，因为我们希望确保每当有值被加入列表或从列表中移除时，平均值也会随之更新。为此，我们在结构体上实现了 add、remove 和 average 方法，如示例 18-2 所示。

公有方法 add、remove 和 average 是访问或修改 AveragedCollection 实例中数据的唯一途径。当使用 add 方法向 list 中添加一项，或使用 remove 方法移除一项时，这两个方法的实现都会调用私有的 update_average 方法，由它负责同时更新 average 字段。

我们让 list 和 average 字段保持私有，这样外部代码就无法直接向 list 字段添加或从中移除项；否则，当 list 发生变化时，average 字段可能会与之不同步。average 方法返回 average 字段中的值，让外部代码可以读取 average，但不能修改它。

由于我们封装了结构体 AveragedCollection 的实现细节，将来就可以轻松地修改其中的某些方面，比如数据结构。例如，我们可以让 list 字段使用 HashSet<i32> 而不是 Vec<i32>。只要 add、remove 和 average 这几个公有方法的签名保持不变，使用 AveragedCollection 的代码就无需修改。如果我们把 list 设为公有的，情况就不一定如此了：HashSet<i32> 和 Vec<i32> 添加和移除项的方法不同，因此如果外部代码直接修改 list，那么它很可能也得跟着修改。

如果封装是一门语言被视为面向对象的必要条件，那么 Rust 满足这个要求。可以选择对代码的不同部分使用或不使用 pub，这就实现了对实现细节的封装。

继承：作为类型系统与代码共享

继承（inheritance）是这样一种机制：一个对象可以从另一个对象的定义中继承元素，从而获得父对象的数据和行为，而无需你再次定义它们。

如果一门语言必须具有继承才算面向对象，那么 Rust 就不是这样的语言。在不使用宏的情况下，无法定义一个继承父结构体字段和方法实现的结构体。

不过，如果你习惯了把继承作为编程工具箱中的一件工具，那么在 Rust 中可以使用其他解决方案，具体取决于你最初想要使用继承的原因。

选择继承主要有两个原因。一是为了复用代码：你可以为一个类型实现特定的行为，而继承让你能够为另一个类型复用这份实现。在 Rust 代码中，你可以通过 trait 方法的默认实现，以一种有限的方式做到这一点。你在示例 10-14 中已经见过这种用法，当时我们为 Summary trait 的 summarize 方法添加了一个默认实现。任何实现了 Summary trait 的类型，无需编写任何额外代码，就可以使用 summarize 方法。这类似于父类有某个方法的实现，而继承它的子类也同样拥有该方法的实现。在实现 Summary trait 时，我们还可以覆盖 summarize 方法的默认实现，这类似于子类覆盖从父类继承来的方法实现。

使用继承的另一个原因与类型系统有关：让子类型能够用在父类型可以使用的地方。这也被称为多态（polymorphism），意思是如果多个对象具有某些共同的特征，那么就可以在运行时相互替换。

多态

对许多人来说，多态就是继承的同义词。但它实际上是一个更通用的概念，指的是能够处理多种类型数据的代码。就继承而言，这些类型通常是子类。

Rust 则使用泛型来对各种可能的类型进行抽象，并使用 trait bound 来约束这些类型必须提供什么。这有时被称为有界参数多态（bounded parametric polymorphism）。

Rust 不提供继承，从而选择了一组不同的权衡。继承常常面临共享过多代码的风险。子类不应总是共享父类的所有特征，但使用继承时却会如此。这会降低程序设计的灵活性。它还可能导致在子类上调用一些没有意义的方法，或者因为方法并不适用于子类而引发错误。此外，有些语言只允许单继承（single inheritance，即一个子类只能继承自一个类），这进一步限制了程序设计的灵活性。
