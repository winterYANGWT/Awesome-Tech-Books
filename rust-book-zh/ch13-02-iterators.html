使用迭代器处理一系列元素

迭代器模式允许你依次对一个序列中的各项执行某些任务。迭代器负责遍历每一项以及判断序列何时结束的逻辑。使用迭代器时，你不必自己重新实现这些逻辑。

在 Rust 中，迭代器是惰性的（lazy），这意味着在你调用消费迭代器的方法将其用尽之前，它不会产生任何效果。例如，示例 13-10 中的代码通过调用定义在 Vec<T> 上的 iter 方法，创建了一个遍历 vector v1 中各项的迭代器。这段代码本身并没有做任何有用的事情。

迭代器被存储在 v1_iter 变量中。一旦创建了迭代器，我们就可以用多种方式来使用它。在示例 3-5 中，我们使用 for 循环遍历一个数组，对其中的每一项执行一些代码。在底层，这会隐式地创建并消费一个迭代器，不过直到现在我们都没有细说它究竟是如何工作的。

在示例 13-11 的例子中，我们把迭代器的创建与在 for 循环中对迭代器的使用分离开来。当使用 v1_iter 中的迭代器调用 for 循环时，迭代器中的每个元素都会用于循环的一次迭代，从而打印出每个值。

在标准库没有提供迭代器的语言中，要实现同样的功能，你很可能需要让一个变量从索引 0 开始，用这个变量索引 vector 来获取值，并在循环中递增这个变量的值，直到它达到 vector 中元素的总数。

迭代器为你处理了所有这些逻辑，减少了那些你可能会写错的重复代码。迭代器让你可以更灵活地对许多不同种类的序列使用同样的逻辑，而不仅限于像 vector 这样可以通过索引访问的数据结构。我们来看看迭代器是如何做到这一点的。

Iterator trait 和 next 方法

所有迭代器都实现了一个名为 Iterator 的 trait，它定义在标准库中。这个 trait 的定义如下所示：

#![allow(unused)]
fn main() {
pub trait Iterator {
    type Item;

    fn next(&mut self) -> Option<Self::Item>;

    // methods with default implementations elided
}
}

注意，这个定义使用了一些新语法：type Item 和 Self::Item，它们为这个 trait 定义了一个关联类型。我们会在第 20 章深入讨论关联类型。现在你只需要知道，这段代码表明实现 Iterator trait 要求你同时定义一个 Item 类型，而这个 Item 类型被用作 next 方法的返回类型。换句话说，Item 类型就是迭代器返回的元素的类型。

Iterator trait 只要求实现者定义一个方法：next 方法。它每次返回迭代器中的一项，并包装在 Some 中；当迭代结束时，则返回 None。

我们可以直接在迭代器上调用 next 方法；示例 13-12 演示了在由 vector 创建的迭代器上反复调用 next 时会返回哪些值。

注意，我们需要让 v1_iter 是可变的：在迭代器上调用 next 方法会改变迭代器内部用来记录其在序列中所处位置的状态。换句话说，这段代码消费（consume）了，或者说用尽了这个迭代器。每次调用 next 都会从迭代器中消耗掉一项。使用 for 循环时，我们不需要让 v1_iter 可变，因为循环获取了 v1_iter 的所有权，并在幕后让它变成了可变的。

还要注意，我们从 next 调用中得到的值是 vector 中值的不可变引用。iter 方法生成的是一个遍历不可变引用的迭代器。如果我们想创建一个获取 v1 所有权并返回拥有所有权的值的迭代器，可以调用 into_iter 而不是 iter。类似地，如果我们想遍历可变引用，可以调用 iter_mut 而不是 iter。

消费迭代器的方法

Iterator trait 有许多不同的方法，标准库为它们提供了默认实现；你可以在标准库 API 文档中查阅 Iterator trait 来了解这些方法。其中一些方法在定义中调用了 next 方法，这就是为什么在实现 Iterator trait 时必须实现 next 方法。

调用 next 的方法被称为消费适配器（consuming adapter），因为调用它们会用尽迭代器。sum 方法就是一个例子，它获取迭代器的所有权，并通过反复调用 next 来遍历各项，从而消费迭代器。在遍历过程中，它把每一项累加到一个总和上，并在迭代完成时返回这个总和。示例 13-13 中的测试演示了 sum 方法的用法。

调用 sum 之后，我们就不能再使用 v1_iter 了，因为 sum 获取了调用它的那个迭代器的所有权。

产生其他迭代器的方法

迭代器适配器（iterator adapter）是定义在 Iterator trait 上、不会消费迭代器的方法。它们会改变原迭代器的某些方面，从而产生不同的迭代器。

示例 13-14 展示了调用迭代器适配器方法 map 的例子，它接受一个闭包，在遍历各项时对每一项调用该闭包。map 方法返回一个新的迭代器，该迭代器产生修改后的各项。这里的闭包创建了一个新的迭代器，其中 vector 中的每一项都会加 1。

然而，这段代码会产生一个警告：

  |

warning: `iterators` (bin "iterators") generated 1 warning
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.47s
     Running `target/debug/iterators`

示例 13-14 中的代码什么也没做；我们指定的闭包从未被调用过。这个警告提醒了我们原因：迭代器适配器是惰性的，我们需要在这里消费这个迭代器。

为了消除这个警告并消费迭代器，我们将使用 collect 方法，我们在示例 12-1 中曾将它与 env::args 一起使用过。这个方法会消费迭代器，并将结果值收集到一个集合数据类型中。

在示例 13-15 中，我们把遍历 map 调用所返回的迭代器得到的结果收集到一个 vector 中。这个 vector 最终会包含原 vector 中的每一项加 1 之后的值。

因为 map 接受一个闭包，所以我们可以指定想对每一项执行的任何操作。这个例子很好地说明了闭包如何让你在复用 Iterator trait 所提供的迭代行为的同时，定制某些行为。

你可以链式调用多个迭代器适配器，以一种可读性良好的方式执行复杂的操作。但由于所有迭代器都是惰性的，你必须调用某个消费适配器方法，才能从迭代器适配器的调用中获得结果。

捕获环境的闭包

许多迭代器适配器都接受闭包作为参数，而我们作为参数传给迭代器适配器的闭包，通常都是捕获其环境的闭包。

在这个例子中，我们将使用接受一个闭包的 filter 方法。这个闭包从迭代器中获取一项，并返回一个 bool。如果闭包返回 true，该值就会被包含在 filter 产生的迭代器中；如果闭包返回 false，该值就不会被包含在内。

在示例 13-16 中，我们使用 filter 和一个从其环境中捕获 shoe_size 变量的闭包，来遍历一个由 Shoe 结构体实例组成的集合。它只会返回指定尺码的鞋子。

shoes_in_size 函数获取一个鞋子 vector 的所有权和一个鞋码作为参数。它返回一个只包含指定尺码鞋子的 vector。

在 shoes_in_size 的函数体中，我们调用 into_iter 来创建一个获取该 vector 所有权的迭代器。然后，我们调用 filter，将这个迭代器适配成一个新的迭代器，新迭代器只包含那些使闭包返回 true 的元素。

闭包从环境中捕获了 shoe_size 参数，并将这个值与每只鞋的尺码进行比较，只保留指定尺码的鞋子。最后，调用 collect 将适配后的迭代器所返回的值收集到一个 vector 中，并由函数返回。

这个测试表明，当我们调用 shoes_in_size 时，得到的只有与我们指定的值尺码相同的鞋子。
