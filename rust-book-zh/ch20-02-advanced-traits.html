Rust 程序设计语言

高级 trait

我们在第 10 章“用 trait 定义共同行为”部分首次介绍了 trait，但没有讨论更高级的细节。现在你对 Rust 已经有了更多了解，我们可以深入探讨其中的细节了。

使用关联类型定义 trait

关联类型（associated type）将一个类型占位符与 trait 关联起来，使得 trait 的方法定义可以在其签名中使用这些占位类型。trait 的实现者会针对特定的实现，指定用来替代占位类型的具体类型。这样一来，我们就可以定义一个使用某些类型的 trait，而在实现该 trait 之前，无需确切地知道这些类型是什么。

我们说过，本章介绍的大部分高级特性都很少用到。关联类型则介于两者之间：它们比本书其余部分讲解的特性用得少，但比本章讨论的许多其他特性用得多。

标准库提供的 Iterator trait 就是一个带有关联类型的 trait 的例子。它的关联类型名为 Item，代表实现了 Iterator trait 的类型所迭代的值的类型。Iterator trait 的定义如示例 20-13 所示。

类型 Item 是一个占位符，next 方法的定义表明它会返回 Option<Self::Item> 类型的值。Iterator trait 的实现者会为 Item 指定具体的类型，而 next 方法则会返回一个包含该具体类型值的 Option。

关联类型看起来可能与泛型是类似的概念，因为后者也允许我们在定义函数时不指定它能处理哪些类型。为了考察这两个概念之间的差异，我们来看一个在名为 Counter 的类型上实现 Iterator trait 的例子，它指定 Item 的类型为 u32：

这种语法看起来与泛型的语法差不多。那么，为什么不直接像示例 20-14 那样用泛型来定义 Iterator trait 呢？

区别在于，像示例 20-14 那样使用泛型时，我们必须在每个实现中标注类型；因为我们还可以实现 Iterator<String> for Counter 或任何其他类型，所以 Counter 可以有多个 Iterator 的实现。换句话说，当 trait 带有泛型参数时，它可以为同一个类型实现多次，每次改变泛型类型参数的具体类型即可。当我们在 Counter 上使用 next 方法时，就必须提供类型注解来表明想要使用哪个 Iterator 实现。

而使用关联类型时，我们不需要标注类型，因为不能为一个类型多次实现同一个 trait。在示例 20-13 中使用关联类型的定义里，我们只能选择一次 Item 的类型，因为只能有一个 impl Iterator for Counter。我们不必在每次对 Counter 调用 next 的地方都指定想要一个 u32 值的迭代器。

关联类型也会成为 trait 契约的一部分：trait 的实现者必须提供一个类型来替代关联类型占位符。关联类型通常会有一个描述该类型将如何被使用的名称，在 API 文档中为关联类型编写文档是一种良好的实践。

使用默认泛型参数和运算符重载

在使用泛型类型参数时，我们可以为泛型类型指定一个默认的具体类型。如果默认类型就能满足需要，trait 的实现者就无需再指定具体类型。在声明泛型类型时，使用 <PlaceholderType=ConcreteType> 语法来指定默认类型。

这种技术非常有用的一个绝佳例子是运算符重载（operator overloading），即在特定情况下自定义某个运算符（比如 +）的行为。

Rust 不允许你创建自己的运算符，也不允许重载任意的运算符。但你可以通过实现与运算符相关联的 trait，来重载 std::ops 中列出的运算及其对应的 trait。例如，在示例 20-15 中，我们重载了 + 运算符，以便将两个 Point 实例相加。我们通过在 Point 结构体上实现 Add trait 来做到这一点。

add 方法将两个 Point 实例的 x 值相加，并将两个 Point 实例的 y 值相加，从而创建一个新的 Point。Add trait 有一个名为 Output 的关联类型，它决定了 add 方法返回的类型。

这段代码中的默认泛型类型位于 Add trait 中。下面是它的定义：

#![allow(unused)]
fn main() {
trait Add<Rhs=Self> {
    type Output;

    fn add(self, rhs: Rhs) -> Self::Output;
}
}

这段代码看起来应该大体眼熟：一个带有一个方法和一个关联类型的 trait。新的部分是 Rhs=Self：这种语法叫作默认类型参数（default type parameters）。泛型类型参数 Rhs（“right-hand side”的缩写，意为“右侧”）定义了 add 方法中 rhs 参数的类型。如果我们在实现 Add trait 时没有为 Rhs 指定具体类型，Rhs 的类型将默认为 Self，也就是我们正在为其实现 Add 的那个类型。

当我们为 Point 实现 Add 时，使用了 Rhs 的默认值，因为我们想把两个 Point 实例相加。我们再来看一个实现 Add trait 的例子，这次我们想要自定义 Rhs 的类型，而不是使用默认值。

我们有两个结构体 Millimeters 和 Meters，分别存放以不同单位表示的值。这种用另一个结构体对现有类型进行轻量封装的做法被称为 newtype 模式（newtype pattern），我们会在“使用 newtype 模式实现外部 trait”部分更详细地介绍它。我们希望将以毫米为单位的值与以米为单位的值相加，并让 Add 的实现正确地完成单位换算。我们可以为 Millimeters 实现 Add，并以 Meters 作为 Rhs，如示例 20-16 所示。

为了将 Millimeters 和 Meters 相加，我们指定了 impl Add<Meters> 来设置 Rhs 类型参数的值，而不是使用默认的 Self。

默认类型参数主要有两种用途：

  1. 在不破坏现有代码的前提下扩展类型
  2. 在大多数用户都不需要的特定情况下允许进行自定义

标准库的 Add trait 就是第二种用途的一个例子：通常你会将两个相同类型的值相加，但 Add trait 提供了超越这一点进行自定义的能力。在 Add trait 的定义中使用默认类型参数，意味着大多数时候你都不必指定这个额外的参数。换句话说，可以省去一些实现上的样板代码，让这个 trait 用起来更加方便。

第一种用途与第二种类似，只是方向相反：如果你想为一个现有的 trait 添加类型参数，可以给它一个默认值，这样就能在不破坏现有实现代码的情况下扩展该 trait 的功能。

消除同名方法之间的歧义

Rust 既不会阻止一个 trait 拥有与另一个 trait 的方法同名的方法，也不会阻止你在同一个类型上同时实现这两个 trait。直接在类型上实现一个与 trait 中的方法同名的方法也是可以的。

因为 fly 方法接受一个 self 参数，所以如果有两个类型都实现了同一个 trait，Rust 可以根据 self 的类型推断出应该使用该 trait 的哪个实现。

然而，不是方法的关联函数没有 self 参数。当有多个类型或 trait 定义了同名的非方法函数时，除非使用完全限定语法，否则 Rust 并不总能知道你指的是哪个类型。例如，在示例 20-20 中，我们为一家动物收容所创建了一个 trait，这家收容所想把所有的小狗都命名为 Spot。我们创建了一个 Animal trait，它带有一个关联的非方法函数 baby_name。Animal trait 为结构体 Dog 实现，同时我们也直接在 Dog 上提供了一个关联的非方法函数 baby_name。

我们在定义于 Dog 上的关联函数 baby_name 中实现了把所有小狗命名为 Spot 的代码。Dog 类型还实现了 Animal trait，这个 trait 描述了所有动物都具有的特征。小狗被称为 puppy，这一点体现在 Dog 对 Animal trait 的实现中，即与 Animal trait 相关联的 baby_name 函数里。

一般来说，完全限定语法的定义如下：

<Type as Trait>::function(receiver_if_method, next_arg, ...);

对于不是方法的关联函数，就没有 receiver：只有其他参数的列表。你可以在任何调用函数或方法的地方使用完全限定语法。不过，Rust 能够从程序的其他信息中推断出来的部分，都允许省略。只有在存在多个同名实现、并且 Rust 需要帮助才能确定你想调用哪个实现的情况下，才需要使用这种更冗长的语法。

使用超 trait

有时你编写的 trait 定义可能会依赖于另一个 trait：对于要实现第一个 trait 的类型，你希望要求该类型同时也实现第二个 trait。这样做是为了让你的 trait 定义能够使用第二个 trait 的关联项。你的 trait 定义所依赖的那个 trait，被称为你的 trait 的超 trait（supertrait）。

例如，假设我们想创建一个 OutlinePrint trait，它有一个 outline_print 方法，用来打印一个经过格式化、被星号框起来的给定值。也就是说，给定一个实现了标准库 trait Display、显示结果为 (x, y) 的 Point 结构体，当我们在一个 x 为 1、y 为 3 的 Point 实例上调用 outline_print 时，它应该打印出以下内容：

**********
*        *
* (1, 3) *
*        *
**********

在 outline_print 方法的实现中，我们想使用 Display trait 的功能。因此，我们需要指定 OutlinePrint trait 只适用于同时实现了 Display、能提供 OutlinePrint 所需功能的类型。我们可以在 trait 定义中指定 OutlinePrint: Display 来做到这一点。这种技术类似于为 trait 添加一个 trait bound。示例 20-23 展示了 OutlinePrint trait 的一个实现。

因为我们已经指定了 OutlinePrint 需要 Display trait，所以可以使用 to_string 函数，任何实现了 Display 的类型都会自动实现这个函数。如果我们没有在 trait 名称后面加上冒号并指定 Display trait 就尝试使用 to_string，就会得到一个错误，提示在当前作用域中找不到类型 &Self 的名为 to_string 的方法。

使用 newtype 模式实现外部 trait

在第 10 章“为类型实现 trait”部分中，我们提到了孤儿规则：只有当 trait 或类型二者之一（或者两者都）属于我们的 crate 本地时，才允许在该类型上实现该 trait。使用 newtype 模式可以绕过这一限制，它的做法是在一个元组结构体中创建一个新类型。（我们在第 5 章“使用元组结构体创建不同的类型”部分介绍过元组结构体。）这个元组结构体只有一个字段，是对我们想要为其实现 trait 的类型的一层轻量封装。这样一来，封装类型就属于我们的 crate 本地，我们就可以在这个封装类型上实现该 trait 了。Newtype 这个术语源自 Haskell 编程语言。使用这种模式不会带来运行时性能损失，封装类型会在编译时被省略掉。

举个例子，假设我们想在 Vec<T> 上实现 Display，而孤儿规则阻止我们直接这样做，因为 Display trait 和 Vec<T> 类型都定义在我们的 crate 之外。我们可以创建一个存放 Vec<T> 实例的 Wrapper 结构体；然后就可以在 Wrapper 上实现 Display，并使用其中的 Vec<T> 值，如示例 20-24 所示。

Display 的实现使用 self.0 来访问内部的 Vec<T>，因为 Wrapper 是一个元组结构体，而 Vec<T> 是该元组中索引为 0 的项。然后，我们就可以在 Wrapper 上使用 Display trait 的功能了。

使用这种技术的缺点是 Wrapper 是一个新类型，所以它不具有其内部值的那些方法。我们必须直接在 Wrapper 上实现 Vec<T> 的所有方法，让这些方法委托给 self.0，这样才能把 Wrapper 完全当作 Vec<T> 来对待。如果我们希望新类型拥有内部类型的所有方法，一种解决方案是在 Wrapper 上实现 Deref trait，让它返回内部类型（我们在第 15 章“像普通引用一样使用智能指针”部分讨论过如何实现 Deref trait）。如果我们不希望 Wrapper 类型拥有内部类型的所有方法（例如，为了限制 Wrapper 类型的行为），就只能手动实现我们确实需要的那些方法了。
