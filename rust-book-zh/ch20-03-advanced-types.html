Rust 程序设计语言

高级类型

Rust 的类型系统有一些我们之前提到过但尚未讨论的特性。我们先从总体上讨论 newtype，看看为什么它们作为类型很有用。然后，我们会转向类型别名，这是一个与 newtype 类似但语义略有不同的特性。我们还会讨论 ! 类型和动态大小类型。

使用 newtype 模式实现类型安全与抽象

本节假设你已经读过前面的“使用 newtype 模式实现外部 trait”部分。newtype 模式还可以用于我们目前讨论过的场景之外的任务，包括静态地确保值永远不会被混淆，以及标明值的单位。你在示例 20-16 中已经见过用 newtype 来标明单位的例子：回忆一下，Millimeters 和 Meters 结构体把 u32 值包装在了 newtype 中。如果我们编写了一个参数类型为 Millimeters 的函数，那么当程序不小心用 Meters 类型或普通 u32 类型的值来调用这个函数时，程序就无法通过编译。

我们还可以使用 newtype 模式来抽象掉某个类型的一些实现细节：新类型可以对外暴露一个与其私有内部类型的 API 不同的公有 API。

newtype 还可以隐藏内部实现。例如，我们可以提供一个 People 类型来包装一个 HashMap<i32, String>，用来存储与人名相关联的 ID。使用 People 的代码只会与我们提供的公有 API 交互，比如一个向 People 集合添加名字字符串的方法；这些代码不需要知道我们在内部会为名字分配一个 i32 类型的 ID。newtype 模式是一种实现封装、隐藏实现细节的轻量级方式，我们在第 18 章“隐藏实现细节的封装”部分讨论过这种封装。

类型同义词与类型别名

Rust 提供了声明类型别名（type alias）的能力，用来给现有类型另起一个名字。为此，我们需要使用 type 关键字。例如，我们可以像这样为 i32 创建别名 Kilometers：

fn main() {
    type Kilometers = i32;

    let x: i32 = 5;
    let y: Kilometers = 5;

    println!("x + y = {}", x + y);
}

现在，别名 Kilometers 是 i32 的同义词（synonym）；与我们在示例 20-16 中创建的 Millimeters 和 Meters 类型不同，Kilometers 并不是一个独立的新类型。类型为 Kilometers 的值会被当作 i32 类型的值来对待：

fn main() {
    type Kilometers = i32;

    let x: i32 = 5;
    let y: Kilometers = 5;

    println!("x + y = {}", x + y);
}

因为 Kilometers 和 i32 是同一种类型，所以我们可以把这两种类型的值相加，也可以把 Kilometers 值传给接受 i32 参数的函数。然而，使用这种方法，我们无法获得前面讨论的 newtype 模式所带来的类型检查方面的好处。换句话说，如果我们在某处混用了 Kilometers 和 i32 的值，编译器并不会报错。

类型同义词的主要用途是减少重复。例如，我们可能会有这样一个很长的类型：

Box<dyn Fn() + Send + 'static>

在函数签名中以及作为类型注解在代码各处书写这个冗长的类型，既乏味又容易出错。想象一下，一个项目中到处都是示例 20-25 中那样的代码。

类型别名通过减少重复，让这段代码更易于管理。在示例 20-26 中，我们为这个冗长的类型引入了一个名为 Thunk 的别名，并且可以用更短的别名 Thunk 替换该类型的所有用法。

这段代码读起来和写起来都容易多了！为类型别名选择一个有意义的名字，也有助于表达你的意图（thunk 一词表示稍后才会被求值的代码，因此用它来命名一个被存储起来的闭包是很恰当的）。

类型别名也经常与 Result<T, E> 类型一起使用来减少重复。来看标准库中的 std::io 模块。I/O 操作通常会返回一个 Result<T, E>，以处理操作失败的情况。这个库有一个 std::io::Error 结构体，代表了所有可能的 I/O 错误。std::io 中的许多函数都会返回 E 为 std::io::Error 的 Result<T, E>，比如 Write trait 中的这些函数：

use std::fmt;
use std::io::Error;

pub trait Write {
    fn write(&mut self, buf: &[u8]) -> Result<usize, Error>;
    fn flush(&mut self) -> Result<(), Error>;

    fn write_all(&mut self, buf: &[u8]) -> Result<(), Error>;
    fn write_fmt(&mut self, fmt: fmt::Arguments) -> Result<(), Error>;
}

Result<..., Error> 被重复了很多次。因此，std::io 中有这样一个类型别名声明：

use std::fmt;

type Result<T> = std::result::Result<T, std::io::Error>;

pub trait Write {
    fn write(&mut self, buf: &[u8]) -> Result<usize>;
    fn flush(&mut self) -> Result<()>;

    fn write_all(&mut self, buf: &[u8]) -> Result<()>;
    fn write_fmt(&mut self, fmt: fmt::Arguments) -> Result<()>;
}

由于这个声明位于 std::io 模块中，我们可以使用完全限定的别名 std::io::Result<T>；也就是说，这是一个 E 被填充为 std::io::Error 的 Result<T, E>。最终，Write trait 的函数签名看起来就像这样：

use std::fmt;

type Result<T> = std::result::Result<T, std::io::Error>;

pub trait Write {
    fn write(&mut self, buf: &[u8]) -> Result<usize>;
    fn flush(&mut self) -> Result<()>;

    fn write_all(&mut self, buf: &[u8]) -> Result<()>;
    fn write_fmt(&mut self, fmt: fmt::Arguments) -> Result<()>;
}

类型别名在两个方面提供了帮助：它让代码更容易编写，并且为整个 std::io 提供了一致的接口。因为它只是一个别名，所以它不过是另一个 Result<T, E>，这意味着我们可以对它使用任何适用于 Result<T, E> 的方法，以及像 ? 运算符这样的特殊语法。

永不返回的 never 类型

Rust 有一个名为 ! 的特殊类型，在类型理论的术语中它被称为空类型（empty type），因为它没有任何值。我们更愿意称之为 never 类型（never type），因为当一个函数永远不会返回时，它会出现在返回类型的位置上。下面是一个例子：

fn bar() -> ! {
    // --snip--
    panic!();
}

这段代码读作“函数 bar 永不返回”。永不返回的函数被称为发散函数（diverging function）。我们无法创建 ! 类型的值，因此 bar 永远不可能返回。

但是，一个永远无法创建值的类型有什么用呢？回忆一下示例 2-5 中的代码，它是猜数字游戏的一部分；我们在示例 20-27 中重现了其中的一小段。

当时，我们跳过了这段代码中的一些细节。在第 6 章“match 控制流结构”部分中，我们讨论过 match 的各个分支必须返回相同的类型。因此，例如下面的代码就无法工作：

fn main() {
    let guess = "3";
    let guess = match guess.trim().parse() {
        Ok(_) => 5,
        Err(_) => "hello",
    };
}

这段代码中 guess 的类型必须既是整数又是字符串，而 Rust 要求 guess 只能有一种类型。那么，continue 返回的是什么呢？在示例 20-27 中，为什么允许一个分支返回 u32，而另一个分支以 continue 结尾呢？

你可能已经猜到了，continue 的值是 !。也就是说，当 Rust 计算 guess 的类型时，它会查看这两个分支，前者的值是 u32，后者的值是 !。因为 ! 永远不会有值，所以 Rust 判定 guess 的类型是 u32。

描述这种行为的正式说法是：! 类型的表达式可以被强制转换为任何其他类型。我们之所以能以 continue 结束这个 match 分支，是因为 continue 并不返回值；相反，它会把控制权交回到循环的顶部，所以在 Err 的情况下，我们永远不会给 guess 赋值。

never 类型在 panic! 宏中也很有用。回忆一下我们在 Option<T> 值上调用的 unwrap 函数，它要么产生一个值，要么引发 panic，其定义如下：

enum Option<T> {
    Some(T),
    None,
}

use crate::Option::*;

impl<T> Option<T> {
    pub fn unwrap(self) -> T {
        match self {
            Some(val) => val,
            None => panic!("called `Option::unwrap()` on a `None` value"),
        }
    }
}

在这段代码中，发生的事情与示例 20-27 中的 match 相同：Rust 看到 val 的类型是 T，而 panic! 的类型是 !，所以整个 match 表达式的结果是 T。这段代码之所以能工作，是因为 panic! 不会产生值；它会结束程序。在 None 的情况下，我们不会从 unwrap 返回值，所以这段代码是有效的。

最后一个类型为 ! 的表达式是循环：

fn main() {
    print!("forever ");

    loop {
        print!("and ever ");
    }
}

这里的循环永远不会结束，所以 ! 就是这个表达式的值。但如果我们加入了 break，情况就不是这样了，因为循环在执行到 break 时就会终止。

动态大小类型与 Sized trait

Rust 需要知道关于其类型的某些细节，比如应该为某个特定类型的值分配多少空间。这使得其类型系统中有一个角落起初会让人有点困惑：动态大小类型（dynamically sized type）的概念。这类类型有时也被称为 DST 或非固定大小类型（unsized type），它们让我们能够编写使用那些只有在运行时才能知道大小的值的代码。

我们来深入研究一个名为 str 的动态大小类型的细节，我们在整本书中一直在使用它。没错，不是 &str，而是单独的 str，它就是一个 DST。在很多情况下，比如存储用户输入的文本时，我们直到运行时才能知道字符串有多长。这意味着我们既不能创建 str 类型的变量，也不能接受 str 类型的参数。来看下面这段无法工作的代码：

fn main() {
    let s1: str = "Hello there!";
    let s2: str = "How's it going?";
}

Rust 需要知道应该为某个特定类型的任何值分配多少内存，并且同一类型的所有值必须使用相同大小的内存。如果 Rust 允许我们编写这样的代码，这两个 str 值就需要占用相同大小的空间。但它们的长度不同：s1 需要 12 字节的存储空间，而 s2 需要 15 字节。这就是无法创建一个存放动态大小类型的变量的原因。

那么，我们该怎么办呢？在这种情况下，你已经知道答案了：我们把 s1 和 s2 的类型设为字符串切片（&str），而不是 str。回忆一下第 4 章“字符串切片”部分的内容：切片这种数据结构只存储切片的起始位置和长度。因此，尽管 &T 是存储了 T 所在内存地址的单个值，但字符串切片却是两个值：str 的地址及其长度。这样一来，我们就可以在编译时知道字符串切片值的大小：它是 usize 长度的两倍。也就是说，无论字符串切片所引用的字符串有多长，我们总是知道字符串切片的大小。一般来说，这就是 Rust 中使用动态大小类型的方式：它们带有一点额外的元数据，用来存储动态信息的大小。动态大小类型的黄金法则是：必须始终把动态大小类型的值放在某种指针之后。

我们可以把 str 与各种指针结合使用：例如 Box<str> 或 Rc<str>。事实上，你之前已经见过这种用法，只不过用的是另一种动态大小类型：trait。每个 trait 都是一个动态大小类型，我们可以通过 trait 的名称来引用它。在第 18 章“使用 trait 对象抽象共同行为”部分中，我们提到过，要把 trait 用作 trait 对象，就必须将它们放在指针之后，比如 &dyn Trait 或 Box<dyn Trait>（Rc<dyn Trait> 也可以）。

为了处理 DST，Rust 提供了 Sized trait 来判断一个类型的大小是否在编译时可知。所有在编译时大小已知的类型都会自动实现这个 trait。此外，Rust 会隐式地为每个泛型函数加上 Sized bound。也就是说，像下面这样的泛型函数定义：

fn generic<T>(t: T) {
    // --snip--
}

实际上会被当作我们写了这样的代码来处理：

fn generic<T: Sized>(t: T) {
    // --snip--
}

默认情况下，泛型函数只适用于在编译时大小已知的类型。不过，你可以使用下面这种特殊语法来放宽这一限制：

fn generic<T: ?Sized>(t: &T) {
    // --snip--
}

?Sized 上的 trait bound 意味着“T 可能是也可能不是 Sized 的”，这种写法覆盖了泛型类型必须在编译时大小已知的默认规则。具有这种含义的 ?Trait 语法只适用于 Sized，不适用于任何其他 trait。

还要注意，我们把参数 t 的类型从 T 改成了 &T。因为这个类型可能不是 Sized 的，所以我们需要把它放在某种指针之后使用。在这里，我们选择了引用。
