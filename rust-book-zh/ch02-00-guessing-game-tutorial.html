Rust 程序设计语言

编写一个猜数字游戏

让我们一起动手完成一个实践项目，直接上手 Rust 吧！本章将通过在一个真实的程序中使用一些常见的 Rust 概念，向你介绍这些概念。你将学到 let、match、方法、关联函数、外部 crate 等更多内容！在接下来的章节中，我们会更详细地探讨这些概念。在本章中，你只需要练习基础知识。

我们将实现一个经典的编程入门问题：猜数字游戏。它的玩法是这样的：程序会生成一个 1 到 100 之间的随机整数，然后提示玩家输入一个猜测值。输入猜测值之后，程序会提示猜测的数字是太小了还是太大了。如果猜对了，游戏会打印一条祝贺信息并退出。

准备一个新项目

要准备一个新项目，请进入你在第 1 章中创建的 projects 目录，然后像这样使用 Cargo 新建一个项目：

$ cargo new guessing_game
$ cd guessing_game

第一条命令 cargo new 接受项目名称（guessing_game）作为第一个参数。第二条命令切换到新项目的目录。

看一下生成的 Cargo.toml 文件：

文件名：Cargo.toml

[package]
name = "guessing_game"
version = "0.1.0"
edition = "2024"

[dependencies]

正如你在第 1 章中看到的，cargo new 会为你生成一个“Hello, world!”程序。来看看 src/main.rs 文件：

文件名：src/main.rs

fn main() {
    println!("Hello, world!");
}

现在，我们使用 cargo run 命令，一步完成这个“Hello, world!”程序的编译和运行：

$ cargo run
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.08s
     Running `target/debug/guessing_game`
Hello, world!

当你需要在项目上快速迭代时，run 命令就能派上用场。我们在这个游戏中正是这样做的：在进入下一次迭代之前，快速测试当前的每一次迭代。

重新打开 src/main.rs 文件。你将在这个文件中编写所有的代码。

处理一次猜测

猜数字游戏程序的第一部分会请求用户输入，处理这个输入，并检查输入是否符合预期的格式。首先，我们要让玩家能够输入一个猜测值。在 src/main.rs 中输入示例 2-1 中的代码。

这段代码包含了很多信息，我们来逐行讲解。为了获取用户输入并将结果打印出来，我们需要把 io 输入/输出库引入作用域。io 库来自标准库，也就是 std：

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

默认情况下，Rust 会把标准库中定义的一组项引入每个程序的作用域。这组项被称为 prelude（预导入），你可以在标准库文档中查看其中的全部内容。

如果你想使用的类型不在 prelude 中，就必须使用 use 语句显式地把这个类型引入作用域。使用 std::io 库可以为你提供许多实用的功能，其中就包括接收用户输入的能力。

正如你在第 1 章中看到的，main 函数是程序的入口点：

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

fn 语法声明了一个新函数；圆括号 () 表示没有参数；花括号 { 是函数体的开始。

你在第 1 章中也学过，println! 是一个把字符串打印到屏幕上的宏：

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

这段代码打印一条提示信息，说明这是什么游戏，并请求用户输入。

使用变量储存值

接下来，我们创建一个变量（variable）来储存用户输入，就像这样：

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

现在程序开始变得有趣了！这短短的一行代码里大有文章。我们使用 let 语句来创建变量。下面是另一个例子：

let apples = 5;

这一行创建了一个名为 apples 的新变量，并把它绑定到值 5 上。在 Rust 中，变量默认是不可变的，也就是说，一旦我们给变量赋了值，这个值就不会再改变。我们会在第 3 章“变量与可变性”部分详细讨论这个概念。要让变量可变，需要在变量名前加上 mut：

let apples = 5; // immutable
let mut bananas = 5; // mutable

注意：// 语法开始一段注释，注释一直持续到行尾。Rust 会忽略注释中的所有内容。我们会在第 3 章中更详细地讨论注释。

回到猜数字游戏程序，现在你已经知道，let mut guess 会引入一个名为 guess 的可变变量。等号（=）告诉 Rust 我们现在要把某个值绑定到这个变量上。等号右边是 guess 所绑定的值，它是调用 String::new 的结果，这个函数会返回一个新的 String 实例。String 是标准库提供的一种字符串类型，它是一段可增长的、UTF-8 编码的文本。

::new 那一行中的 :: 语法表明 new 是 String 类型的一个关联函数。关联函数（associated function）是在某个类型上实现的函数，在这里就是 String。这个 new 函数会创建一个新的空字符串。你会在许多类型上见到 new 函数，因为对于创建某种新值的函数来说，这是一个常用的名字。

总的来说，let mut guess = String::new(); 这一行创建了一个可变变量，它当前绑定到一个新的、空的 String 实例上。呼！

接收用户输入

回想一下，我们在程序的第一行用 use std::io; 引入了标准库中的输入/输出功能。现在我们将调用 io 模块中的 stdin 函数，它让我们能够处理用户输入：

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

如果我们没有在程序开头用 use std::io; 导入 io 模块，仍然可以把这个函数调用写成 std::io::stdin 来使用这个函数。stdin 函数返回一个 std::io::Stdin 的实例，这个类型表示终端标准输入的句柄（handle）。

接下来，.read_line(&mut guess) 这一行调用标准输入句柄上的 read_line 方法来获取用户输入。我们还把 &mut guess 作为参数传给 read_line，告诉它要把用户输入储存在哪个字符串中。read_line 的全部工作，就是把用户在标准输入中键入的任何内容追加到一个字符串中（不会覆盖字符串原有的内容），因此我们要把那个字符串作为参数传给它。这个字符串参数必须是可变的，这样该方法才能修改字符串的内容。

& 表示这个参数是一个引用（reference），它让你可以在代码的多个部分访问同一份数据，而无须把这份数据多次复制到内存中。引用是一个复杂的特性，而 Rust 的一大优势就在于使用引用既安全又简单。完成这个程序并不需要了解太多这方面的细节。目前你只需要知道，引用和变量一样，默认也是不可变的。因此，你需要写成 &mut guess 而不是 &guess，才能让它可变。（第 4 章会更全面地讲解引用。）

使用 Result 处理潜在的失败

我们还在讲解这一行代码。虽然现在讨论的是第三行文本，但请注意，它仍然是同一个逻辑代码行的一部分。下一部分是这个方法：

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

我们也可以把这段代码写成：

io::stdin().read_line(&mut guess).expect("Failed to read line");

不过，一行过长的代码很难阅读，所以最好把它拆开。当你使用 .method_name() 语法调用方法时，引入换行和其他空白来拆分长代码行通常是明智之举。现在我们来讨论这一行代码做了什么。

前面提到过，read_line 会把用户输入的任何内容放进我们传给它的字符串中，不过它还会返回一个 Result 值。Result 是一种枚举（enumeration，通常简称为 enum），枚举类型的值可以处于多种可能状态中的某一种。我们把每一种可能的状态称为一个变体（variant）。

第 6 章将更详细地介绍枚举。这些 Result 类型的作用是编码错误处理信息。

Result 的变体有 Ok 和 Err。Ok 变体表示操作成功，它包含成功生成的值。Err 变体表示操作失败，它包含关于操作如何失败或为何失败的信息。

和任何类型的值一样，Result 类型的值上也定义了方法。Result 的实例有一个可以调用的 expect 方法。如果这个 Result 实例是 Err 值，expect 会让程序崩溃，并显示你作为参数传给 expect 的信息。如果 read_line 方法返回 Err，那很可能是底层操作系统出错导致的。如果这个 Result 实例是 Ok 值，expect 会取出 Ok 中保存的返回值，并只把这个值返回给你，以便你使用。在本例中，这个值就是用户输入的字节数。

如果你不调用 expect，程序也能编译，但你会收到一条警告：

$ cargo build
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
warning: unused `Result` that must be used
  --> src/main.rs:10:5
   |
10 |     io::stdin().read_line(&mut guess);
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   |
   = note: this `Result` may be an `Err` variant, which should be handled
   = note: `#[warn(unused_must_use)]` (part of `#[warn(unused)]`) on by default
help: use `let _ = ...` to ignore the resulting value
   |
10 |     let _ = io::stdin().read_line(&mut guess);
   |     +++++++

warning: `guessing_game` (bin "guessing_game") generated 1 warning
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.59s

Rust 警告你没有使用 read_line 返回的 Result 值，这表明程序没有处理一个可能出现的错误。

消除这条警告的正确做法是真正编写错误处理代码，但在我们的例子中，我们只想在出现问题时让程序崩溃，所以可以使用 expect。你将在第 9 章中学习如何从错误中恢复。

使用 println! 占位符打印值

除了右花括号之外，到目前为止的代码中只剩下一行需要讨论了：

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

这一行会打印出现在已经包含用户输入的那个字符串。这对花括号 {} 是一个占位符：你可以把 {} 想象成一对小小的螃蟹钳子，把值夹在原地。打印变量的值时，可以把变量名放在花括号里面。打印表达式的求值结果时，则在格式字符串中放置空的花括号，然后在格式字符串之后跟上一个以逗号分隔的表达式列表，这些表达式会按相同的顺序依次打印到各个空花括号占位符中。在一次 println! 调用中同时打印一个变量和一个表达式的结果，看起来会是这样：

#![allow(unused)]
fn main() {
let x = 5;
let y = 10;

println!("x = {x} and y + 2 = {}", y + 2);
}

这段代码会打印 x = 5 and y + 2 = 12。

生成一个秘密数字

接下来，我们需要生成一个让用户来猜的秘密数字。这个秘密数字每次都应该不同，这样游戏才能玩上不止一次。我们将使用 1 到 100 之间的随机数，好让游戏不会太难。Rust 的标准库中目前还没有包含随机数功能。不过，Rust 团队确实提供了一个具备这项功能的 rand crate。

使用 crate 增加功能

记住，crate 是一组 Rust 源代码文件的集合。我们一直在构建的这个项目是一个二进制 crate，也就是一个可执行文件。rand crate 则是一个库 crate，它包含的代码供其他程序使用，本身不能单独执行。

Cargo 对外部 crate 的协调管理正是它真正大放异彩的地方。在编写使用 rand 的代码之前，我们需要修改 Cargo.toml 文件，把 rand crate 添加为依赖。现在打开这个文件，在 Cargo 为你创建的 [dependencies] 节标题下方的末尾添加下面这一行。请务必像我们这里一样，用这个版本号来指定 rand，否则本教程中的代码示例可能无法正常运行：

文件名：Cargo.toml

[dependencies]
rand = "0.10.1"

在 Cargo.toml 文件中，标题之后的所有内容都属于该节，一直持续到下一个节开始为止。在 [dependencies] 中，你要告诉 Cargo 你的项目依赖哪些外部 crate，以及需要这些 crate 的哪些版本。在本例中，我们使用语义化版本说明符 0.10.1 来指定 rand crate。Cargo 能够理解语义化版本（Semantic Versioning，有时简称为 SemVer），这是一种编写版本号的标准。说明符 0.10.1 实际上是 ^0.10.1 的简写，意思是任何不低于 0.10.1 且低于 0.11.0 的版本。

Cargo 认为这些版本的公有 API 与 0.10.1 版本兼容，这种写法能确保你获得最新的补丁版本，而且它仍然能与本章的代码一起编译。任何 0.11.0 或更高的版本都不能保证拥有与接下来的示例所使用的相同的 API。

现在，我们不修改任何代码，直接构建项目，如示例 2-2 所示。

你可能会看到不同的版本号（不过多亏了 SemVer，它们都与代码兼容！）和不同的输出行（取决于操作系统），而且这些行的顺序也可能不同。

当我们引入一个外部依赖时，Cargo 会从注册表（registry）中获取该依赖所需的所有内容的最新版本，注册表是 Crates.io 数据的一份副本。Crates.io 是 Rust 生态系统中的人们发布开源 Rust 项目供他人使用的地方。

更新完注册表之后，Cargo 会检查 [dependencies] 节，并下载其中列出的、尚未下载的所有 crate。在本例中，虽然我们只列出了 rand 这一个依赖，但 Cargo 还获取了 rand 正常工作所依赖的其他 crate。下载完这些 crate 之后，Rust 会编译它们，然后在这些依赖可用的情况下编译项目。

如果你不做任何修改，紧接着再次运行 cargo build，那么除了 Finished 这一行之外，你不会看到任何输出。Cargo 知道它已经下载并编译过这些依赖，而你也没有在 Cargo.toml 文件中对它们做任何修改。Cargo 还知道你没有修改代码，所以也不会重新编译代码。既然无事可做，它就直接退出了。

如果你打开 src/main.rs 文件，做一个微不足道的修改，然后保存并再次构建，你只会看到两行输出：

$ cargo build
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.13s

这两行输出表明，Cargo 只根据你对 src/main.rs 文件所做的微小修改来更新构建。你的依赖没有发生变化，因此 Cargo 知道可以复用已经为它们下载和编译好的内容。

确保构建可重现

Cargo 有一种机制，能确保无论是你还是其他任何人在构建你的代码时，每次都能重新构建出相同的产物：在你另行指定之前，Cargo 只会使用你所指定的依赖版本。例如，假设下周 rand crate 发布了 0.10.2 版本，这个版本包含一个重要的 bug 修复，但同时也包含一个会破坏你的代码的回归问题。为了应对这种情况，Rust 会在你第一次运行 cargo build 时创建 Cargo.lock 文件，所以现在 guessing_game 目录中就有了这个文件。

当你第一次构建项目时，Cargo 会计算出符合条件的所有依赖版本，然后把它们写入 Cargo.lock 文件。以后再构建项目时，Cargo 会发现 Cargo.lock 文件已经存在，于是使用其中指定的版本，而不必重新计算版本。这让你能够自动获得可重现的构建。换句话说，多亏了 Cargo.lock 文件，在你显式升级之前，你的项目会一直使用 0.10.1 版本。由于 Cargo.lock 文件对于可重现构建非常重要，它通常会和项目中的其他代码一起提交到源代码版本控制系统中。

更新 crate 以获取新版本

当你确实想要更新某个 crate 时，Cargo 提供了 update 命令，它会忽略 Cargo.lock 文件，并计算出符合 Cargo.toml 中指定要求的所有最新版本。然后，Cargo 会把这些版本写入 Cargo.lock 文件。否则，默认情况下，Cargo 只会查找大于 0.10.1 且小于 0.11.0 的版本。如果 rand crate 发布了 0.10.2 和 0.999.0 这两个新版本，那么运行 cargo update 时，你会看到如下输出：

$ cargo update
    Updating crates.io index
     Locking 1 package to latest Rust 1.96.0 compatible version
    Updating rand v0.10.1 -> v0.10.2 (available: v0.999.0)

Cargo 忽略了 0.999.0 版本。此时，你还会注意到 Cargo.lock 文件发生了变化，其中记录了你现在使用的 rand crate 版本是 0.10.2。如果要使用 rand 的 0.999.0 版本或 0.999.x 系列中的任何版本，你就必须把 Cargo.toml 文件改成下面这样（但请不要真的做这个修改，因为接下来的示例都假定你使用的是 rand 0.10）：

[dependencies]
rand = "0.999.0"

下次运行 cargo build 时，Cargo 会更新可用 crate 的注册表，并根据你指定的新版本重新评估对 rand 的版本要求。

关于 Cargo 及其生态系统，还有很多内容可讲，我们会在第 14 章中讨论，但就目前而言，你只需要了解这些就够了。Cargo 让库的复用变得非常容易，因此 Rustacean 们能够编写出由许多包组装而成的小型项目。

生成随机数

让我们开始使用 rand 来生成一个用于猜测的数字。下一步是更新 src/main.rs，如示例 2-3 所示。

首先，我们添加了 use rand::prelude::*; 这一行。prelude 模块包含了 rand crate 中最常用的部分，而 use 让这些项在我们程序的作用域中可用。

接着，我们在中间添加了两行代码。在第一行中，我们调用 rand::rng 函数，它会给我们提供将要使用的那个特定的随机数生成器：这个生成器位于当前执行线程本地，并由操作系统提供种子。然后，我们调用随机数生成器上的 random_range 方法。这个方法由 RngExt trait 定义，该 trait 属于我们用 use rand::prelude::*; 语句引入作用域的 rand::prelude 模块。random_range 方法接受一个范围表达式作为参数，并生成一个位于该范围内的随机数。我们这里使用的范围表达式的形式是 start..=end，它同时包含下界和上界，所以我们需要指定 1..=100 来请求一个 1 到 100 之间的数字。

注意：你不可能凭空就知道该从一个 crate 中引入哪些内容到作用域、调用哪些方法和函数，因此每个 crate 都附有说明其用法的文档。Cargo 的另一个巧妙功能是：运行 cargo doc --open 命令，就会在本地构建所有依赖提供的文档，并在浏览器中打开。例如，如果你对 rand crate 的其他功能感兴趣，可以运行 cargo doc --open，然后点击左侧边栏中的 rand。

比较猜测的数字和秘密数字

现在我们有了用户输入和一个随机数，可以对它们进行比较了。这一步如示例 2-4 所示。注意，这段代码现在还无法编译，原因我们稍后解释。

首先，我们又添加了一条 use 语句，把标准库中一个名为 std::cmp::Ordering 的类型引入作用域。Ordering 类型是另一个枚举，它有 Less、Greater 和 Equal 这几个变体。这是比较两个值时可能出现的三种结果。

然后，我们在底部添加了五行使用 Ordering 类型的新代码。cmp 方法用于比较两个值，可以在任何能够比较的值上调用。它接受一个指向你想要与之比较的值的引用：这里是把 guess 与 secret_number 进行比较。然后，它会返回我们用 use 语句引入作用域的 Ordering 枚举的一个变体。我们使用一个 match 表达式，根据用 guess 和 secret_number 中的值调用 cmp 后返回的是 Ordering 的哪个变体，来决定接下来做什么。

match 表达式由分支（arm）构成。一个分支包含一个用于匹配的模式（pattern），以及当传给 match 的值符合该分支的模式时应当运行的代码。Rust 会拿到传给 match 的值，并依次检查每个分支的模式。模式和 match 结构是 Rust 中强大的特性：它们让你能够表达代码可能遇到的各种情况，并确保你对这些情况都进行了处理。这些特性将分别在第 6 章和第 19 章中详细介绍。

我们用这里的 match 表达式举个例子，一步步看看它是怎么运作的。假设用户猜的是 50，而这次随机生成的秘密数字是 38。

当代码把 50 与 38 进行比较时，由于 50 大于 38，cmp 方法会返回 Ordering::Greater。match 表达式得到 Ordering::Greater 这个值，开始检查每个分支的模式。它先查看第一个分支的模式 Ordering::Less，发现值 Ordering::Greater 与 Ordering::Less 不匹配，于是忽略这个分支中的代码，转到下一个分支。下一个分支的模式是 Ordering::Greater，它确实与 Ordering::Greater 匹配！这个分支中关联的代码就会执行，在屏幕上打印出 Too big!。match 表达式在第一次成功匹配之后就会结束，所以在这种情况下，它不会再查看最后一个分支。

这个错误的核心是存在类型不匹配（mismatched types）。Rust 拥有一个强大的静态类型系统，但它同时也有类型推断。当我们写下 let mut guess = String::new() 时，Rust 能够推断出 guess 应该是 String 类型，因而不需要我们写出类型。另一方面，secret_number 是一个数字类型。Rust 中有好几种数字类型可以容纳 1 到 100 之间的值：i32，32 位数字；u32，无符号 32 位数字；i64，64 位数字；等等。除非另行指定，否则 Rust 默认使用 i32，如果你没有在别处添加会让 Rust 推断出其他数值类型的类型信息，secret_number 的类型就是 i32。出现这个错误的原因是，Rust 无法比较字符串和数字类型。

最终，我们希望把程序读取为输入的 String 转换成数字类型，以便能在数值上将它与秘密数字进行比较。为此，我们在 main 函数体中添加下面这一行：

文件名：src/main.rs

use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    println!("The secret number is: {secret_number}");

    println!("Please input your guess.");

    // --snip--

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    let guess: u32 = guess.trim().parse().expect("Please type a number!");

    println!("You guessed: {guess}");

    match guess.cmp(&secret_number) {
        Ordering::Less => println!("Too small!"),
        Ordering::Greater => println!("Too big!"),
        Ordering::Equal => println!("You win!"),
    }
}

这一行代码是：

let guess: u32 = guess.trim().parse().expect("Please type a number!");

我们创建了一个名为 guess 的变量。不过等等，程序中不是已经有一个名为 guess 的变量了吗？确实有，但 Rust 很贴心地允许我们用一个新值来遮蔽 guess 之前的值。遮蔽（shadowing）让我们可以复用 guess 这个变量名，而不必被迫创建两个不同的变量，比如 guess_str 和 guess。我们会在第 3 章中更详细地介绍这一点，目前你只需要知道，当你想把一个值从一种类型转换成另一种类型时，经常会用到这个特性。

我们把这个新变量绑定到表达式 guess.trim().parse() 上。表达式中的 guess 指的是原来那个以字符串形式保存输入的 guess 变量。String 实例上的 trim 方法会去除字符串开头和结尾的所有空白字符，我们必须先这样做，才能把字符串转换成 u32，因为 u32 只能包含数值数据。用户必须按下 enter 键才能让 read_line 返回并输入他们的猜测，而这会在字符串中添加一个换行符。例如，如果用户输入 5 并按下 enter，guess 看起来就会是这样：5\n。其中的 \n 代表“换行”。（在 Windows 上，按下 enter 会产生一个回车符和一个换行符，即 \r\n。）trim 方法会去除 \n 或 \r\n，只留下 5。

字符串上的 parse 方法会把字符串转换成另一种类型。在这里，我们用它把字符串转换成数字。我们需要使用 let guess: u32 来告诉 Rust 我们想要的确切数字类型。guess 后面的冒号（:）告诉 Rust 我们要为这个变量标注类型。Rust 有几种内置的数字类型；这里看到的 u32 是无符号 32 位整数。对于较小的正数来说，它是一个不错的默认选择。你将在第 3 章中学习其他数字类型。

此外，这个示例程序中的 u32 注解以及与 secret_number 的比较，意味着 Rust 会推断出 secret_number 也应该是 u32 类型。所以，现在比较的就是两个相同类型的值了！

parse 方法只适用于那些在逻辑上可以转换成数字的字符，因此很容易出错。例如，如果字符串中包含 A👍%，就没有办法把它转换成数字。由于可能会失败，parse 方法会返回一个 Result 类型，这一点与 read_line 方法非常相似（前面在“使用 Result 处理潜在的失败”中讨论过）。我们会用同样的方式来处理这个 Result，也就是再次使用 expect 方法。如果 parse 因为无法从字符串创建数字而返回 Result 的 Err 变体，expect 调用就会让游戏崩溃，并打印我们传给它的信息。如果 parse 能够成功地把字符串转换成数字，它就会返回 Result 的 Ok 变体，而 expect 会返回 Ok 值中我们想要的那个数字。

猜对后退出

我们来添加一条 break 语句，让游戏在用户获胜时退出：

文件名：src/main.rs

use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    println!("The secret number is: {secret_number}");

    loop {
        println!("Please input your guess.");

        let mut guess = String::new();

        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");

        let guess: u32 = guess.trim().parse().expect("Please type a number!");

        println!("You guessed: {guess}");

        // --snip--

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Too small!"),
            Ordering::Greater => println!("Too big!"),
            Ordering::Equal => {
                println!("You win!");
                break;
            }
        }
    }
}

在 You win! 之后添加 break 这一行，就能让程序在用户猜中秘密数字时退出循环。退出循环也就意味着退出程序，因为循环是 main 的最后一部分。

处理无效输入

为了进一步完善游戏的行为，当用户输入非数字时，我们不再让程序崩溃，而是让游戏忽略这个非数字，以便用户可以继续猜。我们可以通过修改把 guess 从 String 转换为 u32 的那一行来实现这一点，如示例 2-5 所示。

我们把 expect 调用换成了 match 表达式，从遇到错误就崩溃转变为处理错误。记住，parse 返回一个 Result 类型，而 Result 是一个拥有 Ok 和 Err 变体的枚举。这里我们使用了一个 match 表达式，就像之前处理 cmp 方法返回的 Ordering 结果时那样。

如果 parse 能够成功地把字符串转换成数字，它就会返回一个包含所得数字的 Ok 值。这个 Ok 值会与第一个分支的模式相匹配，match 表达式会直接返回 parse 生成并放入 Ok 值中的 num 值。这个数字最终会恰好出现在我们想要的位置，也就是我们正在创建的新变量 guess 中。

如果 parse 无法把字符串转换成数字，它就会返回一个包含更多错误信息的 Err 值。这个 Err 值与第一个 match 分支中的 Ok(num) 模式不匹配，但与第二个分支中的 Err(_) 模式相匹配。下划线 _ 是一个通配值；在本例中，我们的意思是要匹配所有的 Err 值，不管其中包含什么信息。因此，程序会执行第二个分支的代码 continue，它告诉程序进入 loop 的下一次迭代，并要求用户再猜一次。所以实际上，程序会忽略 parse 可能遇到的所有错误！
