Rust 程序设计语言

用 trait 定义共同行为

trait 定义了某个特定类型所具有的、并且可以与其他类型共享的功能。我们可以使用 trait 以抽象的方式定义共同行为。我们还可以使用 trait bound 来指定泛型类型可以是任何具有特定行为的类型。

注意：trait 类似于其他语言中常被称为接口（interfaces）的功能，尽管两者之间存在一些差异。

定义 trait

一个类型的行为由我们可以在该类型上调用的方法构成。如果我们可以在不同类型上调用相同的方法，那么这些类型就共享了相同的行为。trait 定义是一种把方法签名组合在一起的方式，用来定义实现某种目的所必需的一组行为。

例如，假设我们有多个结构体，存放着不同种类和数量的文本：NewsArticle 结构体存放在某个特定地点发布的新闻报道；SocialPost 最多可以包含 280 个字符，还带有元数据，用来表明它是一条新帖子、一条转发，还是对另一条帖子的回复。

我们想创建一个名为 aggregator 的媒体聚合器库 crate，用来显示可能存储在 NewsArticle 或 SocialPost 实例中的数据的摘要。为此，我们需要从每种类型中获取摘要，而获取摘要的方式是在实例上调用 summarize 方法。示例 10-12 展示了一个公有的 Summary trait 的定义，它表达了这种行为。

这里，我们使用 trait 关键字声明一个 trait，后面跟着 trait 的名称，本例中是 Summary。我们还把这个 trait 声明为 pub，这样依赖于这个 crate 的其他 crate 也可以使用这个 trait，我们会在后面的几个例子中看到这一点。在花括号中，我们声明描述实现这个 trait 的类型所具有的行为的方法签名，在本例中是 fn summarize(&self) -> String。

在方法签名之后，我们没有在花括号中提供实现，而是使用了分号。每个实现这个 trait 的类型都必须为这个方法体提供自己的定制行为。编译器会确保任何具有 Summary trait 的类型都定义了签名与此完全一致的 summarize 方法。

一个 trait 的主体中可以有多个方法：方法签名每行列出一个，每行都以分号结尾。

为类型实现 trait

现在我们已经定义了 Summary trait 中方法应有的签名，接下来就可以在媒体聚合器中的类型上实现它了。示例 10-13 展示了在 NewsArticle 结构体上对 Summary trait 的实现，它使用标题、作者和地点来创建 summarize 的返回值。对于 SocialPost 结构体，我们把 summarize 定义为用户名后跟帖子的完整文本，并假设帖子内容已经被限制在 280 个字符以内。

在类型上实现 trait 与实现普通方法类似。不同之处在于，在 impl 之后，我们要写上想要实现的 trait 的名称，接着使用 for 关键字，然后指定要为其实现该 trait 的类型名称。在 impl 块中，我们写出 trait 定义中已经定义好的方法签名。不过，我们不再在每个签名后面加分号，而是使用花括号，并在方法体中填入我们希望该 trait 的方法在这个特定类型上所具有的具体行为。

既然库已经在 NewsArticle 和 SocialPost 上实现了 Summary trait，crate 的用户就可以像调用普通方法一样，在 NewsArticle 和 SocialPost 的实例上调用 trait 方法了。唯一的区别是，用户除了要把类型引入作用域，还必须把 trait 也引入作用域。下面是一个二进制 crate 使用我们的 aggregator 库 crate 的示例：

use aggregator::{SocialPost, Summary};

fn main() {
    let post = SocialPost {
        username: String::from("horse_ebooks"),
        content: String::from(
            "of course, as you probably already know, people",
        ),
        reply: false,
        repost: false,
    };

    println!("1 new post: {}", post.summarize());
}

这段代码会打印 1 new post: horse_ebooks: of course, as you probably already know, people。

依赖于 aggregator crate 的其他 crate 也可以把 Summary trait 引入作用域，从而在它们自己的类型上实现 Summary。需要注意的一个限制是：只有当 trait 或类型二者至少有一个是我们 crate 本地定义的时候，我们才能在该类型上实现该 trait。例如，我们可以在 aggregator crate 的功能中，为 SocialPost 这样的自定义类型实现标准库中的 Display 这样的 trait，因为 SocialPost 类型是 aggregator crate 本地的。我们也可以在 aggregator crate 中为 Vec<T> 实现 Summary，因为 Summary trait 是 aggregator crate 本地的。

但是我们不能为外部类型实现外部 trait。例如，我们不能在 aggregator crate 中为 Vec<T> 实现 Display trait，因为 Display 和 Vec<T> 都定义在标准库中，都不是 aggregator crate 本地的。这条限制是被称为一致性（coherence）的性质的一部分，更具体地说，它属于孤儿规则（orphan rule），之所以这样命名，是因为它的父类型不存在。这条规则确保了其他人编写的代码不会破坏你的代码，反之亦然。如果没有这条规则，两个 crate 就可以为同一个类型实现同一个 trait，Rust 将无法知道应该使用哪个实现。

使用默认实现

有时候，为 trait 中的部分或全部方法提供默认行为会很有用，这样就不必要求每个类型都实现所有方法。然后，当我们在某个特定类型上实现这个 trait 时，可以选择保留或覆盖每个方法的默认行为。

在示例 10-14 中，我们为 Summary trait 的 summarize 方法指定了一个默认字符串，而不是像示例 10-12 那样只定义方法签名。

如果想使用默认实现来为 NewsArticle 的实例生成摘要，我们只需用 impl Summary for NewsArticle {} 指定一个空的 impl 块。

虽然我们不再直接在 NewsArticle 上定义 summarize 方法，但我们提供了一个默认实现，并且指定了 NewsArticle 实现 Summary trait。因此，我们仍然可以在 NewsArticle 的实例上调用 summarize 方法，如下所示：

use aggregator::{self, NewsArticle, Summary};

fn main() {
    let article = NewsArticle {
        headline: String::from("Penguins win the Stanley Cup Championship!"),
        location: String::from("Pittsburgh, PA, USA"),
        author: String::from("Iceburgh"),
        content: String::from(
            "The Pittsburgh Penguins once again are the best \
             hockey team in the NHL.",
        ),
    };

    println!("New article available! {}", article.summarize());
}

这段代码会打印 New article available! (Read more...)。

创建默认实现并不需要我们对示例 10-13 中 SocialPost 上的 Summary 实现做任何修改。原因在于，覆盖默认实现的语法与实现没有默认实现的 trait 方法的语法是相同的。

默认实现可以调用同一个 trait 中的其他方法，即使那些方法没有默认实现。这样一来，trait 就可以提供很多有用的功能，而只要求实现者指定其中的一小部分。例如，我们可以把 Summary trait 定义为拥有一个必须实现的 summarize_author 方法，然后再定义一个带有默认实现的 summarize 方法，由它来调用 summarize_author 方法：

pub trait Summary {
    fn summarize_author(&self) -> String;

    fn summarize(&self) -> String {
        format!("(Read more from {}...)", self.summarize_author())
    }
}

pub struct SocialPost {
    pub username: String,
    pub content: String,
    pub reply: bool,
    pub repost: bool,
}

impl Summary for SocialPost {
    fn summarize_author(&self) -> String {
        format!("@{}", self.username)
    }
}

要使用这个版本的 Summary，我们在类型上实现该 trait 时只需要定义 summarize_author：

pub trait Summary {
    fn summarize_author(&self) -> String;

    fn summarize(&self) -> String {
        format!("(Read more from {}...)", self.summarize_author())
    }
}

pub struct SocialPost {
    pub username: String,
    pub content: String,
    pub reply: bool,
    pub repost: bool,
}

impl Summary for SocialPost {
    fn summarize_author(&self) -> String {
        format!("@{}", self.username)
    }
}

定义了 summarize_author 之后，我们就可以在 SocialPost 结构体的实例上调用 summarize 了，而 summarize 的默认实现会调用我们提供的 summarize_author 定义。因为我们实现了 summarize_author，Summary trait 就为我们提供了 summarize 方法的行为，而无需我们再编写任何代码。效果如下：

use aggregator::{self, SocialPost, Summary};

fn main() {
    let post = SocialPost {
        username: String::from("horse_ebooks"),
        content: String::from(
            "of course, as you probably already know, people",
        ),
        reply: false,
        repost: false,
    };

    println!("1 new post: {}", post.summarize());
}

这段代码会打印 1 new post: (Read more from @horse_ebooks...)。

注意，无法在某个方法的覆盖实现中调用该方法的默认实现。

使用 trait 作为参数

既然你已经知道了如何定义和实现 trait，我们就可以探索如何使用 trait 来定义接受多种不同类型的函数了。我们将使用示例 10-13 中在 NewsArticle 和 SocialPost 类型上实现的 Summary trait，定义一个 notify 函数，它会调用其参数 item 上的 summarize 方法，而 item 是某个实现了 Summary trait 的类型。为此，我们使用 impl Trait 语法，如下所示：

pub trait Summary {
    fn summarize(&self) -> String;
}

pub struct NewsArticle {
    pub headline: String,
    pub location: String,
    pub author: String,
    pub content: String,
}

impl Summary for NewsArticle {
    fn summarize(&self) -> String {
        format!("{}, by {} ({})", self.headline, self.author, self.location)
    }
}

pub struct SocialPost {
    pub username: String,
    pub content: String,
    pub reply: bool,
    pub repost: bool,
}

impl Summary for SocialPost {
    fn summarize(&self) -> String {
        format!("{}: {}", self.username, self.content)
    }
}

pub fn notify(item: &impl Summary) {
    println!("Breaking news! {}", item.summarize());
}

我们没有为 item 参数指定具体类型，而是指定了 impl 关键字和 trait 名称。这个参数接受任何实现了指定 trait 的类型。在 notify 的函数体中，我们可以在 item 上调用任何来自 Summary trait 的方法，比如 summarize。我们可以调用 notify 并传入任意 NewsArticle 或 SocialPost 的实例。而用其他任何类型（比如 String 或 i32）调用该函数的代码则无法编译，因为这些类型没有实现 Summary。

trait bound 语法

impl Trait 语法适用于简单直观的情况，但它实际上是一种更长形式的语法糖，这种更长的形式称为 trait bound，它看起来像这样：

pub fn notify<T: Summary>(item: &T) {
    println!("Breaking news! {}", item.summarize());
}

这种更长的形式与上一节中的例子是等价的，只是更啰嗦一些。我们把 trait bound 与泛型类型参数的声明放在一起，位于尖括号中、冒号之后。

impl Trait 语法很方便，在简单的情况下能让代码更简洁；而更完整的 trait bound 语法则能在其他情况下表达更复杂的需求。例如，我们可以有两个实现了 Summary 的参数。使用 impl Trait 语法的写法如下：

pub fn notify(item1: &impl Summary, item2: &impl Summary) {

如果我们希望这个函数允许 item1 和 item2 具有不同的类型（只要两者都实现了 Summary），那么使用 impl Trait 是合适的。但如果我们想强制两个参数具有相同的类型，就必须使用 trait bound，如下所示：

pub fn notify<T: Summary>(item1: &T, item2: &T) {

被指定为 item1 和 item2 参数类型的泛型类型 T 约束了这个函数，使得作为 item1 和 item2 实参传入的值的具体类型必须相同。

使用 + 语法指定多个 trait bound

我们还可以指定多个 trait bound。假设我们希望 notify 既能在 item 上调用 summarize，又能对它使用显示格式化：我们就要在 notify 的定义中指定 item 必须同时实现 Display 和 Summary。这可以通过 + 语法来实现：

pub fn notify(item: &(impl Summary + Display)) {

+ 语法同样适用于泛型类型上的 trait bound：

pub fn notify<T: Summary + Display>(item: &T) {

指定了这两个 trait bound 之后，notify 的函数体就可以调用 summarize，并使用 {} 来格式化 item 了。

使用 where 子句让 trait bound 更清晰

使用过多的 trait bound 也有缺点。每个泛型都有自己的 trait bound，所以有多个泛型类型参数的函数可能会在函数名和参数列表之间包含大量的 trait bound 信息，使函数签名难以阅读。为此，Rust 提供了另一种语法，可以在函数签名之后的 where 子句中指定 trait bound。所以，与其这样写：

fn some_function<T: Display + Clone, U: Clone + Debug>(t: &T, u: &U) -> i32 {

不如像这样使用 where 子句：

fn some_function<T, U>(t: &T, u: &U) -> i32
where
    T: Display + Clone,
    U: Clone + Debug,
{
    unimplemented!()
}

这个函数的签名就没那么杂乱了：函数名、参数列表和返回类型挨在一起，就像一个没有很多 trait bound 的函数一样。

返回实现了 trait 的类型

我们也可以在返回值的位置使用 impl Trait 语法，来返回某个实现了某个 trait 的类型的值，如下所示：

pub trait Summary {
    fn summarize(&self) -> String;
}

pub struct NewsArticle {
    pub headline: String,
    pub location: String,
    pub author: String,
    pub content: String,
}

impl Summary for NewsArticle {
    fn summarize(&self) -> String {
        format!("{}, by {} ({})", self.headline, self.author, self.location)
    }
}

pub struct SocialPost {
    pub username: String,
    pub content: String,
    pub reply: bool,
    pub repost: bool,
}

impl Summary for SocialPost {
    fn summarize(&self) -> String {
        format!("{}: {}", self.username, self.content)
    }
}

fn returns_summarizable() -> impl Summary {
    SocialPost {
        username: String::from("horse_ebooks"),
        content: String::from(
            "of course, as you probably already know, people",
        ),
        reply: false,
        repost: false,
    }
}

通过使用 impl Summary 作为返回类型，我们指定了 returns_summarizable 函数返回某个实现了 Summary trait 的类型，而无需指明具体类型。在本例中，returns_summarizable 返回的是一个 SocialPost，但调用这个函数的代码并不需要知道这一点。

只通过所实现的 trait 来指定返回类型的能力，在闭包和迭代器的场景中特别有用，我们会在第 13 章介绍它们。闭包和迭代器会创建只有编译器才知道的类型，或者写出来非常长的类型。impl Trait 语法让你可以简洁地指定函数返回某个实现了 Iterator trait 的类型，而无需写出一个很长的类型。

不过，只有在返回单一类型时才能使用 impl Trait。例如，下面这段代码把返回类型指定为 impl Summary，却可能返回 NewsArticle 或 SocialPost，这是行不通的：

pub trait Summary {
    fn summarize(&self) -> String;
}

pub struct NewsArticle {
    pub headline: String,
    pub location: String,
    pub author: String,
    pub content: String,
}

impl Summary for NewsArticle {
    fn summarize(&self) -> String {
        format!("{}, by {} ({})", self.headline, self.author, self.location)
    }
}

pub struct SocialPost {
    pub username: String,
    pub content: String,
    pub reply: bool,
    pub repost: bool,
}

impl Summary for SocialPost {
    fn summarize(&self) -> String {
        format!("{}: {}", self.username, self.content)
    }
}

fn returns_summarizable(switch: bool) -> impl Summary {
    if switch {
        NewsArticle {
            headline: String::from(
                "Penguins win the Stanley Cup Championship!",
            ),
            location: String::from("Pittsburgh, PA, USA"),
            author: String::from("Iceburgh"),
            content: String::from(
                "The Pittsburgh Penguins once again are the best \
                 hockey team in the NHL.",
            ),
        }
    } else {
        SocialPost {
            username: String::from("horse_ebooks"),
            content: String::from(
                "of course, as you probably already know, people",
            ),
            reply: false,
            repost: false,
        }
    }
}

由于编译器中 impl Trait 语法的实现方式所带来的限制，返回 NewsArticle 或 SocialPost 二者之一是不允许的。我们会在第 18 章“使用 trait 对象抽象共同行为”部分介绍如何编写具有这种行为的函数。

使用 trait bound 有条件地实现方法

通过在使用泛型类型参数的 impl 块上使用 trait bound，我们可以为实现了指定 trait 的类型有条件地实现方法。例如，示例 10-15 中的 Pair<T> 类型总是会实现 new 函数，用来返回一个新的 Pair<T> 实例（回忆一下第 5 章“方法语法”部分的内容：Self 是 impl 块所对应类型的类型别名，在本例中就是 Pair<T>）。但在下一个 impl 块中，只有当 Pair<T> 的内部类型 T 实现了支持比较的 PartialOrd trait，并且实现了支持打印的 Display trait 时，Pair<T> 才会实现 cmp_display 方法。

我们也可以为任何实现了另一个 trait 的类型有条件地实现某个 trait。为满足 trait bound 的任意类型实现某个 trait，这样的实现称为覆盖实现（blanket implementations），它们在 Rust 标准库中被广泛使用。例如，标准库为任何实现了 Display trait 的类型实现了 ToString trait。标准库中的这个 impl 块看起来类似于下面的代码：

impl<T: Display> ToString for T {
    // --snip--
}

因为标准库有这个覆盖实现，所以我们可以在任何实现了 Display trait 的类型上调用 ToString trait 定义的 to_string 方法。例如，由于整数实现了 Display，我们可以像这样把整数转换为对应的 String 值：

#![allow(unused)]
fn main() {
let s = 3.to_string();
}

覆盖实现会出现在该 trait 文档的“Implementors”（实现者）部分。

trait 和 trait bound 让我们能够编写使用泛型类型参数的代码来减少重复，同时又能向编译器指明我们希望泛型类型具有特定的行为。之后，编译器就可以利用 trait bound 信息来检查我们代码中用到的所有具体类型是否都提供了正确的行为。在动态类型语言中，如果在一个没有定义某个方法的类型上调用该方法，我们会在运行时得到错误。而 Rust 把这些错误提前到了编译时，迫使我们在代码能够运行之前就修复这些问题。此外，我们也不必编写在运行时检查行为的代码，因为我们已经在编译时检查过了。这样做既提升了性能，又不必放弃泛型的灵活性。
