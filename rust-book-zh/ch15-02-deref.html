Rust 程序设计语言

像普通引用一样使用智能指针

实现 Deref trait 允许你自定义解引用运算符（dereference operator）* 的行为（不要与乘法运算符或 glob 运算符相混淆）。通过实现 Deref，让智能指针可以被当作普通引用来对待，你就可以编写操作引用的代码，并把这些代码同样用于智能指针。

我们先来看看解引用运算符是如何作用于普通引用的。接着，我们会尝试定义一个行为类似 Box<T> 的自定义类型，看看为什么解引用运算符在我们新定义的类型上无法像在引用上那样工作。我们会探究实现 Deref trait 是如何让智能指针以类似引用的方式工作的。然后，我们会了解 Rust 的解引用强制转换功能，以及它是如何让我们既能处理引用也能处理智能指针的。

沿着引用找到值

普通引用是一种指针，可以把指针理解为一个指向存储在别处的值的箭头。在示例 15-6 中，我们创建了一个指向 i32 值的引用，然后使用解引用运算符沿着这个引用找到它指向的值。

变量 x 存储了一个 i32 值 5。我们让 y 等于 x 的引用。我们可以断言 x 等于 5。然而，如果想对 y 中的值做断言，就必须使用 *y 沿着引用找到它所指向的值（这就是解引用），这样编译器才能比较实际的值。一旦对 y 解引用，我们就能访问 y 所指向的整数值，并将其与 5 进行比较。

如果我们尝试改写成 assert_eq!(5, y);，就会得到如下编译错误：

  |

不允许比较一个数字和一个数字的引用，因为它们是不同的类型。我们必须使用解引用运算符沿着引用找到它所指向的值。

像引用一样使用 Box<T>

我们可以把示例 15-6 中的代码改写为使用 Box<T> 而不是引用；在示例 15-7 中，作用于 Box<T> 的解引用运算符与示例 15-6 中作用于引用的解引用运算符的工作方式完全相同。

示例 15-7 与示例 15-6 的主要区别在于，这里我们把 y 设置为一个指向 x 的复制值的 box 实例，而不是指向 x 值的引用。在最后的断言中，我们可以像 y 是引用时那样，使用解引用运算符沿着 box 的指针找到值。接下来，我们会通过定义自己的 box 类型，来探究 Box<T> 有什么特别之处，使得我们能够对它使用解引用运算符。

定义我们自己的智能指针

我们来构建一个类似于标准库所提供的 Box<T> 类型的包装类型，以体会智能指针类型在默认情况下的行为与引用有何不同。然后，我们会看看如何为它添加使用解引用运算符的能力。

注意：我们即将构建的 MyBox<T> 类型与真正的 Box<T> 有一个很大的区别：我们的版本不会把数据存储在堆上。这个示例的重点在于 Deref，因此数据实际存储在哪里，远不如类似指针的行为重要。

Box<T> 类型最终被定义为只有一个元素的元组结构体，因此示例 15-8 以同样的方式定义了 MyBox<T> 类型。我们还会定义一个 new 函数，与 Box<T> 上定义的 new 函数相对应。

我们定义了一个名为 MyBox 的结构体，并声明了一个泛型参数 T，因为我们希望这个类型能存储任意类型的值。MyBox 类型是一个元组结构体，带有一个 T 类型的元素。MyBox::new 函数接受一个 T 类型的参数，并返回一个存储了传入值的 MyBox 实例。

我们来试着把示例 15-7 中的 main 函数添加到示例 15-8 中，并把它改为使用我们定义的 MyBox<T> 类型而不是 Box<T>。示例 15-9 中的代码无法编译，因为 Rust 不知道如何对 MyBox 解引用。

得到的编译错误如下：

$ cargo run
   Compiling deref-example v0.1.0 (file:///projects/deref-example)
error[E0614]: type `MyBox<{integer}>` cannot be dereferenced
  --> src/main.rs:14:19
   |
14 |     assert_eq!(5, *y);
   |                   ^^ can't be dereferenced

For more information about this error, try `rustc --explain E0614`.
error: could not compile `deref-example` (bin "deref-example") due to 1 previous error

我们的 MyBox<T> 类型无法被解引用，因为我们还没有为这个类型实现这种能力。要启用 * 运算符的解引用功能，我们需要实现 Deref trait。

实现 Deref trait

正如第 10 章“为类型实现 trait”中所讨论的，要实现一个 trait，我们需要为该 trait 所要求的方法提供实现。标准库提供的 Deref trait 要求我们实现一个名为 deref 的方法，该方法借用 self 并返回一个指向内部数据的引用。示例 15-10 包含了一个要添加到 MyBox<T> 定义中的 Deref 实现。

type Target = T; 语法为 Deref trait 定义了一个关联类型以供其使用。关联类型是声明泛型参数的一种稍有不同的方式，不过你现在无需担心它们；我们会在第 20 章更详细地介绍它们。

我们在 deref 方法体中填入 &self.0，这样 deref 就会返回一个引用，指向我们想通过 * 运算符访问的值；回想一下第 5 章“使用元组结构体创建不同的类型”中讲过，.0 用于访问元组结构体中的第一个值。现在，示例 15-9 中对 MyBox<T> 值调用 * 的 main 函数可以编译了，而且断言也都通过了！

没有 Deref trait 的话，编译器只能对 & 引用进行解引用。deref 方法让编译器能够获取任何实现了 Deref 的类型的值，并调用 deref 方法得到一个它知道如何解引用的引用。

当我们在示例 15-9 中输入 *y 时，Rust 在幕后实际上运行了如下代码：

*(y.deref())

Rust 将 * 运算符替换为先调用 deref 方法、再进行一次普通的解引用，这样我们就不必考虑是否需要调用 deref 方法了。Rust 的这个特性让我们编写的代码无论面对的是普通引用还是实现了 Deref 的类型，都能以同样的方式运行。

deref 方法之所以返回值的引用，并且 *(y.deref()) 中括号外面的普通解引用仍然必不可少，与所有权系统有关。如果 deref 方法直接返回值而不是值的引用，那么这个值就会被移出 self。在这个例子中，以及在大多数使用解引用运算符的情况下，我们都不希望获取 MyBox<T> 内部值的所有权。

注意，每当我们在代码中使用一次 * 时，* 运算符都只会被替换一次：先调用 deref 方法，再调用 * 运算符。因为对 * 运算符的替换不会无限递归下去，所以我们最终得到的是 i32 类型的数据，它与示例 15-9 中 assert_eq! 里的 5 相匹配。

在函数和方法中使用解引用强制转换

解引用强制转换（deref coercion）会把一个实现了 Deref trait 的类型的引用转换为另一个类型的引用。例如，解引用强制转换可以把 &String 转换为 &str，因为 String 实现了 Deref trait，并且返回的是 &str。解引用强制转换是 Rust 对函数和方法的参数所提供的一种便利，它只作用于实现了 Deref trait 的类型。当我们把某个特定类型值的引用作为实参传给一个函数或方法，而它与函数或方法定义中的形参类型不匹配时，解引用强制转换就会自动发生。一系列对 deref 方法的调用会把我们提供的类型转换为形参所需要的类型。

Rust 之所以加入解引用强制转换，是为了让编写函数和方法调用的程序员不必添加那么多使用 & 和 * 的显式引用和解引用。解引用强制转换功能还让我们能编写更多既能用于引用、也能用于智能指针的代码。

为了实际看看解引用强制转换的效果，我们来使用示例 15-8 中定义的 MyBox<T> 类型以及示例 15-10 中为它添加的 Deref 实现。示例 15-11 展示了一个带有字符串切片形参的函数的定义。

我们可以用一个字符串切片作为实参来调用 hello 函数，例如 hello("Rust");。解引用强制转换使得我们可以用一个 MyBox<String> 类型值的引用来调用 hello，如示例 15-12 所示。

这里我们用实参 &m 调用 hello 函数，它是一个 MyBox<String> 值的引用。因为我们在示例 15-10 中为 MyBox<T> 实现了 Deref trait，Rust 可以通过调用 deref 把 &MyBox<String> 转换为 &String。标准库为 String 提供了一个返回字符串切片的 Deref 实现，这一点可以在 Deref 的 API 文档中找到。Rust 再次调用 deref，把 &String 转换为 &str，这就与 hello 函数的定义相匹配了。

如果 Rust 没有实现解引用强制转换，那么为了用 &MyBox<String> 类型的值调用 hello，我们就不得不编写示例 15-13 中的代码，而不是示例 15-12 中的代码。

(*m) 将 MyBox<String> 解引用为 String。然后，& 和 [..] 获取 String 的一个与整个字符串相等的字符串切片，以匹配 hello 的签名。没有解引用强制转换的这段代码充斥着各种符号，更难以阅读、编写和理解。解引用强制转换让 Rust 能够自动为我们处理这些转换。

当所涉及的类型定义了 Deref trait 时，Rust 会分析这些类型，并根据需要多次使用 Deref::deref，以获得与形参类型相匹配的引用。需要插入多少次 Deref::deref 是在编译时确定的，因此利用解引用强制转换不会带来任何运行时开销！

处理可变引用的解引用强制转换

类似于使用 Deref trait 重载不可变引用上的 * 运算符，你可以使用 DerefMut trait 重载可变引用上的 * 运算符。

当 Rust 发现类型和 trait 实现满足以下三种情况时，会进行解引用强制转换：

  1. 当 T: Deref<Target=U> 时，从 &T 转换到 &U
  2. 当 T: DerefMut<Target=U> 时，从 &mut T 转换到 &mut U
  3. 当 T: Deref<Target=U> 时，从 &mut T 转换到 &U

前两种情况除了第二种涉及可变性之外，其余完全相同。第一种情况表明，如果你有一个 &T，并且 T 实现了到某个类型 U 的 Deref，你就可以透明地得到一个 &U。第二种情况表明，同样的解引用强制转换也会发生在可变引用上。

第三种情况比较微妙：Rust 也会把可变引用强制转换为不可变引用。但反过来是不可能的：不可变引用永远不会被强制转换为可变引用。根据借用规则，如果你有一个可变引用，那么这个可变引用必须是该数据的唯一引用（否则程序将无法编译）。把一个可变引用转换为一个不可变引用永远不会违反借用规则。而把一个不可变引用转换为可变引用，则要求最初的那个不可变引用是该数据唯一的不可变引用，但借用规则并不能保证这一点。因此，Rust 不能假设把不可变引用转换为可变引用是可行的。
