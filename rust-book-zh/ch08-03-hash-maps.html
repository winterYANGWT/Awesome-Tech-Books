使用哈希 map 存储键及其关联值

我们要介绍的最后一种常见集合是哈希 map。HashMap<K, V> 类型使用哈希函数（hashing function）来存储从 K 类型的键到 V 类型的值的映射，哈希函数决定了如何将这些键和值放入内存中。许多编程语言都支持这种数据结构，但它们往往使用不同的名字，例如哈希（hash）、映射（map）、对象（object）、哈希表（hash table）、字典（dictionary）或关联数组（associative array），这里仅举几例。

当你不想像使用 vector 那样通过索引来查找数据，而是想通过一个可以是任意类型的键来查找时，哈希 map 就很有用。例如，在一个游戏中，你可以用哈希 map 记录每支队伍的分数，其中每个键是一支队伍的名字，值是每支队伍的分数。给定一个队名，你就能获取它的分数。

本节会介绍哈希 map 的基本 API，不过标准库在 HashMap<K, V> 上定义的函数中还藏着许多好东西。一如既往，请查阅标准库文档来了解更多信息。

和 vector 一样，哈希 map 也将数据存储在堆上。这个 HashMap 的键是 String 类型，值是 i32 类型。与 vector 一样，哈希 map 是同质的：所有的键必须是相同类型，所有的值也必须是相同类型。

这里，score 将得到与 Blue 队关联的值，结果是 10。get 方法返回一个 Option<&V>；如果哈希 map 中没有该键对应的值，get 就会返回 None。这个程序处理 Option 的方式是：先调用 copied 得到一个 Option<i32> 而不是 Option<&i32>，再调用 unwrap_or，在 scores 中没有该键对应的条目时将 score 设置为零。

我们可以用与 vector 类似的方式，使用 for 循环遍历哈希 map 中的每一个键值对：

fn main() {
    use std::collections::HashMap;

    let mut scores = HashMap::new();

    scores.insert(String::from("Blue"), 10);
    scores.insert(String::from("Yellow"), 50);

    for (key, value) in &scores {
        println!("{key}: {value}");
    }
}

这段代码会以任意顺序打印出每一个键值对：

Yellow: 50
Blue: 10

哈希 map 中的所有权管理

对于像 i32 这样实现了 Copy trait 的类型，值会被复制到哈希 map 中。对于像 String 这样拥有所有权的值，值会被移动，而哈希 map 会成为这些值的所有者，如示例 8-22 所示。

在调用 insert 将变量 field_name 和 field_value 移动到哈希 map 中之后，我们就无法再使用它们了。

如果我们将值的引用插入哈希 map，这些值本身不会被移动到哈希 map 中。引用所指向的值必须至少在哈希 map 有效期间一直有效。我们会在第 10 章“用生命周期验证引用”部分中进一步讨论这些问题。

更新哈希 map

尽管键值对的数量可以增长，但每个唯一的键在同一时刻只能关联一个值（反之则不然：例如，Blue 队和 Yellow 队在 scores 哈希 map 中存储的值都可以是 10）。

当你想要修改哈希 map 中的数据时，必须决定如何处理一个键已经被赋值的情况。你可以用新值替换旧值，完全不理会旧值。你也可以保留旧值而忽略新值，只有在键还没有值时才添加新值。或者，你可以把旧值和新值结合起来。我们来看看每种做法该如何实现！

覆盖一个值

如果我们向哈希 map 中插入一个键和一个值，然后又用一个不同的值插入同一个键，那么与该键关联的值就会被替换。尽管示例 8-23 中的代码调用了两次 insert，但哈希 map 只会包含一个键值对，因为我们两次插入的都是 Blue 队这个键的值。

仅在键不存在时插入键和值

一种常见的做法是检查哈希 map 中某个特定的键是否已经存在并有值，然后采取如下行动：如果该键在哈希 map 中确实存在，那么已有的值应保持不变；如果该键不存在，就插入这个键以及它对应的值。

哈希 map 为此提供了一个名为 entry 的特殊 API，它接受你想要检查的键作为参数。entry 方法的返回值是一个名为 Entry 的枚举，它代表一个可能存在也可能不存在的值。假设我们想检查 Yellow 队的键是否已经关联了一个值。如果没有，我们就插入值 50，对 Blue 队也做同样的处理。使用 entry API 的代码如示例 8-24 所示。

Entry 上的 or_insert 方法被定义为：如果对应 Entry 的键存在，就返回该键对应值的可变引用；如果不存在，就将参数作为该键的新值插入，并返回这个新值的可变引用。这种技术比我们自己编写这些逻辑要简洁得多，此外，它与借用检查器配合得也更好。

运行示例 8-24 中的代码会打印 {"Yellow": 50, "Blue": 10}。第一次调用 entry 时，会插入 Yellow 队的键，其值为 50，因为 Yellow 队还没有值。第二次调用 entry 不会改变哈希 map，因为 Blue 队已经有值 10 了。

哈希函数

默认情况下，HashMap 使用一种名为 SipHash 的哈希函数，它能够抵御涉及哈希表的拒绝服务（DoS）攻击1。这并不是现有最快的哈希算法，但为了更好的安全性而牺牲一些性能是值得的。如果你对代码进行性能分析后发现默认的哈希函数对你的用途来说太慢，可以通过指定不同的 hasher 来切换到其他函数。hasher 是一个实现了 BuildHasher trait 的类型。我们会在第 10 章中讨论 trait 以及如何实现它们。你不一定非要从头实现自己的 hasher；crates.io 上有其他 Rust 用户分享的库，提供了实现许多常见哈希算法的 hasher。

总结

当你需要在程序中存储、访问和修改数据时，vector、字符串和哈希 map 会提供大量必要的功能。下面是一些你现在应该已经有能力解决的练习：

  1. 给定一个整数列表，使用 vector 并返回这个列表的中位数（排序后位于中间位置的值）和众数（出现次数最多的值；哈希 map 在这里会很有帮助）。
  2. 将字符串转换为猪拉丁语（Pig Latin）。每个单词的第一个辅音字母会被移到单词末尾，并加上 ay，所以 first 会变成 irst-fay。以元音字母开头的单词则改为在末尾加上 hay（apple 会变成 apple-hay）。请牢记有关 UTF-8 编码的细节！
  3. 使用哈希 map 和 vector，创建一个文本界面，让用户可以将员工姓名添加到公司的某个部门中；例如，“Add Sally to Engineering”或“Add Amir to Sales”。然后，让用户可以获取某个部门的所有人员列表，或者按部门列出公司的所有人员，并按字母顺序排序。

标准库 API 文档中介绍了 vector、字符串和哈希 map 所拥有的方法，它们对完成这些练习会很有帮助！
